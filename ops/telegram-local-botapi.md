# Свой Bot API сервер — как включить и как откатить

Зачем: облако Telegram разрешает боту **отправить 50 МБ** и **скачать 20 МБ**.
Свой сервер с `--local` снимает оба предела — дословно из
[core.telegram.org/bots/api](https://core.telegram.org/bots/api): «Download files
without a size limit», «Upload files up to 2000 MB», «Receive the absolute local
path as a value of the `file_path` field». Нужно монтажёру: обзор квартиры на
полторы минуты в исходном качестве не проходит ни туда, ни обратно.

Пока переменные ниже пусты, **ничего не меняется**: бот ходит в облако, как ходил.

---

## 0. Что понадобится от владельца

**`api_id` и `api_hash`** — «The only mandatory options are `--api-id` and
`--api-hash`». Берутся на **my.telegram.org** (инструкция:
core.telegram.org/api/obtaining_api_id), вход по номеру телефона с кодом из
Telegram. Это учётные данные **приложения**, а не бота: с токеном бота они никак
не связаны и его не заменяют.

Агент этот шаг сделать не может и не должен — коды и пароли вводит только владелец.

---

## 1. Выбрать образ

**Официального докер-образа у Telegram нет** — README проекта
[tdlib/telegram-bot-api](https://github.com/tdlib/telegram-bot-api) предлагает
собирать из исходников. Поэтому образ задаётся переменной, а не прибит в файле:

```
TELEGRAM_BOT_API_IMAGE=<образ>
```

Два честных варианта:

- **Готовый образ сообщества.** Быстро, но это чужая сборка с нашим токеном
  внутри контейнера — доверие к сопровождающему обязательно.
- **Своя сборка из исходников.** Чисто по цепочке поставки, но сборка TDLib
  тяжёлая (долго и требовательна к памяти) — на боевом VPS её лучше не запускать
  в рабочее время, а собрать отдельно и положить образ в реестр.

Решение за владельцем. До тех пор `docker compose ... -f docker-compose.telegram.yml`
честно откажется стартовать с подсказкой вместо того, чтобы тихо взять что попало.

---

## 2. Переменные в `.env.production`

```
TELEGRAM_BOT_API_IMAGE=<выбранный образ>
TELEGRAM_API_ID=<с my.telegram.org>
TELEGRAM_API_HASH=<с my.telegram.org>

# Куда CRM обращается вместо облака
TELEGRAM_API_BASE_URL=http://telegram-bot-api:8081
# Корень тома, из которого CRM читает файлы клиентов
TELEGRAM_LOCAL_FILES_DIR=/var/lib/telegram-bot-api
```

Последние две — это и есть рубильник. Пустые = облако.

---

## 3. Переключение (окно, а не рабочий час)

**Порядок важен.** Пока бот залогинен в облаке, свой сервер получать обновления
не будет: «You must log out the bot before running it locally».

1. Снять вебхук, если он стоит:
   `curl -s "https://api.telegram.org/bot<ТОКЕН>/deleteWebhook"`
2. **Разлогинить бота в облаке:**
   `curl -s "https://api.telegram.org/bot<ТОКЕН>/logOut"`
   После этого **10 минут вернуться в облако нельзя** — Telegram не даст.
3. Прописать переменные из шага 2.
4. Поднять:
   `docker compose -f docker-compose.prod.yml -f docker-compose.telegram.yml up -d`
5. Проверить, что сервер отвечает и бот на нём живой:
   `docker compose exec api node -e "fetch(process.env.TELEGRAM_API_BASE_URL+'/bot'+process.env.TELEGRAM_BOT_TOKEN+'/getMe').then(r=>r.json()).then(d=>console.log(d))"`
   Ожидаем `ok: true` и имя бота.
6. Живая проверка: написать боту, прислать ему фото и голосовое (вложения
   клиентов — самый чувствительный путь, именно они ломаются, если абсолютные
   пути не обработаны), затем провести объект до этапа монтажа и убедиться, что
   ролик ушёл монтажёру файлом.

---

## 4. Откат

1. Очистить `TELEGRAM_API_BASE_URL` и `TELEGRAM_LOCAL_FILES_DIR`.
2. `docker compose -f docker-compose.prod.yml up -d` (без второго `-f`).
3. `curl -s "https://api.telegram.org/bot<ТОКЕН>/logOut"` — теперь уже на своём
   сервере, чтобы отпустить бота, и подождать до 10 минут.

Правок кода откат не требует ни в одну сторону.

---

## 5. Чего ждать и за чем следить

- **Надёжность бота переезжает к нам.** Пока бот в облаке, за доставку отвечает
  Telegram. После переключения упавший контейнер = молчащий бот целиком: и
  переписка с клиентами, и задачи, и ролики. `restart: unless-stopped` поднимает
  его сам, но это стоит держать в голове.
- **Диск.** Сервер хранит файлы в своём томе. При роликах в сотни мегабайт том
  растёт быстро — следить за местом и чистить.
- **Токен в пути запроса.** Порт наружу не выставлен намеренно: сервер доступен
  только контейнерам в сети compose.

## 6. Что уже сделано в коде (12.09.2026)

- `apps/api/src/telegram/api.ts` — адрес Bot API из `TELEGRAM_API_BASE_URL`
  (по умолчанию облако); два РАЗНЫХ предела вместо одного:
  `TELEGRAM_BOT_SEND_LIMIT_BYTES` (50 МБ / 2 ГБ) и
  `TELEGRAM_BOT_DOWNLOAD_LIMIT_BYTES` (20 МБ / без предела);
  `resolveTelegramFile` возвращает либо адрес, либо путь на диске.
- `apps/api/src/messengers/attachments.ts` — вложение может прийти путём, а не
  адресом; путь обязан лежать внутри `TELEGRAM_LOCAL_FILES_DIR`, иначе отвергается.
- `apps/api/src/lib/videoHandoff.ts` — монтажёру уходят ВСЕ ролики объекта
  («ролик 2 из 3»), а не только первый; предел взят правильный; тяжёлое уходит
  прямой ссылкой на скачивание (`Content-Disposition: attachment` — иначе Safari
  на iPhone открывает файл плеером вместо загрузки).
- `apps/api/src/auth/jwt.ts` — срок жизни ссылки на скачивание задаётся вызывающим;
  ссылке в сообщении даётся неделя вместо десяти минут.
