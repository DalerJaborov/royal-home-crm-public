# Диалплан станции в репозитории

`extensions_custom.conf` — единственный файл диалплана, который CRM считает своим:
контексты `royalhome-inbound`, `royalhome-agent-route`, `royalhome-agent-wait`,
`royalhome-agent-out`, `royalhome-live-voice-selftest`, `royalhome-desk-transfer`
и коды перевода в `from-internal-custom`. FreePBX этот файл не
перезаписывает при «Apply Config» — всё, что в нём есть, написано руками.

## Зачем он здесь

До 21.09.2026 файл жил **только на станции**. Его историей были десять файлов
`extensions_custom.conf.bak-*` в том же каталоге — с именами вроде `.bak-rec`,
`.bak-18-08-forward`, `.bak.direct`. Ни ревью, ни выката, ни резервной копии вне
станции: правку в нём нельзя было ни сравнить, ни откатить, ни объяснить через
полгода. При этом от него зависит, дойдёт ли входящий звонок до человека — то
есть цена ошибки в нём выше, чем у почти любого файла в `apps/`.

Копия в git не делает выкат автоматическим намеренно: станция стоит в офисе,
её конфигурацию меняет человек за терминалом, и притворяться, что это часть
конвейера CRM, значило бы обещать больше, чем есть. Здесь — **источник правды
для сравнения и восстановления**, а не деплой.

## Как сверить репозиторий со станцией

```bash
ssh rh-pbx 'cat /etc/asterisk/extensions_custom.conf' | diff -u ops/asterisk/extensions_custom.conf -
```

Пусто — расходждений нет. Есть вывод — кто-то правил станцию мимо репозитория
(или наоборот); разобраться, чья версия верна, и свести руками.

Отдельно проверка, что контексты реально на месте, уже автоматическая и живёт в
коде: `lib/telephony/dialplanContext.ts` спрашивает станцию через AMI `GetConfig`
(секция в файле) и `stationHealth.ts` — что диалплан загружен в память станции.
Эти две проверки и сверка выше отвечают на разные вопросы: «секция есть в файле»,
«станция её прочитала», «файл не разъехался с репозиторием».

## Как выкатить правку на станцию

```bash
# 1. Правим файл здесь, коммитим, ревью.
# 2. Копия на станции — с резервной, как это делалось всегда:
ssh rh-pbx 'cp /etc/asterisk/extensions_custom.conf /etc/asterisk/extensions_custom.conf.bak-$(date +%Y%m%d-%H%M%S)'
scp ops/asterisk/extensions_custom.conf rh-pbx:/etc/asterisk/extensions_custom.conf
ssh rh-pbx 'asterisk -rx "dialplan reload"'
# 3. Убедиться, что контексты загружены (не только лежат в файле):
ssh rh-pbx 'asterisk -rx "dialplan show royalhome-agent-route"'
```

**Выкат CRM этот файл НЕ ставит** (ни таймер на VPS, ни `npm run ship`): правка
здесь начинает действовать только после того, как человек сделал шаги выше на
самой станции. Живой пример — 25.09.2026: в репозитории уже была ветка
консультанта (`Stasis(royalhome-live-voice`), на станции — старая копия без неё,
и выбор «консультант вместо автоответчика» в Настройках не действовал. С 28.09
это видно в сводной проверке («Диалплан: консультант на входящих») и
предупреждением в «Бот → Живой голос».

**28.09.2026 — время в сравнениях по Душанбе.** `RH_NOW` (рабочий день
консультанта и ночной режим) теперь считается как
`STRFTIME(${EPOCH},Asia/Dushanbe,%H:%M)`, а не по часам станции: CRM кладёт
часы в AstDB по Душанбе, а на станции NTP выключен (аудит 25.09). Чтобы это
заработало, файл надо **заново поставить на станцию** шагами выше. Имена файлов
записей (`in-…-ГГГГММДД-ЧЧММСС`) по-прежнему идут по часам станции — их ищет
`callRecordings.ts`, менять их пояс отдельной правкой вместе с поиском.

`dialplan reload`, а не `fwconsole reload`: второй перегенерирует конфигурацию
FreePBX целиком и заодно перезапишет `DEVICE/<номер>/dial` из таблицы
`asterisk.devices` — то есть сотрёт мобильные плечи, которые туда пишет CRM
(`lib/telephony/agentMobileFallback.ts`). Плечи вернёт сверка по расписанию
(cron, раз в 15 минут), но до её прихода входящие у тех, у кого нет настольной
трубки, идут в пустоту.

## Чего в этом файле нет и не должно быть

Строки набора аппаратов (`DEVICE/<номер>/dial`) живут не здесь, а во внутренней
базе станции, и их ведёт CRM. Список участников очереди приёма — тоже CRM
(`lib/telephony/agentIncomingReadiness.ts`, по признаку `Agent.takesUnknownCalls`).
Правило «куда идёт входящий» (`ROYALHOME/failover/*`) — CRM, Настройки → Каналы
связи. Диалплан только читает эти значения и ни одно из них не задаёт.

## Запись разговоров (21.09.2026, владелец: «у всех и всегда»)

Два независимых места, и нужны оба:

1. **Звонки через штатные пути FreePBX** (исходящий из CRM, очередь 1000 →
   добавочный) пишутся по правилу добавочного во внутренней базе станции:
   `AMPUSER/<номер>/recording/in/external` и `.../out/external` = `always`
   (внутренние `.../internal` = `dontcare`, между сотрудниками не пишем).
   Это ЕДИНСТВЕННОЕ хранилище настройки во FreePBX 15: GUI читает и пишет её
   через AstDB (`Core.class.php`), в таблице `asterisk.users` колонка
   `recording` пустая, поэтому «Apply Config» / `fwconsole reload` значение не
   перетирает. Перетереть может только ручное сохранение добавочного в GUI с
   другим выбором. Включение для нового номера (то же делает CRM через AMI
   `DBPut`, у пользователя `royalhome-crm` есть write=system):
   ```bash
   ssh rh-pbx 'asterisk -rx "database put AMPUSER/1013 recording/in/external always"; asterisk -rx "database put AMPUSER/1013 recording/out/external always"'
   ```
2. **Свои контексты** (`royalhome-inbound` «прямо на аппарат» и дежурный,
   `royalhome-agent-route`) идут мимо макросов FreePBX, правило добавочного
   туда не доходит — запись включена в самом диалплане (`MixMonitor(…,b)`,
   файл `in-<звонящий>-<ГГГГММДД-ЧЧММСС>-<uniqueid>.wav`). В agent-route
   дополнительно ставится `__REC_STATUS=RECORDING`, чтобы при запасном пути в
   очередь FreePBX не завела второй файл `external-<номер>-…`.

## Перевод с офисного телефона агенту объекта (24.09.2026, решение Dan)

Оператор во время разговора нажимает на IP-телефоне «Перевод» и набирает `7` и
номер объекта четырьмя-пятью цифрами (объект 132 — `7132`, объект 45 — `7045`).
Коды живут в `[from-internal-custom]`, сам перевод — в `[royalhome-desk-transfer]`:
канал звонящего уходит в Stasis-приложение `royal-home-crm`, CRM
(`apps/api/src/lib/telephony/deskTransfer.ts`) звонит агенту объекта через
`royalhome-agent-route` — с подсказкой по приметам объекта, 30 секунд, не взял —
очередь операторов. CRM не на связи или объект не найден — очередь сразу.

Выкат — как любая правка выше, затем проверка, что перевод действительно
приходит в эти контексты (FreePBX кладёт перевод в `from-internal-xfer`):

```bash
ssh rh-pbx 'asterisk -rx "dialplan show 7132@from-internal"; asterisk -rx "dialplan show 7132@from-internal-xfer"'
```

В обоих ответах должен быть `royalhome-desk-transfer`. Если во втором его нет,
а перевод на аппарате идёт «вслепую» (Blind Transfer) — пришлите вывод, контекст
перевода на этой станции другой.

## Эти настройки трогать не надо — и это теперь заметно

Просьба владельца 21.09.2026: «если всё работает — сделай так, чтобы никто
больше не трогал эти настройки».

Сделано не замком, а свидетелем. Рабочие значения записаны эталоном в
`apps/api/src/lib/telephony/telephonyBaseline.ts`, и сводная проверка станции
(раз в 15 минут) сверяет с ним живое состояние. Отход попадает в журнал ошибок
именем настройки, прежним значением, новым и причиной, по которой значение
охраняется.

Замка нет намеренно: однажды настройку понадобится поменять по делу — сменится
оператор приёма, сменится номер. Запрет в этот день заблокировал бы владельца.
Поэтому изменить можно, изменить **тихо** — нельзя.

Под охраной семь вещей, и каждая стоит за реальной потерей звонков:

| Что | Почему охраняется |
|---|---|
| Приём ведёт очередь, не прямой аппарат | приём на аппарат 1003 стоил **тридцати дней тишины** (21.08–19.09.2026) |
| Известный клиент уходит своему агенту | выключено = все звонки оператору, обратное решению владельца |
| Агенту звоним на мобильный | настольных трубок нет ни у кого с 18.08.2026 |
| При неответе не «ничего не делать» | «none» = обрыв в тишине без записи, вторая половина того же простоя |
| Незнакомый ждёт 120 секунд | решение владельца 21.09.2026 |
| Есть хотя бы один оператор приёма | ноль = очередь станции пустеет за 15 минут |
| В диалплане есть ожидание вердикта CRM | без него оператор перехватывает чужих клиентов (20.09 — три раза за день) |

Поменяли по делу — обновите эталон в том же файле **вместе с причиной**, иначе
сторож будет ругаться каждые пятнадцать минут и его выключат вместе с пользой.
