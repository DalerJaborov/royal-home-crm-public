## Отличие от настоящего помощника

Скрипт использует короткую системную инструкцию: краткость, сохранение чисел и ограничений, запрет выдумывать факты CRM, простые слова. Он не загружает настоящие инструменты, историю, общую память, словарь, права сотрудника, оформления Telegram и голос. Поэтому это сравнение моделей на синтетических заданиях, а не приёмочное испытание Мадины целиком.

Настоящий `apps/api/src/ai/assistant.ts:187` требует отвечать по результатам инструментов CRM, давать ссылки в именах и не выдумывать цифры/клиентов. `personaStyle.ts` добавляет обращение на «вы», краткость и различение подготовленного/выполненного действия. `languageRouting.ts:30` просит простые разговорные слова и сохранение чисел. Словарь подмешивается по запросу. В этих инструкциях сейчас нет явного разграничения простой лексики и стандартной орфографии.

Путь `assistant.ts:1490` возвращает непустой текст без вызовов инструментов. Сам по себе это необходимо для приветствий и навигации, но запрет выдуманной выдачи базы здесь зависит от поведения модели: ответ с придуманными свойствами объекта не сверяется автоматически с результатами поиска. Обнаруженная выдумка Flash в сокращённом тесте показывает риск; она не доказывает воспроизведение того же ответа с полным production-промптом.

## Конкретные следующие исправления и проверки

1. **Подтверждённый дефект маршрутизации:** точный запрос `ru-to-tg` «Переведи на простой разговорный таджикский…» возвращает `ru` из `assistantLanguage()`; это воспроизведено локальным вызовом чистой функции без API. В `languageRouting.ts:13` язык должен следовать сразу после «на», поэтому прилагательные ломают распознавание. Разрешить ограниченный набор описаний стиля внутри явно положительной команды и добавить регрессионный тест; сохранить защиту от отрицания и цитат. Иначе реальный запрос на таджикский может уйти на Flash, несмотря на явный выбор Pro в сравнительном скрипте.
2. **Стиль:** добавить правило «простые повседневные слова, но стандартное письменное написание; не сокращай слова по произношению и не используй диалектные формы, если сотрудник явно этого не попросил». Проверить на тех же примерах с носителем, не подменять его оценку вторым ответом Gemini.
3. **Факты CRM:** для выдачи конкретных объектов строить карточки из типизированных результатов инструмента, проверять ID/ссылки и показываемые числа по полученным записям. Свободный текст модели оставить для краткого пояснения. Просто добавить ещё один запрет в промпт недостаточно для гарантии.
4. **Следующий живой набор:** настоящий системный промпт и объявления инструментов, синтетические ответы поиска: ноль результатов, один объект, несколько объектов, пропуски полей, устаревшая цена, отказ прав. Проверить отсутствие новых ID/цен/адресов и сохранение отрицательных условий. Отдельно оценить 20–30 коротких таджикских формулировок носителем. В этом отчёте такие проверки не выполнены.

Голос ElevenLabs, качество произношения, настоящая CRM, многопользовательская память, запись данных и развёртывание этим тестом не проверялись.
