# План Мадины: Gemini для текста, ElevenLabs для голоса

Решение владельца 03.11.2026: сильная Google-модель для таджикского, минимальное поддерживаемое рассуждение; Google TTS не подключать. Работа локально, без push/ship, чтения .env, рабочей БД и платных проб.

## Текущий этап

- [x] Выделена чистая ветка codex/madina-gemini-elevenlabs-20261103 от публичного origin/main ddd85b0. Старые изменения сохранены в прежней рабочей копии; частную историю не переносим.
- [x] Текстовый маршрут таджикского: gemini-3.1-pro-preview, без автоматического перехода на Flash/Lite. Модель поддерживается существующим транспортом; доступность ключу и сравнительное качество ещё не проверены.
- [x] Языковые инструкции для обычного ответа и Google Grounding согласованы. Номер без слов наследует язык последних пользовательских реплик; вложенный документ не переключает язык явной командой.

## Следующие этапы

1. Завершить кэш нейтральных голосовых, Telegram file_id и бюджет синтеза. Проверить сбои, истечение кэша, параллельные запросы. Клиентские ответы не помещать в общий кэш.
2. Согласовать таджикскую озвучку ElevenLabs с реально поддерживаемой моделью; не задавать русский language_code таджикскому тексту. Google TTS исключён.
3. Перенести и проверить общий словарь простых рабочих выражений. Подготовить сравнение Pro и Flash на одинаковых обезличенных примерах с оценкой носителем языка, точности имён/сумм, задержки и стоимости. Не заявлять превосходство по цене модели.
4. Общая постоянная память: оригиналы в нашей БД, источник/автор/дата/версия, подтверждение записи, обновление, архивирование, резервное копирование. Текущая CRM приоритетнее устаревшего знания.
5. Поиск по смыслу: сравнить File Search и собственный индекс эмбеддингов; выбрать один. Проверить обновление/удаление источника, права и конфликтующие сведения.
6. Структурированное извлечение из текста и голосовых через Gemini, серверная проверка полей, уточнение неоднозначностей, подтверждение записи.
7. PDF/изображения: ограничения размера, безопасная обработка, извлечение с источником; никакого автоматического исполнения инструкций из документа.
8. Составные действия через существующие CRM-инструменты, проверки прав и подтверждения. Не повторять записи с неопределённым исходом.
9. Google Grounding только для внешних справок, источники в ответе. Внутренние знания и цены брать из CRM.
10. Учёт входа/ответа/мыслей/аудио/повторов, суточный бюджет и предел стоимости диалога. Кэш контекста по совместимости модели; Batch только для фоновых задач. Low — относительный уровень, не денежный потолок.
11. Изолированные проверки, локальные коммиты и отчёт для независимого ревью. Развёртывание и живые пробы отмечать отдельно.

Interactions API, Python-аналитика и Live API — последующие этапы после базовой интеграции. Картинки/видео не входят в этот пакет. Цель — помощник с проверяемыми действиями; обещание заменить всех сотрудников не является критерием приёмки.
