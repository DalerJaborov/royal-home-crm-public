# Шабнам умеет всё, что CRM, и отвечает как живой человек — план (07.11.2026)

Цель владельца: «Шабнам умеет всё, что CRM, и отвечает как живой человек». Шабнам —
внутренняя помощница сотрудников: в CRM (панель «Спросить») и в Telegram (личка и группа
«Мушовир - Royal Home»). Код: `apps/api/src/ai/assistant.ts`, `apps/api/src/ai/assistant/**`,
вход Telegram — `apps/api/src/telegram/assistantBot.ts`.

Правила, по которым идёт каждая пачка (из `CLAUDE.md` и правил владельца):
- одна возможность — одна дверь: инструмент помощницы зовёт ту же функцию `lib/*`, что и
  кнопка CRM, права проверяются там же, на сервере; второй копии условия нет;
- запись — только карточкой «Подтвердить / Отмена» (уровень C) или с «Отменить» (уровень B);
- пачка = 2–3 темы, одна ветка, один `npm run ship` после полного `test:api`, precheck и
  ревью `architect`; живая проверка на ключе Gemini прода запрещена.

Метки: ФАКТ (откуда) / ОЦЕНКА / НЕТ ДАННЫХ.

## 1. Что CRM умеет и что из этого умеет Шабнам

|---|---|---|---|

## 2. Пачки

### Пачка 1 — Корзина по правилу владельца, ориентиры, вопрос в журнале (сделана 07.11.2026)
1. Корзина. Одно правило `apps/api/src/lib/trashAccess.ts`: удалённые объекты — справка для
   всех сотрудников (и в группе); вернуть — директор/админ (`properties.delete`) или хозяин
   (ведущий/приёмщик). Удалённые клиенты — хозяину карточки и руководству (`archive.view`),
   в общей группе — никому. Одна дверь восстановления `restorePropertyFromTrash`
   (`lib/trashProperty.ts`) — её зовут и кнопка CRM, и новый инструмент `restore_property`
   (карточка «Восстановить / Отмена», право проверяется при подготовке и при нажатии).
2. Ориентиры. Сверено с лицензированным слоем города (`.data-geo/`, вне git): «91-й
   микрорайон» есть (Сино по границе), «Караболо» — точка в `FOLK_PINS` (Сино по границе),
   «Воданасос» — ни в ориентирах, ни в улицах, ни в массивах (НЕТ ДАННЫХ о точке; народный
   список относит к Исмоили Сомони). Починено: район, подставленный моделью, больше не
   перебивает район места (так «у Воданасоса» отдавало весь Сино: Навбахор, Военный
   городок, Гипрозем); номер «91» не находит «191 мкр»; при поиске только по району ответ
   честно это говорит (`zoneOnly`).
3. Журнал: колонка `AiAssistantAuditLog.question` (аддитивная миграция), маска телефона и
   500 знаков в одной точке `lib/aiAssistantAudit.ts`; вопрос виден в Настройки → Система.

### Пачка 2 — «как живой человек»: язык и честные ответы (приоритет 1)
1. Таджикский частичный ответ: `partialAnswer.ts` сейчас пишет только по-русски; язык брать
   из `languageRouting.ts` того же хода, тексты — парой ru/tg, тест на оба языка.
2. Журнал хода целиком: одна строка на ход (вопрос, итог: ответ/частичный/отказ, число
   шагов, длина ответа, без текста ответа клиентских данных) — чтобы находить «не справилась»
   без перебора строк инструментов. Срок хранения (например, 90 дней) — рубильником.
3. `get_property_card` и `find_property` по номеру удалённого объекта: отвечать «в Корзине,
   удалён тогда-то» вместо «не найден» (справка для всех — по `lib/trashAccess.ts`).

**Сделано 07.11.2026** (ветка `feat/shabnam-batch2-07-11`, журнал
`docs/journal/2026-11-07-shabnam-batch2.md`): все три пункта; плюс быстрый путь по номеру и
отказ записывающих инструментов тоже говорят «в Корзине»; журнал хода — `AiAssistantTurnLog`,
срок `Settings.aiAssistantLogRetentionDays` (90, 7–730) и крон `assistant-log-retention`; экран —
переключатель «Ответы / Обращения к данным» с фильтром «Где не справилась». Ждёт: полный
`test:api`, ревью `architect`, «да» на выкат. Остаток того же класса — «не нашла» в групповых
командах монтажа/Instagram по номеру удалённого объекта (закрыт доработкой ниже).

**Доработка по ревью 07.11.2026** (журнал `docs/journal/2026-11-07-shabnam-batch2-review.md`): сутки
журнала по Душанбе, сторож каскада на сотрудника (нашёл и `PropertyChangeRequest`), итог `aborted`,
отказы ru/tg, «в Корзине» в командах группы. Решения владельца 07.11 (дословно):
- «да может» — агент возвращает свой объект, удалённый директором: оставлено как есть.
- «агенту не показывать телефон удаленного клиента» — сделано: хозяин видит свою удалённую карточку без
  контактов, руководство с «Архивом» — с телефоном.
- «воданасос это лишь проверка можно любой район проверить, воданасос проверь по адресу например рудаки
  177» — «улица + номер» теперь точка дома из справочника домов, поиск по радиусу 500 м вокруг неё.
- «сначала подними все и прочитай а потом узнаем чего не хватает ... я бы хотел чтобы она всегда была
  лучше всех и человека и всегда могла помочь» — шагов 30, срок 120 с, оба рубильниками на экране
  журнала; защита от кругов; фактические шаги и время каждого хода — в журнале, по ним подбирать числа.
  Перед выкатом проверить на сервере Caddy `write 30s` (иначе ответ CRM дольше 30 с оборвётся).

### Пачка 3 — карточки в Telegram и «коробка у Ашана» (приоритет 1)
1. Карточки найденных объектов в Telegram: сейчас карточка с фото уходит только из быстрого
   пути и только для одного объекта (`sendTelegramPropertyCard`). Нужен показ первых 3–5
   результатов `find_properties_by_place` карточками (фото, цена, этаж, ссылка), в группе —
   без контакта собственника.
2. «Коробка у Ашана» по координатам: точку «Ашан» взять из справочника ориентиров (если её
   нет — завести агентом через «Народные ориентиры», не кодом), прогнать поиск по радиусу
   по живым и Корзине; кандидаты ОБ-000130, ОБ-000157 (HANDOFF 07.11) показать владельцу.
   Писать владельцу в личку — только штатным путём и с его отдельным «да».
3. Народные названия без точки (Воданасос и др.): экран «Народные ориентиры» показывает
   список «нет точки на карте» (`check-folk-places.ts` уже считает его) — агент ставит точку
   руками. Точку из интернета без проверки в справочник не писать.

### Пачка 4 — восстановление клиента и запись по клиенту (приоритет 2)
1. `restore_client` карточкой — через ту же функцию, что `POST /clients/:id/restore`

2. Статус клиента / отказ / «отложить» карточкой — те же `lib/*`, что кнопки карточки.
3. Свои удалённые объекты и клиенты на экране CRM для агента (сейчас Корзина открыта только
   «Архиву») — экран + API в одной пачке, ПК и телефон.

### Пачка 5 — руководителю (приоритет 3)
1. Контроль руководителя и активность команды: «кто сегодня ничего не сделал», просрочки —

2. Сделки: открыть сделку, этап, документы (чтение), без денег без `finance.view`.

### Пачка 6 — знания и личность (приоритет 2, параллельно)

2. Знания компании (`knowledge*.ts`): частые вопросы из журнала → карточки знаний,

## 3. Риски и что проверять в каждой пачке
- Обход прав: каждый новый инструмент — тест «чужой агент — отказ», «группа — отказ», «акционер —
  только чтение», проверка и при подготовке, и при нажатии.
- Расхождение REST и помощницы: одна функция `lib/*`, тест вызывает обе двери.
- Цена ошибок модели: район/цена/валюта, подставленные моделью, сверять кодом (как
  `districtIgnored`), а не правилом в промте.
- Рост журнала: вопрос — 500 знаков на строку инструмента; при 150 ходах в день на сотрудника
  это ОЦЕНКА ≈ 1–3 МБ в месяц, но срок хранения нужен (пачка 2).

## 4. Спорные места пачки 1 (ждут слова владельца)
- Агент теперь может вернуть из Корзины СВОЙ объект, даже если удалило руководство по его же
  заявке. Так сказал владелец; если удаление руководством должно быть окончательным для
  агента — одна строка в `canRestorePropertyAs`.
- REST «Восстановить» тоже пускает хозяина объекта (одна дверь с помощницей), но экрана
  Корзины у агента нет — вернуть объект он может только через Шабнам.
- В общей группе удалённые объекты видны (справка для всех), удалённые клиенты — нет.
