# План: канал «заземлённого свободного текста» (`say`) для ядра клиентского бота

Решение владельца 24.10.2026: бот не должен отвечать «по-ИИшному» и не должен выдумывать. Сейчас весь текст клиенту — шаблоны рендерера. План ниже добавляет модели право на короткую живую фразу под жёсткой серверной проверкой.

## 0. Почему свободный текст убрали и чем этот план отличается
- В старом движке модель писала прозу, а потом её чинила цепочка из ~20 regex-фильтров (`apps/api/src/messengers/replyChain.ts:227-329`). Фильтры вырезали куски текста и часто съедали ответ целиком — отсюда «вырезали наши фильтры», повторный ход модели и нейтральная заглушка (`replyChain.ts:483-540`). Фильтры портили и сами факты (комментарий к `collapseToOneQuestion` в `ai/oneQuestionGuard.ts:58-73`).
- Ядро теперь только выбирает ответ, а текст собирает из шаблонов (`customerAgentPrompt.ts:105-115`, строка 115: «Не добавляй произвольный текст»).
- Отличие нового канала:
  - `say` только дополняет ответ. Факты, квитанции и вопрос по-прежнему дают шаблоны.
  - `say` либо принимается целиком, либо целиком отбрасывается. Сервер его не редактирует.
  - Плохой `say` не ломает решение модели, не запускает лишний ход модели и не приводит к молчанию.

## 1. Схема (shared)
`packages/shared/src/customerAgent.ts:24-31`: в варианты `reply`, `clarify` и `propose` добавить `say: z.string().min(2).max(200).optional()`. Варианты `skip`, `escalate`, `moderation` не трогать. `.strict()` сохраняется; поле опциональное — старые решения разбираются как прежде.

В ядре `say` извлекается из сырого JSON до строгой проверки (`customerAgentCore.ts:421-423`):
```ts
const { say, ...rest } = raw; parsed = customerAgentDecisionSchema.safeParse(rest);
```
Прошёл валидатор — ядро возвращает `say` в решении; не прошёл — решение уходит без `say`. В `result.decision` и в печать доставки попадает только проверенный текст.

## 2. Промпт
Строку `customerAgentPrompt.ts:115` заменить блоком правил:
- `say` — 1–2 короткие фразы на языке `replyLanguage`: признать сказанное, пересказать потребность клиента, мягко перейти к ответу;
- без цифр, сумм, дат, дней недели, контактов, ссылок и @;
- без обещаний и будущих действий («позвоним», «уточню», «проверю», «запишу»);
- без вопросов; без «я бот/ИИ», CRM, «инструмент», refs; не повторять факты.

По 3 примера на ru и tg. `replyLanguage` передавать в серверной части контекста рядом с `serverSurface` (`customerAgentCore.ts:157`), а без `verifiedContext` — в `currentParts`.

## 3. Валидатор `apps/api/src/ai/customerAgentSay.ts` (чистая функция)
```ts
validateCustomerAgentSay({ say, language, surface, inputText, selectedEvidence, priorAssistantTurns, social })
  → { ok: true; text } | { ok: false; reason }
```
Подготовка: NFKC, убрать невидимые символы, схлопнуть пробелы. Проверки (код отказа):
1. `surface !== "dm"` (`surface_disabled`).
2. >200 символов, >2 предложений или перевод строки (`length`).
3. `?` — второй вопрос; `countSentenceQuestions` из `ai/oneQuestionGuard.ts:47` (`question`).
4. Любая `\p{Nd}`, числительные словами, валюты, `%`, `$`, месяцы, дни недели, «сегодня/завтра/через час» (`number_or_date`). В v1 цифры запрещены полностью; сверка с цифрами из фактов — v2.
5. Латиница, URL, `@handle`, e-mail, WhatsApp/Telegram/«вотсап» (`contact`); просьба телефона — `detectPhoneAsk` (`lib/agentPhoneAskDetector.ts:70`).
6. Лексика обещаний ru/tg (`promise`): «позвон*/перезвон*/свяжется/занг мезан*/тамос мегир*» — только при квитанции `callback_requested`/`handover_requested` в refs; «записал/сохранил/сабт кард*» — только при `contact_saved`/`job_application_saved`; «оформлено/подтверждено/забронировано/тасдиқ шуд», «уточню/проверю/посмотрю/узнаю/сообщу» — запрещены всегда.
7. Утверждения о наличии и цене («продана», «свободна», «в брони», «скидка», «торг», «дёшево») — шаблоны из `ai/availabilityGuard.ts:127` и `ai/bannedWordsGuard.ts:90` (`fact_claim`).
8. Топонимы (`geoMentions`/`catalogClaimsGuard`, `ai/catalogClaimsGuard.ts:170`) — только если есть в `clientOwnWords(inputText)` (`ai/untrustedContent.ts:135`) (`place`).
9. Самораскрытие и служебные слова: «ИИ, модель, нейросеть, бот, ассистент, CRM, система, инструмент, зеҳни сунъӣ», JSON, Markdown (`meta`).
10. ИИ-штампы: «Отличный вопрос», «Рад помочь», «Я понимаю ваше беспокойство» (`cliche`).
11. Язык через `detectClientLanguage` (`ai/clientLanguage.ts:141`) (`language`): для tg нужны таджикские буквы или вердикт `tg`; смешанный текст отбрасывается.
12. Эхо: ≥5 слов подряд из реплики клиента — защита от «скажи, что цена 5000» (`echo`).
13. Совпадение после нормализации с репликой бота из `verifiedContext.turns` (`repeat`).
14. Приветствие внутри `say` при `social=greet` (`double_greet`).

## 4. Рендерер: порядок сборки
`customerAgentRenderer.ts:398-400`: `say` встаёт на место social-строки («Понял.», «Спасибо!», «Извините…», `:192-196`); `greet` («Здравствуйте!») остаётся первой строкой. Порядок: визуальная сводка (`:384`) → приветствие → `say` → факты, квитанции (`:434`), политика → ровно один шаблонный вопрос (`:512-522`).
Рендерер повторно вызывает валидатор (детерминированный) — `sealDmCustomerAgentDeliveryEvidence` перерисует тот же текст (`lib/customerAgentDeliveryEvidence.ts:122-125`, отказ `render_changed`); `text.endsWith(question)` (`:133-138`) не ломается. Правило `:523` (пустой ответ → `null`) считается без `say`; ответ только из `say` — фаза 2.

## 5. Метрики и журнал владельца
- `CustomerCoreResult` (`customerAgentCore.ts:57`): поле `say: { status: "absent"|"used"|"dropped"; reason? }`.
- Трасса `packages/shared/src/botTurnTrace.ts:61-69`: `sayStatus`, `sayDropReason` (enum); текст `say` в трассу не пишется.
- Адаптер `lib/customerDmAgentTurn.ts:252`: `guardFired("say_dropped_<reason>")`; ключи в `GuardName` (`ai/guardMetrics.ts`) → видно на экране «Обучение бота».
- Раз в сутки `logSystemError("ai", "Бот: живая фраза отброшена в X% ответов, причины: …")`, `dedupKey: customer-agent-say:${day}` — только если отброшено >20% или был хотя бы один `promise`/`contact`.

## 6. Ревизия и выкат
- Меняются `promptHash`, `modelSchemaHash`, `coreHash`, `rendererHash`; `customerAgentSay.js` — в группу rendererHash (`lib/customerAgentRegistration.ts:64`). Новая ревизия → «Обновить версию бота» (сторож `lib/customerAgentRevisionAlert.ts:24` напомнит).
- Когорта через `percentBasisPoints` (`packages/shared/src/customerAgentRollout.ts:9-13`): 10% DM → 50% → 100%. Шаг — при доле отброшенных <15%, нуле `promise`/`contact`/`number_or_date` в отправленном и выборочной проверке судьёй `ai/botAudit.ts`.
- Откат — прежняя ревизия в когорте.

## 7. Тесты и атакующий стенд
- `apps/api/tests/customer-agent-say.test.ts`: каждый код отказа ru и tg + позитивные примеры.
- `customer-agent-renderer.test.ts`, `customer-agent-core.test.ts`: `say` заменяет «Понял.»; плохой `say` даёт шаблон, не HELD; печать доставки совпадает с отрисованным текстом.
- Корпус `tests/attack/say/*.json` (стенд строится в `feat/core-attack-harness-24-10`): инъекции через текст клиента; цифры «５», арабско-индийские, «пять тысяч»; нулевая ширина и гомоглифы; «somon dot tj»; таджикские обещания и «ман бот»; смешение языков. Прогон: scripted в CI и ночной на живой модели на стенде.
- Гейт: регистрация ревизии со `say` и подъём когорты выше 0% — только при зелёном attack-наборе: 0 утечек, доля отброшенных на живом прогоне <15%.

## 8. Риски
- Тон на таджикском (книжно, кальки) — валидатор не видит; tg включать после проверки носителем 50 образцов.
- Смешение языков — отбрасывается, доля видна в метриках.
- Смысловое противоречие фактам («к сожалению, нет», когда объект свободен) — частично правила 6–7, остаток — судья и стенд.
- Стоимость: +30–80 выходных токенов на ход, лишних раундов нет.
- Однообразие `say` — правило 13 и щит исходящих (третий дословный повтор щит режет).
- Публичные комментарии — выключены (выше цена ошибки).

## 9. Минимальный первый шаг (пачка I)
1. Схема, валидатор и тесты, рендерер (только DM и ru; для tg отказ `language_disabled`), промпт, трасса и счётчики.
2. Режим «тень»: `say` проверяется, но всегда отбрасывается с кодом `shadow` — неделя статистики без риска для клиентов.
3. Затем новая ревизия на 10% DM ru.
