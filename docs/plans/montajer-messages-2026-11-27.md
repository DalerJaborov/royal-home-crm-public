## 1. Что сейчас уходит монтажёру

Единая дверь текста: `lib/montageObservers.ts::sendToMontajer` (копия наблюдателям без кнопок, строка «Копия. Монтажёр: …»). Файлы идут мимо неё через `sendMontageCopies`; сторож `tests/montage-copy-door.test.ts` следит, чтобы мимо двери никто не писал.

### А. CRM пишет сама (9 видов)
| # | Сообщение | Когда | Копия админу |
|---|---|---|---|
| A1 | Задание на монтаж или перемонтаж: подпись к каждому файлу-документу («Объект №N · файл i из N · размер/длительность/звук» + 7 строк фактов + строка про голос + «Дальше в очереди» + «Без звука»). Тяжёлый файл вместо документа: текст со ссылкой на 7 дней | Объект встал на место монтажёра; перемонтаж; «Вернуть монтажёру»; смена монтажёра; досылка сторожем | да, файлами |
| A2 | «Отправлено N из N файлов объекта №N» + кнопки «Очередь» и «Пропустить» | После раздачи файлов | да, без кнопок |
| A3 | Озвучка: mp3-документ, подпись в одном из 3 шаблонов, текст озвучки в подписи или вторым сообщением | После видео, если озвучка одобрена; вручную из карточки | да |
| A4 | «Объект №N: озвучка задерживается, сервис озвучки на паузе…» | Кончились кредиты озвучки | нет |
| A5 | «Объект №N: агент выбрал «Без озвучки»…» | Агент выключил голос, пока ролик у монтажёра | да |
| A6 | «⚠️ В карточке ОБ-… изменилось: … Учтите в монтаже.» | Любая правка видимых фактов, пока ролик у монтажёра | да |
| A7 | «Объект №N <продан / снят / удалён / сняли с монтажа> — доделывать не нужно, ролик можно не присылать.» | Закрыта передача объекта, который держал монтажёр | да |
| A8 | «Объект №N передан другому монтажёру.» (код в двух местах) | Смена монтажёра в Настройках | да |
| A9 | «Объект №N: ролик «имя» так и не дошёл файлом… Ссылка…» | Сторож после 6 неудачных досылок, раз в сутки | да |

Сторож досылки сам повторяет A1 до 6 раз (паузы 10 мин, потом до 6 ч). Тревоги «завис», «недоставка», «монтажёр не назначен» монтажёру не приходят, только модераторам и наблюдателям.

### Б. Ответы бота на действия монтажёра (копии нет)
Меню, «помощь», «очередь», «объект N», «фото», «исходники», «файлы», «где», «сдал», «сроки», кнопки управления очередью (пропустить, сделаю позже, взять, выше/ниже, уже сделан, не нужен), отказы приёма файла (фото вместо ролика, кружок, голосовое, альбом, не тот номер, не скачался), квитанция о приёме, вопрос «Чей это ролик?», озвучка текста. Подробно: `inv-narration-bot.md`, разделы B1 до B5.

## 2. Что лишнее, дублирует, шумит

### Нужно действие (оставляем, делаем яснее)
- A1 задание и перемонтаж; A6 правка карточки; A7 снять с работы; A3 голос, который надо вклеить; «Чей это ролик?»; отказы приёма файла; A9 ссылка, если файл не дошёл.

### Информация (можно не читать, делаем короче)
- Квитанция о приёме; A8 «передан другому»; A5 «Без озвучки»; A4 «озвучка задерживается»; «Отправлено N из N».

### Служебное (убрать или слить в один тихий итог)
- Строка «Дальше в очереди: K роликов» в подписи; блок «⚠ Без звука»; «Отправлено 1 из 1» (шум при одном файле); хвост «Озвучка следующим сообщением» в итоге; пауза очереди; мёртвая просьба «пришлите без голоса».

### Конкретные дубли (ФАКТ, по коду)
1. Озвучка объявляется трижды: строка в подписи файла 1, хвост под «Отправлено», подпись самого mp3.
2. «Задерживается» и «Без озвучки» уже есть строкой в задании, потом уходят ещё и отдельным сообщением.
3. Одна передача из M файлов даёт M+2 или M+3 сообщения (файлы, итог, mp3, иногда текст озвучки). Админу столько же копий.
4. 7 строк фактов повторяются под каждым файлом (осознанное решение 19.09, спросить, держим ли).
5. Номер объекта в подписи стоит 2-3 раза; «Без звука» дважды.
6. Номер пишется «Объект №N» везде, а в A6 «ОБ-…».
7. «Передан другому монтажёру»: один текст в `montajerHandover.ts:84` и `routes/settings.ts:1888`.
8. Копии админу несогласованы: вопрос «чей ролик» с кнопками копируется, такой же отказ без кнопки нет; A4 не копируется, A5 копируется.
9. Мёртвый код: «пришлите ролик без голоса» (`askMontajerForVoicelessCopy()` всегда false, кнопки `mj:nv`, `mj:nvx`); `bot.ts:648` недостижим для монтажёра.
10. Устаревшая кнопка возвращает «меню» без объяснения.
11. Нет прямых тестов на A4, A5, «Чей это ролик», «Жду ролик», «Из альбома», `montajerViews`.

## 3. Как стало бы

Правила текстов: на «вы», короткие предложения, номер всегда «Объект №N», без тире, слова простые («голос», а не «озвучка версии 2 одобрена»), тип файла в начале подписи: 🎬 видео, 🎙 голос.

Структура одной передачи (было M+2 сообщения, станет M+1):
1. Файлы 🎬, подпись одной строкой. Факты и просьба про голос только в подписи первого файла.
2. Один итог с кнопками «Очередь» и «Пропустить»: он же единственное место, где сказано про голос. При одном файле и без голоса итог не шлём, кнопки переезжают на подпись последнего файла.
3. Файл 🎙 голос отдельно и подписан («Объект №235 · голос, версия 2»), текст озвучки в подписи, если не влезает, то вторым сообщением как сейчас.

## 4. Как делать после «да»

1. Один модуль текстов `lib/montajerTexts.ts` (все шаблоны в одном месте, правило «Объект №N», без тире). Сейчас тексты размазаны по 12 файлам.
2. Рубильник `Settings.montajerShortMessages`, по умолчанию ВКЛ, подпись в Настройках: «Короткие сообщения монтажёру». ВЫКЛ возвращает прежние тексты (старые шаблоны остаются в модуле до недели спокойной работы, потом удаляем).
3. Структура не меняется: очередь передачи, квитанции, «Вернуть монтажёру», сторож досылки, коды кнопок `mj:*`, имена файлов `№.mp4` / `№_iизN`, запись `MontajerMessage`, первая строка квитанции («Что я сдал»), `sendToMontajer` и сторож `montage-copy-door`.
4. Тесты: структурные остаются как есть (`montage-copies`, `montajer-queue-controls`, `montajer-queue-handover`, `video-handoff-redelivery`, `montajer-delivery`, `montajer-file-number` по логике номеров). Тесты на тексты обновляю на новые и добавляю недостающие: A4, A5, «Чей это ролик», «Жду ролик», «Из альбома», `montajerViews`, тяжёлый файл. Каждый такой тест гоняется в двух режимах рубильника.
5. Проверка на стенде с тестовым монтажёром (не с Шамшодом): передача из 1 и 3 файлов, перемонтаж, голос, правка карточки, снятие, квитанция, «чей ролик», копия админу. Кадры чата для владельца.
6. Реальному Шамшоду ничего не шлю без отдельного «да» владельца на конкретный текст.
7. Порядок: `npm run precheck`, ревью агентом `architect` (больше 5 файлов, бот для сотрудника), потом `npm run ship`; журнал `docs/journal/`.
8. Отдельным PR после: убрать мёртвую просьбу «без голоса» (`voicelessCopyAsk`, `mj:nv`, `mj:nvx`) и недостижимую ветку `bot.ts:648`.

## 5. Риски

- Что-то может читать наши подписи назад (журнал, «Что я сдал», сторож). Перед правкой проверю grep-ом, кто разбирает `MontajerMessage` и подписи; первую строку квитанции и имена файлов не трогаю.
- Предел Telegram на подпись 1024 знака: новые тексты короче, правило обрезки остаётся.
- Если Шамшод привык к текущему виду, смена текстов заметна: первые дни лучше предупредить его одной строкой в чате (текст согласуете вы).
- Копия админу: владелец сам выключит переключателем `montageCopiesTelegram`; в задачу не входит, но после выключения часть правок в копиях не нужна.
