# Инвентарь: автосообщения CRM монтажёру — очередь, досылка, правки, виды очереди

Источник: ветка claude/montajer-bot-simplify-61b520, apps/api/src (только чтение). Пути ниже относительны apps/api/src.
Не входит (разбирают другие): lib/videoHandoff.ts (само задание с файлами, подписи, квитанция, снятие с монтажа, sendGiveUpFallbackLinks, notifyMontajerFinalUploadedManually), lib/narration*.ts, telegram/*. Но на них есть ссылки там, где мои сообщения их вызывают.

## 0. Общая дверь отправки и «копия наблюдателям»

- lib/montageObservers.ts:105 `sendToMontajer(chatId, text, {copy, replyMarkup, propertyShortId})` — единая точка. Кнопки уходят только монтажёру. Если `copy !== false`, каждому наблюдателю (Agent.montageCopiesTelegram=true, активный, есть чат, не сам монтажёр, до 50) уходит голый текст, без кнопок:
  `Копия. Монтажёр: <ФИО монтажёра | «не назначен»>\n\n<текст>`.
- `copy:false` ставит только бот на ответы на команды меню самого монтажёра (telegram/montajerBot.ts:218, `reply`). Остальные автосообщения копируются.
- Тревоги руководству (alertMontageStuck, раздел 1) идут не монтажёру, а: CRM-уведомление + пуш модераторам монтажа (право properties.moderate, не по роли) + в Telegram наблюдателям (с заголовком-копией). Монтажёр их НЕ получает.
- Часы алармов: `isWithinAlarmHours` — по умолчанию 09:50–14:45 Душанбе (Settings.alarmHoursStart/End). Вне окна тревоги молчат, следующий тик досчитает.
- Журнал: каждое сообщение «вида» пишется в MontajerMessage (`recordMontajerMessage`, kinds: HANDOFF, REMAKE, CANCELLED, PROPERTY_DELETED, RECEIPT, FACTS_CHANGED, QUEUE_CONTROL; lib/videoHandoff.ts:350).
- Тест защиты двери: tests/montage-copy-door.test.ts (каждый файл, шлющий в чат монтажёра, обязан звать sendToMontajer/sendMontageCopies), tests/montage-copies.test.ts.

## 3. Ответы бота монтажёра (по запросу человека; копии наблюдателям НЕТ)

Всё через `reply` -> `sendToMontajer(..., {copy:false})`; разбор слов/кнопок — telegram/montajerBot.ts:151 `parseMontajerText`, :168 `parseMontajerCallback`; данные — lib/montajerViews.ts. Все виды: любой объект, кроме удалённых; пустое = «нет», не падение.

Меню (текст MONTAJER_MENU_TEXT, кнопки MONTAJER_MENU_BUTTONS): `🗂 Очередь`(mj:queue) | `📋 Данные объекта`(mj:card — карточка объекта в работе) | `✅ Что я сдал`(mj:done) | `⏱ Сроки`(mj:time) | `📥 Дослать файлы`(mj:files) | `🎙 Озвучить текст`(mj:nar) | `❓ Помощь`(mj:help). Слова: «меню», «/start»; незнакомое слово -> `queueStatusForMontajer()` + «Напишите «меню» — …». Строка про пропуск показывается только при montajerQueueControlEnabled.

### 3.1 «очередь» / `🗂 Очередь` — montajerQueueView (montajerViews.ts:98)
Текст:
```
🗂 Очередь монтажа
В работе у вас: №{N} · {район}, {адрес} · {K} комн. · видео: {V} (файлы ушли {H} ч назад)     | «В работе у вас ничего нет.»
(пусто) / Дальше:
1) №{N} · … · видео: V{ · 🔁 переделка}{ · ⏸ отложен}      (до 10 штук, «… и ещё M»)
⏸ Очередь на паузе, включает руководитель: новые объекты пока не придут. Причина: …
Нажмите номер из очереди: взять сейчас, передвинуть или отметить «уже сделан».   (с управлением)
| без управления: «Нажмите номер — откроется карточка объекта.»
```
Кнопки (управление включено): ряд держателя `📋 №N`(mj:obj:N) + `⏭ Пропустить №N`(mj:sk:N); ждущие по 4 в ряд `№N`(mj:qi:N). Без управления: `📋 №N` по 3 в ряд (mj:obj:N).

### 3.2 `⏭ Пропустить №N` / «пропустить» — montajerSkipMenuView (montajerQueueControl.ts:84)
`Что сделать с №N?` + пояснения и кнопки: `🕓 Сделаю позже`(mj:skl:N — держатель в конец, следующий выдаётся сразу; недоступно при паузе или пустой очереди) | `✅ Уже сделан, ролик пришлю`(mj:skd:N — снять, бот ждёт ролик) | `🚫 Не нужен`(mj:skn:N — снять, ролика не ждать) | `Отмена`(mj:x). Строка «Руководитель получит уведомление.»

### 3.3 Подменю ждущего `№N` — montajerQueueItemView (:176)
Текст: `№N · адрес · комн. · видео: V`, `В очереди P-м из Q.`, `🔁 Переделка.`, при удержании `⏸ Отложен руководителем (причина): взять его сейчас нельзя.` или `⏸ Очередь на паузе, включает руководитель. Взять сейчас нельзя.`
Кнопки: `▶️ Взять №N сейчас`(mj:tk:N:{держатель|0}) | `⏫ В начало`(mj:mv:N:f) `⬆️ Выше`(mj:mv:N:u) `⬇️ Ниже`(mj:mv:N:d) | `✅ Уже сделан, ролик пришлю`(mj:qd:N) `🚫 Не нужен`(mj:qn:N) | `📋 Данные`(mj:obj:N) `🗂 Очередь`(mj:queue). Для держателя: «Объект №N сейчас у вас в работе.» + `⏭ Пропустить №N` + `🗂 Очередь`.

### 3.4 Итоги действий (тексты, везде кнопка `🗂 Очередь`)
- Later: `Хорошо, №N в очереди P-м. Вам идёт №M, файлы придут следом.` (+ фон. dispatch нового) / отказы: «Объект №N уже не у вас.», «⏸ Очередь на паузе, включает руководитель. №N остаётся у вас.», «Других объектов в очереди нет, №N остаётся у вас.»
- Done/NotNeeded: `Готово: №N снят из очереди, руководителю сообщил.{ Ролик №N пришлите сюда, когда будет готов.}` + для держателя `Следующий у вас: №M, файлы придут следом.` | паузa | `В очереди больше никого.`; отказ «Объект №N отложен руководителем, снять его может только руководитель.»
- Take: `Готово: №N теперь у вас, файлы придут следом.{ №M вернулся в очередь P-м.}` / «Очередь только что изменилась, откройте её заново.»
- Move: `Передвинул: №N теперь K-й.` или `№N уже на этом месте.` + подменю.
- Cancel: `Хорошо, ничего не меняю.`
- Нет доступа: `Этот чат сейчас не назначен монтажёром.` / `Управление очередью из бота выключено руководителем. Порядок очереди меняет руководитель в CRM.` (рубильник Settings.montajerQueueControlEnabled, по умолчанию ВКЛ).
- Следствия: каждое действие -> MontajerMessage QUEUE_CONTROL + аудит (PROPERTY_VIDEO_HANDOFF_MONTAJER_DEFERRED/_TOOK/_DONE/_MOVED); «Уже сделан/Не нужен» шлёт руководству пуш (через `cancelVideoHandoffQueueEntry`, в videoHandoff.ts); «Сделаю позже» и «Взять» запускают отправку следующего (`dispatchInBackground`).

### 3.5 Объект №N — montajerObjectView (:166)

## 5. Дубли и шум (по делу)

1. «Объект №N передан другому монтажёру.» — два кода: routes/settings.ts:1888 и montajerHandover.ts:84 (один текст). Свести в одну функцию.
2. Три разные тревоги про один зависший объект: 1.3 (досылка, с ~30 мин, раз в 6 ч), 1.4 (24 ч), и «ролик ждёт проверки» (2.6). Монтажёру они не идут, но наблюдатели получают копию каждой.
3. Правка карточки (2.1): отдельное сообщение монтажёру на КАЖДОЕ сохранение/загрузку фото/видео; массовая загрузка = много сообщений и столько же копий. Нет объединения по времени.
4. Досылка 1.1: монтажёр может получить то же задание (файлы + подпись) до 6 раз за ~5 ч, если Telegram не принимает; потом ссылки (1.2). Копии наблюдателям при каждой попытке.
5. Ответы на команды меню без копии наблюдателям (сознательно); но результат «Сделаю позже/Взять/Не нужен» руководству приходит пушем отдельно — копии этих кнопок наблюдателям нет, видно только в журнале монтажа.
6. Вид «Очередь» читает `EDITOR_HOLDER_WHERE` + `orderedQueue()` отдельными запросами в нескольких местах (montajerViews, montajerQueueControl.currentHolder, bot.holderShortId): логика «кто держатель» размножена; единая функция была бы надёжнее.
7. agentSharePost.ts лежит в списке «монтажёр», но к монтажёру не относится — исключить из задачи упрощения монтажёрского бота.
