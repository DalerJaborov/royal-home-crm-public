# Закон о владении клиентом

Утверждён владельцем 17.09.2026. Источник — `docs/audit/lead-ownership-17-09.md` §2
(текст правил, дословно) и §4 (решения владельца по спорным пунктам, вплетены в
описание своего правила). Разбор нарушавших закон механизмов —
`docs/audit/recon-17-09/02-auto-transfer-mechanisms.md`.

Формат заведён для мета-теста (`apps/api/tests/law-lead-ownership.test.ts`): каждое
правило — заголовок `## П-N. …` и строка `**Статус:** …` сразу под ним. Тест требует
хотя бы один `it("П-N: …")` на каждый номер со статусом «реализовано в А1» и
`it.todo("П-N")` на остальные — так неполнота реализации не тонет молча.

## П-1. Владелец клиента

**Статус:** реализовано в А1 (частично — ветка «удалён» готова целиком; остальные
пути замка — пачка Г)

Владелец клиента — агент в `Client.assignedAgentId`. Меняет его только
`changeClientAgent` с указанным актором (человек) или с вердиктом политики
(автоматика). Удалённый клиент (Корзина) автоматика не трогает вовсе — владельца
меняет только явное восстановление человеком (`canAutoTransfer` → `ruleNo: "П-1"`).

## П-2. Контакт состоялся

**Статус:** реализовано в А1

Единое определение (решение владельца Р-2): ЛЮБАЯ попытка агента связаться с
клиентом — звонок любой длительности (в том числе «не ответил», «недоступен»,
«неверный номер»), сообщение из CRM (даже без ответа), показ, встреча. Считается
функцией `hasContactAttempt(client)` и больше нигде; поля-источники: `firstContactAt`,
`lastAgentAttemptAt`, Interaction агента с типом не SYSTEM/STATUS_CHANGE.

## П-3. После принятия и контакта клиент не уходит автоматически

**Статус:** реализовано в А1

После принятия (`acceptedAt`) и контакта (П-2) клиент НЕ уходит другому агенту
автоматически. НИКОГДА. Любой крон/детектор, желающий передать такого клиента,
обязан вместо передачи эскалировать руководителю (запись в хронологию + уведомление
+ пуш агенту + строка в его делах — `escalateInsteadOfTransfer`), а владелец остаётся.
Жёстко проверяется в самой точке записи (`lib/changeClientAgent.ts`) — не только в
трёх механизмах этой пачки, а во всех, кто меняет владельца без актора.

## П-4. До контакта

**Статус:** реализовано в А1

До контакта автоматика действует так: не принял за `leadAcceptMinutes` →
следующему, у прежнего гаснут пуш и окно (`reassignStaleLeads`); принял и не сделал
попытки связаться за `leadCallMinutes` → следующему, тумблер владельца
(`penalizeMissedFirstCalls`). Пула «ничьих» и кнопки «Забрать из пула» нет — убран
целиком (решение Р-3: добавлен 01.09.2026 по спецификации «гонка в пуле», владелец
этого не заказывал).

## П-5. Передача после контакта — только человек с правом

**Статус:** реализовано в А1 (частично — источники `lifecycle.assign`, `restore`,
`freeze`, `handover`; `transfer*`/`refuse` — пачка А2, см. отчёт по заданию)

Передать клиента после контакта может только человек с правом `clients.assign`
(руководитель/директор), либо сам агент кнопкой «Передать» — с актором в аудите.
`requireHumanActor(source)` в `changeClientAgent` бросает ошибку в dev/test и пишет
`logSystemError` в проде, если такой источник вызван без `actorId`.

## П-6. Портфель полон

**Статус:** реализовано в А2

Система не выбирает жертву сама: агенту показывается список, из которого нельзя
выбрать клиента с разговором; режим `random` отменяется.

## П-7. Увольнение/заморозка

**Статус:** реализовано в А2

Раздача портфеля с актором = руководитель, каждому клиенту запись «передан от X к
Y руководителем Z».

## П-8. Возврат из Корзины/Потерянных/реактивация

**Статус:** пачка А2

Клиент возвращается прежнему агенту (`lastAgentId`), если тот активен; иначе —
эскалация, не очередь. (Смежное решение Р-5 — возврат из «вернулся с историей
разговоров», `reassignStaleReturns` — реализовано в А1, но это отдельный механизм
из §1.3, не сам П-8; см. отчёт по заданию.)

## П-9. Слияние дублей

**Статус:** реализовано в А2

Если у дубля другой агент, пишется запись о передаче обеим карточкам и
уведомление обоим агентам.

## П-10. Каждая запись хронологии подписана актором

**Статус:** реализовано в Б1 (частично — переведены точки записи, тронутые заданиями А1/А2/Б1; полный перевод всех 88 мест — пачка Б2, см. docs/audit/recon-17-09/04-timeline-authorship.md)

Человек (только `req.agent`, ответивший по добавочному, дежурный оператор),
Система, ИИ, Бот, Клиент. Автоматика никогда не подписывается человеком. Запись
звонка подшивается только при совпадении добавочного.

## П-11. Каждый уход клиента из вида агента — с уведомлением

**Статус:** пачка В

Корзина, Неактивные, OTHER, дубль, кандидат, передача — сопровождается
уведомлением агенту с причиной; у агента есть вкладка «Все мои» без скрытых
состояний и строка «почему не в основном списке».

## П-12. Ручные правки данных на проде

**Статус:** пачка Г

Делаются только скриптом, который пишет в хронологию с актором «Система (ручная
правка, кто)» и проверяет, какие кроны читают тронутые поля.
