# Разбор карты продукта — 20.09.2026

Что проверялось: отстала ли карта (`docs/product-map.*`, `docs/product-flows.*`,
`docs/product-map-simple.json`) от кода, и не потерялись ли в ней функции,
сделанные за последние две недели в других чатах Claude Code (не в этой сессии).

Карту **руками не менял** — она собирается скриптом. Правил только
`docs/product-map-labels.json` (человеческие подписи) и пересобрал карту им же.

## 1. Карта была красной прямо перед проверкой

До перестройки `npm run map:check` падал (код возврата 1):

```
Лабиринты отстали от кода: docs/product-flows.md, docs/product-flows.json. Выполните: npm run map
  docs/product-flows.md, строка 7:
    в файле: "...вместе с задачами по расписанию и фоновыми заданиями — 2247...»
    в коде:  "...вместе с задачами по расписанию и фоновыми заданиями — 2255...»
```

Причина — новая задача по расписанию `instagram-pending-containers` (коммит
`bfa5b97d`, «не терять публикацию, если Meta не успела за окно ожидания», #623,
20.09.2026): она есть в `cron.ts`, но карту после неё никто не пересобрал.
Кто-то делал `npm run map` раньше (для соседних правок в том же коммите), а вот
для этой — нет.

Прогнал `npm run map` — карта пересобралась (445 путей → без изменений, 2255
развилок вместо 2247, 84 задачи по расписанию вместо 83). Полный список того,
что изменилось, — в `git diff` перед моей правкой (сохранён смысл ниже).
После пересборки `npm run map:check` стал зелёным:

```
Лабиринты совпадают с кодом (445 путей, 2255 развилок).
Карта продукта совпадает с кодом.
Человеческая карта совпадает с кодом (445 путей, 48 экранов).
```

**Вывод:** механизм проверки работает правильно — он поймал именно то отставание,
для которого создан. Дальше смотрел то, что `map:check` НЕ ловит (он не требует
подписи, только совпадения фактов с кодом).

## 2. Чего не хватало по смыслу — подписи

`map:check` зелёный даже без подписи новой задачи: подпись — дело
необязательное для проверки, но обязательное для владельца, который в
терминах разработки не разбирается. Раздел карты «5. Без человеческой подписи»
до правки показывал:

```
- Задач по расписанию: instagram-pending-containers, telephony-station-health
- Модулей сервера: нет
```

Обе — из последних двух недель:

- **`instagram-pending-containers`** (`*/5 * * * *`, 20.09.2026, #623) — Meta не
  успевает обработать ролик Instagram за время ожидания, публикация раньше
  просто терялась. Новая задача каждые 5 минут проверяет такие «зависшие»
  ролики и доводит их до публикации сама, как только Meta закончит обработку.
- **`telephony-station-health`** (`*/15 * * * *`, 20.09.2026, #565) — сводная
  проверка самой телефонной станции целиком (жива ли связь, загружены ли
  настройки приёма звонков, есть ли свободный оператор), заведена после того,
  как три отдельные поломки станции в один день не поймала ни одна из
  существующих узких проверок.

Обе подписи дописаны в `docs/product-map-labels.json` простым языком, без
терминов («ролик», «станция», «оператор» вместо «контейнер», «ARI/AMI»,
«диалплан»). Модули сервера (раздел API) и все 62 экрана — подписаны
полностью, пробелов не нашёл.

## 3. Прошёлся по журналу правок за последние ~2 недели

Просмотрел ~300 последних коммитов и список `feat`-коммитов с 10.09 по
20.09 (около 140 штук — репозиторий очень активный, несколько параллельных
Claude Code сессий сливаются в `main` каждый день). Крупные пласты за это
время: политика владения клиентом (П-1..П-5), предохранитель исходящих
сообщений бота («щит»), единая хронология действий (`actorKind`), TikTok как
пятый канал публикации, Instagram Stories вслед за Reels, переезд меню на
вкладки внутри экранов (34 пункта → 21), мобильная переодежда экранов под
единый макет, тренажёр бота, голосовые ответы, карта объектов на MapLibre,
временный пароль при первом входе, и т.д.

Ни один из них не потребовал ручной правки карты, кроме двух подписей выше —
и это ожидаемо, а не потому что я не проверял: карта строится из кода
(`navigation.ts`, роуты, `cron.ts`), поэтому **новый экран, новый адрес сервера
или новая задача по расписанию сами появляются в карте при следующем
`npm run map`** — уходит только подпись, потому что её пишет человек. Разделы
меню, вкладки, число пунктов — тоже подтянулись сами (были в `git diff` при
пересборке, отдельно их не трогал).

Специально проверил кандидатов на «подпись, которая теперь врёт» — случаи,
где старый ярлык мог перестать соответствовать новому поведению:

- `/api/v1/bot-training` («Экран «Манера» — закрыт тумблером»): после слияния
  «Обучение ИИ» и «Тренировки» в один экран с вкладками (#419) старый адрес
  `/bot-training` теперь просто ведёт на `/ai-learning?tab=manner` — подпись
  уже описывает это верно, поправлена раньше меня.
- Клиентские модули (`/api/v1/clients` — «передачи, отказы, подбор»): после
  переписанной политики владения (П-1..П-5) и единой панели «Подбор» смысл
  подписи не изменился — она достаточно общая, чтобы оставаться верной.
- TikTok (`/api/v1/tiktok` — «Публикация в TikTok») — подпись верна и после
  того, как канал стал пятым в цепочке автопубликации.

Явно врущих подписей не нашёл. Это не значит, что их гарантированно нет нигде
— на 138 подписей (82 задачи + 56 модулей) за разумное время нельзя построчно
сверить каждую с кодом; проверил модули и задачи, которые статистически чаще
всего меняют смысл (те, что тронуты правками последних двух недель), и явных
расхождений не увидел.

## 4. Что осталось спорным / не проверял

- **198 «без перевода» фрагментов** в `docs/product-map-simple.json` (условия и
  шаги внутри путей, которые скрипт не смог перевести на понятный язык) — это
  не то же самое, что «без подписи»: словарь переводов фрагментов не лежит в
  `product-map-labels.json` и не входит в задачу «допиши подписи»; трогать его
  не стал, чтобы не выйти за рамки того, что можно править руками.
- Не сверял человеческие описания в `docs/product-flows.md` построчно с кодом
  внутри каждого из 84 путей задач — файл целиком генерируется скриптом без
  ручных вставок, ручных подписей там нет в принципе, сверять нечего.
- Список меню (складки/пункты) не проверял на «понятно ли владельцу название
  пункта» — это уже вопрос вкуса формулировок в самом коде (`navigation.ts`), а
  не пробел карты; при желании владелец может попросить отдельный проход по
  формулировкам пунктов меню.
