# 26.11.2026 — Стенд агента работает без Docker (внешний Postgres)

- Что изменилось: `scripts/agent-stand.mjs` умеет брать базу не из контейнера `rh-stand-pg`, а из внешнего Postgres (portable 16 на `127.0.0.1:15502`). Режим выбирает чистая `choosePgMode`: `STAND_PG=external|docker` принудительно, иначе Docker, а если `docker version` не отвечает за 5 с и внешний Postgres доступен (слушает или запускается `pg_ctl`) — внешний, со строкой в выводе. Все обращения к базе идут через `pgRun`/`psqlOut`/`dbExists`/`dbUrl`; в режиме Docker команды прежние. Эталон `seeded` и копия `CREATE DATABASE agent_<порт> TEMPLATE seeded` работают так же; во внешнем режиме `DROP` идёт с `WITH (FORCE)`. Добавлено: запись `.rh-stand/state-<порт>.json` (дерево, база, режим) — `down` и `up` не трогают стенд другого дерева без `--force` (класс «другой чат взял тот же порт и снёс мою базу»); проверка портов API и Vite (занят или «исключённый диапазон» Windows) с предложением другой пары.
- Почему: Docker Desktop на ПК владельца завис (виртуальная машина WSL), без базы нельзя было снять живые кадры экранов.
- Чем проверено: `node --test scripts/agent-stand-template.test.mjs` 17 из 17 (внесение поломки в выбор режима роняет 2 теста); стенд поднят на портах 4760/5260 на внешнем Postgres: миграции накатились, `/api/v1/health` 200, Vite 200, вход по коду формой, кадры входа и списка чатов 1440 и 390; `down` удалил только `agent_4760`; без `docker` в PATH режим включился сам.
- Что осталось: нет проверки при реально мёртвом (зависшем, а не отсутствующем) Docker — таймаут 5 с проверен только по коду; стенды, поднятые прежней версией скрипта, `down` теперь отклоняет без `--force` (записи нет).
