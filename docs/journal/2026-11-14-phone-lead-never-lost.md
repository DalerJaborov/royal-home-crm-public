# 14.11.2026 — Клиент дал номер боту — карточка обязана появиться

- Что изменилось: сторож «номер есть — карточки нет» (`apps/api/src/lib/phoneLeadWatchdog.ts`) закрыл четыре дыры.
  1. Диалог со стадией «done» без карточки (карточку удалили, диалог отвязали) больше не блокирует приём:
     захват в `acceptLead` (`messengers/conversation.ts`) считает такую стадию брошенной. Раньше номер не
     принимался никогда — ни живым ходом, ни сторожем, только тревога руководству.
  2. «Одна попытка на диалог навсегда» заменена на «одна попытка на одни и те же реплики»: если клиент
     написал после прошлой попытки, сторож разбирает только новые реплики. Старый номер не воскрешает.
  3. Соискатели работы из нового ядра бота (тема `job` в CustomerInquiry, анкета по `customerInquiryId`)
     больше не получают карточку клиента «Прочее».
  4. Клиенту нового ядра приём получает намерение (покупатель/продавец) из темы ядра или из слов клиента
     (`ai/customerAgentIntake.ts`) — раньше все такие карточки уходили в «Прочие обращения» без агента.
  Плюс разовый добор потерянного: `apps/api/scripts/phone-leads-backfill-14-11.ts` (сухой прогон по
  умолчанию, `--apply` только по «да» владельца, журнал для отката рядом).
- Почему: владелец 14.11 — «бот отвечает „приняли ваш номер“, а лида нет; починить так, чтобы не было
  никогда». Разбор прода за 8–14.11: все 12 карточек сторожа — «Прочее» без агента, 9 из них соискатели;
  живой Instagram 10.11 — «Приняли ваш номер», карточки нет (стадия «done» без карточки).
- Чем проверено: `tests/phone-lead-never-lost-core.test.ts` (7 тестов; без починки 5 красных),
  обновлён `tests/conversation-deleted-client-phone.test.ts` (старое ожидание «заводит человек»),
  смежные тесты приёма и сторожа зелёные на временной базе.
- Что осталось: добор `--apply` на проде (ждёт «да»); 9 ошибочных карточек соискателей «Прочее» за 8–11.11
  не чистились; WhatsApp-клиент без набранного номера (номер = отправитель) сторож не видит.
