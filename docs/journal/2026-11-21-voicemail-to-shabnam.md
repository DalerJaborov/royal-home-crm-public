# 2026-11-21: сообщение с автоответчика приходит директору в Шабнам

**Что.** После разбора каждого нового сообщения автоответчика (не пустышки) директору (роль DIRECTOR, активный, с `telegramChatId`) в Telegram уходит: полный номер, карточка (если есть), время по Душанбе, расшифровка по-русски (до 1500 знаков), ссылка на карточку или `/calls`, затем сам аудиофайл документом. Модуль `apps/api/src/lib/telephony/voicemailToShabnam.ts`, вызов из `processVoicemail` после отметки `processedAt`.

**Почему.** Владелец 21.11.2026: «в нерабочее время звонки пусть идут на автоответчик, потом пусть придёт на Шабнам». До этого уходил только веб-пуш агенту или аларм руководству.

**Решения.**
- Один раз на файл: замок `VoicemailMessage` (уникальное имя файла) и вызов строго после `processedAt`; повторный проход файл пропускает.
- Получатель только директор: номера видит он один (решение #298), поэтому номер целиком.
- Рубильник `voicemailToShabnamEnabled` (Settings, умолчание ВКЛ, группа «Уведомления» на экране автоматики). Выключен: ничего не шлём и не пишем в журнал.
- Отказ Telegram не ломает разбор: текст и файл шлются независимо, у каждого таймаут, ошибки в `logSystemError` с постоянными ключами.
- Миграция `20261121160000_voicemail_to_shabnam`: только ADD COLUMN.

**Проверено.** `tests/voicemail-to-shabnam.test.ts` (5: уходит директору, не агенту и не директору без chatId; повтор не шлёт; рубильник; сбой текста; сбой файла) и `tests/voicemail-ingest.test.ts` (19) зелёные; сборка shared/api/web, `map:check`, `precheck`.

**Осталось.** Живой прогон на проде не делался (нужен звонок в нерабочее время и привязанный Telegram директора). Если директоров несколько, сообщение получат все с привязкой.
