# Approved customer revision continuity

After the seventeenth approved revision advance, the fixed depth16 traversal stopped recognizing the oldest customer assignments. The owner publication checked ancestry only to the old candidate, allowing the next edge to strand them. The same limit also discarded eligible customer-stated words from older revisions.

Migration537 replaces only the structural reachability function with an exact revision/cohort closure using UNION deduplication. It terminates on the finite append-only registry without an arbitrary release count and also lets the existing insertion guard detect long return-path cycles. No old migration, assignment, source, owner, edge or receipt is rewritten.

Own-word continuity uses the same finite pair traversal, pinned to the actual current policy/candidate/cohort and the original assignment/scope. Approved time and policy-revision fences remain, traversal stops at the exact target, and the caller still validates original FINAL input, ownership and user-only statements. Structural ancestry is not a private-memory grant.

The owner publication now verifies every proposed root-to-new-candidate path after the tentative edge and before commit. A failed observation rolls back that edge, the policy and audit together. No historical source is renewed or resent.

Before the fix, real PostgreSQL tests failed on17/18/65-edge paths, a65-edge return cycle, and an actual retained HTTP publication crossing16→17. The repaired controls cover exact/wrong cohorts, missing/reverse paths, future-approved edges, source time/policy/scope, target stopping, original source pins and a deny-only prospective-check fault. Semantic test times are fixed. Existing revision/context tests passed alongside them. No claim of production acceptance is made from local tests; the combined package still requires exact cloud full validation and independent deployment checks.
