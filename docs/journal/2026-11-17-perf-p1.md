# 17.11.2026 — пять правок скорости из аудита (P1)

Источник: аудит скорости 17.11 (`D:/TASKS-2026-11-14/reports/audit-2026-11-17/performance.md`,
разделы P1; замеры на проде там же). Ветка `perf/p1-17-11`, каждый пункт — свой коммит.

## 1. Фото и миниатюры /uploads — кэш 30 дней
- Было: `express.static(uploadsDir)` без настроек → `public, max-age=0`; браузер перепроверял
  каждую картинку при возврате в «Объекты»/карточку/карту, Cloudflare не держал (MISS).
- Стало: `lib/uploadsCacheControl.ts` + `setHeaders` в `app.ts`. Долгий `public, max-age=2592000,
  immutable` — ТОЛЬКО по списку: файл в корне uploads и в `thumbs/` (все писатели — uuid или
  метка времени: photos.ts, drafts.ts, sellerMedia.ts, photoEnhance.ts, логотип, аватар сотрудника).
  `telephony/` (имена постоянные, перезаписываются из Настроек) — `no-cache`; `video|automontage|
  handoff` (закрыты подписью/входом) — `private, no-cache`; всё прочее — прежнее умолчание.
- Цена: удалённое фото до 30 дней может отдаваться из кэша Cloudflare по старому uuid-адресу.
- Тест: `apps/api/tests/uploads-cache-control.test.ts` (правило по пути + настоящие ответы, 304).

## 2. «Рынок: цены» — кэш 10 минут
- Было: каждое открытие и смена фильтра — до 20 000 объявлений в процесс API + медианы в JS.
- Стало: `findSegmentsCached` (lib/market/segments.ts) по образцу `findOverpricedPropertiesCached`:
  10 мин, общий расчёт для одновременных запросов, ключ из ВСЕХ полей запроса, не больше 100 ключей.
  Маршрут `GET /market/segments` идёт через кэш; строка покупателя и «дороже рынка» — как были.
- Сброс по сигналу сборщика невозможен: сборщик в контейнере worker, кэш в памяти API — так же
  устроен и кэш «дороже рынка» (сброс только сроком и `resetSegmentsCache` в тестах).
- Тест: `apps/api/tests/market-segments-cache.test.ts` (второй вызов не идёт в базу, срок, ключи, предел).

## 3. «Чаты» — список не чаще раза в 5 секунд
- Было: каждое `message.new`/`conversation.updated` через 1 с гасило весь `["conversations"]` —
  и открытый диалог, и тяжёлый список со счётчиками срезов, у каждой вкладки с открытыми «Чатами».
- Стало (`apps/web/src/lib/liveEvents.ts`): открытый диалог — как раньше, 1 с; списки
  (`["conversations", {фильтры}]`, очереди пульта `["conversations","pult-inbox",…]`) — одной
  волной не чаще раза в 5 с, задний фронт гарантирован. Первое событие после затишья приходит
  в список так же через секунду. Незнакомая форма ключа остаётся на секунде.
- Тест: `apps/web/src/lib/__tests__/liveEventsConversations.test.ts`.

## 4. nginx — сжатие ответов для Caddy/Cloudflare
- `gzip_proxied any;` (без него nginx не сжимал запросы с `Via`: CSS 696 090 Б вместо 157 553 Б),
  в `gzip_types` добавлены `text/plain text/javascript application/manifest+json`.
  `text/event-stream` намеренно НЕ добавлен.
- Сторож: третье правило в `scripts/audit-nginx-conf.mjs` (`audit:nginx`). Проверен внесением
  поломки: без `gzip_proxied any` — красный; с `text/event-stream` в типах — красный.

## 5. Вектор подбора не едет в каждый запрос объекта
- `src/db.ts`: глобальный `omit: { property: { embedding: true } }` (вектор — 58 % строки).
  Явно просит вектор одно место — `lib/embeddingSearch.ts` (`select: { embedding: true }`);
  запись вектора (`ai/embeddings.ts`, `data:`) не затронута; сырого SQL `Property.*` нет.
- Типы: `PropertyRecord` и `PropertyDefaultOmit` в db.ts; 23 ошибки сборки в 15 файлах сведены
  к ним (`siteSync`, `metaCatalogFeed`, `propertyListItem`, `staffPropertySearch`,
  `telegramModeration`, `propertyChangeRequestService`, `propertyReview`, `propertyPhotoRemoval`,
  `changeRequestTool`) — без `as`/`any`.
- Оговорка: у `tx` в `prisma.$transaction(async (tx) => …)` Prisma теряет глобальный omit в
  ТИПАХ (в работе действует). Поэтому сторож-тест `apps/api/tests/property-embedding-omit.test.ts`:
  в работе вектора нет и в транзакции, явный select его отдаёт, `.embedding` читается только в
  трёх разрешённых файлах.
