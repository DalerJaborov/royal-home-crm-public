# 13.11.2026 — Режим бота «только заявки» (рубильник, ядро и старый путь)

- Что изменилось:
  - Настройки (миграция `20261113090000_bot_lead_only_mode`, только добавление колонок):
    `botLeadOnlyMode` (по умолчанию **выкл.**), `botUseWhatsappNumber` (вкл.), `botMaxPhoneAsks` (2, 1..3),
    `botHotIntentHandover` (вкл.). Экран «Настройки → Бот → Рубильник и каналы», группа «Режим: только заявки».
  - Одна дверь решений и текстов для обоих маршрутов: `apps/api/src/ai/leadOnlyMode.ts` (сценарий хода:
    горячие слова / понравившийся объект / продавец / покупатель; тексты ru/tg на «вы»/«шумо», без «—»;
    честное время звонка вне рабочих часов; фильтр ссылок и подборки). Чтение настроек и цена «от N» из базы —
    `apps/api/src/lib/leadOnlySettings.ts` (тот же подбор `findMatchingProperties`, что у поиска бота).
  - Ядро (`lib/customerDmAgentTurn.ts` → `lib/customerLeadOnlyCore.ts`): сценарии заявки отвечаются сервером
    без модели; заявка оформляется фоновым заданием `customer-lead-only-intake` ПОСЛЕ того, как ответ хода
    отпущен (привязка карточки меняет bindingRevision), тем же `acceptLead` в тихом режиме, с объектом → его
    агенту сразу. В остальных ходах модели не предлагается `search_public_properties`, нет предчтения
    подборки, памятки, фото и ссылок; «передать сотруднику» теперь ответ клиенту, а не молчание; ответ со
    ссылкой или подборкой заменяется коротким «передаю агенту». Новые файлы добавлены в `coreHash` ревизии.
  - Старый путь (`messengers/conversation.ts` → `messengers/leadOnlyLegacy.ts`): тот же ответ после склейки
    сообщений, заявка `acceptLead` (новая опция `fixedReply` для короткого «номер получил»); фото/ссылки
    выключены в `loadBotCapabilities`, подборка убрана из промта, правило `LEAD_ONLY_MODE_RULE`, показ объекта
    и памятка не уходят, ответ модели чистит фильтр.
