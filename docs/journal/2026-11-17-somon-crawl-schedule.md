# 17.11.2026 — частота полного обхода Somon настройкой, по умолчанию раз в неделю

**Что изменилось.** В #260 полный обход Somon стал ночным («45 2 * * *») без отдельного выбора, а на проде
`MARKET_CRAWL_ENABLED=1` уже стоит — после выката обход пошёл бы каждую ночь без решения владельца (он на вопрос
«каждую ночь или раз в неделю» не ответил). Теперь частота — переменная `MARKET_SOMON_CRAWL_SCHEDULE`
(`apps/api/src/lib/market/somonCrawlSchedule.ts`, одна функция на крон и на экран «Состояние функций»):

- пусто или `weekly` — раз в неделю, воскресенье 02:45 по Душанбе (было 02:30; сдвиг на 15 минут, потому что
  ночной Paydo в #260 перенесён на 02:30, а замок обходов общий — в воскресенье один из двух пропускался бы);
- `nightly` — каждую ночь в 02:45;
- любое другое значение — раз в неделю и одна запись в журнал ошибок (по значению, без повторов).

**По умолчанию на проде ничего не меняется:** без переменной обход остаётся недельным. Остальное в #260 (обход
по счётчику сайта, `no_pagination`/`too_small`, Paydo в 02:30 с повторами) — без изменений.

**Как включить ночной обход** (отдельное «да» владельца на операцию с сервером): в `.env.production` на сервере
дописать `MARKET_SOMON_CRAWL_SCHEDULE=nightly` и пересоздать контейнеры api и worker (значение читается при
старте). Переменная проброшена в `docker-compose.prod.yml` (общий блок окружения api/worker).

**Проверено:** `tests/somon-crawl-schedule.test.ts` 5/5 (без переменной — недельное, `nightly` — «45 2 * * *»,
мусор — недельное с пометкой; крон берёт расписание из функции; переменная есть в compose); внесённая поломка
(пусто → ночное) даёт 2 красных. `cron-schedule-registry` 9/9, `function-status` 19/19.

**Осталось:** решение владельца о частоте.
