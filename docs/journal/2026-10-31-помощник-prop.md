# 31.10.2026 — Помощник П3, группа «объекты»: цена, статус, заявки, перемонтаж

- Что изменилось:
  - В ИИ-помощнике появились четыре инструмента уровня C (с подтверждением человека): `change_property_price`, `change_property_status`, `request_property_change`, `send_to_remake` (`ai/assistant/tools/*`, список — `propertyTools.ts`).
  - **Фаза 1** (по документу §3): цена, статус и прочие правки опубликованного объекта идут не напрямую, а ЗАЯВКОЙ руководителю — той же, что кнопка «Запросить изменение» в карточке. Руководитель одобряет существующим экраном заявок. Подтверждение человека в помощнике = «подать заявку», объект сразу не меняется.
  - `send_to_remake` исполняет «Вернуть монтажёру» (`sendBackToMontajer`) после подтверждения, НЕОБРАТИМО (`preview.irreversible`, отката нет).
  - Чтобы не писать вторую копию правил, тела обработчиков вынесены в `lib/*`, а REST и помощник зовут ОДНИ функции (поведение REST не менялось, его тесты зелёные):
    - `lib/propertyAccess.ts` — `canManagePropertyAs`, `publishedActionDeniedReasonAs` (`canManageProperty` / `publishedActionDeniedReason` в `routes/properties/shared.ts` стали обёртками);
    - `lib/propertyChangeRequestService.ts` — `checkPropertyChangeRequest`, `createPropertyChangeRequest`, `cancelPropertyChangeRequest`, `closeForOtherReviewers` (из `routes/properties/changeRequests.ts`);
    - `lib/propertyStatusDealGuards.ts` — `manualStatusChangeBlock`, `completedDealRevertBlock`, `saleReadinessBlock` (из `PATCH /properties/:id`, `crud.ts`);
    - `lib/propertySendBack.ts` — `sendPropertyBackToMontajerAs`, `sendBackDenied` (из `POST /properties/:id/send-back-to-montajer`, `videos.ts`);
    - `lib/marketingRole.ts` — `hasMarketingRole` (роут `marketing.ts` его реэкспортирует);
    - `lib/propertyRef.ts` — какой объект имел в виду человек (ОБ-000088 / 88 / id / ссылка Instagram / кусок адреса); не найден или несколько — отказ со списком кандидатов, выбирать за человека нельзя.
  - В `sendBackToMontajer` добавлены два необязательных параметра: `guard: {videoRemakeCount}` (условие записи под замком объекта) и `dryRun` (те же отказы без записи — для честного превью). REST их не передаёт.
- Гонки, которые закрыты:
  1. Двойное «Подтвердить»: брокер исполняет действие один раз; повтор отдаёт прежний результат (проверено тестом, в базе одна заявка).
  2. Цену/статус успели поменять между превью и подтверждением: снимок сравнивается брокером (409 STALE), и ЕЩЁ РАЗ под замком объекта внутри записи заявки (`expect` в `createPropertyChangeRequest`) — окно между сравнением и записью закрыто.
  3. Две заявки одного вида на объект: проверка «уже есть ждущая» и создание идут под одним замком (`withPropertyLock`), как у REST; ждущая заявка входит в снимок.
  4. Двойной перемонтаж: `videoRemakeCount` растёт при каждом возврате, `guard` под замком объекта отказывает со `stale`, если счётчик не тот, что видел человек.
  5. Откат заявки: условный переход PENDING → CANCELLED; если руководитель уже решил, откат отказывает 409, решение не затирается.
- Чем проверено: `build:shared`, `build:api`, `build:web` (код 0); тесты `ai-assistant-property-tools` (23), `assistant-send-back-guard` (6) и смежные (`ai-assistant-*`, `assistant-actions-*`, `property-change-requests`, `property-status-*`, `video-remake`, `published-video-fix`, `clip-review` и др. — всё зелёное); `map:check`, `map:gate`, `audit:deps:gate`, `audit:rules`, `audit:mocks` — чисто. Сторожа проверены нарочной поломкой: убрано сравнение `expect` под замком / проверка владельца объекта / `guard` / `dryRun` — соответствующие тесты краснеют.
- Что осталось / расхождения с документом:
  - Видов заявки «смена статуса» в системе нет — использован существующий `OTHER` с текстом «Сменить статус объекта ОБ-…: «А» → «Б»». По такой заявке CRM ничего не выполняет, руководитель меняет статус сам. Фаза 2 (`lib/propertyUpdate.ts`, прямое изменение цены и статуса для `properties.editForeign`) — отдельной пачкой.
  - Заявки в CRM существуют только для ОПУБЛИКОВАННЫХ объектов (AVAILABLE/RESERVED/SOLD/WITHDRAWN). Для объекта в подготовке инструменты цены и статуса отвечают «до публикации правят сами» — это поведение REST. Статус в REST агент может менять напрямую (поле открыто и после публикации); в помощнике по требованию задания — заявкой.
  - Заявка «Другое» требует ≥ 10 символов, одна ждущая на пару «объект + вид»: заявка «Другое» на статус блокирует другую «Другое» по тому же объекту (правило REST).
  - Ссылка Somon в базе не хранится; адресный поиск в `resolvePropertyRef` — только при единственном совпадении. Группа «read» (`find_property`) может иметь свой разбор ссылки — стоит свести к `lib/propertyRef.ts` при слиянии, иначе будет два.
  - `send_to_remake` по объекту без исходников на сервере (после публикации их убирает уборка) отказывает так же, как кнопка: «Загрузите новый исходник в окне «Вернуть монтажёру»» — загрузка файла через помощника невозможна.
  - Параметр `STATUS_LABEL` в `propertyAutoStatus.ts` не менялся, добавлен экспорт `PROPERTY_STATUS_LABEL_RU` (подписи статусов в превью — те же, что в карточке).
