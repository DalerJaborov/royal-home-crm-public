# 08.11.2026 — Бот ядра: вежливый тон, таджикский живой текст, без петли «Бори дигар такрор мекунам»

- **Почему.** Владелец 08.11: бот «очень грубый и резкий». Разбор 68 переписок прода 05–07.11:
  клиент семь раз спросил точный адрес объекта №192 и семь раз получил «Ҷойгиршавӣ: Сино, Душанбе.»
  (шесть раз с «Бори дигар такрор мекунам:»); две одинаковые строки «не найдено» в одном сообщении;
  «Агар саволи ман дар боло номафҳум буд…»; на фото — общий вопрос «какой объект»; на чужую публикацию
  без текста — русское «Эта публикация не наша.» таджикоязычной аудитории (10 раз); ни приветствия, ни
  «спасибо». В журнале ошибок: «живая фраза отброшена в 100% ответов (12 из 12), причины: language_disabled».
- **Что изменилось** (только сервер, промпт ядра НЕ менялся — пара качества V3 не нужна):
  - `ai/customerAgentSay.ts`: таджикский живой текст включён (`SAY_ENABLED_LANGUAGES = ["ru","tg"]`).
    Причина прежнего запрета (план 24.10, п. 8: «книжный тон, кальки, нужен носитель на 50 образцах»)
    закрыта кодом: валидатор отбрасывает запрещённые владельцем слова (`ai/agencyVoice.ts`: лутфан,
    илтимос, безаҳмат, муфассал, мутахассис, сипос, «бо камоли майл», «дар хизмати шумо» и др.) и тире;
    набор из 50 образцов `CUSTOMER_AGENT_SAY_TG_REVIEW_SAMPLES` — владельцу на просмотр. Клиенту фраза
    уходит только при `CUSTOMER_AGENT_SAY_MODE=live` (по умолчанию тень).
  - `ai/customerAgentRenderer.ts`: адрес — фраза «Объект №192 находится в районе Сино, Душанбе. Точный
    адрес и ориентир агент подскажет перед показом.» (в списке карточек — короткая форма). Повтор тех же
    фактов объекта больше не пересказывается: «в карточке указан только район / остальное расскажет агент»
    + один раз вопрос телефона (если номера нет), затем мягкие уведомления; «Повторю ещё раз» / «Бори
    дигар такрор мекунам» убраны (для офиса/часов — «Напомню:»). Первый ответ диалога здоровается
    («Здравствуйте!» / «Ассалому алайкум!»). Одинаковая строка в одном сообщении не повторяется (факты
    объектов не сливаются). Фото + вопрос без номера — «по фото объект не определить, пришлите номер или
    ссылку». Ход без слов при неизвестном языке — коротко на таджикском и русском. Уведомления о повторе
    переписаны без «лутфан», второе предлагает агента. Комиссия без тире.
  - `ai/customerAgentAttachmentInput.ts`: «Похоже, эта публикация не наша: такого объекта нет в нашем каталоге…»
    (без «спасибо» — решение 30.10 для «лайк за лайк»), без тире и «лутфан»; старые строки узнаются в истории.
    Приветствие первого хода не мешает правилу «второй пустой файл — молчание».
  - `ai/customerAgentRecruitmentProtocol.ts`, `lib/recruitmentAnsweredFact.ts`: вопрос об опыте без тире; старая
    формулировка по-прежнему читается как «опыт» в истории (сторож тона нашёл её тестом класса).
  - Первый ход = в памяти диалога нет ни одной реплики (после смены версии слова клиента остаются — не здороваемся снова).
  - `ai/customerDmLanguage.ts`: `customerDmHistoryLanguage` — одна дверь «что история говорит о языке»
    (её же зовёт `resolveCustomerDmLanguage`).
  - `lib/customerPropertyFactIntent.ts`: «суроға», «ориентир», «нишона», «точный/аниқ» — вопрос адреса.
  - `ai/customerAgentCore.ts`: рендер ядра получает те же входы, что повторный рендер доставки
    (`attachmentInput`, контекст в ветке неразборчивого медиа) — иначе разные тексты = `render_changed`.
- **Чем проверено.** Новые тесты `customer-agent-tone-08-11.test.ts`, `customer-agent-say-tajik.test.ts`,
  судья стенда: правила `no-duplicate-sentence`, `no-stock-phrase`, `greets-first` (+ красные тесты в
  `judge.test.ts`), 9 новых сценариев `tests/attack/corpus/tone.json`. Стенд scripted: до — 385/386 старым
  судьёй (221/386 новым: 174 первых ответа без приветствия, 6 «стоковых» фраз), новые сценарии 0/9;
  после — 385/386 и 9/9 обоими судьями (единственный провал `multi-turn-ru-005` — тот же, что до).
  49 файлов задетых тестов API (1293 теста) зелёные; `npm run precheck`.
  Грабля стенда: прогон всего корпуса одним заходом на одной базе после ~190 сценариев сыплется
  (`own_identity_registry_incomplete`, `original_context_changed`) — гонять половинами на свежих базах.
- **Что осталось.** Живой прогон на отдельном ключе Gemini (ключа прода не трогали). Владельцу: прочитать
  50 таджикских образцов и пары «было → стало» (`D:/CRM-migration-20261021/tone-before-after.md`, вне git);
  решить про `CUSTOMER_AGENT_SAY_MODE=live`. После выката версия бота примется сама (менялся только код,
  без промпта и инструментов).

## Независимое ревью коммита 49bce6d8f — исправлено вторым коммитом

Тест на каждую находку (`customer-agent-tone-review-08-11.test.ts`, `customer-recent-bot-message-postgres.test.ts`);
на коде 49bce6d8f новые тесты красные (15 из 25), после правки зелёные.
1. Петля адреса привязана к объекту: строка факта несёт №, другой объект — новый ответ (раньше «а №250 где?» после
   петли по №192 получал строку петли).
2. Петля — про один вид факта: после петли адреса «цена?» отвечается ценой, а не «в карточке больше нет».
3. `say` с приветствием отбрасывается всегда (`double_greet`): приветствие — забота сервера.
4. Новый код отказа `tone`: «ты/тебя/тебе/твой…», «знаешь/хочешь/можешь» (ru); «ту/туро/ба ту», формы 2 л. ед. ч.
   «навиштӣ, мехоҳӣ, медонӣ…» (tg). Русское «на ту квартиру» не задевается: списки проверяются только для своего языка.
5. Тире: ещё «―», «‒» и ASCII « - » с пробелами; дефис внутри слова пропускается.
6. Ход из одного «Салом!» больше не считается уведомлением о повторе (приветствия исключены из набора уведомлений).
7. Приветствие решает история сообщений диалога (`lib/customerRecentBotMessage.ts`): любое сообщение бота (старого или
   ядра) за 12 часов или запланированная/ожидающая часть ядра — без второго «Здравствуйте!». Ошибка чтения → прежнее
   правило памяти, без догадки. Файл добавлен в отпечаток ядра.
8. «нишона» — вопрос об ориентире только рядом с вопросительным словом или «?» (иначе это «знак»). Тот же классификатор
   зовёт старый бот (`messengers/conversation.ts`): «суроға/ориентир/нишона? /точный» и у него теперь распознаются как
   вопрос адреса и отвечаются его прежней строкой «Ҷойгиршавӣ: …»; голое «нишона» по-прежнему не трогается.

## Третья проверка (cd2dd6b58) — упрощение петли, четвёртый коммит

Правило-инвариант (тест перебором всех 780 последовательностей до 4 вопросов из {где, цена, этаж, комнаты, «цена и
адрес»} + те же после карточки, `customer-agent-tone-review3-08-11.test.ts`): каждый факт, спрошенный в этом ходе и
имеющийся в карточке, есть в ответе. Единственное исключение — адрес, когда петля адреса этого объекта открыта.
- Петля бывает только у адреса; вид «other» и его строки убраны. Повторно спрошенный обычный факт выдаётся снова,
  «Напомню:» — только если ответ иначе совпал бы с предыдущим.
- Петля адреса объекта открывается только если в ПРЕДЫДУЩЕМ ответе бота есть строка района этого объекта или его строка
  петли. Строки петли теперь с номером объекта («По объекту №192 точнее подсказать не могу…») и добавлены в память ядра
  рядом с фактами объекта. Долгая история — только выбор следующей формулировки и счётчик вопросов о телефоне.
- Вопрос о нескольких фактах: обычные факты выдаются всегда, строка района при открытой петле заменяется строкой петли.
- На 10 «где?»: район один раз, телефон не больше двух раз, двух одинаковых ответов подряд нет (ru и tg).
- Регулярка `\d` в запросе истории доходит до базы верно: postgres-тест отличает свежую отметку от «вчера».
