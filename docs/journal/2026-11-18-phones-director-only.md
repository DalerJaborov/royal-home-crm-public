# 18.11.2026 — Номера телефонов видит только директор

## Решение владельца (дословно)

«Номера продавцов закрыть от агентов совсем. Никто не может видеть своих, даже клиентов.
РОП полностью тоже закрыть номера. То есть, кроме директора, ни у кого вообще не будет
доступа к номерам телефона вообще.»

Права `clients.viewPhone` и `properties.viewOwners` уже были `directorOnly` (16.11.2026),
поэтому ни РОП, ни администратор, ни агент их не получают даже галочкой. Номер утекал
обходными путями — их и закрыли.

## Что было открыто и что сделано

1. **Свой объект открывал номер.** `stripOwnerContact` (lib/ownerContact.ts) отдавал
   `ownerContact` целиком ответственному, интейкеру и создателю карточки. Исключение
   снято: решает только `properties.viewOwners`. Сигнатура стала `(property, canViewOwners)`,
   все вызовы (REST-списки и карточка, история объекта, помощник `get_property_card` и
   `find_properties_by_place`, правка PATCH) переведены.
2. **Агент на своём объекте не потерял связь с продавцом.** GET /properties/:id отдаёт тому,
   кто ведёт объект, `sellerClient` (имя, ссылка) и `ownerContactMasked` (`+992•••••57`).
   «Позвонить» звонит через станцию на номер карточки продавца (`callPhone` только у директора).
   Текст «Номер видят руководитель и агент этого объекта» заменён на «Номер видит только
   директор»; в правке объекта — «Номер видит и меняет только директор».
3. **Мастер объекта.** Сервер по-прежнему кладёт в `ownerContact` номер выбранной карточки
   продавца, но ответ (`presentProperty`) теперь всегда закрыт без права.
4. **Рынок.** Новый `lib/crmContactPhones.ts`: номер объявления Somon/Paydo прячется, если он
   уже есть у нас — контакт владельца любого объекта или любой номер карточки клиента
   (основной, WhatsApp, запасные). Применено в `/market/matches/property/:id`,
   `/market/listing-contact` (403 `CRM_PHONE_HIDDEN`) и в «недавно ушли»
   `/market/property/:id/dynamics`. Раньше сверка шла только по `ownerContact` и только для
   чужих объектов — WhatsApp-номер продавца проходил насквозь.
5. **Свободный текст.** Маской (`phoneSafeText`) теперь закрыты: заметка, причина отмены и
   отметка выплаты сделки (`dealTextPhoneSafe` — список «Сделки» и сделки в карточке
   клиента), `refusalReason` / `deferredReason` клиента, `showingOffCrmDetails` показа,
   любые цифры номера в meta записей истории объекта.

## Проверка

- Новый сторож `apps/api/tests/phones-director-only-guard.test.ts`: агент и РОП обходят
  карточку и список объектов, карточки продавца и покупателя, список клиентов, сделки,
  совпадения рынка, номер объявления, историю объекта — ни в одном ответе нет девяти цифр
  ни одного номера, хотя всё своё; директор видит номера целиком. Проверен поломкой:
  вернул «свой объект видит номер» в GET /properties/:id — сторож покраснел (2 теста),
  откатил. Он же нашёл утечку заметки сделки в карточке клиента, закрыта.
- Обновлены тесты старого правила: `owner-contact-guard`, `property-card-seller-client`,
  `market-own-match`; веб — `PropertyPeople.test.tsx` (маска + кнопка звонка).

## Что осталось

- **АТС (не тронута, нужно «да» владельца).** Прочитано на `rh-pbx` только чтением:
  - Входящие на аппараты сотрудников (Zoiper, офисный 2020, очередь 1000) идут с
    `CALLERID(num)` клиента — номер виден на экране и в истории Zoiper.
  - У внутренних номеров `Send RPID: Yes` — при звонке кнопкой «Позвонить» станция после
    ответа клиента шлёт аппарату агента обновление «с кем соединён» с номером клиента.
  - Переадресация на мобильный уходит через транк 1 с `FORCEDOUTCID_1 = 6501414`: на
    мобильном виден номер агентства (ОЦЕНКА по конфигу, проверить звонком).
  - Предложение — в заметке группы `PBX-caller-id-proposal.md`.
- Описание объекта (`Property.description`) не маскируется: это текст объявления для сайта,
  правка формы записала бы маску поверх настоящего текста. Ник соцсети клиента
  (`socialUsername`) не закрыт — не номер.
- Заголовки пушей маскируются узким разбором (`maskPhonesInText`): номер, набранный с
  пробелами в «следующем шаге» задачи, может дойти до пуша агента.
