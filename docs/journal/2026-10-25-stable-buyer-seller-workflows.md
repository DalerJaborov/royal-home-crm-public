# Покупатель, продавец и закрытые проверки — подготовка версии

Дата: 25.10.2026. Ветка разработки: `codex/private-review-refusal`. База объединена с публичным main `eb4cefc30011f4050772c05f919e99bcdfec9c32`. Это подготовка исходников; разрешения на выпуск и включение новых отправок нет.

## Решения владельца

- Закрытые проверки доступны только администратору и директору, включая обходы через права, журналы, аудио, AI и агрегаты.
- Окончательный отказ завершает назначение и освобождает слот; агент сохраняет просмотр истории. При второй роли или открытой сделке работу сохраняем до решения руководства. Обычные отложенные карточки сохраняют прежнее поведение.
- Двойная роль определяется автоматически по актуальным фактам; противоречие требует уточнения. Постоянный вопрос в обзоре убран, ручное изменение находится в редактировании. Ручное решение имеет приоритет; администратор/директор может вернуть автоматический режим.
- Личный номер агента в существующих объявлениях сохраняется.
- Озвучка использует ElevenLabs и настраиваемый список голосов без ограничения двумя голосами. До выбора ключа/модели/голоса генерация недоступна с понятным объяснением.
- Новые автоматические отправки и звонки остаются в режиме расчёта и предпросмотра.

## Изменения

Исправлены отбор показов по времени события, авторство через subjectAgentId, подтверждение разговора по серверной длительности, сохранение роли на момент показа, гонки согласования числа объектов и изменений карточки во время AI-анализа. Подбор учитывает действующие покупательские роли, исключает собственные объекты и параметры другой стороны.

Отменённые задачи сохраняются с текстом и сроком, не становятся выполненными и не оживают после переназначения. Пересчёт прошлых KPI учитывает дату отмены. Новая метка изменения Client служит только для конкурентных записей, не подменяет даты исторических событий.

Добавлены приватные дела проверки, факты с источниками, решения с историей и защитой повторов, настройки описательной повторяемости. Один разговор не превращается в несколько независимых доказательств. Подтверждение нарушения — только решение человека. Данные и конфигурация не доступны обычным ролям через общие settings/API.

Снятие объекта через статус, одиночное и массовое удаление и одобрение заявки создаёт единое закрытое досье. Новые формы требуют причину. Для старых клиентов API без причины сохранена совместимость с честной отметкой неизвестной причины. Постоянное удаление не менялось.

Озвучка хранит версии текста, фактов и голоса, требует одобрения и повторной проверки после изменения фактов. Неизвестный результат платной генерации не повторяется автоматически. Передача монтажёру, обновление публикаций и месячный отчёт собственнику пока создают только предварительные записи, без отправки. Планирование отчёта выключено по умолчанию и требует явного предварительного согласия.

Выбор дополнительного номера использует подписанный идентификатор полного номера, а не совпадение масок. Изменившийся выбор отклоняется до звонка. История добавления дополнительных номеров фиксирует только будущие изменения, не придумывает даты для старых данных.

Карточка подбора показывает краткие условия, три варианта в обзоре, полный список отдельно, понятное количество результатов, соответствия и неизвестные параметры. Предпросмотр и реальная отправка различаются.

Выбранные объекты видны отдельным списком и удаляются из выбора по одному даже после смены страницы или фильтра. Закрытие полного списка возвращает обзор к первой странице. Подготовленный текст и адресат закреплены отпечатком: изменение цены, текста или получателя требует повторного предпросмотра до отправки. Старые клиенты API без предпросмотра сохраняют прежний контракт.

## Проверка и границы

Изменения проверяются на отдельной PostgreSQL, с синтетическими данными и отключёнными внешними ключами отправок. Предыдущий этап имел 615 профильных API-тестов и 50 frontend-тестов; итоговый полный прогон этой расширенной версии фиксируется отдельно после завершения. Внешняя доставка, настоящие голоса ElevenLabs и установленная production-версия этим документом не подтверждаются.

До выпуска необходимы полный облачный прогон точного коммита, проверка миграций на свежей базе, приёмка ролей и экранов, резервная копия и проверенный сценарий отката. Возврат старого приложения после новых отказов без совместимости новых маркеров не считается безопасным откатом.

На отдельной свежей базе применены все 560 миграций; сравнение со схемой пустое. Локальные профильные прогоны: 91 тест ролей/конкурентных правок/показов, 42 теста приватности/озвучки/предпросмотров, затем 25 тестов исправленных проекций приватности и аудио, 23 теста отправки с защитой предпросмотра — без падений. Прогоны пересекаются; числа не суммируются как уникальное покрытие. Проверки общего интерфейса и точного финального коммита фиксируются отдельно.

Полный локальный интерфейс: 318 файлов и 1924 теста без падений. После исправления узких подмен модулей ещё 34 серверных теста прошли отдельно. На локальном API и Vite сохранены пожелания покупателя и проверен пересчёт подбора, выбор и предпросмотр под AGENT/ADMIN на 1440 и 390 пикселях. Использовались только синтетические карточки без настоящих фотографий; созданные фикстуры удалены, процессы остановлены. Это не проверка production или реальной доставки.

Первый полный облачный прогон обнаружил пропущенную интеграцию новых связей при слиянии и устаревшие тесты доступа руководителя группы. При слиянии теперь сохраняются происхождение номеров без выдуманных дат, исходные факты и решения проверки, предварительные отчёты; совпадающие записи истории не удаляются. Старая проверка перенесённой карточки не меняет текущий итог основной карточки даже при совпадении агента и времени назначения. Ручная роль основной карточки имеет приоритет, отменённые задачи сохраняют исторического исполнителя. Актуальные данные основной карточки перечитываются под блокировкой, чтобы параллельное ручное изменение не потерялось. Обычные проверки руководителя группы остаются доступными, закрытые данные — только установленным ролям.
