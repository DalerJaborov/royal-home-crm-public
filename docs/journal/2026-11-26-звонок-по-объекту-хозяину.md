# 26.11.2026 — Звонок по объекту уходит хозяину объекта: узнавание с допуском на ошибки расшифровки

- **Живой случай.** ПК-001086 (05:36 UTC, IncomingCall dc43451a…, Interaction 2f4408ac…): клиент позвонил
  оператору по ролику Instagram про объект №230 («ду хонага… масҷиди Мехкалон, Қазоқон… 165 ҳазор…
  Зайниддин Файзуллоев»). Карточка №230: 2 комнаты, 3 этаж, «возле мечети в Қазоқон», 965 000 с.,
  принял Сайфуллоев Илҳом (assignedAgentId пуст), создан 25.11. Подпись ролика: «Цена: 965 000 с.…
  +992 93 770-17-18 Агент Сайфуллоев… Объект №230». Заявка ушла по очереди Миҷгоне; хозяин не узнал.
- **Причины (ФАКТ по коду и хронологии):**
  1. `identifyProperty` вычёркивал объект, если цена объявления расходится дальше 20 % (`PRICE_VETO`);
     расшифровка потеряла первую цифру («саду» вместо «нӯҳсаду»), 165 000 против 965 000 — объект №230
     вылетел из кандидатов целиком (в хронологии ни одного «похожего»).
  2. `sameWord` требует общее начало ≥4 букв: «Казакон» и «Қазоқон» (а/о) не совпадали вовсе.
  3. `matchRequestedAgent`: «Файзуллоев» подошёл с двумя ошибками и Сайфуллоеву, и уволенному
     Нарзуллоеву — «тёзки», заявка по очереди. Имя разбиралось ДО объекта, хозяин объекта ничего не разводил.
  4. Расшифровка звонка не знала ни фамилий сотрудников, ни ориентиров, ни правила «числа целиком».
- **Что изменилось:**
  - `lib/propertyClueScoring.ts` (новый): цена — примета, не вето (точная +4, близкая +3, другая валюта +2,
    без тысяч +2, одна цифра иначе +1, совсем другая −3); ориентиры с допуском на написание (Левенштейн 1 от
    6 букв); вид места TJ↔RU («масҷид» = «мечеть») +1; свежий объект (14 дней) +1.
  - `lib/propertyMatch.ts::identifyProperty`: без вето по цене, `strong` (место + ≥2 числовые приметы) и
    `lead`; комнаты-противоречие −4.
  - `lib/numberWords.ts` (новый): числа словами ru/tg → цифры; применяется к расшифровке перед моделью
    (`ai/incomingCallLead.ts`) и к подсказке номера (`resolveCallPropertyHint`: «объект двести тридцать»).
  - `lib/requestedAgent.ts`: расстояние имени (точное побеждает похожее), `preferAgentIds` (хозяин объекта
    разводит похожие фамилии), среди похожих с ошибкой уволенные уступают действующему; `resolvedBy` в заметке.
  - `lib/telephony/qualifyIncoming.ts`: объект узнаётся первым, его хозяева идут в разбор имени; объявление
    клиента (`Client.sourceAdId` → один объект) — прямое указание; сильное совпадение перебивает снявшего
    трубку; похожие без уверенности — подсказка руководству в колокольчик; рубильник.
  - Рубильник `callObjectToOwnerEnabled` (ВКЛ): shared `automationSwitches.ts`, Settings + миграция
    `20261126170000_call_object_to_owner_switch`.
  - `ai/transcribe.ts` + `lib/telephony/transcriptionVocabulary.ts`: инструкции звонку — фамилии действующих
    продавцов, ориентиры объектов в продаже, народные места (с запретом вписывать непроизнесённое) и «числа
    целиком, нӯҳсаду = 900».
- **Гипотезы владельца:** (1) «Файзуллоев» = «Сайфуллоев» — ПОДТВЕРЖДЕНО косвенно: подпись ролика №230
  «Агент Сайфуллоев», клиент читал её; «Зайниддин» — НЕТ ДАННЫХ (в ролике имени нет). (2) 165 ↔ доллары —
  НЕ СХОДИТСЯ: 965 000 / 9,28 = 104 тыс. $, 165 000 $ = 1,53 млн с.; ни одна конвертация не даёт 965 000.
  Реальная причина — потерянный разряд «нӯҳсад» (900) в расшифровке; по аудио локально не проверить:
  faster-whisper (small/medium) таджикскую речь не разбирает (НЕТ ДАННЫХ по аудио), подтверждение
  косвенное — Миҷгона после разговора записала 965 000 и 3 этаж.
- **Чем проверено:** `tests/call-object-clues.test.ts` (чистые правила), `tests/call-object-owner-230.test.ts`
  (регрессия звонка и таблица случаев), обновлён `tests/property-identify.test.ts`; `incoming-auto-lead`,
  `requested-agent`, `live-voice-property-tools`, `bots-search-30-queries`, `automation-switches`;
  `npm run precheck` — результаты в PR.
- **Что осталось:** живая проверка на проде следующим звонком по объекту (запрос к IncomingCall/Interaction в
  PR); порядок «хозяин = принял → ведёт → завёл» (`propertyOwnerAgentId`, 11.09) оставлен как был —
  владелец сформулировал «ведёт → принял», для №230 одинаково, решение за ним; заморозка/пауза хозяина
  по-прежнему не отменяет владение (решение 11.09), владелец 26.11 сказал «если активен и не заморожен» —
  конфликт правил вынесен в отчёт.

## Вторая итерация — по ревью architect (26.11.2026, вечер)

Ревью (без контекста автора) вернуло «выкатывать нельзя». Исправлено:
- **Б1 числа словами портили суммы** («миллион двести» → 1 000 200, «пятьсот шестьсот тысяч» → 1 100 000,
  «детский сад» → «детский 100»). `lib/numberWords.ts` переписан на строгую грамматику: одно число =
  [группа тысяч] [группа], разряды по убыванию; два числа подряд, «миллион», одинокое «сад» — остаются
  словами. Перевод включается только рубильником (`extractIncomingCallLead({ normalizeNumbers })`,
  `resolveCallPropertyHint({ spelledNumbers })`); число с единицей («сто двадцать квадратов») — не номер карточки.
- **В1 путь «объект по объявлению клиента» удалён**: сравнивал `Client.sourceAdId` (id Meta) с внутренним
  `AdProperty.adId` — на проде 0 совпадений; починка в лоб засчитывала бы первое касание прямым указанием
  мимо защиты продавца. Оставлено в «чего не хватает».
- **В2 допуск на цену — только звонок и только старший разряд.** `comparePrice(..., { tolerateAsr })`: без
  флага (чат, бот, голосовой консультант, рубильник выкл) — правило 24.09 «дальше 20 % — другой объект»
  (тест «400 против 300» возвращён как был). С флагом: потерянный/иной старший разряд при значащем хвосте
  («165»↔«965», «65»↔«965»), потерянные тысячи, другая валюта — плюс; соседние сотни (300↔400), 1,2↔1,9 млн — минус три.
- **В3 «сильное» совпадение, перебивающее снявшего трубку, считается только по приметам объявления**
  (второй проход `identifyProperty` без desired*/бюджета/района/типа). Тест: покупатель описал, что ищет, —
  снявший остаётся.
- **В4 рубильник ВЫКЛ = поведение main:** те же вызовы без флагов; узнавание по приметам с верной ценой
  по-прежнему отдаёт хозяину (тест). Подсказки расшифровке (`asrHints`), числа словами, нечёткие ориентиры
  с заменой буквы, вид места, тай-брейк свежести, сверка имени с хозяином (`asrAware`, `preferAgentIds`) —
  только при ВКЛ. Для всех каналов оставлено одно: «о»=«а» в ориентирах (Қазоқон/Казакон) — строго
  расширяет прежнее совпадение по началу слова.
- **В5 свежесть — не баллы**, только порядок при равных баллах (и только с флагом).
- Мелочи: исход в подсказке руководителю по факту (снявший / названный / раздача); `resolvedBy:
  "similar_property"` для слабого кандидата; сбой словаря расшифровки → `logSystemError`; регулярки вида
  места собираются один раз; номер SIP в тесте — `reserveExtensionBase`; `кв\b` в регулярке заменён на
  `кв(?![\p{L}])` (`\b` по кириллице молчит).
- **Решение за владельцем (не менял):** порядок «хозяин объекта» (`propertyOwnerAgentId`: принял → ведёт →
  завёл, правило 11.09) и то, что заморозка/пауза хозяина не снимает владение (11.09).

## Третья итерация — по повторному ревью (26.11.2026, ночь)

- **Блокер:** подсказка руководству («объект не узнан уверенно») и сверка названной фамилии с хозяином
  строились по проходу с пожеланиями покупателя. Теперь обе — по второму проходу только по приметам
  объявления и только если такая примета прозвучала; «ищу двушку в районе» → ни колокольчика, ни
  разведения тёзок (тест).
- Числа словами: порядковые («сто втором», «двадцать пятом году», таджикское «-ум»), цифры рядом
  («нӯҳсаду 65») и «сад два» без союза — остаются словами.
- Допуск «старший разряд»: названное должно начинаться с 1 (от «нӯҳсаду» остаётся «саду») либо
  старшего разряда нет совсем при значащем хвосте; 250↔350, 450↔650, 500 000↔1 500 000 — другая цена.
- Инструкция модели «заполняй приметы объявления» — только при рубильнике (`objectHints`).
- Скорость: «о→а» сворачивается один раз на слово; цена 0 в карточке без допуска снова вычёркивает.
