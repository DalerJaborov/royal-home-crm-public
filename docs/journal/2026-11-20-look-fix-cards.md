# 2026-11-20 — «Новый вид»: правки карточек объекта и клиента по кадрам владельца с iPhone

Ветка `fix/look-cards-20-11`. Источник — кадры `docs/design/oblik-2026-11-17/owner-shots-20-11-2005/` и добавка координатора про озвучку.
Кадры до/после — `docs/design/oblik-2026-11-17/fix-cards/` (`before-*`, `after-*`, ПК 1440 и телефон 390).

## Что изменилось

Карточка объекта
- Фото: целиком по центру (`object-fit: contain`) поверх размытой и затемнённой копии того же снимка — `PropertyPhoto` (`contain`),
  галерея всегда его включает. Горизонтальное, вертикальное и квадратное фото одинаково аккуратны. Миниатюры остаются `cover`.
  Видео в этой ленте нет (только фото), отдельной правки не требовалось.
- Район один раз: `districtOnce` (`objectTone.ts`) — если район уже в заголовке, под ценой и в адресе его нет; иначе стоит в адресе.
- Плашка этапа: `stagePillView` — «На проверке · 60 дн. (срок 3)»; жёлтая при просрочке, красная с огнём только при превышении срока втрое.
- Озвучка: заголовок «Послушайте новую озвучку» и строка про последствие (без повтора); свой плеер (круглая кнопка, полоса,
  «0:12 / 0:27», длина из записи, Infinity/NaN игнорируются), системный `<audio controls>` убран — вместо него «Открыть запись»;
  наложение: «Накладываем озвучку на ролик, обычно 2–3 минуты», «Начали в 17:01 · идёт N мин», с 6 минут «Дольше обычного» и кнопка
  «Проверить», с 15 минут — рассказ про повтор. Выдуманной полосы прогресса нет (в коде её уже не было после #334).
- Карточки голосов: одной высоты (`h-full`, кнопка прижата вниз), подпись «по умолчанию / вы выбирали» маленькой меткой, имя не режется.
- Фото на телефоне — такая же карточка с отступами и скруглением, как соседние блоки.

Карточка клиента
- «Взять из разговора: дом, Назди Сомон»: `GET /clients/:id/requirements-suggestion` разбирает строку «Ищет:» сводки
  (`lib/requirementsFromSummary.ts`, без вызова ИИ, пустые поля, ничего не пишет); запись — по нажатию обычным
  `POST /clients/:id/buyer-requirements` (те же права), после неё подбор пересчитывается.
- Подбор: общее «Чего мы не знаем о клиенте / Спросить» — один раз над списком (`commonMatchGaps`); на карточке только своё.
- Липкая панель «Отправить выбранные» стоит над нижним меню (104 px + safe-area), неактивная кнопка серая.
- «Лид» → «заявка» в видимых текстах карточки клиента, приёма, главных экранов агента, подбора, передачи (в коде и ключах не тронуто).
- Оценка ИИ: «Шанс сделки: низкий · 30/100», без красного.
- Заметки без крика: `softenShouting` (капс → обычный регистр, значки убраны) в хронологии и «Пожеланиях».

## Ревью #338 (architect) — что исправлено вторым заходом

1. Утечка номеров: `GET /clients/:id/requirements-suggestion` отдаёт только `{ available, labels }` (ни полей, ни заметок, ни цифр).
   Запись — `POST …/requirements-suggestion/apply`: сервер заново считает предложение по текущей карточке и дописывает слова
   клиента к заметкам, лежащим в базе сейчас; запись — общая дверь `writeBuyerRequirements` (ручная правка тоже через неё).
   Тест: агент без права на номера не получает цифр ни в GET, ни в ответе apply; свежая заметка не пропадает.
2. Ложный бюджет: валюта только вплотную к числу, районы/этажи/км/м² вырезаются до разбора, порог 10 000 сомони (1 000 $);
   по тесту на фразы «до 5 этажа», «до 3 км», «квартиру еще».
3. Затирание свежих заметок закрыто пунктом 1; после сохранения формы предложение сбрасывается.
4. Разбор: отрицание, «рядом с …», «3-4 комнаты» = от 3, дом/участок — тип не предлагается, район по позиции в тексте,
   границы слов через `BW/EW/TAIL`; тест на каждый случай.
5. Плашка этапа — одна функция `propertyStagePill` на список и карточку: обычный этап нейтральный; просрочка жёлтая
   «срок прошёл на N дн.»; от 3× срока красная «просрочено на N дн.», без огня.
6. Запасной вариант плеера — штатный `<audio controls>`; подпись кнопки меняется, `aria-pressed` убран.
7. `softenShouting` — только известные метки («ПРОСИТ ПЕРЕЗВОНИТЬ», «ТИП ОБРАЩЕНИЯ НЕ ОПРЕДЕЛЁН»); «ЖК ДИАМОНД», «ГУВД» не трогаются.
8. «Лид» → «заявка»: Clients.tsx, Notifications.tsx, ответы сервера (`routes/**`, `actor.ts`, `propertyDraftMedia.ts`, `assignment.ts`),
   род («Отклонена: заявка ушла», «Назначена агенту»). Сторож `noLeadWord.guard.test.ts`: новый файл или строка со словом краснит;
   в маршрутах сервера слова нет совсем; остаток (настройки, финансы, отчёты, источники, команда) — в `noLeadWord.baseline.json`, только убывает.
9. Поле текста озвучки растёт по тексту (`AutoGrowTextarea`), весь текст виден; тест.
Мелочи: подложка фото — миниатюра, режим только в «Новом виде»; панель над меню через `--ry-nav-clear`; бюджет в подписи «до 500 000 с.»;
повторно то же не предлагается (сравнение с заметками); заголовок «Из разговора и пожелания клиента»; `district.findMany` с `orderBy`.

## Повторное ревью #338 — второй заход

- Baseline сторожа слова «лид» подогнан после свода с #336 (Oversight убран, Reports → 2).
- Два района через «или», «и», «/», запятую («Сино или Фирдавси») — район не предлагается; тест.
- «Лид» → «заявка» в уведомлениях агентам: «🔔 Новая заявка…», «⏳ Заявка ждёт назначения», «Обращение стало заявкой»
  (приём, первый звонок, повторная раздача, реактивация, обращение по объекту), «Мои заявки», «Источники заявок», подписи журнала
  (`audit.ts` LEAD_ACCEPT/ASSIGN/DECLINE), «Новые заявки» в сводке. Менялись только строки текста.
  Сторож расширен на `.ts` и на поля `title/body/message/error/label` сервера; остаток записан в `noLeadWord.baseline.json`,
  а маршруты, приём заявок, первый звонок и уведомления в список попасть не могут.
- Строка «… задерживает объект» в каталоге без огня; тон через ту же `propertyStagePill` (красный только при тройной просрочке).
- `AutoGrowTextarea`: пересчёт по ResizeObserver при смене ширины, `overflow-y: auto` страховкой; тест.
- `POST …/apply` принимает отпечаток предложения (`fingerprint` из GET); не совпал или не прислан — 409 «Предложение обновилось,
  посмотрите ещё раз», ничего не пишется; тест.
- `--ry-nav-clear` оставлен в слое «Клиентов»: общей переменной оболочки сейчас нет, вынос — отдельная правка с чужим слоем
  (`theme-look-royal.css`), её держит другая ветка.
