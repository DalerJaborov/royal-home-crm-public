# 31.10.2026 — Помощник: действия с подтверждением (AssistantAction, ConfirmationBroker, чистка)

П2, задачи 2.3 и 2.6 из `docs/design/internal-assistant-architecture-2026-10-31.md` (раздел 2.3, раздел 6).

## Что изменилось

- **Миграция `20261031130000_assistant_action`**: новый тип `AssistantActionStatus`
  (PENDING/CONFIRMED/EXECUTED/FAILED/CANCELLED/EXPIRED/UNDONE) и новая таблица
  `AssistantAction` с индексами `[agentId, createdAt]`, `[status, expiresAt]`,
  уникальным `idempotencyKey`. Существующие таблицы не меняются; FK на `Agent`
  намеренно нет (никаких блокировок существующих таблиц, модель `Agent` не тронута).
- **`apps/api/src/lib/assistantActions.ts`** — брокер:
  `createPendingAssistantAction` (снимок «было» + превью, ничего не пишет;
  идемпотентно), `confirmAssistantAction` (ровно один запуск: переход
  PENDING→CONFIRMED одним условным `updateMany`), `cancelAssistantAction`,
  `undoAssistantAction` (только пока снимок «стало» не изменился; захват отката
  через `undoClaimedAt`). Реестр исполнителей `registerAssistantActionExecutor`
  (интерфейс `AssistantActionExecutor`) — реальных инструментов записи пока нет,
  их регистрирует П3. Коды: чужое 403, нет 404, истекло 410, устаревший снимок
  409 `{stale:true, action:<новое превью>}`, уже исполняется 409 `IN_PROGRESS`,
  повтор исполненного — 200 `replay:true` с прежним результатом.
- **`apps/api/src/lib/canonicalJson.ts`** — канонический JSON для сравнения
  снимков (JSONB переставляет ключи).
- **`routes/ai.ts`** — в конец файла: `POST /ai/assistant/actions/:id/confirm|cancel|undo`
  (`requireAuth`, Zod uuid на `:id`, тот же рубильник `isAiAssistantEnabled`,
  лимит 40/час на агента своим счётчиком). Актор собирается из `req.agent` на
  каждом нажатии — права перечитываются.
- **`jobs/assistantActionsSweep.ts`** + `cron.ts` (`assistant-actions-sweep`,
  `35 * * * *`): PENDING с истёкшим сроком → EXPIRED; CONFIRMED дольше 15 мин
  (процесс упал посреди исполнения) → FAILED + `logSystemError`; EXPIRED старше
  7 дней удаляются. EXECUTED/UNDONE/FAILED/CANCELLED не удаляются никогда.

## Решения и почему

- `idempotencyKey` = sha256(agentId, tool, canonical(args), hash(снимка), окно 10 мин);
  **nullable** и обнуляется на любом выходе из PENDING/CONFIRMED. Снимок в ключе —
  чтобы та же просьба над изменившимися данными давала новое превью, а не старое;
  обнуление — чтобы после отмены/истечения/отката ту же просьбу можно было
  повторить (NULL в уникальном индексе Postgres не конфликтует).
- Устаревший снимок: старое действие → CANCELLED и создаётся НОВОЕ с новым
  превью. Не правим старое на месте: иначе второе нажатие по старому id
  (двойной клик) исполнило бы превью, которого человек не видел.
- Права: брокер проверяет `requires` и канал исполнителя (по умолчанию только
  `crm`), но исполнитель обязан проверять права по `actor` сам.
