# 25.11.2026 — Шабнам: подключить сотрудника легко, без привязки «не в тот аккаунт»

- Что изменилось:
  - Профиль: блок «Личный чат с ботом CRM в Telegram» виден каждой роли (директор, админ,
    РОП, маркетинг, СБ, акционер…). Условие было скопировано в трёх вёрстках `Profile.tsx`
    (обычная, Clean, мобильная) — теперь одно правило `canSeeTelegramLink` в
    `apps/web/src/lib/staffShabnam.ts`. Акционеру (режим просмотра) разрешены свои
    `POST /me/telegram-link` и `/me/telegram-unlink` (иначе блок виден, а кнопка отказывала).
  - Настройки → Сотрудники: у каждого «Шабнам: подключена / не подключена»; в действиях
    строки «Подключить к Шабнам» (одноразовая ссылка + «Скопировать», сутки, один раз) и
    «Отключить Шабнам» (с подтверждением). После «Добавить сотрудника» — предложение сразу
    получить ссылку. Только директор/админ: маршруты `POST /agents/:id/telegram-link` и
    `/telegram-unlink` (agents.manage + подтверждение личности), тела — `lib/staffAdmin.ts`
    (учётку директора — только директор, раздающего права — только раздающий). В журнал
    пишется факт выдачи (`TELEGRAM_LINK_CODE_ISSUED`, `issuedBy: admin`), сам код — нет;
    ответ с кодом `Cache-Control: no-store`. Кнопки «Открыть в Telegram» у руководителя нет
    намеренно: открыв ссылку сам, он привязал бы к чужой учётке свой Telegram.
  - Код привязки живёт сутки (`Agent.telegramLinkCodeExpiresAt`, миграция
    `20261126100000_staff_telegram_link_expiry_same_person`). Код без срока (выдан до
    выката) действует как раньше.
  - «Не в тот аккаунт»: если этот чат или Telegram-аккаунт уже у ДРУГОЙ действующей
    учётки, код не съедается — бот спрашивает «Перепривязать … с А на Б?» кнопками
    `tl:y:<код>` / `tl:n:<код>`; код живёт ещё не дольше 15 минут; нажать может только
    владелец чата; двойное нажатие гасит `claimCallback`; «Нет» ничего не меняет.
    Прежняя учётка, которой чат больше не принадлежит, получает строку журнала
    `TELEGRAM_UNLINKED` (`source: telegram-relink`). Отключённая прежняя учётка
    (увольнение и новый найм) — без вопроса, как раньше.
  - «Это тот же человек»: `Agent.samePersonAgentId` (необязательное, при удалении учётки
    обнуляется). Ставится в правке сотрудника, показывается строкой с обеих сторон.
    Только подпись: права, клиенты и Telegram учёток не объединяются.

## Доработка по независимому ревью (25.11, вечер)
- Вопрос «перепривязать?» больше не режет срок самого кода до 15 минут: после «Нет» ссылка живёт свои 24 часа и привяжет второй Telegram. Давность вопроса проверяется на нажатии «Да» по дате сообщения (15 минут), иначе бот просит открыть ссылку заново.
- `/start <код>` с просроченным кодом получает «ссылка устарела», а не уходит клиентскому боту (`isExpiredLinkCode`).
- Второе быстрое «Да» (другой id нажатия) не затирает «Перепривязано» словами «устарела».
- В окне «Отключить Шабнам» добавлено предупреждение про единственный рабочий вход (монтажёр).
- Не сделано: пуш старой учётке при перепривязке; срок для старых кодов без срока (решает владелец).
- Проверено: build:api/web, tsc по api без ошибок, test:web 3339. Тесты с базой (`staff-shabnam-link.test.ts`: устаревший вопрос, двойное «Да», `isExpiredLinkCode`) идут в полном test:api при ship.
