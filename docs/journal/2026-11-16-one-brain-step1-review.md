# 16.11.2026 — один мозг, шаг 1: исправления по независимому ревью #211

Источник: ревью `reports/review-211-2026-11-16.md` (вне репозитория) и его пробник. Проверка по словам пропускала
перевёрнутые факты: комиссия 0%/2% наоборот, «да, в Худжанде тоже», «аренда есть», «продан» → «свободен», чужая цена,
«бесплатно», «документы готовы», годы из `updatedAt`. Решение — рекомендация ревьюера: модель факты не пишет вообще.

## Что сделано
1. Модель пишет только человеческую часть: `answer = { lead, ask, close }` (вступление, свой вопрос, тёплая концовка).
   Сервер собирает: приветствие шаблона (если вступление не здоровается) + lead + строки фактов шаблона дословно +
   (ask | вопрос шаблона) + close (только без вопроса). Проверка «всё или ничего», ничего не режется.
2. Человеческая часть отклоняется при любом признаке факта: цифры, № и %, валюта, числа словами, даты и сроки, латиница,
   места и имена, «да/нет», «работаем/продаётся/сдаём», документы, новостройка, годы, «рядом/центр», «бесплатно»,
   «много/все», похвала объекта, контакты, обещания. Вопрос — ровно одна тема, та же, что выбрал сервер; слова своей темы
   («район», «комнат», «позвонил») разрешены только в нём. Вопрос о звонке должен спрашивать согласие, а не объявлять звонок.
3. Один список слов на оба канала модели (`ai/customerAgentHumanText.ts`): «ты/ту» и глаголы на «ты» (ru «хочешь»,
   «подскажи»; tg «дорӣ», «бигӯ», «ме…ӣ»), слова другого языка (ru в tg и наоборот), утверждения о сервисе. `say` читает
   те же списки (там была та же дыра: «Да, в Худжанде тоже работаем» проходило, раз клиент сам назвал город).
4. Согласие на звонок и вопрос имени записываются по решению, а не по концу текста (`customerAgentSentQuestion`):
   «да» на вопрос своими словами создаёт звонок. Проверка сохранённой строки — «вопрос последней строкой».
5. Принятые слова модели попадают в память диалога (`customerAgentMemoryText`): строка без фактов проходит повторную
   проверку; повтор и второе приветствие теперь видны. Ответ на свой вопрос модели о районе/комнатах/бюджете продолжает поиск.
6. Свой рубильник `CUSTOMER_AGENT_ANSWER_MODE` (пусто = тень, `live`, `off`), строка в `docker-compose.prod.yml`.
   `CUSTOMER_AGENT_SAY_MODE=live` больше не отправляет ответы модели; `off` возвращает правила `say`.
7. Дневная строка `reportCustomerAgentAnswerDay`: «годные» = отправленные + тень; попытки написать факт считаются отдельно
   и никогда не «годные»; особые случаи и выключенное — вне доли.
8. Исключение в проверке — причина `error`, уходит шаблон, ход не падает (и в рендере, и в ядре).

## Раунд 2 после повторного ревью (чёрный список не закрывается: 74 из ~150 обходов прошли)
- Белый словарь вместо чёрного списка: `lead`/`close` — только слова из `HUMAN_VOCABULARY` (ru и tg, по `tajik-phrasebook`:
  приветствие, «понимаю», благодарность, извинение, мягкое вступление; формы слов перечислены). Любое другое слово — шаблон.
- Рядом с отказом, «продан/в брони», зоной работы, «не могу подтвердить», пустым поиском — только нейтральные слова и без `close`.
- `ask` — только утверждённая формулировка своего вида (`APPROVED_ASKS`), без вопросов о городе; согласие на звонок и вопрос имени
  ставятся только на утверждённую формулировку. Словарь и формулировки показаны модели в правилах.
- «ты»: дефис делит слово («Скажи-ка», «Бигӯ-чӣ»), таджикский без спецбукв («дори», «бигу», «мехари»), «шав», «биёр», «поделись»,
  «опиши», вопрос в прошедшем времени без «вы» («определился?»), обращения «брат/дружище/бародар» («ака» — уважение, не ловим).
- Сторож условий продавца — только на вопрос («?», «какие», «чи»…), не на описание «все условия есть», «ҳама шароит дорад».
- Тест `customer-agent-answer-review2-16-11` — все случаи probe2/probe3 (на прежнем коде 107 падений, на новом зелёный).
