# 26.11.2026 — недозвон: тревога только агенту, причина словами

**Что попросил владелец.** Ему как администратору приходило «⚠️ Клиент: не отвечает — Агент X не может дозвониться, проверьте контакт с клиентом». Вопрос: зачем это мне, что я могу сделать; пусть дёргает только агента и пишет причину — не ответил, занято, международный номер.

**Как было.** `lib/noAnswerStreak.ts::notifyNoAnswerEscalation`: на 3-й (Настройки → `noAnswerMaxAttempts`) недозвон подряд — общая задача «Проверить контакт с клиентом» и пуш через очередь алармов всем с правом `clients.assign` (директор, админ, руководитель, РОП). Вызывается из трёх мест: звонок через CRM (`callTracker.ts`), исход, записанный руками (`routes/clients/interactions.ts`), исход от ИИ по записи (`aiCallOutcome.ts`). Соседний сигнал `agentNoPickupGuard.ts` («Телефон агента не отвечает», 3 набора подряд без ответа на аппарате агента) — тоже руководству. Станция при этом сообщала точную причину (DIALSTATUS: BUSY / NOANSWER / CHANUNAVAIL / CONGESTION), но все четыре сливались в «клиент не ответил».

**Что изменилось.**
- Рубильник `NO_ANSWER_LEADERSHIP_ALERTS` (по умолчанию выключен = новое поведение). Выключен: руководству ничего; агенту, который звонил, — одна автозадача нового вида `no_answer_agent_followup` («напишите в WhatsApp или Telegram; не отвечает и там — переведите в Неактивные», гаснет сама при состоявшемся разговоре, входит в `CALLBACK_AUTO_TASK_KINDS`) и строка в колокольчике. «Телефон агента не отвечает» — тоже самому агенту, запись в журнал ошибок без пуша директору (`silent`).
- `callTracker.ts::describeNoAnswerReason`: причина по DIALSTATUS — «клиент не ответил», «занято», «номер выключен или вне сети», «сеть не пропустила вызов»; для полного номера с чужим кодом страны (не 992) при CHANUNAVAIL/CONGESTION — «международный номер…» с подсказкой написать в мессенджер. Текст идёт в окно звонка агента (`outcome`), в хронологию клиента и в задачу.

**Чем проверено.** `tests/no-answer-agent-only.test.ts` (новый: нет алармов руководству, задача и колокольчик агенту, без дублей, причины словами, иностранный номер); `tests/call-outcome.test.ts` (старый путь — под `NO_ANSWER_LEADERSHIP_ALERTS=1`); соседние тесты звонков; `npm run precheck`.

**Что осталось.** Исход по-прежнему NO_ANSWER для всех четырёх причин (серия попыток считается одинаково) — если окажется, что «сеть не пропустила» массово идёт на местные номера, это сигнал про транк, а не про клиента; смотреть счётчик в журнале. Международные номера станция, судя по коду, набирает как есть — пропускает ли их транк, не проверено на живом звонке.
