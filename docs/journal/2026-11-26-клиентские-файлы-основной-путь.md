# 26.11.2026 — Клиентские файлы сохраняются на основном пути приёма (ядро), причина потери всегда видна

- **Корень (ФАКТ, прод 25–26.11):** сохранение #428 (`lib/customerInputMedia.ts`) вызывалось только из старого цикла
  `processMessengerTurn` и ветки HELD вебхука. Клиентов ведёт ядро: подписанный вебхук → durable-вход →
  `customer-inbox-consume` → `prepareCustomerDmInboxCoreContext` → `recordScopedCustomerInput`. Вебхук на ядре делал
  `continue; // P11 owns CORE`, а запись реплики писала только текст или «[вложение без текста]». Файл не качался
  вообще: 8 из 8 потеряно молча, таблица `CustomerPendingMedia` пуста, в журналах про вложения ни строки.
- **Что изменилось:**
  - единая дверь `sourcesFromIngressMedia` / `keepIngressMediaInBackground` (`lib/customerInputMedia.ts`): из записанного
    входящего (kind, url, media_id WhatsApp) строит источники, качает сразу и прикрепляет к реплике. Зовётся из
    `recordScopedCustomerInput` (ядро, один раз — в транзакции, что записала реплику) и `recordHeldCustomerMessage`
    (удержанное до ACK). Прежний вызов в ветке HELD вебхука убран (путь один);
  - потолки платформы для сотрудника («staff» в `messengers/attachments.ts`): фото и голос до 25 МБ, видео и документы до
    100 МБ, без потолка по длительности; потолки разбора моделью не тронуты;
  - причина потери видна всегда: новые причины `unavailable` («канал не отдал файл») и `no_key` (ключ канала не принят;
    для WhatsApp — ответ Graph 401 + тревога руководству `raiseChannelKeyAlarm`, для Instagram/Messenger — отметка
    `accessLostAt` аккаунта). `lookupWhatsAppMedia` возвращает причину вместо молчаливого `null`;
  - старый цикл Meta и оба пути Telegram теперь тоже пишут `attachmentsLost` (`lostAfterStore`), а не голое «[вложение: image]»;
  - диск: меньше 1 ГБ свободного — файлы не качаются, пометка + громкая запись в журнал;
  - показ: «[📎 файл не открылся]» и «[📎]» в списке чатов — «Клиент прислал файл»; подписи потерь без цифр потолков.
- **Чем проверено:** `customer-core-media-kept-postgres.test.ts` (подлинный подписанный вход Instagram → настоящая запись
  реплики; без правки 4/4 красные, с правкой зелёные), `customer-input-media-all-paths.test.ts` (перечень путей записи по
  коду + поведение двери на настоящем разборе WhatsApp image/audio/video/document/sticker; сторож проверен внесением
  поломки), `media-attachments.test.ts` (профиль staff), `service-markers`, web-тесты подписей.
- **Что осталось:** восстановление файлов за 30 дней (только анализ, см. отчёт); старый цикл качает для модели по
  малым потолкам (большое фото там помечается «слишком большой файл», а не сохраняется) — вынести в ту же дверь; Telegram
  качается по потолкам модели; WhatsApp-вебхук до сих пор не прогнан живым файлом.
