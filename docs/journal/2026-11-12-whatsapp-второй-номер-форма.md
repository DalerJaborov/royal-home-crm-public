# 12.11.2026 — Второй номер WhatsApp: форма подключения и дыры вокруг отправки

- Что изменилось:
  - Экран «Настройки → Каналы → Аккаунты» (`MessengerAccounts.tsx`) умеет заводить номер
    WhatsApp: название, «Идентификатор номера (Phone number ID)», маркер, «Как бот называет
    компанию». Подсказка, где взять идентификатор и маркер. Отдельного мобильного двойника
    экрана нет, один адаптивный (`.fgrid`/`.fld` темы). У номера WhatsApp нет звезды «основной»
    и чипа «основной»: основной номер живёт в Настройках.
  - Сервер при подключении номера (`POST /settings/messenger-accounts`, канал WHATSAPP) читает
    номер у Meta этим маркером (`whatsappNumberIdentity` в `messengers/meta.ts`,
    `GET /{phone_number_id}?fields=id,display_phone_number,verified_name`, таймаут 15 с) и
    отвечает 400 «Маркер не принят» / «Номер не найден…» / «Не удалось проверить у Meta».
    Идентификатор — только цифры; тот же номер, что основной в Настройках, — 409.
  - Маркер второго номера НЕ может совпадать с маркером основного номера или другого аккаунта
    (`findTokenCollision` в `messengers/accounts.ts`; зеркальная проверка в `PATCH /settings`
    для маркеров WhatsApp и Страницы Facebook). Причина: `resolveLegacyMetaSendTransport`
    выбирает аккаунт по совпадению маркера, и совпадение даёт `account_mismatch` у ОБОИХ номеров,
    включая основной, который до этого работал.
  - Найденные дыры вокруг отправки (правка того же класса «основной номер в Настройках, второй в
    таблице»):
    1. `accountTokenById(null, "WHATSAPP"|"FACEBOOK")` отдавал маркер второго номера как «аккаунта
       по умолчанию» — напоминания, повтор зависших диалогов и просьба о номере для диалога
       ОСНОВНОГО номера отбивались. Теперь для диалога без аккаунта берётся маркер Настроек.
    2. `whatsAppMediaSource` читал файлы клиента маркером Настроек; у второго номера (свой
       кабинет, свой маркер) фото и голосовые не доходили бы до бота. Вебхук передаёт маркер
       аккаунта, в который написал клиент.
    3. «Здоровье системы»: при наличии строки второго номера проверка «жив ли WhatsApp» смотрела
       ТОЛЬКО на неё, смерть маркера основного номера осталась бы незаметной. Теперь «WhatsApp»
       — основной из Настроек, плюс строка `WhatsApp «название»` на каждый дополнительный
       включённый номер (`checkWhatsappAccountsHealth`); проверка прав маркера смотрит на основной.
    4. `rememberBusinessAccountFromWebhook` мог запомнить кабинет WhatsApp второго номера как
       кабинет шаблонов первого сообщения (если его вебхук придёт первым). Вебхук теперь
       передаёт только основной номер из Настроек.
- Почему: владелец подключает второй номер WhatsApp для дочерней компании «Арван» (Instagram
  arvan__estate уже подключён). Сервер несколько номеров умел, экран — нет.
- Чем проверено: `tests/whatsapp-second-number-route.test.ts` (13), `tests/whatsapp-second-number-send.test.ts`
  (все пути отправки — текст, фото, видео, голосовое, документ, геоточка, реакция, «прочитано» —
  на phone_number_id и маркер нужного номера, оба номера; одинаковый маркер; входящее; здоровье;
  разбор ответа Graph), фронт `messengerAccountsWhatsapp.test.tsx`. Тесты ловят поломку: при выключенных
  исправлениях №1 и сторожа маркера шесть из них краснеют.
- Что осталось (не чинилось, нужно решение):
  - Первое сообщение клиенту шаблоном (`lib/whatsappFirstContact.ts`) всегда уходит с ОСНОВНОГО
    номера и из кабинета шаблонов основного: для второго номера (своя WABA, свои шаблоны) нужна
    отдельная разработка.
  - Восстановление «зависших» входящих WhatsApp ядром (`lib/customerIngressClassification.ts`,
    ветка `WHATSAPP`) считает «свой номер» по единственному установленному ресурсу и при двух
    номерах возвращает `own_phone_identity_unavailable` (удерживает). Прямой путь «вебхук → ответ»
    это не затрагивает.
  - Второй номер в ДРУГОМ приложении Meta не подписывается: привязки секрета приложения для
    WhatsApp (как `InstagramAppBinding`) нет, `appSecret` в маршруте запрещён. Номер должен
    быть в том же приложении Meta, что и основной.
  - Та же схема «Страница в Настройках + строки в таблице» у Facebook: проверка здоровья Страницы
    смотрит на первую строку таблицы; не менялась.
