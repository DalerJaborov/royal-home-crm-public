# 2026-10-30 — язык ответа при вложении без текста и латинском мусоре (P3)

**Что.** `resolveCustomerDmLanguage` (ai/customerDmLanguage.ts): (1) JSON-заглушки истории
`{"incomingAttachments":..}` и `previouslyObservedCustomerMedia` не считаются свидетельством языка
(`isCustomerHistoryPlaceholder`, `customerHistoryOwnWords`); (2) третий параметр `publicState.language`
диалога — запасной источник, когда окно из 6 ходов не дало решающей реплики (смена ревизии, длинный диалог);
(3) латиница без кириллицы и без таджикских латинских слов («Binenw») не решающая (`isUnreadableLatin`
в clientLanguage.ts, устаревший `detectClientLanguage` для старого движка не тронут). `customerDmAgentTurn.ts`
— только передача `publicState.language`.

**Почему.** Таджикоязычный клиент присылал рилс без текста — бот отвечал по-русски; «Binenw» читалось как tg.

**Решение вне задания.** Свежая решающая реплика окна сильнее хранимого языка (хранимый — после неё): иначе
устаревшее значение перебило бы явную смену языка клиентом. Сейчас в DM-пути `publicState.language` никто не
пишет (остаётся `unknown`) — запись хранимого языка отдельная задача.

**Транскрипт чужого ролика.** Язык выбирается только на ходе 159 и в `customerAgentMediaReplyLanguage` (только
файлы самого клиента: голосовое, своё видео). Чужой рилс идёт через adjacent-наблюдение и язык не меняет — код не правился.

**Проверено.** vitest: customer-dm-language-resolve (+4 теста), client-language, preference, colloquial,
media-perception, corpus — зелёные; build apps/api — 0; атака `--model scripted --category language` 36/36 (+6 сценариев language-attach-*).
