# 19.11.2026 — ship: второй слой против молчаливого выхода с кодом 0

**Что изменилось.** `scripts/ship.mjs`:
- `holdProcessUntilSettled` теперь слушает ещё и `exit`: если процесс уходит, не
  дождавшись итога (в том числе через `process.exit(0)` из любого места), строка
  «✘ Выкат оборвался» пишется напрямую в stderr (`writeSync`), а код выхода
  подменяется на 1.
- Этап 7 (`git push` ветки) идёт с `GIT_TERMINAL_PROMPT=0` и пределом 5 минут;
  повисший вход в GitHub кончается остановкой с понятной причиной, а не вечным
  ожиданием. После пуша печатается «ветка отправлена».

**Почему.** 19.11 выкат #291 (журнал `D:/PublicWorktrees-20261021/own-music-ship4.log`)
оборвался уже с защитой #292: вывод кончился заголовком этапа 7, код 0, строки
«оборвался» нет, в main ничего не попало. Пуш при этом на GitHub дошёл (повтор
сказал «Everything up-to-date»). Значит, выход был не через пустой цикл событий
(`beforeExit` молчал), а через `process.exit` или снаружи. Причину точно не
воспроизвёл: в самом ship других `process.exit` нет, `taskkill /F` даёт код 1.
Против убийства процесса снаружи код не поможет — тогда признак успеха один:
последняя строка «✔ Правка #N на main».

**Чем проверено.** `node --test scripts/ship.test.mjs` — 50/50, два новых теста:
`process.exit(0)` посреди ожидания даёт код 1 и строку; после итога код не трогается.

**Что осталось.** Если обрыв повторится — смотреть, есть ли строка «оборвался»:
есть — виноват кто-то внутри процесса; нет — процесс убили снаружи.
