# Relevant customer reply segments

The common renderer previously printed every returned property field and the
entire selected vacancy card. A candidate submitting work examples could receive
the job description again alongside a genuine application receipt; published CV
instructions could also be followed by the same instruction a second time.

Explicit property questions now select the requested fact kinds from validated
observations. Vacancy introductions and specific conditions use a relevant view
of the existing staff-authored paragraphs. Paragraphs, amounts and restrictions
are not paraphrased or truncated. Unrecognized layouts and cross-paragraph
conditions remain complete; asking for full conditions retains the whole text.
This is a bounded presentation improvement, not a universal language classifier.

A saved application must not hide a question in the same turn: pay aliases and
explicit question markers conservatively retain the conditions answer. Two
additional negative regressions reproduced the omission before this correction.

The first combined full run caught a public portfolio question replaced by the
generic private CV invitation. Retain its original optional professional question
while adding the private-channel direction. The real digest scenario now asks
for both price and characteristics explicitly and adds a price-only negative
control; sold/private membership and freshness assertions are retained.
The digest's synthetic publication is unique per CI attempt: an assertion failure
must not leave a same-ID/different-membership post that makes its retry ambiguous.
The separate intentional catalog collision controls remain unchanged.

The next full run exposed the Telegram moderation test's global model spy
catching an unrelated asynchronous client-scoring request. Isolate that scoring
dependency in this test; keep the strict no-comment-model assertion intact.

A bare public number now resolves after this inquiry's genuinely accepted object
clarification. The existing accepted-list selection takes priority. Phone-shaped
numbers, other questions, job context and another customer's history do not grant
selection. The original focus resolver and locks still decide availability.

Signed Settings public-envelope inputs can stop an older reply before a busy
worker finishes FINAL; this observation grants no new input or action authority.
For a photo followed immediately by a caption, only finite visual labels from
the adjacent safely abandoned turn can be reused within 30 seconds, with the
same account, credential, controller, policy and revision. No OCR, transcript,
private history, accepted/unknown output or intervening message is reused by this
bridge. General Instagram private-memory eligibility is deliberately unchanged.
Tests cover the actual two-Settings-secret ingress configuration rather than
substituting the stronger per-account-secret path used by earlier fixtures.

A genuine application-saved receipt no longer causes unsolicited republication
of the vacancy, while an explicit question about its conditions still gets those
facts. An application invitation already present in the chosen paragraphs is not
duplicated. Public professional questions invite private messages without
requesting a public CV or claiming that any private message was sent.

Validation: synthetic RU/TG regressions, existing common-core/public/recruitment
companions and a real PostgreSQL inbox/core/read-witness/outbox fixture with
strictly synthetic provider I/O. No paid model replay or production sends were
used. Full release acceptance and real customer text review remain separate.
No new handover, fallback, provider, voice, rollout or business-rights behavior.
