- Что изменилось:
  - **Многостраничный PDF** (`telegram/assistantExpenseBatchIntake.ts` `rowsFromPdf`,
    `ai/assistant/mediaProbe.ts` `readExpensePdfText`/`renderExpensePdfPage`): до 30 страниц и 10 МБ.
    Страницы с текстовым слоем (`pdftotext -layout`) — одна сквозная таблица, разбирается кодом без ИИ;
    страница без текста — скан, ИИ порциями (как фото таблицы). Ключ повтора у всех строк — хэш файла +
    номер строки: тот же PDF второй раз не запишется. Одностраничный PDF без таблицы в тексте — прежний
    путь «один чек». Невидимый текст PDF человек видит в карточке до записи.
  - **Старый .xls** (`lib/xlsRead.ts`): свой читатель Compound File + BIFF8 без зависимости. Почему не
    библиотека: SheetJS в npm (`xlsx`) застыл на 0.18.5 с известными уязвимостями разбора чужих файлов
    (исправления — только в сборках с сайта SheetJS, не в npm) — ОЦЕНКА по памяти, первоисточник не
    перепроверялся в этой сессии; ставить пакет в общий `node_modules` копий тоже нельзя. Читаются SST
    (с CONTINUE посреди строки), LABELSST, LABEL, NUMBER, RK, MULRK, FORMULA (сохранённое значение и
    STRING), дата и валюта по формату (XF → FORMAT). Пределы: файл 10 МБ, поток, 5000 строк, 200
    столбцов, число записей; цикл в цепочке секторов — отказ.
  - **Реклама и зарплата** (`resolveRows` в `ai/assistant/tools/expenseBatchTool.ts`, словарь каналов —
    `AD_CHANNELS` в `ai/assistant/expenseArticles.ts`): канал — по словам строки (ru/tg/латиница),
    сотрудник — по имени через общую дверь `lib/agentNameLookup.ts` (бывший свой `findAgentByName`

    карточка. Не выбрали — «Прочее», как и раньше, но вслух. Требования REST к статьям — те же.
  - Вопрос «Это расходы?» — на таджикском, если разговор по-таджикски (язык по истории чата).
  - **REST без курса**: `POST /expenses`, смена валюты на доллар в `PATCH` и оплата долларового плана
