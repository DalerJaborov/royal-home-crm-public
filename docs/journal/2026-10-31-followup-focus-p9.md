# 31.10.2026 — P9: уточнение про только что показанный объект, таджикский продавец, продолжение подбора

Ветка `fix/core-followup-focus-31-10` от `fix/core-search-preread-31-10` (PR #80). Живой Gemini, многоходовые сценарии 14/24.

## Что было и почему
1. «а этаж?», «район», «цена» после показанного объекта давали «Я уже писал об этом выше…». Три причины:
   - «район»/«ноҳия» не распознавались как вопрос о факте (`classifyCustomerPropertyFactIntent`), код объекта «ОБ-000088» не читался как номер;
   - после показа ОДНОЙ карточки поиска фокус объекта не ставился → `property_unresolved` → «Какой объект?»;
   - сторож повторов `avoidRepeatedReply` подменял ответ-факт заметкой, если те же строки уже были в прошлом ответе, а второй раз «Какой объект?» превращал в «Я уже писал».
2. «хонаи фуруши дорам» → модель ответила `clarify_previous` без предыдущего вопроса → «Чиро муфассалтар шарҳ диҳам?»; плюс формы «фуруши дорам», «барои фурӯш» роль не читалась; «мефурушам, ду хонагӣ…» запускал поиск и показывал продавцу объекты.
3. «в Фирдавси» после вопроса бота о районе → «Какой объект вы имеете в виду?» (ответ без слова-запроса поиск не запускал).
4. Судья: правило `answers-the-question` валило список вакансий, оканчивающийся вопросом.

## Что изменено
- `lib/customerPropertyFactIntent.ts`, `lib/customerPropertyReferenceText.ts`: район/ноҳия — вопрос о факте (адрес); «ОБ-000088» — номер объекта (тире обязательно, «об этом 5 этаже» не номер).
- `lib/customerSearchSelection.ts`, `lib/customerAgentMediaFocus.ts`: голый вопрос о факте без названного объекта + ровно одна показанная карточка последнего поиска → она становится фокусом (та же проверка источника под замками, что у выбора «второй»). Несколько карточек не угадываются. Уже выбранный фокус заменяется, только если поиск был самым последним сообщением бота.
- `ai/customerAgentRenderer.ts`: заданный сейчас факт никогда не заменяется заметкой («Повторю ещё раз» + строка); повтор вопроса «какой объект» → «Я уточнял, о каком объекте речь…» вместо «Я уже писал»; после списка из ≥2 объектов вопрос «Какой из объектов вы имеете в виду: №A, №B или №C?» (по номерам из прошлого сообщения бота).
- `ai/customerAgentRole.ts`: «фуруши/фурушӣ дорам», «барои фурӯш». `ai/customerAgentSellerGuard.ts`: `clarify_previous` без вопроса бота перед ним у продавца → `seller_details`.
- `ai/customerAgentSearchIntent.ts`: `customerSearchContinuation` — ответ на фиксированный вопрос бота о районе/комнатах/бюджете продолжает подбор (условия из последних двух ходов клиента + ответ); «мефурушам/фурухтан» исключают поиск. Подключено в `lib/customerDmAgentTurn.ts` (только предчтение).
- `tests/attack/judge.ts`: строки списка считаются частями ответа. `tests/attack/attackStand.ts`: плейсхолдер `{{p1.ob}}`. `tests/attack/corpus/multi-turn.json`: 6 новых сценариев (021–025, tg-005).

## Чем проверено
`tests/customer-followup-focus-31-10.test.ts` (38 тестов) — без правок исходников 19 красных, с правками зелёные. Сборка `npm run build --workspace=apps/api`, смежные тесты и `--category multi-turn` / `seller` в отчёте задачи.

## Что осталось
- Скриптовая модель стенда сама ищет по названию района и сама тянет доказательства из прошлых ходов, поэтому сценарии 021–025 на ней зелёные и без починки (красным без правки остаётся только tg-005); настоящую проверку даёт живой прогон `--model live`.
- «цена 69» (голое число после слова «цена») по-прежнему не номер объекта.
- Промпт, схемы shared, описание инструментов не тронуты.
