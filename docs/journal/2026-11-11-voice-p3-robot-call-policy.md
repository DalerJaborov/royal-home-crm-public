# 11.11.2026 — Одна дверь «можно ли звонить роботом» (П3 плана робозвонка)

- Что изменилось:
  - `apps/api/src/lib/robotCallPolicy.ts` — `robotCallAllowed` / `robotCallRefusal`: часы
    09:00–19:00 по Душанбе, общие выходные и новые праздники (`Settings.companyHolidays`),
    отметка «Не звонить роботом» (новая модель `RobotCallStop`, номер в 9 цифрах + карточка),
    «не беспокойте» из переписки (`optedOutAt`), чёрный список станции (AMI), частота на номер
    (`Settings.robotCallDailyMaxPerNumber` = 1, `robotCallWeeklyMaxPerNumber` = 3, по исходящим
    `LiveVoiceSession`). Проверочный звонок идёт мимо часов и частоты, запреты человека — как у всех.
  - Мост `liveVoiceBridge.ts`: одна строка-блок первой строкой каждой `originate*` (тест,
    карточка, сценарий). Отказ по времени/частоте — «занято» (сценарий переносит, попытку не
    тратит), по запрету — окончательный `notDialed` с причиной словами.
  - `scenarioCallEligibility.ts` — обёртка над дверью (вызовы опроса и проверки продавца прежние;
    отметка «не звонить» отдаётся им как `do_not_contact`).
  - Ручка `GET/PUT /clients/:id/robot-call-stop` (схема `packages/shared/src/robotCallPolicy.ts`),
    права — как у правки карточки; просьбу клиента снимает только руководство.
  - Карточка клиента: строка-тумблер «Не звонить роботом» в меню «Ещё» (одно меню на ПК и телефон),
    переключается сразу. Кнопка «Звонок роботом» показывает причину отказа двери (409 словами).
  - Миграция `20261111120000_robot_call_policy` — аддитивная.
