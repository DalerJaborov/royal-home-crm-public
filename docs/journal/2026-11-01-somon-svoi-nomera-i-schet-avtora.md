# Somon: свои номера, маркеры агентства и счёт объявлений автора (01.11.2026)

Перенос четырёх правок из приватной истории (635b0d664, df4e2c319, e267024db, 022472db4,
база 9dcc8d5fe — до PR56) на публичный main поверх PR56 (28.10: проверка профиля продавца
`sellerPropertyCheck`, статус REVIEW_SELLER, `sellerCheck`/`lastCheckedAt`).

## Что изменилось
- Номер действующего сотрудника (`loadStaffPhoneChecker` в `reserveSomonDelivery`) — KNOWN_CONTACT, агенту не уходит.
- `SomonPhoneSighting` (только ключевой хеш номера): номер в 3+ разных объявлениях за 30 дней — REJECTED.
- Маркеры агентства в тексте/имени с границами слов (`BW`/`TAIL`): комиссия, посредник, риелтор, маклер, агент по недвижимости, realtor/real estate, «наша компания», «звоните в офис». Отрицания («без посредников и риелторов», «риелторов не беспокоить», «комиссии нет», «исключая посредников») — сигнал собственника; «комиссия (не) включена» — агентство.
- Счёт объявлений АВТОРА в «Квартиры, продажа, Душанбе» по нашей выдаче (`SomonSeenAdvert.sellerKey` = HMAC от `user.id`, сам ID не храним). «Вероятно собственник» — только при ровно одном объявлении автора в категории и не больше пяти на сайте; при счёте ≠ 1 карточка и телефон не запрашиваются. Автор неизвестен — отложено (SELLER_UNKNOWN, до 3 дней).
- Карточка агенту без предупреждения о дате.

## Как сведено с PR56 (одна логика, не две)
- Одна оценка `assessSeller` (поле `distinctApartments` заменено на `categoryAdverts` + `totalActiveAdverts`); «предварительная» оценка PR56 с подставленной единицей убрана — `processSomonPending` берёт `detail.assessment`.
- От PR56 оставлено: слово «собственник» не требуется; при 3+ объявлениях на сайте профиль автора проверяется по категориям (`checkSellerProperties`), больше двух объявлений недвижимости — REJECTED; неполный профиль — REVIEW_SELLER; сброс `sellerCheck` на каждом конечном статусе (добавлен и в новые ветки).
- Порядок: счёт автора (без запросов) → карточка → оценка → (дозапись ключей) → профиль PR56 при total > 2 → телефон → повтор номера → резерв (сотрудник/контакт).
- Строже PR56: total 6..30 теперь «проверить» без обхода профиля (мягкий потолок 5 из правки e267024db).

## Baseline: без сброса (решение этой правки)
Исходная миграция сбрасывала baseline — на проде это остановило бы рассылку на ~40+ минут
и потеряло бы объявления за это время. Вместо сброса: `SomonMonitor.sellerKeyRekeyPage`
(миграция ставит 1, если записи уже есть) и проход `rekeySellerPage` — одна страница выдачи
за тик после доставки, ТОЛЬКО дописывает ключ существующим записям. Пока проход идёт,
занижение счёта возможно (старые объявления автора ещё без ключа), поэтому собственником
пропускается лишь автор с ОДНИМ объявлением на всём сайте (`active_adverts` = 1 — занижение
невозможно); остальные откладываются (SELLER_UNKNOWN) и возвращаются в очередь по окончании
прохода (`requeueAfterRekey`). Риск «агентство за собственника» не растёт, рассылка не стоит.

`npm run build:api` код 0; `npx vitest run tests/somon-*.test.ts --no-file-parallelism` на стенде 4743 — 16 файлов, 88 тестов зелёные. Новый тест: при незавершённой дозаписи автор с 2 объявлениями отложен, с 1 — отправлен; после прохода счёт честный (2) — отказ без запроса карточки. Тест миграции: baseline не сбрасывается.

## Осталось
- Проход дозаписи ≈ число страниц выдачи тиков (~153 при 1 тике/мин ≈ 2,5 ч); если источник остановлен дольше 3 дней — отложенные истекут (не отправятся, это безопасная сторона).
- Завышение счёта старыми baseline-записями (проданное объявление остаётся в счёте) — не чинилось.
- Повтор номера срабатывает только после получения телефона: первые два объявления агентства могут уйти.
- Наличие `user.id` в живой выдаче подтверждено только кодом разбора и фикстурами.
