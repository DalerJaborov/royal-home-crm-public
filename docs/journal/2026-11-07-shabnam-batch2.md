# 07.11.2026 — Шабнам, пачка 2: язык частичного ответа, журнал хода, удалённый объект по номеру

План: `docs/design/shabnam-parity-plan-2026-11-07.md`, раздел «Пачка 2». Ветка `feat/shabnam-batch2-07-11`.

- Что изменилось:
  - **Частичный ответ на языке собеседника.** `ai/assistant/partialAnswer.ts` пишет парой ru/tg
    (таджикский на «шумо»); язык — тот же, что выбрал `assistantLanguagePolicy` этого хода. Одно
    правило «отвечать по-таджикски» — `repliesInTajik` (`languageRouting.ts`), им же пользуются ядро
    (таджикская модель, глоссарий, фраза про ссылки) и новая фраза «помощницу выключили посреди хода».
  - **Журнал хода целиком.** Новая таблица `AiAssistantTurnLog` (аддитивная миграция
    `20261107200000_assistant_turn_log`): одна строка на ответ — вопрос (та же маска телефонов и
    500 знаков, что у строк инструментов), итог `answer | partial | refusal | error`, причина
    (`off_topic`, `card_evidence`, `rounds`, `disabled`, код сбоя), маршрут, число шагов модели,
    число инструментов, длина ответа, время. Текста ответа нет. Пишут: конец `runAssistantDetailed`
    и быстрые пути без модели (CRM-роут, Telegram: номер/телефон/ссылка, список клиентов агента,
    очередь монтажа). Одна дверь — `lib/aiAssistantAudit.ts::logAssistantTurn`.
  - **Срок хранения — настройка** `Settings.aiAssistantLogRetentionDays` (по умолчанию 90, пределы
    7–730 общие для сервера и экрана: `ASSISTANT_LOG_RETENTION_DAYS` в `@royal-home/shared`). Крон
    `assistant-log-retention` (04:25 по Душанбе): ходы старше срока удаляются, у строк инструментов
    стирается только текст вопроса (факт обращения остаётся для разбора).
  - **Экран.** Настройки → Система → «Журнал ИИ-ассистента»: переключатель «Ответы / Обращения к
    данным»; в «Ответах» итог хода бытовыми словами, причина, канал, шаги, длина ответа, фильтр «Где не
    справилась», поле «Хранить журнал, дней» (только с правом настроек). API — `GET /ai/assistant-turns`
    (право `auditLog.view`, как у журнала инструментов). Одна адаптивная вёрстка `.list/.row/.filters`.
  - **Номер удалённого объекта.** `get_property_card`, `find_property` и быстрый путь по номеру
    отвечают «ОБ-… в Корзине: удалён <дата по Душанбе>, удалил <кто>» и кто может вернуть, вместо «не
    найден». Справка без продавца, контакта собственника и описания. Права — `lib/trashAccess.ts`;
    ссылка на страницу удалённого объекта — только тем, кому её откроет REST (`canOpenTrashedPropertyPage`,
    ту же функцию теперь зовёт `GET /properties/:id`). Записывающие инструменты (цена, статус…) на
    удалённый объект говорят «в Корзине, сначала восстановить», а не «не найден» (`resolvePropertyRef`).
  - Класс «ссылка на закрытую страницу»: `find_properties_by_place` больше не даёт `href` удалённого
    объекта тем, у кого нет «Архива» (раньше ссылка вела на «Объект не найден»).
  - Один разбор точной ссылки на объект (`parseExactPropertyRef`: номер, голый номер, href, id) —
    общий для `restore_property` и справки Корзины.
- Почему: владелец — «Шабнам отвечает как живой человек» и «прочитать, где она не справилась».
- Чем проверено: `tests/ai-assistant-batch2.test.ts` — 22 теста (оба языка частичного ответа,
  ход по-таджикски до конца шагов, итоги answer/refusal/error/partial и быстрый путь в журнале, право и
  фильтр экрана, срок хранения и зажим значения, крон, справка Корзины для агента/хозяина/директора/
  группы, отсутствие клиентов в справке, write-отказ, разбор ссылки). Сторожа краснеют на нарочно
  сломанном коде (язык частичного ответа, справка в `get_property_card`). Смежные файлы — см. отчёт.
  Gemini подменён, живых вызовов нет.
- Что осталось: полный `test:api` в облаке, ревью `architect`, `npm run ship` после «да» владельца;
  кадры экрана ПК/телефон — сборщику пачки. Не сделано: «не нашла» в групповых командах монтажа и
  Instagram по номеру удалённого объекта (`telegram/assistantBot.ts::groupMontageReply`,
  `replyWithInstagram`) — тот же класс, отдельной правкой; `routes/properties/stats.ts` держит свою
  копию условия «Архив» для удалённого объекта.
