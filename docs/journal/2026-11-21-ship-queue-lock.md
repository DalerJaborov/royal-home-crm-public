# 21.11.2026 — очередь выкатов: замок на GitHub

**Владелец:** «Сделай так, чтобы никогда такого не было, все по очереди».

## Что было

Очередь `npm run ship` держалась на строках RUNNING/QUEUED в WORKSPACES.md на машине владельца — каждый
чат писал и читал их сам. 21.11 #365 стоял первым, но #373 и #374 запустили ship параллельно: облачные
прогоны встали в очередь на одном раннере, main уезжал, каждый ship сводил ветку заново и начинал
облачный прогон с нуля — ни один не доезжал час.

## Что сделано

- `scripts/ship-lock.mjs`: замок — ссылка `refs/ship/lock` в репозитории GitHub (не ветка: сторож веток
  её не видит, сервер выката смотрит только main). Создание ссылки атомарно: второй получает 422 и ЖДЁТ,
  каждую минуту печатая, кто выкатывает. Признак жизни раз в 5 минут; молчит дольше 45 минут —
  брошенный, снимается. Отпускается в любом исходе; чужой замок не снимает.
- `scripts/ship.mjs`: этап «1а. очередь выкатов» — замок берётся ДО того, как запомнить main (пока
  ждали, main уехал — сводим со свежим); отпускается в точке входа рядом с уборкой облачного прогона.

## Проверено

- `scripts/ship-lock.test.mjs` 7/7 (свободно, занято и ждёт, брошенный, чужой не снимаем, признак жизни,
  ошибки не глотаются); `scripts/ship.test.mjs` 50/50.
- Вживую на GitHub: первый взял, второй ждал, первый отпустил — второй взял, замок снят.

## Осталось

- Работает у ship, запущенного из ветки, где этот код уже есть. Ветки, начатые до вливания, получают его
  при сведении с main — до этого их ship замка не берёт.
