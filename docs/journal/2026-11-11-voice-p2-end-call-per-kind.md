# 11.11.2026 — робозвонок ElevenLabs, П2: свой end_call у каждого вида звонка, встроенный end_call выключен, хранение 30 дней

Ветка `feat/voice-end-call-per-kind-11-11` (от `feat/voice-el-ready-11-11` @2466ffb8). План — `docs/voice-robot-plan-2026-11-11.md`, находки Б2 и В8.

## Что было не так

- Б2. Функции ElevenLabs искались по ИМЕНИ и правились `PATCH /v1/convai/tools/{id}`. У приглашения кандидата и опроса
  после показа одно имя `end_call`, но разные слова причины (`INTERVIEW_INVITE_CALL_TOOLS` — без «перезвоню»). Кто
  готовился последним, тот отдавал своё описание всем видам звонка; кеш подготовки держал id, а содержимое под ним уже было
  чужим. Функции общие на аккаунт, поэтому та же правка задевала и других агентов (боевого).
- Список функций читался одной страницей (30 по умолчанию): с ростом числа функций — дубли.
- Две подготовки одного агента разом затирали `tool_ids` друг друга.
- В8. `platform_settings.privacy.retention_days` CRM не ставила: по умолчанию `-1` — «без предела».

Пробные функции (`P2PROBE …`) удалены (DELETE 204 ×3). Тестовый агент остался с `retention_days = 30`. Во время замера
тестового агента параллельно переписывали симуляции (промпт и `tool_ids` менялись между запросами) — тестовый агент
общий, одновременные прогоны мешают друг другу. После «agent not available» (кредиты 131000/131000, координатор)
разговоров больше не запускалось.

## Решение

Основной путь — **одно имя `end_call`, функции по содержимому** (запасной `end_call_<вид>` не нужен: замер показал, что
одинаковые имена разрешены). Запасной путь хуже по конкретной причине: персоны пишут «вызови end_call», и модель видела бы
в промпте одно имя, а в функциях другое.

- `elevenLabsToolContentKey` = имя + sha256 проекции на НАШИ поля (`canonicalClientToolContent`), одна функция для
  объявления и для строки сервиса. Есть такая функция — её id (предпочтение прикреплённой к агенту), нет — POST.
  `PATCH /v1/convai/tools` убран совсем. POST одного содержимого в полёте не дублируется.
- Список функций — постранично (`types=client&page_size=100`, до 10 страниц, дальше запись в журнал).
- Подготовки одного агента — по очереди (в процессе): `tool_ids` = прочитанные ∪ свои не затираются.
- Кеш подготовки — по ключам содержимого набора + политика.
- `ELEVENLABS_AGENT_CRM_POLICY` (рядом с `ELEVENLABS_PHONE_AGENT_TUNING`, его не трогал): `retentionDays: 30`,
  `disabledBuiltInTools: ["end_call"]`. PATCH №1 несёт `built_in_tools.end_call = null` и
  `platform_settings.privacy` (срок + простые флаги владельца; меньший срок владельца не удлиняется); PATCH №2 тоже
  ставит `end_call = null` (снимок агента взят до PATCH №1 и иначе вернул бы встроенный). `apply_to_existing_conversations`
  не шлётся — прошлые разговоры по-старому, решение владельца.
- `elevenLabsVoiceClient.ts`: закрытие 1008 «Tool IDs not attached» → `forgetElevenLabsAgentSync(agentId)` и запись в
  журнал: следующий звонок готовит агента заново, а не падает так же до перезапуска.
- `patch-check.mjs`: функции по видам звонка отдельно, по содержимому, постранично; проверки «у каждого вида свои функции»,
  «повторная подготовка не заводит новых», ключевые поля PATCH №1 (`built_in_tools.end_call`, `retention_days`).
  Ключ содержимого берётся из TS-модуля сервера, не копией. `ensureTools(request, tools, toClientTool)` — прежняя
  подпись, `suite.mjs` работает без правок.

## Правки по ревью (второй коммит, 11.11.2026)

Независимое ревью (architect): блокеров нет; исправлено в той же ветке.

1. **1008 «Tool IDs not attached» больше не теряет звонок.** Закрытие сразу после метаданных (агент ещё молчит, окно
   `ELEVENLABS_TOOLS_RETRY_WINDOW_MS` = 5 с) — тот же звонок переоткрывается без подмены функций (`toolIds = null`,
   функции агента), служебные реплики до первого звука повторяются, мост закрытия не видит. Закрытие до метаданных —
   повтор внутри `connect`. Повтор один на звонок; не открылся — закрытие-сбой наружу, как раньше.
   `noteElevenLabsToolsNotAttached` (одно место): первый 1008 — забыть подготовку агента; второй за 30 мин — пауза
   подмены функций на 30 мин (звонки идут с функциями агента, без 12-секундной переподготовки на каждый звонок) и одна
   тревога `elevenlabs-tools-override-paused`.
   После PATCH подготовка сверяет `tool_ids` GET-ом: наших id нет — подготовка не готова (бросает, звонки без подмены
   до повтора после паузы).
   `this.ws` ставится в момент метаданных, а не после `await` в `connect`: закрытие, пришедшее раньше, не теряется.
2. **Одна очередь подготовок агента.** Кнопка «Проверить агента» (`routes/settings.ts` → `syncElevenLabsAgentDetailed`)
   и звонок (`ensureElevenLabsAgentReady` → тот же `syncElevenLabsAgentDetailed`) идут через `serializePerAgent`;
   прогрев П1, если пойдёт через эти функции, — тоже. Сторож: запись `convai/agents|tools` в `apps/api/src` только в
   `ai/elevenLabsAgentSync.ts`, а `syncElevenLabsAgentNow` вызывается только из `serializePerAgent`. Тест: кнопка и
   звонок разом с разными наборами — у агента оба, функций ровно столько, сколько разных содержимых.
3. **Сторож переходного периода:** нигде в `apps/api/src` и `scripts/elevenlabs` нет `PATCH` на `/convai/tools/`
   (эвристика: метод в ±300 знаков от пути; путь, собранный в переменной далеко от вызова, не увидит).
   **НЕ ВКЛЮЧАТЬ `Settings.liveVoiceProvider = elevenlabs`, пока ветки `test/voice-clients-11-11` и
   `test/voice-staff-11-11` не сведены с этой правкой:** их скрипты сводят функции по имени, и прогон симуляций до
   свода снова менял бы общие функции аккаунта (`suite.mjs` берёт `ensureTools` отсюда — без PATCH, но с одним
   `end_call` на все виды).
4. `patch-check`: после PATCH №1 — «чужие поля целы» (`collateralLoss(before, after1, patch1)`); то, что мы сами
   обнулили (`built_in_tools.end_call: null`), потерей не считается. НЕ ПРОВЕРЕНО живым прогоном (кредиты).
5. Содержимое функции учитывает поля поведения, которых мы не шлём (`disable_interruptions`, `interruption_mode`,
   `force_pre_tool_speech`, `pre_tool_speech`, `assignments`, `tool_call_sound(_behavior)`, `tool_error_handling_mode`,
   `execution_mode`, `dynamic_variables`; у параметров — `constant_value`, `dynamic_variable`, `is_system_provided`,
   `allowed_values…`, `is_omitted`), со значениями сервиса по умолчанию (замер GET 11.11). Поправленная в кабинете
   функция с тем же описанием — уже не наша. Сменит сервис умолчание — patch-check покажет «повторная подготовка
   заводит новые».
6. Текст тревоги о пределе списка: удалять только функции, «не прикреплённые ни к одному агенту».
7. **Уборка функций — отдельная задача (в этой пачке у ElevenLabs ничего не удаляется).** План: реестр всех наборов
   функций звонков в одном модуле (экспорт `LIVE_VOICE_TOOLS` из моста — П1) → при подготовке снимать с агента id
   клиентских функций с ИЗВЕСТНЫМ нам именем, содержимое которых не совпадает ни с одним набором реестра (чужие имена
   владельца не трогать) → функции, не прикреплённые ни к одному агенту (`used_by_agent_id`), удалять отдельной
   командой с «да» владельца.
8. **ОЦЕНКА ревью неверна:** `LIVE_VOICE_TOOLS` (bridge:642–661) содержит `END_CALL_TOOL` (bridge:602, имя `end_call`).
   ФАКТ по исходнику. Все наборы звонков (`CONSULTANT_TOOLS`, `POST_SHOWING_CALL_TOOLS`, `INTERVIEW_INVITE_CALL_TOOLS`,
   `SELLER_PROBE_CALL_TOOLS`, `LIVE_VOICE_TOOLS`) несут `end_call` — сторож по исходнику краснеет, если из какого-то
   пропадёт (встроенный выключен, трубку иначе не положит никто, кроме предела длительности). Добавлять в мост ничего не
   нужно.

временными JWT/ключом шифрования, их нет в `.env` копии); `node --test scripts/elevenlabs` 41/41; `tsc` 0. Нарочные

## Что осталось

- НЕ ПРОВЕРЕНО до пополнения кредитов (сброс 10.12): подмена `[B]` при прикреплённых A и B действительно прячет A;
  поведение разговора при включённом встроенном `end_call` рядом с нашим; живой звонок.
- `tool_ids` агента только растёт — план уборки отдельной задачей, см. п. 7 правок по ревью; предел ElevenLabs на
  число функций агента — НЕТ ДАННЫХ.
- Повтор без функций после 1008 и пауза подмены — НЕ ПРОВЕРЕНО живым звонком (кредиты); в режиме без подмены модель
  видит функции агента целиком (всех видов звонка), чужие для этого звонка обработчик моста не исполнит.
- `LIVE_VOICE_TOOLS` в мосту не экспортирован — сторож видит его только через исключение с причиной; экспорт — пачке П1.
- `suite.mjs` (ветки test/*) сводит функции всех видов по ИМЕНИ (первая встреченная) — в симуляциях у всех видов звонка
  один `end_call`. Править там: ensureTools на вид звонка.
- Runbook `docs/voice-elevenlabs-runbook.md` о новых шагах patch-check не говорит.
