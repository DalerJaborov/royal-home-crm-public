# 11.11.2026 — робозвонок ElevenLabs, П2: свой end_call у каждого вида звонка, встроенный end_call выключен, хранение 30 дней

Ветка `feat/voice-end-call-per-kind-11-11` (от `feat/voice-el-ready-11-11` @2466ffb8). План — `docs/voice-robot-plan-2026-11-11.md`, находки Б2 и В8.

## Что было не так

- Б2. Функции ElevenLabs искались по ИМЕНИ и правились `PATCH /v1/convai/tools/{id}`. У приглашения кандидата и опроса
  после показа одно имя `end_call`, но разные слова причины (`INTERVIEW_INVITE_CALL_TOOLS` — без «перезвоню»). Кто
  готовился последним, тот отдавал своё описание всем видам звонка; кеш подготовки держал id, а содержимое под ним уже было
  чужим. Функции общие на аккаунт, поэтому та же правка задевала и других агентов (боевого).
- Список функций читался одной страницей (30 по умолчанию): с ростом числа функций — дубли.
- Две подготовки одного агента разом затирали `tool_ids` друг друга.
- В8. `platform_settings.privacy.retention_days` CRM не ставила: по умолчанию `-1` — «без предела».

Пробные функции (`P2PROBE …`) удалены (DELETE 204 ×3). Тестовый агент остался с `retention_days = 30`. Во время замера
тестового агента параллельно переписывали симуляции (промпт и `tool_ids` менялись между запросами) — тестовый агент
общий, одновременные прогоны мешают друг другу. После «agent not available» (кредиты 131000/131000, координатор)
разговоров больше не запускалось.

## Решение

Основной путь — **одно имя `end_call`, функции по содержимому** (запасной `end_call_<вид>` не нужен: замер показал, что
одинаковые имена разрешены). Запасной путь хуже по конкретной причине: персоны пишут «вызови end_call», и модель видела бы
в промпте одно имя, а в функциях другое.

- `elevenLabsToolContentKey` = имя + sha256 проекции на НАШИ поля (`canonicalClientToolContent`), одна функция для
  объявления и для строки сервиса. Есть такая функция — её id (предпочтение прикреплённой к агенту), нет — POST.
  `PATCH /v1/convai/tools` убран совсем. POST одного содержимого в полёте не дублируется.
- Список функций — постранично (`types=client&page_size=100`, до 10 страниц, дальше запись в журнал).
- Подготовки одного агента — по очереди (в процессе): `tool_ids` = прочитанные ∪ свои не затираются.
- Кеш подготовки — по ключам содержимого набора + политика.
- `ELEVENLABS_AGENT_CRM_POLICY` (рядом с `ELEVENLABS_PHONE_AGENT_TUNING`, его не трогал): `retentionDays: 30`,
  `disabledBuiltInTools: ["end_call"]`. PATCH №1 несёт `built_in_tools.end_call = null` и
  `platform_settings.privacy` (срок + простые флаги владельца; меньший срок владельца не удлиняется); PATCH №2 тоже
  ставит `end_call = null` (снимок агента взят до PATCH №1 и иначе вернул бы встроенный). `apply_to_existing_conversations`
  не шлётся — прошлые разговоры по-старому, решение владельца.
- `elevenLabsVoiceClient.ts`: закрытие 1008 «Tool IDs not attached» → `forgetElevenLabsAgentSync(agentId)` и запись в
  журнал: следующий звонок готовит агента заново, а не падает так же до перезапуска.
- `patch-check.mjs`: функции по видам звонка отдельно, по содержимому, постранично; проверки «у каждого вида свои функции»,
  «повторная подготовка не заводит новых», ключевые поля PATCH №1 (`built_in_tools.end_call`, `retention_days`).
  Ключ содержимого берётся из TS-модуля сервера, не копией. `ensureTools(request, tools, toClientTool)` — прежняя
  подпись, `suite.mjs` работает без правок.

## Что осталось

- НЕ ПРОВЕРЕНО до пополнения кредитов (сброс 10.12): подмена `[B]` при прикреплённых A и B действительно прячет A;
  поведение разговора при включённом встроенном `end_call` рядом с нашим; живой звонок.
- `tool_ids` агента только растёт: каждая правка описания функции заводит новую и прикрепляет её; старые не снимаются
  (CRM не знает, какие наборы ещё живы). Нужен реестр всех наборов → снимать устаревшие. Пока рост = число правок
  описаний; предел ElevenLabs на число функций агента — НЕТ ДАННЫХ.
- `LIVE_VOICE_TOOLS` в мосту не экспортирован — сторож видит его только через исключение с причиной; экспорт — пачке П1.
- `suite.mjs` (ветки test/*) сводит функции всех видов по ИМЕНИ (первая встреченная) — в симуляциях у всех видов звонка
  один `end_call`. Править там: ensureTools на вид звонка.
- Runbook `docs/voice-elevenlabs-runbook.md` о новых шагах patch-check не говорит.
