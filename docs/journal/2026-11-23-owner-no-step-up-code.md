# 23.11.2026 — директор и администратор без кода подтверждения

**Решение владельца:** «выключить Google Authenticator для директора и администратора полностью, для любых действий из Телеграма и для настроек: такая защита не нужна».

**Что изменилось**
- `lib/stepUp.ts`: `stepUpExemptRole(role)` — DIRECTOR и ADMIN подтверждения не проходят; `requireElevation` пропускает их (Настройки, сотрудники, обучение бота и остальные ~90 маршрутов за окном).
- `lib/assistantActions.ts`: у исполнителя действий новое поле `stepUpExempt`; `assertStepUp` и `assertStepUpPossible` его уважают (в Telegram директору без Authenticator больше не отказывают с 412).
- `telegram/assistantBot.ts`: кнопка карточки без «🔐 Подтвердить кодом», код для директора/админа не запрашивается ни на исполнении, ни на откате.
- `routes/auth.ts` (`GET /auth/step-up`) и `lib/customerAgentOwnerPolicy.ts`: те же правила для экрана Настроек и политики клиентского агента.
- Подсказки модели (`assistant.ts`, `promptSections.ts`, `staffWriteTools.ts`, `directorTools.ts`) больше не обещают код директору.

**Не менялось:** вход в CRM и код при входе (SMS/TOTP), права по ролям, всё для остальных ролей (им код по-прежнему нужен).

**Рубильник:** `STEP_UP_OWNERS_EXEMPT=0` в окружении сервера возвращает прежнюю защиту без правки кода. Тесты ставят его в `tests/setup.ts`, чтобы старые проверки 428 остались в силе.

**Проверено:** `tsc` api чисто; `step-up-owner-exempt.test.ts` (5, новый), `assistant-staff-rights`, `ai-assistant-director-tools`, `step-up-no-push` — 60 зелёных.

**Осталось:** ничего по коду. Риск принят владельцем: украденный токен директора теперь открывает Настройки и ключи без второго подтверждения.

**Свод с #401 (тот же день):** #401 завёл «дверь» `lib/assistantStaffStepUpWaiver.ts` (директор без кода на часть действий с сотрудниками, рубильник, по умолчанию выкл). Моё исключение вставлено В ЭТУ ЖЕ дверь: `staffStepUpWaived` сразу отвечает «код не нужен», если у актора `stepUpExempt` (роль DIRECTOR/ADMIN). Брокер (`assertStepUp` — в журнал идёт `stepUpWaived`), `assertStepUpPossible` и кнопка карточки спрашивают одну и ту же функцию, поэтому не расходятся. Для канала crm `assertStepUp` тоже пропускает такого актора. Рубильник #401 для остальных случаев не тронут.
