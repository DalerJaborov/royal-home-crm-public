## Что сведено в одно (правило «одна возможность — одна реализация»)
- **Разбор ссылки на объект.** Было два: `lib/propertyRef.ts` (prop, для записи) и
  `lib/propertyRefLookup.ts` (read, `find_property`). Оставлен второй (полнее: фото-посты
  Instagram, токены слов, Somon, скрытие объекта под своей заявкой на удаление);
  `resolvePropertyRef` переехал туда и строится на `findPropertiesByRef`. Для записи строже:
  голый номер без такой карточки — «не найден» (а не объект с этими цифрами в адресе), слова
  короче 3 букв — «не найден», Somon — отказ, несколько — 409 со списком кандидатов.
  `lib/propertyRef.ts` удалён.
- **`safeField`**: приватная копия в `ai/assistant.ts` убрана, импорт из `tools/safeField.ts`.
- **`plainField`** (текст карточки в превью для человека): было две разные копии — в
  `propertyToolSupport.ts` (резала `<>`) и `showingToolSupport.ts` (гасила через
  `neutralizeFence`). Одна в `tools/safeField.ts`: `neutralizeFence` + управляющие знаки и
  обратные кавычки + длина; пусто → `null`.
- **`propertyHref`** — один, в `propertyPresenter.ts` (с необязательным хвостом запроса).
- `npm run audit:rules` — новых двойников нет; общий поиск по экспортам новых `lib/*` и
  `tools/*` других определений тех же имён не нашёл. `lib/agentNameLookup.ts` пришёл из read и
  owner байт-в-байт одинаковым — слился в один файл.

## Что изменено при сборке
- **Превью для модели.** `runAssistantToolPlugin` отдаёт модели `previewForModel(preview)` —
  копию, где каждая строка (имя клиента, адрес, причина, заголовок, риск) обёрнута
  `wrapUntrusted`; `href` и булевы — как есть. Событие `confirm` и сохранённое превью — без
  тегов (их читает человек). `change_client_agent` больше не кладёт `<client_content>` в само
  превью (было в ветке owner), имя — через `plainField`.
- **`interactionId` показа.** `list_my_tasks` отдаёт `interactionId` у каждой строки (вместо
  `id`); `get_client_card` — `nextTask.interactionId` и новое `nextShowing` (ближайший
  предстоящий неотменённый показ с `interactionId`). Описания говорят, куда его передавать.
- **Канал.** `pluginDeclarations(actor, confirmUi, channel)`: запись объявляется только в
  канале из `executor.channels` (по умолчанию CRM — step-up из Telegram не ввести).
  `BUILTIN_ASSISTANT_TOOL_NAMES` — экспорт имён встроенных инструментов для сверки.
- **Найдено тестом реестра:** `request_property_change` объявлял `patch` как `{type:"object"}`
  без свойств — Gemini отвергает такую схему 400 и ронял бы ВЕСЬ запрос помощника с
  `confirmUi`. У `patch` теперь явные поля (подмножество `CAPTION_FACT_FIELDS`, сверяется
  типом); район/детали/удобства — через `kind=OTHER`.
- **Найдено сквозным прогоном:** без `confirmUi` запись модели не объявлялась, но названная
  наугад (или из старой истории) ИСПОЛНЯЛАСЬ: `add_client_note` (B) писал сразу,
  C создавал карточку, которую некому показать. `runAuditedTool` теперь отказывает.
- Тест read «висящая заявка на удаление» брал голый номер и при общем прогоне ловил объект
  соседнего файла с теми же цифрами в адресе — переведён на номер `ОБ-`.
