# Recruitment context and one-time corrections

Vacancy replies could describe background furniture instead of the recruitment
content already perceived by Gemini. A later model read could duplicate the
prefetched catalog. A busy worker also processed a media message after its
caption had already arrived, causing retained media context to be omitted.

The core reuses identical validated catalog refs, renders job context instead
of incidental scenery, retains earlier genuine receive-order user media through
queue processing, and suppresses an older turn when a newer protected input is
already pending. Echoes, referrals, unprotected and corrupt envelopes cannot
create that supersession observation. Historical content grants no new action.

The legacy text path now receives the same live public recruitment catalog,
separating role conditions and optional resumes from its older agent defaults.
Quoted video/document duties are not executable customer requests in the
off-topic filter. Existing real voice requests are still screened.

An explicit administrator/director action may queue up to50 reviewed one-time
bot corrections. The service captures source, transport, public catalog and
controller; checks opt-out, HUMAN/HOLD, native staff pauses, provider window and
unknown prior sends; and records an immutable single physical attempt and
provider receipt. A separately reviewed admin resumption never overrides HUMAN
ownership. Unreviewed bounded native pauses are scheduled through the existing
job queue only if their end is still inside the reply window. No synthetic
inbound, lane promotion, fake acceptance, unknown retry or new staff handover.
Accepted corrections contribute bounded public context to a future genuine IN.
Receipts survive native deletion without preventing conversation deletion.
The reviewed source hash/time must still match before enqueueing. A correct
reply or decline arriving after review cannot become a new implicit target.
A native conversation can receive this historical correction only once,
independently of the campaign label, including after an UNKNOWN outcome.

Validation: targeted core/renderer/media/signed-input and PostgreSQL migration
regressions, role-separated legacy catalog, off-topic boundaries, and durable
delivery simulations. External media/model/provider behavior in tests is
synthetic; these tests do not prove live customer delivery. Official exact-SHA
full cloud gates, production verification, retained rollout and actual approved
campaign receipts remain separate release/acceptance steps.

Private dialogue review and recipient data remain outside this public repository.
Rollout stays at its existing percentage; voice, provider changes and general
fallback mechanisms are outside this change.
