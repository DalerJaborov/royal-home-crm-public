# 16.11.2026 — один мозг, шаг 3а: ядро для Telegram, сайта и YouTube, поля анкеты, голос компании

Источник: решение владельца 16.11 («один мозг», старый бот удалить полностью), шаги 1–2 — PR #211, #213.
Этот PR — первая половина шага 3 (адаптеры). Удаление старого бота — следующий PR поверх этого.

## Что сделано
1. `lib/customerChannelCore.ts` — ОДНА дверь ядра для каналов без своего транспорта ядра (бот Telegram, чат сайта,
   комментарии YouTube): тот же закреплённый выпуск, `runCustomerAgentTurn`, рендер и проверка ответа (шаг 1), что у
   Meta-DM; только публичные инструменты чтения, ни одного инструмента записи. Тень шага 2 теперь идёт через него же.
2. Рубильник `CUSTOMER_AGENT_CHANNEL_CORE=telegram,website,youtube` (по умолчанию пусто = как сегодня). Ключи Meta
   (`meta_dm`, `arvan`) здесь не принимаются: их дверь — `rolloutConfig.allowed`. `core` сильнее `shadow`.
3. Дверь `ai/legacyQualifyDoor.ts`: канал в `core` — отвечает ядро вместо старого бота, результат в прежней форме,
   поэтому «тело» канала (заявка по номеру, стражи, история, отправка, повтор при сбое ИИ) не менялось. Эскалация или
   просьба действия, которого на канале нет (показ, звонок) — клиенту ничего, сотруднику «ответьте вручную»
   (`lib/channelStaffAlert.ts`: сайт — общая дверь `alertClientWaiting`, Telegram — пуш раз в 6 ч на чат).
4. YouTube: `messengers/youtubeCoreComment.ts` — в `core` решение по комментарию принимает ядро (surface public_comment),
   дальше прежний путь (спам-фильтры, пауза, публикация, эскалация). Ответ, зовущий «в личные сообщения», на YouTube не
   публикуется (там их нет) — эскалация. Модерация ядра — только «скрыть».
5. Личные сообщения Telegram-канала (0 диалогов за всё время): автоответ модели и его повтор сняты, номер по-прежнему
   оформляет заявку, сотруднику — «ответьте вручную». Задания повтора в очереди закрываются без модели.
6. Анкета ядра: `locationOutsideDushanbe` (другой город РТ → «Прочие обращения», номер берём) и
   `locationDifferentCountry` (продавец, объект за границей → без заявки) — кодом по словам клиента
   (`ai/coverageGuard.ts::detectForeignPlace` + `detectOutsideCoverage`); Душанбе или Рудаки в словах снимают отсечку.
7. Голос компании по аккаунту: блок `serverBrand` в ходе (имя компании из `MessengerAccount.brandName`; голос владельца
   из `MessengerAccount.systemPrompt`/`Settings.botSystemPrompt` — только при `CUSTOMER_AGENT_BRAND_VOICE=on`).
   Системный промпт и его хэш не менялись (тест сверяет с V2.toPrompt); меняются coreHash/modelSchemaHash —
   выпуск бота обновится сам после выкатки.

## Факты (прод, только чтение, 16.11)
- Старый бот реально звал модель за 7 дней: Instagram 78, Facebook 8, WhatsApp 1 хода (BotTurnTrace, legacy coverage) —
  в основном Арван (32 диалога IG за неделю). Сайт: 1 диалог за неделю. YouTube: 5 комментариев за неделю, 78 за месяц.
- Аккаунты: Arvan IG/FB — brandName «Арван», без своего голоса; Royal Home Info — голос 2881 знак; Settings — пусто.

## Решения и почему
- Не клонировать конвейер Meta (ingress → claim → outbox) для Telegram/YouTube: у них нет CustomerEndpointScope и
  подписи входа, а OAuth YouTube не привязан к установке (`managed_public_transport_unbound` — сознательный запрет).
  Повторное использование ядра + «тела» канала даёт ту же проверку текста без второго пути доставки.
- Голос Royal Home Info выключен по умолчанию: аккаунт уже живёт на ядре, текст писался для старого бота — сначала образцы.
- `propose` на этих каналах = сотрудник: записать показ/звонок тут нечем, обещать нельзя.

## Не сделано / ограничения
- Запись показа, обратный звонок, вопрос собственнику, анкета кандидата на Telegram/сайте/YouTube ядром не оформляются
  (нет инструментов записи без субъекта ядра) — вместо этого заявка по номеру и «ответьте вручную».
- Чистая замена «Ты консультант Royal Home» в системном промпте — только парой V3 с «да» владельца.

- M4: текст ядра не правят старые сторожа (`verifiedCoreReply`: только щит повтора); в нейтральных заготовках нет «лутфан/муфассал».
- Уведомления Telegram: на каждое неотвеченное сообщение (пачка до 2 мин — одним пушем), а не раз в 6 ч; сторож молчания Telegram (`runTelegramSilenceSweep`) включается в 3б.
