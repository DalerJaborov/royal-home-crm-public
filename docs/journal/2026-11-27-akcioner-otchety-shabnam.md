# 27.11.2026 — Акционер: отчёты как у директора, Шабнам только читает; бот Telegram только для сотрудников

- Что изменилось:
  - **Получатели.** `findAgentsWithPermission` (lib/recipients.ts) больше не отдаёт роли режима
    просмотра (акционер): по правам «смотреть» он получал ВСЕ тревоги с действием — «клиент ждёт»,
    «бот не ответил», «кандидат оставил номер», «оплата подписки», хотя сделать ничего не может.
    Одна дверь на ~60 вызовов и очередь тревог руководству.
  - **Отчёты акционеру** — новая дверь `lib/reportRecipients.ts` под рубильником «Отчёты акционеру»
    (`Settings.shareholderReportsEnabled`, ВКЛ): утренняя сводка, разбор проблемных мест (неделя и
    месяц), месячный отчёт (акционеру «откройте, чтобы прочитать»), разбор маркетинга, советы ИИ к
    собранию, финансовый PDF 1-го числа в Telegram.
  - **Шабнам и режим просмотра.** Запись помощницы закрыта акционеру одной дверью: брокер действий
    (`assertRoleMayWrite`, роль из базы, до разбора аргументов — создание, подтверждение, откат) и
    объявление инструментов (`assistantPluginAllowed`). Найдено обходом: `book_showing`,
    `reschedule_showing`, `cancel_showing`, `add_client_note`, `link_property_to_registry`
    объявлялись акционеру (своего запрета в `allowed` не было). Исключение одно — «не присылать такое»
    в личке Telegram (флаг исполнителя `readOnlyRoleAllowed`).
  - **«Пришли финансовый отчёт PDF».** Новый инструмент `send_finance_report_pdf` (чтение): тот же
    файл, что рассылка 1-го числа, сразу в свой Telegram, текущий или названный месяц. Общая дверь с
    кнопкой «В Telegram» на экране отчётов — `lib/reportPdf/ownTelegram.ts`: не чаще раза в минуту на
    человека, тайм-аут сборки прежний (30 с), отказы в журнал ошибок и честный ответ. Строка в промте:
    PDF присылает сама, «не могу сделать PDF» не говорить. Акционеру — строка «режим просмотра».
  - **Жирный не рвётся на суммах** («3 561,**25 TJS**»): одно правило суммы `MONEY_AMOUNT` для
    жирного и для защиты суммы от маски телефонов (telegram/assistantReply.ts).
  - **Режим просмотра пускает своё:** отметка «прочитано» в своём колокольчике, свои виды уведомлений
    (`PATCH /push/preferences`). Привязка своего Telegram и PDF себе были открыты раньше.
  - **Привязка по номеру:** акционер добавлен к директору и администратору — только кодом из профиля
    (он видит деньги). Текст отказа называет путь: CRM → Профиль → «Личный чат с ботом CRM в
    Telegram» → «Привязать».
  - **Telegram-бот только для сотрудников** (рубильник `Settings.telegramStaffOnlyEnabled`, ВКЛ):
    незнакомый личный чат получает памятку (по-таджикски и по-русски): сотруднику кнопка
    «Я сотрудник» (если включена привязка по номеру) и путь в CRM, клиенту — наш сайт. Переписка,
    карточка и заявка из Telegram не заводятся; старая кнопка «Позвать агента» тоже ведёт к памятке.
    ВЫКЛ — прежний клиентский путь без изменений.

## Дополнение по ревью #506 и решению владельца (27.11.2026, вечер)

- **Памятка — только новому незнакомцу.** Прежним путём при ВКЛ идут: переписка с карточкой
  клиента, любая переписка с активностью за 30 дней (сообщение, правка, пауза бота), кандидат на
  работу (черновик «работа» или слова соискателя, в том числе «кор ҳаст?»). Входящее незнакомца,
  получившего памятку, пишется в журнал действий `TELEGRAM_STAFF_ONLY_INBOUND` (чат, начало текста).
- **Подпись рубильника честная:** Direct Messages канала и комментарии группы обсуждения не задеты;
  кнопка «Я сотрудник» только при включённой привязке по номеру, иначе только путь через профиль.
- **Действие без карточки** (`sideEffect` у инструментов уровня A, `tools/writeGate.ts`):
  `send_finance_report_pdf` (`own` — себе, акционеру можно) и `set_group_quiet` (`shared` —
  акционеру закрыто) больше не считаются чтением: в ходе «только прочитать» их нет, идут по одному.
  PDF не уходит молча, если срок ответа помощницы истёк, пока собирался файл.
- **Суммы:** тысячи только группами по три (девять цифр телефона перед «500 TJS» больше не прячутся от маски),
  регулярка отдаётся фабрикой `moneyAmountPattern()` без общего состояния.
- **Финансовый PDF 1-го числа** (решение владельца): директор, администратор и учредитель — все с
  правом на финансы. Круг — одна дверь `findAutoPdfRecipients(permission)` в `lib/reportRecipients.ts`
  для любого автоматического PDF (одна выборка, права поверх пресета роли, без N+1); сторож в
  `shareholder-reports-27-11` не пропускает файл, который сам собирает и шлёт PDF мимо этой двери.
  Подпись тумблера в Настройках → Система: «Присылать руководству в Telegram» (директор, администратор,
  учредитель с доступом к финансам). Рубильник рассылки в базе НЕ включён: владелец включит после
  одобрения образцов.
- **Тесты при ВКЛ рубильнике:** `/start <код>`, `/start staff` → контакт → шесть цифр, монтажёр сдаёт
  ролик (`telegram-agent-link`, `montajer-bot`, `staff-shabnam-link` теперь идут при ВКЛ).
- Чем проверено (вечер): 8 файлов сервера, 118 тестов зелёные (портативный Postgres, своя база).
  Нарочные поломки: круг PDF только директор, файл-обход двери PDF, снятые `sideEffect`, снятые
  «кандидат» и «30 дней» → 7 красных; старое правило суммы → 1 красный. Сборка shared/api/web,
  `test:web` (3567), `map`; `precheck` — все шаги до тестов сервера зелёные. Полный `test:api` на этой
  машине до конца не дошёл (процесс оборвался); упавшие в нём файлы (`assistant-telegram`,
  `instagram-app-binding-settings`, `background-jobs`, пять `*-postgres` ядра) на чистой базе дают
  ровно те же падения и на коде `main` e832da8f — это окружение машины, не правка. Полный прогон
  сделает `npm run ship`.
- Осталось: живая проверка памятки и /start у учредителя после выката; ежемесячный PDF включает владелец.
