# 08.11.2026 — Комментарии страницы Facebook снова заводят досье и интерес к объекту

- Что изменилось: в `apps/api/src/messengers/comments.ts` появилась одна дверь
  `commentAuthorScope(row, accountId)` — namespace автора комментария для всех
  записей в CRM: досье комментатора, личное и письмо собственнику в переписке,
  интерес к объекту (`recordClientInterest`). Строка аккаунта есть — прежний путь
  без изменений. Нет (страница Facebook подключена через Настройки, строки
  `MessengerAccount` у неё нет) — namespace берётся из подписанного Meta
  получателя комментария `row.accountExternalId`, сверка «это страница из
  Настроек» остаётся в `accountForEndpoint`, чужая страница по-прежнему получает отказ.
- Почему: ErrorLog прода 15.10–07.11.2026 — 50 записей `Customer endpoint denied:
  account_unknown` («Досье комментатора … не заведено», «Интерес клиента к объекту
  №192/№193/№147 не записан», «Личное по комментарию … не записано в переписку»,
  «Письмо собственнику …»). Все — комментарии страницы Facebook 873975375804470:
  путь комментария передавал дальше только `account.id = null`, без страницы.
  Личное входящее (`routes/webhooks.ts`) передаёт обе половины и работало; ответ
  под постом и личное уходили, поэтому снаружи поломку не было видно. Не связано
  с переездом 04.11: первые записи 15–16.10, последний CLIENT_SHARED по Facebook — 13.10.
- Чем проверено: `apps/api/tests/comment-author-settings-page-scope.test.ts` (7
  тестов: досье и интерес в namespace страницы, повтор — тот же диалог, голый null
  — отказ, чужая страница — отказ, IG/YouTube без изменений, сторож класса по
  исходнику comments.ts). Нарочно сломанная дверь даёт 3 красных, голый
  `account.id` в `recordClientInterest` — красный сторож. Задетые тесты комментариев
  и интереса, `npm run precheck`.
- Что осталось: дозапись потерянного за 15.10–07.11 (17 авторов без диалога, 18 без
  интереса к объекту) — только с «да» владельца, отдельной разовой командой; одна
  запись `scope_unknown` 04.11 (объект №132) — вероятно, ссылка из Telegram:
  `recordClientInterest` для TELEGRAM не поддержан scope-слоем, решение отдельное.
