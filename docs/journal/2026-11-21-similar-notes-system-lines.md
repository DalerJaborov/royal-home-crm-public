# 2026-11-21 — «Похоже на … заметки совпадают на 84%» больше не ловит ярлыки бота

## Что было
- Снимок владельца (iPhone): «Прочее обращение» из WhatsApp показывало подряд три подсказки
  «Похоже на … — заметки совпадают на 82–84%. Может, один человек?» с тремя разными людьми.
- Причина: `lib/fuzzySearch.ts::fuzzySimilarClientNotes` вырезал из заметок перед сравнением только
  строки с пятью значками (🏷💼🔑❓📞). Ярлыки `ai/leadKind.ts` «🌍 ВНЕ ДУШАНБЕ — клиент назвал «…»,
  мы работаем только по городу» и «🚫 НЕ НАШ ПРОФИЛЬ…» в список не попали. У карточек из одного
  такого ярлыка отличается лишь название города — сходство 77–84%.
- Замер прода 21.11 (только чтение): подсказку получали 20 карточек, 162 пары; все от ярлыков 🌍/🚫,
  ни одной с общим номером. 114 пар были выше порога пуша руководству (0.75, `services/leads/intake.ts`,
  та же функция), то есть ложный пуш «Похоже на дубликат карточки» тоже уходил.
- Ещё: отклонённые «Разные люди» отсекались ПОСЛЕ `LIMIT 3` — три отклонённые пары закрывали четвёртую.

## Что сделано
- Один список служебных строк заметок — `lib/clientNoteLabels.ts` (`CLIENT_NOTE_LABELS`): ярлыки
  `decideLeadKind`, пометки направления, «📞 ПРОСИТ ПЕРЕЗВОНИТЬ», «📍 вне зоны», обёртки комментариев под
  постами, «Подходящие покупатели в базе…», «⚠️ Код переопределил тип…», «Со страницы:», старые ярлыки
  прода. Вырезается только то, что в списке: объявление клиента значками («🏠 Продаю…
📍 Сино») остаётся
  (первый вариант правки — «любая строка со значка» — стирал его, находка слепого ревью).
- Обёртка вокруг слов клиента уходит, цитата остаётся: «Слова клиента: «…»» в просьбе перезвонить, текст
  комментария в «Продаёт свою недвижимость: … «…»», пересказ после «⚠️ Код переопределил тип (…).».
- Одни и те же регулярки для JS (открытая карточка) и Postgres (кандидаты); края — ровно [ 
	], как
  btrim; длина — в кодовых точках, как length().
- Остаток короче 40 знаков не сравнивается: общая фраза пересказа («Клиент ищет дом») — не уникальное
  содержание, у разных людей совпадает дословно.
- Отклонённые пары передаются в SQL и отсекаются до `LIMIT`.
- Одна дверь: правка в `fuzzySimilarClientNotes` чинит и баннер карточки (ПК и телефон — один
  `SimilarNotesWarning`), и пуш руководству при новой заявке.

## Чем проверено
- `apps/api/tests/client-similar-notes-system-lines.test.ts` (13): сторожа списка — префикс есть в своём
  файле; каждая строка со значка в файлах ярлыков из списка или названа «не заметкой»; каждая фраза рядом с
  записью `requirementsNotes` по всему серверу из списка или с причиной; все ярлыки `decideLeadKind` и
  константы вырезаются целиком. Поведение — равенство JS/Postgres на 12 образцах; случай ПО-000935;
  длинная заметка против карточки из одних ярлыков; одна обёртка комментария с разными объявлениями;
  объявление значками с двух номеров находится; короткая фраза; отсев отклонённых до LIMIT.
- Поломка нарочно: переименованный ярлык в leadKind.ts и шаблон в comments.ts — 4 сторожа красные.
- Тот же разбор на проде (только чтение, запрос собран из того же списка): подсказок 0 (было 20 карточек,
  162 пары), самая похожая пара 0.646; сравнимый остаток есть у 308 карточек из 463.
