# 2026-11-21 — «Похоже на … заметки совпадают на 84%» больше не ловит ярлыки бота

## Что было
- Снимок владельца (iPhone): «Прочее обращение» из WhatsApp показывало подряд три подсказки
  «Похоже на … — заметки совпадают на 82–84%. Может, один человек?» с тремя разными людьми.
- Причина: `lib/fuzzySearch.ts::fuzzySimilarClientNotes` вырезал из заметок перед сравнением только
  строки с пятью значками (🏷💼🔑❓📞). Ярлыки `ai/leadKind.ts` «🌍 ВНЕ ДУШАНБЕ — клиент назвал «…»,
  мы работаем только по городу» и «🚫 НЕ НАШ ПРОФИЛЬ…» в список не попали. У карточек из одного
  такого ярлыка отличается лишь название города — сходство 77–84%.
- Замер прода 21.11 (только чтение): подсказку получали 20 карточек, 162 пары; все от ярлыков 🌍/🚫,
  ни одной с общим номером. 114 пар были выше порога пуша руководству (0.75, `services/leads/intake.ts`,
  та же функция), то есть ложный пуш «Похоже на дубликат карточки» тоже уходил.
- Ещё: отклонённые «Разные люди» отсекались ПОСЛЕ `LIMIT 3` — три отклонённые пары закрывали четвёртую.

## Что сделано
- Один список служебных строк заметок — `lib/clientNoteLabels.ts` (`CLIENT_NOTE_LABELS`): ярлыки
  `decideLeadKind`, пометки направления, «📞 ПРОСИТ ПЕРЕЗВОНИТЬ», «📍 вне зоны», обёртки комментариев,
  «Подходящие покупатели в базе…», «⚠️ Код переопределил тип…», «Со страницы:», старые ярлыки прода.
  Вырезается только то, что в списке: объявление клиента значками остаётся (первый вариант правки —
  «любая строка со значка» — стирал его, находка слепого ревью).
- Обёртка вокруг слов клиента уходит, слова остаются: «Слова клиента: «…»» и старая форма «📞 …: «…»»,
  хвост «Когда звонить: «…»» вырезается; многострочный комментарий — до парной кавычки (вложенные «»
  считаются); незакрытая кавычка (обрезка по длине) — всё после «; «⚠️ … (… (…)).» — скобки любой вложенности.
- Хранимая копия: `Client.requirementsNotesPlain` + `requirementsNotesPlainRev` (миграция
  `20261122090000_client_notes_plain`: только две колонки и GIN-индекс по триграммам). Пишет ОДНА дверь —
  перехват записи Client в `db.ts` (create/createMany/update/updateMany/upsert, в том числе в транзакциях).
  Сверка `lib/clientNotesPlainSweep.ts` проходит ВСЕ карточки и пишет только расходящиеся (старые строки,
  смена списка или разбора — версия = хеш списка и текста функций разбора, запись мимо двери); при старте
  worker и каждую ночь в 03:50 по Душанбе (`client-notes-plain-sweep`); сверяет заметку, чтобы не затереть
  живую запись.
- Колонки скрыты по умолчанию (omit в `db.ts`, тип `ClientRecord`): иначе слова клиента уезжали бы в ответы
  API мимо маски номера. Четыре места, типизированные голым `Client`, переведены на `ClientRecord`.
- Поиск похожих — по этой колонке оператором % через индекс; очистки регулярками в SQL нет (повторное
  ревью: она стоила 4 с на 5000 карточек).
- Остаток короче 40 знаков не сравнивается; отклонённые «разные люди» отсекаются до LIMIT; одна функция
  чинит и баннер карточки (ПК и телефон), и пуш руководству при новой заявке.

  заметках был только ярлык «вне Душанбе» (по старой логике совпадение 100%) — похоже на слияние по
  ложной подсказке; показать владельцу.
- До досчёта при старте worker (≈20 с после выката) старые карточки в поиске похожих не участвуют.
- Пересказы модели («Клиент продаёт N-комнатную… кв.м… этаж») доходят до 0.646 — у порога 0.65.
