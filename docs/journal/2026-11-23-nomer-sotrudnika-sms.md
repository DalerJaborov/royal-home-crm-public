# 2026-11-23: номер сотрудника — одна запись, вход по СМС находит любую

Что было: двум новым сотрудникам номер лёг в `Agent.phone` девятью цифрами (`97•••••••`), остальным — `+992•••••••••`.
Вход искал только `как ввели`, `+992…`, `992…`; «+992 97…» учётку не находил, сервер отвечал заглушкой, СМС не уходила
и в `SmsMessage` не писалось ничего. Номера в журнале — только маской.

Что сделано:
- `packages/shared/src/tajikPhone.ts`: `normalizeStaffPhone` (любая таджикская запись -> `+992` + 9 цифр; иностранный как есть;
  обрывок/маска -> null) и `staffPhoneLookupForms` (все записи, в которых номер мог лечь: как ввели, `+992N`, `992N`, `N`, `0N`).
- `staffPhoneSchema` (`schemas.ts`) нормализует номер сам: через неё идут создание/правка сотрудника (`staffAdmin.ts`, REST и Шабнам),
  свой профиль (`routes/me.ts`). Неверный номер — 400 с текстом «+992 и девять цифр».
- Шабнам: аргумент `create_staff.phone` берёт ту же схему, карточка показывает `+992…`, неполный номер — отказ (модель переспросит);
  описание инструмента поправлено. `update_staff` шёл через `agentUpdateSchema` и уже нормализуется.
- Поиск по номеру через `staffPhoneLookupForms`: вход `/auth/login/code` (`phoneCandidates`), занятость номера при создании/правке/
  в профиле/в карточке Шабнам, «звонил сотрудник» в `autoLeadFromCall`. Занятый номер в другой записи — 409, не дубль.
- `seed-prod.ts`: номер директора нормализуется.
- Шаги step-up и `/login/totp` ищут по id сотрудника, не по номеру — их не трогали.

Тесты: `apps/api/tests/staff-phone-login-23-11.test.ts` (вход по «+992 97…» при записи `97…`, создание, правка, 409), путь Шабнам —
в `assistant-staff-rights.test.ts`.

Осталось: уже записанные кривые номера в проде приводить к `+992…` отдельной правкой данных (нужно «да» владельца на SQL);
до неё вход работает за счёт поиска по всем формам.
