# 17.11.2026 — починка по разбору журнала ошибок прода и две находки аудита безопасности

Источник: разбор журнала ошибок прода 13–16.11 (187 строк) и аудит безопасности 17.11
(отчёты сессии аудита, вне репозитория). Ветка `fix/errors-audit-17-11`, коммит на пункт.

## Что изменилось и почему

1. **«Чаты» с фильтром по каналу или аккаунту отдавали 500** (`routes/conversations.ts`,
   сгруппированный список). Фильтр заменяет часть веток объединения заглушкой с
   `NULL::text`, а настоящая ветка отдавала тип клиента и источник перечислением базы —
   Postgres не сводит enum с text (42804). Во всех трёх настоящих ветках `cl.kind::text`,
   `cl.source::text`. Других объединений с заглушками `WHERE FALSE` в `apps/api/src` нет
   (поиск по всему каталогу).
2. **Служебные сообщения сотруднику резал щит клиентских диалогов** (весть хозяину об
   автопубликации ролика, кнопки озвучки). Щит «знал» чат сотрудника с тех пор, как тот
   писал боту клиентом, и копил «монолог». Одна дверь в самом щите
   (`lib/outboundShield.ts::isLinkedStaffChat`): чат, привязанный к действующей учётке,
   клиентские правила не проходит и в счётчики не попадает. Так защищены все ~30 файлов
   со служебными отправками из списка сторожа `staff-notice-one-door`, включая будущие.
3. **Лиды без агента после сторожа номера.**
   - Разбор слов (`ai/customerAgentRole.ts`, одно место на все пути) читает таджикский и
     русский латиницей (`xonai furushi dorum`), говор «дорум/дорим», опечатки «продат/купит»,
     вопрос покупателя «…дорен?» и просьбу «вариант пешниход кунед». Латиница
     переписывается только для чтения роли: `foldCustomerText` не тронут (по нему узнают
     язык и чужой текст).
   - Сторож номера читает слова и у старого пути, если модель намерение не записала.
   - Намерение так и не понято (переписка или комментарий, номер есть) — карточка
     больше не «прочее» без агента: покупатель с первой строкой «❓ ТИП ОБРАЩЕНИЯ НЕ
     ОПРЕДЕЛЁН — уточните первым звонком» в общей раздаче, тем, кто назначает агентов
     (право `clients.assign`), — пуш вида «Новые лиды» (`services/leads/intake.ts`).
     Правило — в `services/leads/intakePolicy.ts::classifyInbound`, им же пользуется
     ответ бота, поэтому обещание звонка и карточка не расходятся. Остальные «прочие»
     (аренда, работа, другой город, услуги, реклама без слов, «модель не уверена») — как были.
4. **Шум.** Сводка «живая фраза отброшена» писалась каждые 10 минут: ключ дня был, но окно
   дедупа оставалось 10 минут. Окно — сутки, и без пуша директору (`silent`), это метрика
   качества. Утренний отчёт брал 30 самых свежих типов — теперь сортирует по важности и
   числу повторов (`lib/errorLogClassify.ts`), отдаёт `firstAt`, `errorGroupsTotal`,
   `errorGroupsHidden`.
6. **Привязка своего Telegram без подтверждения личности** (аудит S2). `POST /me/telegram-link`
   под `requireElevation` (как 2FA и ключи устройства); запись `TELEGRAM_LINK_CODE_ISSUED`
   и `TELEGRAM_LINKED` в журнал действий; самому сотруднику — сообщение вида
   «безопасность» о привязке. Экран профиля проводит через окно подтверждения и повторяет
   запрос (ПК и телефон — один адаптивный экран).
7. **Код подтверждения перед Настройками уходил пушем на ту же сессию** (аудит S2). Для
   step-up пуш убран: СМС, затем Telegram. Ноль каналов не остаётся: у кого нет ни
   таджикского номера (СМС шлётся только по Таджикистану), ни Telegram — пуш остаётся,
   но не на устройство, которое просит код (браузер передаёт адрес своей подписки).
   Вход по коду (не step-up) не менялся.

## Чем проверено

Сборки shared/api/web, точечные тесты (список и итог — в описании PR), `npm run map`,
`npm run map:check`. Новые тесты: `grouped-conversations` (фильтры по 4 каналам и
аккаунту), `outbound-shield-staff-chat`, `lead-intent-latin-unknown.unit`,
`customer-agent-say` (окно сутки), `error-log-classify` (40 групп), `morning-report`,
`step-up-no-push`, `me-telegram-link` (428 и аудит).

## Что осталось

- Пункт 5 разбора (файл ролика в базе есть, на диске нет) — не начат.
- Почему живой путь пропустил номер (9 цифр без кода, «вотсап», комментарий) — отдельная задача.
- `confident: false` у модели по-прежнему «прочее» — сознательно не трогали.
- Хук утреннего отчёта в рабочей папке владельца может показать `errorGroupsHidden`.
- Код привязки Telegram живёт до использования — срок жизни (нужна миграция) не делали.
- Узнать, есть ли сотрудники без таджикского номера и без Telegram (только у них step-up
  остаётся пушем на другое устройство; с одним устройством у них кода не будет).
