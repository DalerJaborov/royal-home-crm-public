# Перемонтаж по новой цене: старые посты уходят, когда выходит новый ролик

**Что было.** Заявка агента «новая цена + перемонтаж» снимала старый ролик из всех соцсетей
в момент возврата монтажёру. Пока монтажёр работал (часы или дни), объекта в соцсетях не было.
Instagram и TikTok удалить через API нельзя, поэтому они оставались в `publishedChannels`,
и новый ролик туда уже не выходил: публикация пропускает каналы, где ролик уже стоит.

**Решение владельца (30.10.2026):** снимать старый пост, «когда выйдет новый».

**Что изменилось.**
- `VideoRemakeRequest` получил `replaceOldPostsOnPublish` и `oldPostsReplacedAt` (аддитивная миграция).
- `sendBackToMontajer(..., { removeFromSocial: "on-new-video" })` ставит отметку и ничего не снимает.
  `true` по-прежнему снимает сразу (кнопка «Вернуть монтажёру» с галочкой — не тронута).
- Заявка агента с перемонтажом (`changeRequestExecutor`) теперь идёт с `"on-new-video"`.
- `replaceOldPostsBeforeRemakePublish` вызывает задание публикации нового ролика перед публикацией:
  снимает старые посты тем же `removeFromSocial`, Instagram и TikTok вычёркивает из карточки,
  чтобы новый ролик туда вышел, и шлёт хозяину объекта пуш со ссылками на старые посты для ручного удаления.
  Отметка ставится до сетевых вызовов: повтор задания не снимет уже вышедший новый ролик.
- `removeFromSocial` получил `insidePublishJob`: само задание публикации — не гонка с собой.

**Проверено.** `build:api`; `tests/remake-replace-old-posts.test.ts` (новый, 3 теста),
`property-change-requests`, `published-video-fix`, `video-remake`, `clip-review`,
`video-handoff-*`, `audit2-e-published-marks` — 163 теста зелёные на чистой базе.

**Осталось.** Объекты №137, №164 и №143 (29.10) и №82 и №181 (30.10) возвращены монтажёру
до выката этой правки: отметку для них ставит разовый скрипт после выката. Сохранение
telegram file_id исходников после уборки (чтобы перемонтаж пересылал их сам) — отдельная задача.
