# 31.10.2026 — перевод веток комментариев LEGACY → ядро (шаг 3 удаления старого бота)

## Что изменилось

Перевод поколений LEGACY → CORE (миграция 20261031120000, флаг
`CUSTOMER_AGENT_LEGACY_CUTOVER`) работал только для лички (`dm`). Ветки
комментариев IG/FB, начатые при старом боте (baseline), навсегда оставались
LEGACY и отвечал им старый `handleComment`. Теперь тот же механизм работает и для
`public_comment`:

- `lib/customerAgentEnrollment.ts` — `cutoverLegacySubjectTx` принимает обе
  поверхности; для ветки комментариев перед допуском берёт строку LEGACY
  `FOR UPDATE` (сериализует перевод с одновременной записью нового комментария,
  чья ссылка FK на ту же строку ждёт этот замок). Аудит
  `CUSTOMER_AGENT_LANE_CUTOVER` теперь несёт `surface`.
- `lib/customerAgentLegacyCutover.ts` — допуск ветки
  `readCustomerPublicLegacyCutoverReadiness`: остаётся LEGACY, если в ветке есть
  скрытый/удалённый комментарий (спам), передача сотруднику (ESCALATED), ручной
  ответ (`manual_reply` или STAFF_PUBLIC_COMMENT_REPLY), неразобранная строка
  старого (PENDING/WORKING), непрояснённая доставка (READY/IN_FLIGHT/UNKNOWN),
  строка с печатью ядра или больше 200 строк. Плюс две проверки «строка
  переведена» / «строка — результат перевода».
- `lib/customerPublicCommentStore.ts` — перевод просит только НОВЫЙ комментарий
  (повторная доставка — никогда). Повторная доставка СТАРОГО комментария
  переведённой ветки больше не даёт вечный 503 (раньше «смена полосы» считалась
  подменой), строка сохраняет прежнюю привязку. Свежая строка LEGACY в уже
  переведённую ветку не ложится (held → Meta повторит, повтор пойдёт в ядро).
- `lib/customerPublicAgentTurn.ts` + `messengers/comments.ts` —
  `publicAgentCommentLane` видит эффективную полосу: строка LEGACY переведённой
  ветки получает `moved`, `handleComment` закрывает её SKIPPED
  `legacy_lane_moved` без ответа (страховка; при допуске выше сюда попадать не должно).
- Миграция `20261031150000_customer_agent_public_legacy_cutover`: правило БД
  разрешало перевод только `surface='dm'`; теперь `dm` или `public_comment`,
  остальные условия те же. Схема Prisma не менялась.

Файлы `customerAgentEnrollment.ts`, `customerPublicCommentStore.ts`,
`customerPublicAgentTurn.ts`, `messengers/comments.ts` входят в `coreHash` —
после выката нужна новая регистрация ревизии ядра (как после каждой правки ядра).

## Откат

Выключить `CUSTOMER_AGENT_LEGACY_CUTOVER` — новые переводы прекращаются (и личка,
и комментарии). Уже переведённые ветки остаются в ядре (append-only, как и для
лички). Код — revert коммита; миграцию откатывает повторное применение тела
функции из 20261031120000.
