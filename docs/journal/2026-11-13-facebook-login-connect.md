# 13.11.2026 — «Войти через Facebook»: Страницы, Instagram и кабинеты одной кнопкой

- Что изменилось:
  - Настройки → Каналы → «Подключить через Facebook»: кнопка «Войти через
    Facebook» → окно Facebook → CRM показывает найденные Страницы (с их
    Instagram) и рекламные кабинеты галочками → «Подключить выбранное» → итог
    по каждой строке. Рядом поле «Номер конфигурации входа (config_id)».
  - Вход в Meta теперь ОДИН (`lib/metaLogin.ts`): state хранит цель
    (`ads` — прежняя рекламная кнопка, `assets` — новая), адрес возврата общий
    `/api/v1/ads/callback` (новый адрес в Meta вписывать не нужно), право
    проверяется на старте и заново в колбэке. `lib/ads/metaAdsOAuth.ts` —
    тонкая обёртка, поведение рекламной кнопки не изменилось.
  - Выбор и подключение — `lib/metaLoginAssets.ts` (сессия в памяти 30 мин,
    привязана к сотруднику, маркер наружу не уходит); маршруты
    `POST /settings/meta-eternal/login`, `GET /login/:id`,
    `POST /login/:id/connect` (settings.manage, подтверждение личности на
    старт и подключение).
  - Подключение Страницы и Instagram — одна дверь `lib/metaPageConnect.ts`;
    её же теперь зовёт «Подключить Messenger» (ключ компании). Подписка
    Страницы вынесена в `subscribePageWithToken` (поля объединяются, feed не
    снимается).
  - Instagram, у которого маркер — маркер Страницы (`EAA…`), говорит только
    через Страницу без рубильников (`pageOnlyRoute`), без отката «личным».
    Весь класс мест, ходивших на graph.instagram.com маркером аккаунта:
    `instagramTokenIdentity` спрашивает Страницу; `instagramRequest` переносит
    такие запросы (кроме `/me`) на graph.facebook.com; суточная проверка
    ключей проверяет Страницу; продление, проверка подписки Instagram и пробы
    прав пропускают такой аккаунт; аккаунт «по умолчанию» с маркером Страницы
    не отдаёт его ленте/публикации.
  - Кабинеты дописываются в `metaAdAccountId` без дублей; маркер рекламы
    заменяется маркером входа, только если вход видит ВСЕ кабинеты, иначе
    ничего не меняется и строка говорит, какой кабинет мешает. Предел поля
    `metaAdAccountId` в PATCH поднят со 100 до 1000 символов.
  - Миграция `20261113150000_meta_login_config_id`: одна пустая колонка
    `Settings.metaLoginConfigId`.
- Почему: владелец 13.11 — «чтобы любую страницу подключали с настроек CRM:
  нажать „Войти через Facebook“, дать разрешения — и всё, без игры с токенами».

## Пачка 2 — номера WhatsApp Business и честные подписи публикации (13.11.2026)

- Просьба владельца дословно: «подключить страницу можно не только через
  мессенджер, а всё прям подключить: и вотсап, и фб, и инста, и что ещё у нас
  там есть».
- Что изменилось:
  - После входа в выборе новая секция «WhatsApp»: номер, имя, аккаунт
    WhatsApp, состояние («не зарегистрирован», «не подтверждён кодом»,
    «основной номер», «подключено»). Итог по строкам.
  - Одна дверь `lib/metaWhatsappConnect.ts`: перечисление номеров, «чей ключ»,
    подписка аккаунта WhatsApp Business (`POST /{waba}/subscribed_apps`, один
    раз на аккаунт за подключение), подключение номера через существующий
    `saveAccount` (MessengerAccount WHATSAPP, externalId = phone_number_id,
    ключ входа). Основной номер из Настроек не подключается второй раз; новая
    строка НЕ «по умолчанию», пока в Настройках есть основной номер (иначе она
    забрала бы старые диалоги основного номера); имя, данное человеком, при
    повторном входе не перетирается. Регистрацию номера (PIN) CRM не делает —
    итог говорит словами, если номер не зарегистрирован.
  - Ключ личный (нет `client_business_id` у `/me`) — в итоге каждой строки
    WhatsApp и на экране предупреждение: «перестанет работать при смене
    пароля, для постоянной работы — конфигурация входа с ключом компании».
  - Класс «ключ Настроек вместо ключа аккаунта»: отправка, «прочитано» и
    реакции уже берут ключ и номер строки (`customerMetaTransport.ts`),
    единственное исключение — скачивание фото/голосовых клиента
    (`meta.ts::whatsAppMediaSource`) брало только ключ Настроек. Теперь вебхук
    передаёт ключ номера-получателя; у аккаунта без ключа Настройки не
    подставляются. Шаблоны первого касания (`whatsappFirstContact.ts`) идут
    только с основного номера — так задумано, не трогал.
  - `META_LOGIN` += `whatsapp_business_management`, `whatsapp_business_messaging`,
    `instagram_content_publish` (Instagram, подключённый через Страницу,
    появляется в выборе «куда» у свободных роликов и публикуется маркером
    Страницы). `pages_manage_posts` не добавлен: на Facebook публикуем только
    в основную Страницу маркером из Настроек.
  - Экран: строка «свои Страницы, Instagram и WhatsApp заработают сразу; для
    клиентов чужих компаний нужно одобрение Meta»; у Страниц — «ролики на
    Facebook пока только на основную Страницу»; у Instagram — «ролики объектов
    в основной Instagram, этот можно выбрать для свободных роликов».
- Сверено с документацией Meta: ФАКТ — debug_token granular_scopes/target_ids
  и owned/client_whatsapp_business_accounts (docs/whatsapp/embedded-signup/
  manage-accounts), поля phone_numbers и code_verification_status
  (documentation/business-messaging/whatsapp/solution-providers/
  manage-phone-numbers), `POST /{waba}/subscribed_apps` (docs/graph-api/
  webhooks/getting-started/webhooks-for-whatsapp, через поиск), ключ компании
  узнаётся по `client_business_id` (docs/facebook-login/
  facebook-login-for-business). ОЦЕНКА — `platform_type ≠ CLOUD_API` значит
  «не зарегистрирован»; поле `type` у debug_token документация не описывает —
  по нему не судим.
- Чем проверено: `meta-facebook-login.test.ts` (+6 тестов WhatsApp, нарочно
  ломал правило «не по умолчанию» — два теста краснеют), тест фронта секции,
  сборки, карта.
- Что осталось / риски:
  - Два номера одним входом получают ОДИН ключ. Ответы ядра идут с транспортом
    и работают; путь без транспорта (`resolveLegacyMetaSendTransport`) на
    одинаковом ключе отказывает (безопасно, не утечка).
  - Имя компании для бота у нового номера пустое → бот представится
    «Royal Home». Для номера другой компании — вписать имя в Каналах.
  - Приложение Meta должно иметь продукт WhatsApp и вебхук с полем `messages`
    (НЕТ ДАННЫХ, проверить в панели Meta); без этого подписка аккаунта не
    принесёт входящих.
  - Выбор «куда публиковать» для Facebook: нужны pageId в публикаторе вместо
    `creds.pageId`, право `pages_manage_posts` и строка выбора в свободных
    роликах — отдельная пачка.
