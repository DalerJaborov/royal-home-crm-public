# 25.11.2026 — потолок фонового повтора ответа бота и причина «blocked» в трассе

**Случай (разбор прода 24.11, только чтение).** В трассе ходов `no_reply` с источником `ai_retry`: Instagram 325 на 23 переписки, Facebook 33, WhatsApp 16; три переписки по 31–35 раз, последний повтор 24.11 17:02. Заблокированные ходы (WA 211, IG 95, FB 44) легли в трассу без причины.

**Причина петли (ФАКТ, из кода).** Крон `health-automation` (каждые 30 минут) ставит `ai-reply-retry` на каждую переписку с неотвеченной репликой клиента. Если повтор заканчивается «отвечать не нужно» (ход ведёт ядро, аккаунт выключен, бот промолчал, ход сменился…), задание завершается успехом, переписка остаётся «без ответа», и через полчаса крон ставит новое. Счёт жил в задании и умирал вместе с ним. Отказ ключа канала (HTTP 401, Meta 190/102) повтор считал обычным сбоем отправки: лесенка до 46 попыток, каждая заново звала ИИ. Какая именно ветка «отвечать не нужно» крутила три переписки — НЕТ ДАННЫХ: до этой правки трасса причину не писала (теперь пишет, см. ниже).

**Сделано.**
- `jobs/aiReplyRetryCap.ts`: счёт пустых повторов на реплике клиента в `ProcessedMessage` (канал `ai-retry-no-reply`, без миграции, уборка общая через 3 дня). Третий пустой повтор или отказ ключа — стоп: одна строка в журнал ошибок на переписку (`dedupKey ai-retry-stop:<id>`), при мёртвом ключе ещё и сигнал ответственному через `alertClientWaiting(trigger: "failed")` (см. второй круг ниже). Дальше задания по этой реплике завершаются сразу, без ИИ и без строки в трассе. Новая реплика — новый счёт. «ИИ лежит» и обычный сбой не считаются: лесенка и сдача поставщика как раньше.
- `lib/stuckConversations.ts`: исход `channel-dead` (401 / 190 / 102, только ошибка транспорта Meta, не «HTTP 401» чужого сервиса); ответ помечается «не дошло».
- Рубильник `botRetryCapEnabled` («Автоматика ИИ» → «Бот клиентов», ВКЛ, миграция `20261125090000`). Выключен — прежнее поведение.
- Трасса: поле `outcomeReason` (закрытый список кодов `traceOutcomeReasonSchema`, без текста) для `blocked` и `no_reply`; проставлено во всех местах, где ход получает `blocked` (вебхук, повтор, доставка карточки объекта), и в ветках «отвечать не нужно» повтора.
- `channelCoreMessageKey` вынесен в `lib/customerMessageKey.ts` (одна функция для счёта ядра и потолка), правило «намеренное молчание» — одна функция `episodeAllIntentional` для сторожа молчания и потолка.
- Тесты: `ai-reply-retry-job.test.ts` (потолок, мёртвый ключ, новая реплика, лесенка не тронута, рубильник), `stuck-conversations.test.ts` (channel-dead), `bot-turn-trace.test.ts` (причина). Красные без правки проверены.

**Второй круг (независимое ревью PR #423).**
- Остановка больше не вечная. Кнопка «Повторить зависшим» снимает остановки и счёт (`resetAiRetryCap`) до постановки заданий. Остановка «ключ мёртв» привязана к отпечатку ключа (12 знаков sha256, сам ключ не хранится): переподключили аккаунт — ближайший повтор (крон или кнопка) отвечает. Тест «переподключили, нажали кнопку, ответ ушёл» есть в `stuck-conversations-retry.test.ts`.
- После 3 пустых повторов людям сигнал не шлётся: это дело сторожа молчания с его правилами (выключатель, «бот отвечает сам», спам, звонок агента). Сигнал остался только для мёртвого ключа. Текст «ответ бота не ушёл, ключ канала не работает (руководство об этом знает)» не отправляет агента в Настройки.
- «Ключ мёртв» сужен: 401 или 190/102 с текстом про маркер. 401 запасного личного ключа после отказа пути Страницы (`MetaGraphCallError.fellBackFromPage`) и 190 «окно ответа истекло» сюда не попадают.
- Порядок: сначала сигнал (один на эпизод) и журнал, потом метка. Если упали между ними, следующий повтор доводит дело.
- Плитка «Сейчас ждут ответа» по-прежнему считает остановленные переписки. Это решение: клиент там правда ждёт человека, и прятать его хуже.

**Что смотреть на проде после выката.** `BotTurnTrace.payload->>'outcomeReason'` по `source='ai_retry'` и `outcome in ('no_reply','blocked')` — какая ветка крутила; строки «Повтор ответа бота остановлен» в журнале ошибок; число `ai-reply-retry` в `BackgroundJob` по одной переписке за сутки (ожидание: не больше 3 с ходом, дальше пустые завершения).

**Не сделано.** Крон по-прежнему ставит задание раз в 30 минут и на остановленную реплику (оно завершается сразу, без ИИ). Кнопка «Повторить зависшим» тоже уважает потолок. Ключ Instagram — действие владельца (переподключить в Настройках → Каналы).
