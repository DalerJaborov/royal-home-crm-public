# 12.11.2026 — вечные ключи Meta: сторож мёртвых ключей, самопроверка, путь через Страницу (заперт до App Review)

**Что случилось (ФАКТ, прод 12.11).** 11.11 в 10:12Z владелец сменил пароль Instagram. Личный маркер входа
через Instagram (IGAA…) аккаунта @royal.home.tj стал отвечать 401 «session has been invalidated because the
user changed their password». Входящие доходили, ответить было нечем; лиды с рекламы терялись. В журнале
ошибок — 91 строка и ни одного пуша: «Новая проблема» уходит только на впервые увиденный текст.
Инвентарь ключей (debug_token 12.11, координатор): `metaWaToken` и `metaIgManageToken` — системный
пользователь royalhome-crm, вечные; `metaPageToken` — маркер Страницы от ЛИЧНОГО пользователя; `metaAdsToken` —
личный; `metaIgToken` и маркеры трёх аккаунтов Instagram — личные IGAA.

**Главное ограничение (ФАКТ, Meta DevTools 12.11, координатор).** У приложения 1684679092586215 нет Advanced
Access к `pages_messaging` и `instagram_manage_messages` (только standard), у `pages_messaging` api_testing
NOT_STARTED. Значит, путь через Страницу ответит только людям с ролью в приложении, клиентам — нет. Поэтому
сейчас главная ценность правки — сторож и самопроверка; путь переписки через Страницу собран, но заперт, пока
директор не отметит «App Review одобрен».

**Что изменилось.**
- Сторож `lib/channelKeyAlarm.ts` (работает при любом положении рубильника): 401 / код Meta 190, 102 /
  Telegram 401 → CRITICAL-тревога директору и администратору через `enqueueDirectorAlert`, одна на ключ за 12 ч.
  Проверка «тревога уже есть» и запись идут под `pg_advisory_xact_lock` в одной транзакции — без гонки между
  одновременными отказами и между api и worker. Подключён в `callGraph`, в рекламе, в Telegram-боте и в суточной
  проверке ключей (Страница, WhatsApp, Instagram, новый «Вечный ключ Meta»). Маркер в текст не попадает.
  Очередь тревог подгружается по требованию: статический импорт тянул `push.ts` в транспорты.
- `lib/metaEternalTokens.ts` — одна дверь вечного пути. Ключ системного пользователя (`metaIgManageToken`) →
  маркер Страницы `GET /{page}?fields=access_token,instagram_business_account` (кэш 10 мин, отказ 5 мин).
  - Путь переписки включается только при всём сразу: рубильник `metaSystemTokenPreferred` + отметка
    `metaAppReviewApproved` (обе ВЫКЛЮЧЕНЫ по умолчанию, и для существующей строки) + у ключа компании есть права
    по `/me/permissions` (Instagram: `instagram_basic`, `instagram_manage_messages`, `pages_manage_metadata`;
    Facebook: `pages_messaging`) + у аккаунта задана Страница (`MessengerAccount.pageId`) + Meta подтвердила, что
    к ней привязан именно этот Instagram. Facebook — только на адресе известной Страницы этого маркера.
  - Подмена — у физического вызова `meta.ts::callGraph`. Чёткий отказ Meta на пути Страницы (4xx с телом error)
    → один повтор личным ключом (сообщение не принято — задвоения нет), Страница «на скамейке» 5 минут, на
    кодах прав (3, 10, 190, 102, 200–299, 230, 551) — тревога. Таймаут, обрыв, 5xx — без повтора.
  - Учёт физической отправки считается по логическому сообщению, до подмены пути.
  - Успешная отправка с mid через Страницу пишет `eternalLastSentAt` (аккаунт) / `metaPageEternalLastSentAt`.
    Эхо такой отправки узнаётся прежним механизмом: mid ответа Send API попадает в `rememberOutgoingMid`, плюс
    сверка по тексту и времени (`isOwnInFlightEcho`).
  - Реклама: ключ компании, только если у него не меньше прав на рекламу, чем у личного, и в КАЖДОМ кабинете у
    системного пользователя задача ADVERTISE или MANAGE (стоп-лосс ставит паузу, `reelsAutoBoostMeta.ts`).
    Проверка кэшируется (6 ч, отказ 5 мин), одновременные вызовы — одна проверка.
- Суточная проверка Instagram при вечном пути продолжает проверять личный ключ; его смерть — предупреждение в
  журнале, без тревоги.
- Настройки → Каналы → «Вечные ключи» (`MetaEternalKeys.tsx`, один экран для ПК и телефона): рубильник,
  отметка «Meta одобрила приложение (App Review)», права ключа компании, по каждому аккаунту/Странице/рекламе —
  честный статус: «ждёт одобрения Meta», «не хватает прав: …», «нужно выдать доступ: где нажать», «готов, ждёт
  первой отправки», «работает: была отправка» (только после реальной отправки). Подсказка: проверять сообщением
  с профиля БЕЗ роли в приложении. «Подписать Страницу» отказывает, если не узнали приложение или текущую
  подписку; поля объединяются, `feed` не снимается. Маршруты — `routes/settingsMetaEternal.ts`.

**Первоисточники Meta (сверено 12.11).**
- ФАКТ: нужен «Allow Access to Messages» (Instagram → Сообщения и ответы на истории → Управление сообщениями →
  Подключённые инструменты) — Messenger Platform → Instagram → Get started.
- ФАКТ: отправка Instagram через Страницу — `/{PAGE_ID}/messages`, получатель IGSID, маркер Страницы; вебхук
  `object: "instagram"`, `entry.id`/`recipient.id` — IGID (= `externalId` аккаунта), `sender.id` — IGSID.
- ФАКТ: поля Instagram подписываются в панели приложения; Страница — `POST /{page}/subscribed_apps`.
- ФАКТ: пока аккаунт подключён двумя путями, сообщения могут прийти дважды (Instagram Login migration guide).
- ФАКТ: окно ответа 24 ч (до 7 дней после Click-to-Direct); вне окна в Instagram — только HUMAN_AGENT (7 дней,
  App Review, только ручной ответ человека).
- ОЦЕНКА: IGSID одинаков при входе через Instagram и через Facebook; формат mid эха через Страницу — проверим живьём.

**Чем проверено.** `tests/meta-eternal-tokens.test.ts` — 29 тестов, на каждую правку ревью свой; каждая правка
проверена нарочной поломкой (скрипт мутаций: поломка → красный, возврат → зелёный). Список — в отчёте к PR #161.

**Что осталось.** App Review (`pages_messaging`, `instagram_manage_messages`, Advanced Access) — без него путь
через Страницу клиентам не ответит; до тех пор бот Instagram оживает только новым личным маркером. Клики
владельца — в PR. Ревью `architect`; `npm run ship`. Не сделано: аккаунт Instagram без личного маркера вовсе,
комментарии/лента/публикация через Страницу, четыре одинаковых чтения `metaIgManageToken` в `photoPosts`,
`publishedChannelsAudit`, `publishedVideoFix`, `socialReposts` — кандидат в одну дверь.
