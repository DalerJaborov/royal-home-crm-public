# 25.11.2026 — Мёртвый ключ Instagram: одна дверь на все пути

- **Что было (прод, 24.11 03:18 → 25.11).** Ключ Arvan Estate после смены пароля отвечал HTTP 401 / код 190
  «The session has been invalidated because the user changed their password». Дверь `lib/instagramAccountAccess.ts`
  метила аккаунт только на «войдите в Instagram и пройдите проверку», поэтому каждый путь встречал мёртвый ключ
  заново: «Сообщение в INSTAGRAM не отправлено» ×67, «Повтор зависшего диалога … не удался» ×100+ (одни и те же
  переписки раз в 30 минут, каждый раз с ходом ИИ), «Публикация … не получена» ×20, «Профиль … не получен» ×19,
  «Сообщение из INSTAGRAM не обработано» ×18, «Комментарий … не обработан» ×16, личное по комментарию ×5+.
- **Что изменилось.**
  - Дверь: `isInstagramKeyRefusal` = «аккаунт закрыт» ИЛИ «ключ не принят» (узкая проверка
    `channelKeyAlarm.ts::isMetaAuthFailure`: 401 или 190/102 с текстом про маркер; 5xx/429/лимиты — нет). Отметка
    `accessLostAt` ставится один раз, своим текстом для смены пароля («Заменить маркер», без «пройдите проверку»),
    одна тревога руководству на эпизод — та же метка `ig-account-locked:*`.
  - Пока отметка стоит, в Meta этим ключом не ходим: `instagramAccessGate` в `meta.ts::callGraph` (все отправки,
    личное по комментарию, «печатает»), профиль собеседника, публикация для комментария, разбор очереди комментариев
    (комментарий ждёт без траты попытки), повтор зависших (`channel-paused`: ни ИИ, ни Meta, без лесенки и без
    счёта пустых повторов). Отказ без запроса — `InstagramAccessLostError`; его не пишут в журнал отправка, вебхук,
    повтор, комментарии; сотрудник при ручной отправке видит причину.
  - Самоизлечение: раз в 30 минут на аккаунт (в процессе) один запрос идёт пробой; Meta приняла — отметка снимается.
    Ошибочная отметка на живом аккаунте не глушит его до суточной проверки.
  - «Заменить маркер» снимает отметку (как и было) и теперь ещё остановки повтора «ключ мёртв» по перепискам
    аккаунта (`aiReplyRetryCap.ts::releaseAiRetryKeyStops`) — ответ уходит с ближайшим кроном (до 30 минут), а не
    через 2 часа. **Предел честно:** крон повтора берёт только переписки, где клиент писал СЕГОДНЯ по Душанбе
    (`stuckConversations.ts::stuckWhere`); недоставленный ответ — до 24 часов. Более ранним клиентам после замены
    ключа отвечать вручную. Комментарии ждут не дольше 3 суток, затем закрываются «access_lost».
  - Ревью #432 (второй коммит): ворота и отметка — только для ВЫЗОВА Instagram (по адресу запроса,
    `metaGraph.ts::isInstagramApiUrl`), а не по совпадению ключа: у Instagram через Страницу ключ общий с Facebook
    этой Страницы (`lib/metaPageConnect.ts`). Голый 401 без кода 190/102 и без слов про ключ/сессию (отказ прокси)
    не метит. Успешный ответ Instagram этим ключом, включая отправку ядра (durable), снимает отметку. «Meta точно не
    приняла» — одно правило `lib/metaProviderRejection.ts` для транспорта, карточки объекта
    (`customerPropertyDelivery.ts`, одна строка) и трассы; потеря доступа посреди хода — `channel-paused`, не к
    потолку повторов. Очередь комментариев исключает аккаунты с отметкой в самом запросе (`selectDueComments`).
    Отказ профиля пишется на тот ключ, которым шёл запрос (через Страницу — не метит личный).
  - Суточная проверка ключей ведёт 401/190 в ту же дверь (вместо «Ключ не работает» второй тревогой).
  - Шум Meta: «Профиль Messenger … Unsupported get request» — одна строка в сутки без пуша; личное по комментарию с
    отказом «окно закрыто/получатель недоступен» (в т.ч. «This user cant reply» — распознаётся по тексту) — одна
    строка в сутки на канал и вид без пуша. Права, ключ, прочее — как раньше.
  - Сторож `tests/instagram-key-door-sites.test.ts`: новый файл с запросом в Graph Instagram не проходит, пока не
    проведён через дверь или не вписан с причиной.
- **Решение, которое поменялось.** Тест #352 утверждал «мёртвый ключ — не «закрыт», строка ленты раз в сутки».
  Прод показал цену: остальные пути отметку не видели. Теперь мёртвый ключ метится той же дверью; тест переписан.
- **Чем проверено.** `tests/instagram-access-lost-door.test.ts` (7: отправка 401/190 → одна отметка и тревога, дальше
  без запроса и без строки; проба мёртвая/ожившая; живой ключ и отказ «про клиента» — без отметки; профиль; повтор
  зависшего → `channel-paused` без ИИ и Meta, после «Заменить маркер» — `sent`; суточная проверка; «cant reply»),
  `tests/instagram-key-refused-door.test.ts`, сторож путей (сломан нарочно — красный). Снятие ворот в `callGraph`
  нарочно — тест красный. Тесты прежнего решения «мёртвый ключ — не закрыт» переписаны под дверь:
  `instagram-company-key`, `instagram-webhook-subscription` (+ случай «отказ не про ключ — строка, без отметки»),
  `meta-eternal-tokens`. Соседние зелёные: `ai-reply-retry-job`, `stuck-conversations(-retry)`, `meta-send-policy-block`,
  `meta-facebook-login`, `comment-day-review-23-11-postgres`, `customer-echo-then-reply-postgres`,
  `one-brain-core-run-ledger`, `social-publish-instagram-delete`. `precheck`: build:shared/api зелёные, все audit-шаги,
  map:check, сторож карты, журнал — зелёные; build:web в worktree красный только из-за отсутствия
  `@testing-library/react`/`recharts` в общем node_modules (apps/web не тронут). Полный test:api — на ship.
- **Что осталось (слепые пятна).** Пути клиентского ядра (`customer*`: медиа DM, имя отправителя, публикация для
  ответа ядра, durable-отправка) по задаче не трогали — они ещё ходят в Meta мёртвым ключом. Статистика
  (`instagramInsights.ts`, `postStats.ts`) и проверка контейнеров публикации — не через дверь. Живой входящий ход
  на закрытом аккаунте всё ещё зовёт ИИ (ядро бота не трогали), отправка уже не ходит в Meta. Проба — в памяти
  процесса (api и worker пробуют каждый свой раз в 30 минут); кэш учётных записей worker (до 60 с) может
  отставать от «Заменить маркер» — не чинили (ревью #432, п.5). Ожидаемый шум «Unsupported get request» схлопнут
  в строку в сутки, причина у Meta не выяснена (п.8).
