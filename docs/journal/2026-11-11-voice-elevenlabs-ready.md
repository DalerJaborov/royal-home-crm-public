# 11.11.2026 — Робозвонок на ElevenLabs: проверка одной-двумя командами, когда придёт ключ

- Что изменилось (только скрипты, тесты и документ, код сервера не тронут):
  - `scripts/elevenlabs/preflight.mjs` (`npm run voice:preflight`, `-- --dry` без сети): доступ к API
    (код, задержка, страница защиты по странам), ключ, агент по `ELEVENLABS_AGENT_ID`, голоса,
    знает ли `eleven_v4_turbo` таджикский (список языков `/v1/models`). Только чтение.
  - `scripts/elevenlabs/patch-check.mjs` (`npm run voice:patch-check`): те же два PATCH, что у сервера
    (`buildAgentSyncPatch` + `buildAgentTuningPatch` берутся из исходников через tsx), на агенте
    `ELEVENLABS_TEST_AGENT_ID`, после каждого GET и сравнение; отдельно ключевые поля
    (`language_detection`, `language_presets.tg`, формат звука, `turn.*`) и «глубокое слияние»
    (что из неотправленного пропало). Отказ, если тестовый агент равен боевому.
  - `scripts/elevenlabs/suite.mjs` + `scenarios.mjs` (`npm run voice:sim`): 19 симуляций на ТЕКУЩИХ
    промптах CRM (`crm-prompts.mjs` берёт их из `apps/api/src`): приглашение кандидата ru (6) и tg (3),
    опрос после показа (3), проверка собственника (3), звонок клиенту (4). Судья ElevenLabs +
    проверки кодом по расшифровке: нужная функция с нужными полями, нет «лутфан», нет запрещённой функции.
  - `docs/voice-elevenlabs-runbook.md`: переменные, порядок, откат на Google.
  - `scripts/elevenlabs/elevenlabs-scripts.test.mjs` (25 тестов, в `test:scripts`): разбор ответов,
    сравнение PATCH на подставном сервере (глубокое слияние / замена разделов / молча отброшенное поле /
    отказ 422), симуляции на подставном сервере, сторож «ключ не печатается».
- Из наработок 24.10 (`origin/feat/elevenlabs-voice-agents-24-10`) перенесена идея 28 сценариев
  (адрес, зарплата, перенос, «вы робот?», не тот человек, таджикский, «лутфан») и критерии судьи;
  временные id агентов и ключи не переносились, тексты промптов 24.10 не копировались (проверка идёт
  на промптах CRM). Скрипты `call2`, `llmbench`, `style`, `voice-lab` не переносились: звонки и подбор
  голоса — решение владельца, не автоматика.
- Находка по методу: `simulate-conversation`, на котором был `suite.mjs` 24.10, по справочнику
  ElevenLabs СНЯТ с 31.10.2026 (страница помечена deprecated). Заменён на тесты агента:
  `POST /v1/convai/agent-testing/create` (type `simulation`), `POST /v1/convai/agents/{id}/run-tests`,
  `GET /v1/convai/test-invocations/{id}`. Формы сверены со справочником 11.11.2026; прогон на живом
  ключе НЕ делался.
- Почему: журнал 10.11 оставил «НЕ ПРОВЕРЕНО на настоящем агенте» (принимает ли PATCH все поля, как
  сливает подобъекты, доступ из Германии). Чтобы с приходом ключа это занимало минуты, а не вечер.
- Чем проверено: `node --test scripts/elevenlabs/elevenlabs-scripts.test.mjs` — 25 из 25; сторож
  ключа проверен нарочной поломкой (печать `${apiKey}` краснит тест); `--dry` всех трёх скриптов,
  `npm run map` + `map:check`, `npm run precheck` (результат — в коммите).
- Что осталось (НЕ ПРОВЕРЕНО без ключа):
  - формы запросов тестов агента и ответа `test_runs` сверены только со справочником; возможны
    расхождения по полям (`tool_mock_overrides`, `agent_responses.tool_calls`);
  - поля `tool_mock_config` для клиентских функций: в справочнике сказано «системные инструменты не
    подменяются», клиентские должны подменяться — подтвердить первым прогоном;
  - судья ElevenLabs оценивает по таджикскому хуже, чем по русскому — tg-сценарии читать глазами;
  - распознавание таджикского и задержка линии — только слухом на живом звонке;
  - `end_call` у приглашения и опроса — одно имя функции с разным списком причин: сервер переписывает
    её под вид звонка перед каждым звонком; параллельные звонки разных видов на одном агенте не
    предусмотрены (линия одна), но стоит помнить при втором агенте.
