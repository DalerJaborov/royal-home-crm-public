# 04.11.2026 — Передать ключ отчётов резервного копирования в production

- Что изменилось: общий environment API/worker принимает BACKUP_REPORT_API_KEY из окружения; пример production-конфигурации описывает отдельный ключ и безопасное пустое значение.
- Почему: при наличии ключа на сервере Compose раньше не передавал его API, и штатные backup-скрипты не могли авторизовать отчёт в разделе резервных копий.
- Чем проверено: fixture-only Docker Compose config проверяет пустое значение, явную передачу отдельного тестового ключа и отсутствие секрета у web/PostgreSQL. Реальные секреты в проверке не используются.
- Что осталось: штатный выпуск, серверная настройка отдельного ключа и отчёт реального backup-скрипта. Этот патч не создаёт фиктивных записей и не меняет хранение копий.
