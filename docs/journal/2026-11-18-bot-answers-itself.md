# 2026-11-18: «Бот отвечает сам», номер из комментария — разговор и скрытие, щит считает только доставленные

## Коротко для владельца
- **Клиенту.** Оставил номер под постом — карточка заводится сразу, бот пишет ему ОДНО личное «увидели ваш номер, что вас
  интересует: купить, продать или работа?», комментарий скрывается. Ответил — агент получает заявку с его словами; молчит
  20 минут (в рабочее время) — заявка уходит агенту с пометкой «боту не ответил». Личное невозможно — короткий ответ под
  постом и сразу агенту. На трудный вопрос при включённом «Бот отвечает сам» клиент слышит не «передал сотруднику», а
  просьбу номера (номер уже просили — телефон офиса, только для Royal Home).
- **Руководству.** При «Бот отвечает сам» нет уведомлений «бот передал / агент уточнит / комментарий требует человека /
  трижды не по теме» по чатам без карточки. Остаются: агенту — о его клиенте, заявки, сбои бота (клиент совсем без
  ответа, ИИ недоступен, ключ, аварийный рубильник), блокировка Meta (#273).
- **Два тумблера** (Настройки → Бот): «Бот отвечает сам, не зовёт руководство» — по умолчанию ВЫКЛ;
  «Номер под постом: написать человеку и скрыть» — по умолчанию ВЫКЛ (включается после «да» владельца на тексты); ВЫКЛ — карточка с пометкой, а ответ под постом как раньше.
- **Откат.** Без выката: выключить нужный тумблер — поведение прежнее (оба ВЫКЛ = как до правки: ни личного, ни скрытия, ответ модели под постом; номер из комментария только становится карточкой).
  Полный откат — revert коммитов ветки `claude/bot-answers-itself-18-11`; колонки миграции `20261118170000` можно оставить
  (только добавление, по умолчанию прежнее поведение).
- **Проверено.** tsc 0, `precheck --no-tests` зелёный, затронутые тесты на стенде с базой (`bot-answers-itself*`,
  `comment-phone-*`, `instagram-comments`, `telegram-group-comments`, `client-waiting-alert`, `customer-escalate-notify`,
  `ai-offtopic-handover`, `bot-channel-off`, `comment-decision-consumers` и соседние) — зелёные.

Шаг 1b плана «бот как живой сотрудник». Слова владельца: «бот никак не вызывал администратора, директора… полностью сам
все отвечает… и по возможности брал заявки. И в комментариях»; про номер в комментарии: «неправильно, ИИ должен
поговорить, чтобы узнать, что он хочет», «скрой, это возможно спам».

## A. Настройка «Бот отвечает сам» (по умолчанию ВЫКЛ)
- `Settings.botAnswersItself` (миграция `20261118170000_bot_answers_itself`), тумблер в Настройки → Бот.
- Одна дверь: `lib/botAnswersItself.ts` — чтение настройки и таблица `staffSignalAllowed` (вид сигнала × свой агент ×
  карточка). Сторож в CI `tests/bot-answers-itself-guard.test.ts`: файл бота, зовущий людей пушем, обязан спросить дверь
  или стоять в списке исключений с причиной.
- Подключено: `clientWaitingAlert` (ядро Meta и старый путь, сайт), `channelStaffAlert` (Telegram), `customerHeldMessage`
  (`notifyEscalatedCustomerTurn`), выход ядра из тупика (`customerDmAgentTurn.planSafetyLine`), дверь старого бота на
  сайте/Telegram (`legacyQualifyDoor`: вместо «передал сотруднику» — шаг к номеру, вложение — «не открылось»),
  комментарии Meta/YouTube и Telegram-обсуждение (escalate → свой ответ под постом), сводка «комментарий ждёт человека»,
  офтопик старого пути.
- Остаётся всегда: агенту о его клиенте, карточка без агента, техсбой, аварийный рубильник канала, вакансия (рекрутер).
  Клиент совсем без ответа — сбой: сигнал как раньше (ревью 1b, №1).

## B. Щит исходящих и остатки #266
- `outboundShield.noteOutboundUndelivered`: явный отказ провайдера (Graph HTTP 4xx/5xx, запрет до отправки, ошибка
  Telegram API на первом куске) возвращает счёт «подряд», темп инициативы и отпечаток текста. Таймаут — не возвращает.
  Подключено в `meta.ts::sendMessage` и `telegram/api.ts::sendMessage`. Живой случай: Арван 17.11, Meta 368.
- `#266`: готовые ответы старого пути до двери (только заявки, факты объекта, приветствие, «не разобрал номер») на
  выключенном канале не уходят; `arvan` под постами — по аккаунту комментария (`isCustomerAgentCommentOff`); сбой чтения
  бренда — выключено + журнал.
- Блокировка Meta (#273, `lib/metaSendBlock.ts::isAccountSendBlocked / isMetaSendBlockError`):
  ядро при блоке личных не зовёт модель (намеренное молчание `meta_send_blocked`), номер из комментария идёт запасным путём.

## C. Номер из комментария (основа — #270, поведение заменено)
- Одна дверь `comments.ts::handleCommentPhone` раньше всех веток модели: карточка сразу (придержка раздачи
  `Client.commentPhoneHoldUntil` = 20 минут), ОДНО личное с вопросом о цели, комментарий скрыть. Личное невозможно →
  короткий публичный ответ (4 по очереди), скрыть, карточка сразу в раздачу с пометкой. Скрыть не вышло → пометка и
  журнал без тревоги. recipient_id ответа Meta → его переписка к той же карточке.
- Раздача: `lib/commentPhoneHold.ts` в тике `lead-distribution` перед волной — ответил боту (его слова в хронологию) или
  срок вышел («боту не ответил»). Волна не берёт карточку до срока.
- YouTube: ответ + заявка с пометкой + `heldForReview`; Telegram-обсуждение: заявка с пометкой, не удаляем.
- Полоса ядра комментариев (managed): заявка с пометкой сразу (личное этой полосе шлёт только ядро).
