# 12.11.2026 — каталог Somon: только своя рубрика, чистка мусора, инкремент при паузе, повторы

**Что случилось.** В `MarketListing` (source somon.tj) 23 373 строки, недвижимости из них ~9 843; остальное
(автозапчасти, окна-двери, ноутбуки, услуги) записано «квартирами/домами на продажу» ручным обходом
11.11 12:57–14:04 UTC. Причина — ФАКТ, живые страницы 12.11: адрес `/nedvizhimost/prodazha-domov/dushanbe/`
у Somon больше не раздел домов, а общая лента «Все объявления» (`"rubric":{}`, `"url":"/search/dushanbe/"`,
9 326 страниц). Раздел домов теперь `/nedvizhimost/prodazha-domov-havli-i-dach/dushanbe/` (рубрика 218,
24 страницы, 1 435 объявлений); квартиры — список 216, объявления 2829–2839 (151 страница, 9 050).
Тип объекта угадывался по словам в предках рубрики, всё неопознанное становилось «квартирой»; у домов
(предок — просто `nedvizhimost`) — тоже «квартирой», а «3 этажн.» читалось как этаж.

**Что изменилось.**
- `lib/market/somonRubrics.ts` — одно место правила: список рубрик недвижимости Somon (номер → сделка и тип),
  `marketCatalogWhere()` для чтения, `isReadableCatalogRow` — то же в памяти.
- Сборщик (`somonCrawler.ts`): раздел знает рубрику своей страницы и белый список рубрик объявлений;
  чужая страница — стоп `wrong_scope` (в журнал), чужие объявления не пишутся, страница без своей
  рубрики — конец раздела (console, не ошибка). Адрес домов исправлен, дверь `fetchSomon` пропускает
  новый адрес и больше не пропускает старый. Тот же разбор — у записи из парсера лидов (`saveSomonPageHtml`).
- Разбор (`somonParser.ts`): тип и сделка только по рубрике (нет в списке — объявление не наше); дома —
  `parseHouseTitle`: этажность → `totalFloors`, комнаты, сотки → новое поле `landSotki` (миграция
  `20261112130000_market_listing_land_sotki`, только ADD COLUMN), площадь дома — если указана.
- Чтение: `marketCatalogWhere()` в сегментах, подборе покупателю, оценке похожих, динамике, сверке с
  нашими объектами (и подсчёте объявлений по номеру), проверке дублей, счёте «прежний размер» перед
  пометкой «исчезло». Сторож `tests/market-catalog-read-guard.test.ts`: новое чтение каталога без правила
  краснеет (проверено: убрал правило из `segments.ts` — красный, вернул — зелёный).
- Повторы: `dedupeAcrossSources` → `dedupeListings` (одна дверь для сегментов, подбора, оценки, динамики):
  плюс склейка повторов ОДНОЙ площадки — тот же район, комнаты, этаж (у обоих), площадь ±0,5 м², цена ±1 %,
  ремонт и продавец, если известны у обоих, — те же. `listingDedupe.ts` не подошёл: он ищет дубль одного
  нового объявления запросом в базу, а здесь нужен счёт в памяти.
- Инкремент Somon (`lib/market/somonIncremental.ts`, cron `market-somon-incremental`, минуты 7/22/37/52,
  флаг `MARKET_CRAWL_ENABLED=1`): первые 3 страницы домов всегда, квартир — только когда парсер лидов сам
  не пишет (`somonMonitorFeedsMarket`: пауза уведомлений, лиды выключены/остановлены). Общий бюджет
  `fetchSomon` (фон), общий замок обходов; источник остановлен или бюджет закрыт > 1 мин — тик пропускается.
  Исчезнувшими не помечает.
- Чистка: `lib/market/purgeSomonJunk.ts` — по умолчанию просмотр (рубрики, сколько уйдёт, каскад снимков и
  совпадений, сколько строк своих рубрик переписать); `--apply` удаляет чужие рубрики пачками и переписывает
  дома/участки/офисы, записанные «квартирами». Прод: `node dist/lib/market/purgeSomonJunk.js [--apply]` в
  контейнере api — запускает только сборщик после «да» владельца, перед `--apply` — копия таблиц.

**Чем проверено.** Новые тесты: `market-somon-rubrics` (разбор, правило чтения в базе, сегменты, чистка на
своей полосе строк), `market-somon-incremental` (пауза → инкремент идёт; лиды пишут → квартиры не качаются;
403/остановка/замок), `market-somon-crawler` (общая лента → `wrong_scope`, чужие не пишутся, конец раздела,
дом), `market-catalog-read-guard`; обновлены фикстуры страниц под живую форму (`tests/helpers/somonPage.ts`).
Внесение поломки: без фильтра рубрик сборщик — 3 красных теста. Скрипт чистки прогнан на стенде (просмотр).

**Что осталось.** Запуск чистки на проде (оценка: удалит ~13 500 строк, НЕТ ДАННЫХ о точном числе
переписанных). Аренду/участки/офисы не собираем — дверь `fetchSomon` закрыта для них намеренно. Копия
разбора `somonLeads/listingParser.ts` (`toListing`/`detectCategory` по словам) в коде не вызывается, кроме
тестов, — кандидат на удаление. Совпадения с нашими объектами на мусорных строках уйдут каскадом при чистке.

## Ревью #160 (второй коммит той же правки)

- Рубрика страницы читается разбором объекта `rubric` целиком (JSON), без привязки к порядку ключей.
- Парсер лидов (`saveSomonPageHtml`): чужой список — запись в журнал (`somon-market-ingest-wrong-scope-216`),
  а не молчание: пока лиды пишут каталог сами, инкремент квартиры пропускает, и тихий отказ был бы простоем.
- Чужие рубрики на своей странице — в журнал по записи на номер рубрики
  (`market-somon-foreign-rubric-<страница>-<рубрика>`): новая подрубрика недвижимости не пропадёт молча.
- Страница только чужих рубрик раньше известной последней — `wrong_scope` (обход неполный), а не конец раздела.
- Чистка: удаляемые рубрики, похожие на недвижимость (slug `kvartir|komnat|dom|uchast|arend|ofis|nedvizh` или
  предок «Недвижимость» 121 в сырье), печатаются отдельным списком; `--apply` при них отказывает без `--force`.
- Инкременты Somon и Paydo не стартуют 02:15–03:15 по Душанбе (`inNightFullCrawlWindow`, nightly.ts).
- Проверено: тесты на 1–4 и окно; внесение поломки — без проверки `page < lastPage` и без отказа по
  подозрительным рубрикам по красному тесту на каждую.
