# 27.11.2026 — «Чаты» открываются за 0,2 с вместо 8 с: JIT Postgres выключен, список одним проходом

- Что изменилось:
  1. **JIT Postgres выключен на каждом соединении приложения** (`lib/prismaAdapter.ts`, `withSessionSettings`):
     к адресу базы дописывается `options=-c jit=off`, как уже едет `statement_timeout`. Одна дверь — там,
     где создаётся каждое соединение (сервер, воркер, сиды, тесты). Рубильник: `PG_JIT=on` возвращает JIT
     без выката кода.
  2. **Список «Чатов» (`GET /conversations?grouped=1`) — один запрос вместо двух**: сводка для чисел на
     вкладках раньше считалась отдельным запросом по той же выборке, теперь едет в той же выдаче
     (`metrics` + `LEFT JOIN`, пустая страница отдаёт строку только со сводкой).
  3. **Поле переписки распаковывается один раз, а не четыре**: новая дверь `lib/lastMessageSql.ts`
     (`jsonb_path_query_first(... 'strict $[last]' ...)` с тем же смыслом, что прежний `CASE`), число
     реплик считается только для сорока строк страницы. `conversationWaitingParts()` берёт ту же дверь —
     это ускоряет и плоский список, и счётчики «Ждут».
  4. Шаги ответа списка, не зависящие от выборки (каналы Telegram Direct, аккаунты, тихие строки, рубильник
     архива), и три дозапроса по строкам страницы идут параллельно, а не друг за другом.
  5. Сайт: ответ закрытого экрана живёт в памяти 30 минут вместо 5 (`gcTime` в `lib/queryClient.ts`) —
     возврат в раздел рисуется сразу, свежие данные догружаются фоном.
- Почему: владелец 27.11 — «скорость барахлит везде, даже в чате жду по 5 секунд». Замер на проде
  (только чтение): журнал nginx за 26.11 — `GET /conversations` p50 0,80 с, p95 1,8 с, после выката #469
  (вечер 26.11) 8–10 с на каждое открытие. `EXPLAIN ANALYZE` двух запросов списка на боевой базе:
  исполнение 0,25 + 0,46 с, JIT-компиляция поверх 3,6 + 4,1 с (Optimization ~2,1 с, Emission ~1,5 с).
  JIT включается по ОЦЕНКЕ стоимости (jit_above_cost 100 000), а оценку раздувают коррелированные
  подзапросы правил архива и «ждёт человека», хотя таблицы маленькие (3 157 переписок).
- Чем проверено (прод, только чтение, `BEGIN READ ONLY`):

  |---|---|---|---|

  | «Архив» | 8 499 мс | 656 мс | 168 мс |

  Выдача прежней и новой версии сверена на боевых данных по семи вариантам запроса (все, стр. 2, архив,
  ждут, поиск, пустая страница, канал): числа на вкладках, состав страницы, хэш последней реплики, число
  реплик группы, «ждёт с» и «непрочитано» совпали полностью. Тесты: `prisma-jit-off.test.ts` (живое
  соединение отвечает `jit = off`; без правки тот же замер даёт `on` — сторож проверен поломкой),
  `last-message-sql.test.ts` (новая дверь против прежнего CASE на восьми формах значения, включая битые),
  существующие `grouped-conversations`, `chat-list-archive-interest-avatar`, `inbox*`.
- Что осталось (нужно «да» владельца, это конфиг прода): `jit = off` ещё и в самом Postgres
  (`ALTER SYSTEM`) — для разовых скриптов и чужих подключений; `shared_buffers` 128 МБ (умолчание) при
  лимите контейнера 2 ГБ — поднять до 512 МБ. Выкатов 26.11 было 37, каждый — перезапуск API и ~7
  ответов 502 (279 за сутки) и сброс снимка кэша сайта (`queryPersist` привязан к версии сборки).
