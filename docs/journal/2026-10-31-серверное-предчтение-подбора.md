# Серверное предчтение подбора (P8, 31.10.2026)

**Что.** Живая атака Gemini 30–31.10: на «ищу двушку в Сино», «есть ли двушки», «хочу купить квартиру до 600000 сомони»,
«что есть в Шохмансуре» модель не вызывала `search_public_properties` и отвечала `propose` без ref, клиент получал вопрос или тишину.
Теперь код распознаёт явную просьбу подобрать варианты и читает каталог ДО ответа модели (как «дешевле»).

- `ai/customerAgentSearchIntent.ts` (новый, чистый): `customerSearchIntent` (ru/tg, только BW/EW/TAIL) и `customerSearchPreRead`
  (тип или район обязательны, как у самого инструмента; «двушка» без типа = квартира; бюджет только с названной валютой; «недорого» = sort cheap
  только без бюджета, иначе сработал бы режим «дешевле фокуса»).
- `lib/customerDmAgentTurn.ts`: предчтение добавляется, если нет фокуса объекта, нет `followUp`/«дешевле»; место после предлога сверяется
  `resolveSearchPlace` (не опознано — район не передаётся; за городом — не передаётся).
- `ai/customerAgentDecisionRepair.ts`: `propose` без ref и без вопроса при ровно одном результате поиска → `reply` с refs этого результата.
  Отступление от задания: `propose` с ref поиска нельзя — рендерер требует evidence вида `proposal`, поэтому ремонт делает `reply`.
- `ai/customerAgentCore.ts`: короткий путь «дешевле нет» теперь только для настоящего поиска «дешевле» (`isCheaperThanSearch`); пустой обычный поиск идёт к модели.
- `tests/attack/judge.ts`: цена «1 500 000 сомони» принималась за чужой телефон (7 цифр) — вычитается перед проверкой.

**Проверено.** Юнит `customer-agent-search-intent` (28), `customer-agent-search-preread` (4), `decision-repair`, `follow-up`; сборка api, код 0;
`attack-customer-core --model scripted --category buyer` 72/72 (4 новых сценария buyer-search-001..004).

**Осталось.** Живой прогон с Gemini не делался (ключа в копии нет). Промпт, схемы и описания инструментов не тронуты.
