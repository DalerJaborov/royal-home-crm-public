# 20.11.2026 — Одна оболочка «Нового вида»: агент на телефоне, раскладка по ширинам, меню

Пачка B плана `docs/design/oblik-2026-11-17/audit-20-11/PLAN.md` (решение владельца 20.11:
одна оболочка для всех, старая тема потом удаляется).

- Что изменилось:
  1. **Один признак нового вида.** Телефон агента держал прежний интерфейс
     (`MobileAgentHome`, `components/mobile/*`) даже тем агентам, кому сервер выдал
     «Новый вид»: запрет чистой оболочки на телефоне агента (`shellDevicePolicy.ts`)
     и список `royalLookAgentIds` были двумя независимыми рубильниками, а `/ui-shell`
     с телефона агента не спрашивался вовсе. Теперь телефон агента спрашивает сервер,
     и выданный вид (без личного отказа `?look=legacy`) снимает запрет: одна оболочка
     на всех устройствах. Без вида — как было. Личный выбор вида вынесен в
     `hooks/royalLookChoice.ts` (иначе цикл импортов), `useRoyalLook.ts` его переизлучает.
  2. **Раскладка по ширине, а не по устройству** (`theme-look-royal.css`): 320–767
     телефон; 768–1023 рейка 88 px слева с подписями (то же нижнее меню, «+» и «Ещё»);
     1024+ боковое меню с подписями (220 px, с 1440 — 248 px) — на сенсорном планшете
     тоже; 1440+ содержимое по центру, 1280 px, обзорные экраны 1600 px
     (`lib/shellLayout.ts`, атрибут `data-ry-wide`). Генерируемые темы не тронуты.
  3. **Меню**: до восьми главных пунктов (порядок — личная настройка «Порядок вкладок»,
     `preferences.navigation`), остальное в свёрнутых группах «Работа», «Команда и
     контроль», «Отчёты», «Маркетинг», «Система» (`royalSideNavigation` в
     `lib/cleanNavigationOrder.ts`). Было 33 строки подряд у директора. Права не тронуты:
     на вход идёт уже отфильтрованный реестр, каждый путь ровно один раз.
- Почему: critic-uiux.md P0-1, P0-4, P1-6, P1-7; владелец 20.11 «одна оболочка».
- Чем проверено: `npm run test:web` (419 файлов, 2838 тестов); новые сторожа —
  `src/lib/__tests__/royalSideNavigation.test.ts` (все роли: ≤ 8 главных, путь один
  раз, личный порядок), `src/oneShellMobileBaseline.test.ts` (подключения
  `components/mobile` и `home/mh` только убывают), `useCleanShellPolicy.test.ts`
  (вид на телефоне агента, отказ, аварийное выключение), e2e `tests/e2e/one-shell.spec.ts`
  (директор и агент на 320/390/768/1024/1440/1920 + сенсорный 1100: меню с подписями,
  нет горизонтальной прокрутки, содержимое не под меню, по центру на 1440+). Сторож
  проверен поломкой: снятый признак вида на телефоне агента и рейка 80 px на 1024 — красный.
  Кадры до/после — `docs/design/oblik-2026-11-17/one-shell/` (в основной папке D:\CRM).
- Что осталось:
  - Остальные экраны ещё выбирают телефонную копию по устройству (`MobileChatsList`,
    `MobileMore`, `MobileFunnel` и др.; список — в `oneShellMobileBaseline.test.ts`):
    волна 3 плана. Жесты агента из `MobileClientsList` (смахивание строк) в новом виде
    на телефоне не работают — перенести в общий список.
  - Содержимое страниц на сенсорном планшете по-прежнему телефонное (useMobileUx —
    по устройству); «список + подробности» на планшете для чатов/клиентов — отдельная
    правка экранов (их держат другие исполнители).
  - Телефон агента теперь ждёт ответа `/ui-shell` перед первым кадром (как директор).

## Дополнение после ревью #329 (20.11.2026)

- Телефон агента больше не ждёт `/ui-shell` на холодном старте: ждёт только устройство,
  которое помнит выданный вид (`rh-look-granted:<сотрудник>`, одна дверь —
  `hooks/royalLookChoice.ts`; память пишет выбор оболочки по каждому удачному ответу,
  мастер объекта её только читает). Впервые выданный вид включается со следующего запуска.
- На телефоне вид решается на сессию (до перезагрузки): выдали или сняли вид посреди
  работы — экран не перестраивается, черновики целы. Сразу действует только аварийное
  `enabled: false`. На ПК — как раньше.
- Сенсорный планшет 1024+: от нижнего меню осталась кнопка «+» (быстрые действия и голос).
- «Записать показ» у агента на телефоне в новом виде открывает быструю форму показа, как
  на ПК (у прежнего телефона вела в календарь) — намеренно: одно действие на всех устройствах.
- Широкий режим и для вложенных путей (`/reports/<срез>`); подсказка установки помечена
  `data-install-hint` (правило рейки — только для неё); раскрытые группы меню — на сотрудника.
- Сторожа: `useCleanShellPolicy.test.ts` (телефон агента без вида не ждёт; вид на сессию),
  точные списки в `oneShellMobileBaseline.test.ts`, проверка самой функции меню в
  `royalSideNavigation.test.ts`, e2e задержки и сбоя `/ui-shell` у агента на телефоне.
