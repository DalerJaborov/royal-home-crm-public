# 10.11.2026 — Мастер объекта в Telegram у Шабнам умеет всё, что мастер CRM

- Что изменилось:
  - Видео в черновик из Telegram (видео, кружок, видео файлом) — теми же сессиями
    загрузки частями, что `POST /properties/drafts/current/videos/sessions` → части →
    `complete`; тела маршрутов вынесены в `apps/api/src/lib/propertyDraftMedia.ts`,
    маршруты в `routes/properties/drafts.ts` стали тонкими. Предел — меньшее из
    предела Bot API (20 МБ у облачного Telegram) и `UPLOAD_VIDEO_MAX_BYTES`; больше —
    честное сообщение «загрузите в мастере CRM». Файл читается кусками по 8 МБ.
  - Рынок, стадия и отделка (один вопрос, как в мастере: вторичка + состояние или
    фаза новостройки), документы (пресеты + «Другое»), характеристики, «куда пойдёт
    объект» — из текста/голоса (`assistantPropertyFields.ts`, «Поле: значение» без
    ИИ, русские и таджикские подписи) и кнопками.
  - Обязательные поля — одни правила для CRM и Telegram:
    `packages/shared/src/propertyWizardRules.ts` (`propertyWizardStepErrors`,
    `propertyWizardErrors`, `propertyWizardTypeChange`, подписи характеристик,
    `PROPERTY_DOCUMENT_PRESETS`); `apps/web/.../types.ts` и `detailCopy.ts` зовут их.
    Бот больше не требует фото и точку на карте — мастер CRM их тоже не требует.
  - Дубль до создания — `lib/propertyDuplicates.ts` (тело `GET /properties/duplicate-check`):
    номер ОБ и кнопка «Всё равно создать».
  - «Добавь объект продавца ПР-000456» — `importClientIntoDraft` (тело
    `POST /properties/drafts/from-client/:clientId`) с теми же правами; вопросы
    «заменить черновик / фото» кнопками. `canAccessAssignedAgent`/`scopeToOwnAgent`
    принимают `Pick<Request, "agent">` (расширение типа параметра, поведение то же).
  - Точка на карте → район (как было) и ориентир в пустое поле —
    `suggestLandmarksForPoint` (`lib/landmarkPick.ts`), её же зовёт `GET /geo/landmarks`.
  - Карточка «Проверьте объект»: все поля мастера, текст для озвучки (`suggestedNarration`,
    как на шаге «Проверка»), список недостающего, кнопки «Создать / Исправить поле /
    Выйти»; «Исправить поле» — выбор поля кнопкой, значение кнопкой, текстом или голосом.
    Обязательное поле с вариантами (вид, состояние, валюта) спрашивается кнопками сразу.
  - Разговор по-русски или по-таджикски — по словам сотрудника; адрес и телефон продавца
    в чате не повторяются. Никаких своих напоминаний: только ответы на действия
    (решение владельца 10.11 «редко беспокоить людей»).

  чтобы работало прямо как мастер по добавлению объектов»

## «Кому подходит» всем агентам и «Предложить коллеге» (решение владельца 10.11)

- Агент сразу после создания объекта видит ВСЕХ подходящих клиентов одним сообщением:
  «⭐ Ваши» полностью, «👥 У коллег» — без имени и телефона (номер, кто ведёт, бюджет,
  комнаты, район). Руководство (clients.viewAll) — всех с именами. Процента совпадения
  нет (владелец: это не качество совпадения) — причины подбора как есть: ✅ / ⚠️, без
  причин — «❓ требования неполные». Маскировка — `lib/propertyMatchingClients.ts`
  (`matchingClientsForAssistant`), правила подбора не менялись (`routes/matching.ts`,
  добавлено только сужение выборки `MatchingScope` и признак компромисса `isMatchTradeoff`).
- **Расширение только в помощнике:** REST `GET /properties/:id/matching-clients` для агента
  по-прежнему 403 (право clients.viewAll), его ответ не изменился.
- «🤝 Предложить: Умед · ПК-…» — одно сообщение агенту-владельцу клиента в личку
  Telegram с кнопками «📤 Отправлю клиенту / 🙅 Не подходит» (без Telegram — уведомление
  в CRM через `createNotification`). Клиенту ничего не уходит, владелец клиента не
  меняется. Новая таблица `PropertyClientOffer` (миграция `20261110133630_property_client_offer`,
  только добавление), уникальна пара объект+клиент — повторное нажатие не шлёт второй раз.
  «Предложить Умеду» в дательном падеже не пишем: склонять имена надёжно нельзя.
- Повторное ревью: класс разделителей цены («750 000/750.000/750,000», «1,5 млн», «$120k»,
  «120к»; «млрд» → ИИ); «Убрать файл» по id файла, а не по номеру; точный список хостов
  карт (https, без порта и логина) на каждом шаге перенаправления; ссылка на карту вместе
  с описанием сохраняет и поля; «ll»/«@» — центр карты, «проверьте точку»; перепутанные
  координаты меняются местами, если так попадают в Таджикистан; одиночный «%» не роняет
  разбор; альбом — перевзвод таймера при упавшем фото, подпись не даёт лишней карточки;
  ролик качается в фоне (не держит ход помощника), не больше двух загрузок разом; getFile
  фото на своём Bot API — общий таймаут, буфер по размеру файла; путь от Bot API читается
  только внутри `TELEGRAM_LOCAL_FILES_DIR` (если задан); старые кнопки — «устарела» и
  свежая карточка.
- Тесты: `property-client-offers.test.ts` (6), `assistant-property-wizard-review.test.ts` (12),
  `map-point-and-matching-viewer.test.ts` (4); сторожа пп. 1–3 ломались нарочно — красные.

## Третье ревью (до выкатки)

- Подпись к видео разбирается сразу; в фон уходит только перекачка файла. Сессия загрузки
  открывается в ходе сообщения — ролик виден в карточке «⏳» и держит «Создать».
- Очередь роликов: не больше одной загрузки на сотрудника и двух на процесс; ролик в очереди —
  «⏳ в очереди» в карточке и «видео в очереди на загрузку» в списке недостающего. После
  перезапуска процесса, который обслуживает Telegram (поллер или вебхук), незаконченные
  загрузки из Telegram снимаются (`recoverInterruptedTelegramDraftUploads`) и сотрудник
  получает «загрузка прервалась, пришлите ещё раз».
- Предложение коллеге: PENDING до подтверждённой доставки (повтор при PENDING шлёт заново),
  SENT после; ответ из CRM — `POST /api/v1/property-offers/:id/answer` и кнопки
  «Отправлю клиенту / Не подходит» в ленте уведомлений (`Notifications.tsx`), та же функция,
  что кнопки в Telegram; отвечает только текущий владелец клиента. При смене владельца
  открытые предложения закрываются (`lib/ownershipSatellites.ts` →
  `lib/propertyClientOfferClose.ts`). Индекс по `clientId`. Кнопка «Открыть объект» остаётся
  после ответа. Кнопка «Предложить» подписана (HMAC на агента, объект, клиента).
- Карточка «кому подходит» собирается до 3 800 знаков, остальное — «И ещё N».
- `schema.prisma` — прежнее форматирование, добавлена только новая модель и обратные связи.
- Путь от своего Bot API — общая `isInsideTelegramFilesDir` (пустой том — отказ, как у вложений).
- Цена: «0», больше миллиарда и «1,500 млн» — не угадываем.
- Не сделано: кадры ПК и телефона для двух новых кнопок в ленте уведомлений.
