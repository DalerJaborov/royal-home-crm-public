# 2026-11-25 — блок входа по коду: сброс директором, подсказки, сторож

**Случай.** Сотрудница не могла войти: СМС доходили, она жала «ещё раз», сработал лимит 5 кодов за скользящий час (503). Снять блок можно было только на сервере.

**Сделано**
- `POST /api/v1/agents/:id/login-code/reset` (`resetStaffLoginCodeBlock`, `lib/staffAdmin.ts`): только директор (админ с `agents.reset2fa` получает 403), `agents.manage` + step-up, Zod на id. Удаляет `LoginSmsCode` сотрудника за последний час, пишет аудит `LOGIN_CODE_BLOCK_RESET`. Кнопка-ключ в строке сотрудника, Настройки → Сотрудники и права (`TeamTab`), только директору и не на директора.
- 503 по лимиту часа теперь отдаёт `retryAt` (самый ранний из пяти кодов + 1 час, ISO) и `telegramAvailable`; поле `error` прежнее. Экран входа: «Код уже запрашивали 5 раз за час. Подождите до HH:MM (по Душанбе) или попросите директора сбросить блок», подсказка «Код приходит до минуты, повторно не нажимайте», кнопка «Прислать в Telegram» крупной кнопкой.
- Сторож `lib/loginCodeWatch.ts`: 3+ отказа за 15 минут у одного сотрудника (лимит часа, «Не удалось отправить код», неверный код) → одна запись `logSystemError("api")` с `dedupKey` по сотруднику и суткам (Душанбе); директору уходит штатным пушем «Новая проблема» (onNewSystemError). Счёт в памяти, запись в фоне — вход не замедляется.

**Проверено:** `tests/login-code-unblock-25-11.test.ts` (8) + sms-login-code, login-code-push, step-up-no-push, staff-phone-login (51 зелёных); web `loginRetry.test.ts`; кадры ПК и телефон на стенде.

**Ограничения.** Лимит 5/час общий для всех каналов, поэтому Telegram при самом блоке не поможет — только после снятия или сброса. Счётчик сторожа обнуляется при перезапуске API.
