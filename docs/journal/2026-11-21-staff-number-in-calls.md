# 21.11.2026 — номер сотрудника в журнале звонков больше не «потерянный клиент»

**Что было.** Агент перезвонила в офис со своего мобильного (+992 77…, номер из её
карточки сотрудника) — скорее всего на пропущенный от станции, когда CRM соединяла
её с клиентом. Станция честно записала входящий с внешней линии, никто не снял —
и в «Звонках» строка читалась «Пропущенный · до оператора не дозвонился · в базе нет ·
никто не перезвонил» с кнопкой «Больше не звонить». Руководству уходил пуш
«звонили с номера … — в базе такого клиента нет». Карточку на сотрудника CRM и так
не заводила (createCardForUnknownCaller), отсюда «в базе нет».

**Что изменилось.**
- `routes/calls.ts`: GET /calls/incoming и /calls/feed отдают у входящего поле
  `staff` (`{ id, fullName }` действующего сотрудника по хвосту номера, один запрос
  на страницу через `loadStaffPhoneChecker`); бейдж «без перезвона» на таких строках
  не горит.
- `lib/telephony/incomingCalls.ts` `notifyMissed`: пропущенный с номера сотрудника
  (без карточки) не будит руководителей пушем.
- Web (`MobileCalls.tsx`, `Calls.tsx`, оба вида — новый и прежний): имя
  «Сотрудник · ФИО», метка «свой номер, не клиент», без «в базе нет», «никто не
  перезвонил» и «Больше не звонить». Кнопка позвонить осталась.

**Чем проверено.** Новый `apps/api/tests/calls-staff-caller.test.ts` (2 теста;
без правки сервера оба красные, с правкой зелёные) + соседние `calls-section`,
`calls-feed-cursor` — 17/17; `npm run precheck`.

**Что осталось.** Счётчик «пропущено N» в шапке журнала по-прежнему считает и
звонки сотрудников (это count по базе, номера сотрудников в нём не отфильтровать
одним where без хранения признака в строке). Если будет мешать — писать признак
`fromStaff` в IncomingCall при старте звонка.
