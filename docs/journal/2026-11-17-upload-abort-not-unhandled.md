# 17.11.2026 — обрыв загрузки «Request aborted» больше не «[unhandled]»

**Что было.** После выката #254 в журнале прода 14:47:36 UTC: `[unhandled] Error: Request aborted`
(сигнал проводника очереди). Источник — multer: он слушает `req.on("aborted")` и бросает обычный
Error «Request aborted», когда человек закрывает вкладку или теряет связь посреди одиночной
отправки (фото, файлы). Соседний текст того же обрыва («Unexpected end of form») обработчик ошибок
`app.ts` уже ловил с 17.09; этот — нет, и он уходил в общий «[unhandled]» с пушем директору.
Загрузка ЧАСТЯМИ (#253/#254) тут ни при чём: части идут через express.raw, его `request.aborted`
отвечает 400 без записи; брошенные сессии убирает крон `chunked-uploads-cleanup` (срок 2 ч),
повтор продолжает ту же сессию (докачка недостающих частей, #254).

**Что сделано.** Ветка обработчика «обрыв загрузки» ловит оба текста; запись в журнал
эксплуатационная — с дедупом по объекту и без пуша (`silent`). multer на своей ошибке сам удаляет
уже записанные временные файлы.

**Чем проверено.** `tests/upload-abort-handled.test.ts`: настоящий multipart-запрос рвётся посреди
тела → строка «Обрыв загрузки файла», `[unhandled]` нет. Без починки тест красный (проверено).
