# 17.11.2026 — Шабнам, волна 2: ложные отказы ссылок, сбои attempt_limit, таджикский голос и «удали присланное»

Источник — журнал ходов Шабнам на проде за 10–17.11 (56 обращений): 3 ложных отказа
`card_evidence`, 2 сбоя `attempt_limit`, непонятые таджикские просьбы про голос и «удали
присланное». Каждая тема чинилась как класс.

## 1. Сторож ссылок на карточки (`ai/assistant/cardLinkEvidence.ts`, `ai/assistant.ts`)

- Причина: сторож заменял ВЕСЬ ответ отказом, если в нём была хоть одна ссылка на
  `/properties/…` или `/clients/…`, которой не вернул инструмент этого хода. Под это попадали
  адреса разделов (`/properties/new`, список с фильтрами `/properties?…`), номер объекта из слов
  человека (запись `change_property_price` вернула только карточку «Подтвердить», номера в
  доказательствах нет) и ответы без инструментов.
- Что изменилось: адреса разделов и списки с фильтрами — не карточки; исполненные записи, чей
  номер карточки берётся из базы (цена, статус, заявка, вывод из монтажа, восстановление,
  новый клиент), дают доказательство; неподтверждённая ссылка превращается в обычный текст
  (подпись без ссылки, голый путь убирается) — ответ уходит, в журнал хода пишется причина
  `card_link_unverified`. Отказ остаётся, только если очистить не вышло (размер, кодировки).
  Выдуманная ссылка ссылкой человеку по-прежнему не уходит.

## 2. Сбои attempt_limit (`ai/assistant/attemptLimit.ts`, `ai/assistant.ts`, `partialAnswer.ts`)

- Причины: (а) предел попыток хода был зашит 9 при `aiAssistantMaxRounds = 30`; повторы после
  503 и запасная модель тратят тот же счётчик, поэтому ход умирал на 4–5 шаге, а приказ
  «ответь по найденному» приходил только на 30-м; (б) отказ инструмента не кэшируется и не
  считался повтором — модель кружила по одному и тому же отказу; (в) `set_staff_permissions`
  принимал только id права, на «видеть номера клиентов» модель гадала ключи и получала «Таких
  прав нет» без подсказки; (г) исчерпание попыток хода показывалось как «Лимит вызовов ИИ
  достигнут» — неправда, дневной лимит был цел; (д) длинный текст «для озвучки» без формы
  «Озвучь текст:» уходил модели, и она ходила по инструментам с адресами и ценами из текста.
- Что изменилось: предел попыток = шаги + запас (`assistantTurnAttemptCap`, 30 шагов → 45);
  последний шаг — и по шагам, и по остатку попыток; повтор отказавшего вызова считается
  повтором; после `TOOL_FAILURE_LIMIT` (3) отказов одного инструмента следующий шаг — только
  ответ; исчерпание попыток ХОДА (scope `turn`) даёт честное «что сделано / что не вышло /
  как продолжить» (`honestStopAnswer`), дневной лимит и деньги (scope `budget`) — как раньше.
  Права: `tools/permissionLookup.ts` — id, подпись из реестра прав или бытовые слова;
  неоднозначно — кандидаты модели; «менять нечего» — с причиной (`clients.viewPhone` есть
  только у директора). Длинная диктовка для озвучки в личке — подсказка без модели
  (`looksLikeNarrationDictation`), голосом — ещё и расшифровка, чтобы поправить и прислать.

## 3. Таджикский голос и «удали присланное» (`telegram/assistantChatCommands.ts`, `sentMessageLog.ts`)

- «Повтори голосом» понимается по-таджикски (со спецбуквами, без них и латиницей): «овоз
  барор», «овозатро равон кун», «бо овоз гӯ», «ки хомӯш кард» и др.; русские — прежние плюс
  «повтори голосом», «кто выключил голос».
- «Удали всё, что прислала» / «удалить кун ҳамаи равон кардагиатро»: только личка, только свои
  сообщения младше 48 часов (предел Telegram), без карточки, ответ числом. Номера своих
  сообщений раньше не хранились: теперь каждая успешная отправка в личный чат пишет номер в
  журнал в памяти (`telegram/api.ts` → `sentMessageLog.ts`), а `saveHistory` кладёт его в
  `payload.sent` состояния диалога — переживает перезапуск без миграции. Группа не тронута:
  её chat_id отрицательный, путь удаления есть только в личке.

## Что осталось

- Прогнать сборку, тесты выше и `npm run precheck`, `npm run map` / `map:check`.
- Удаление не трогает сообщения, отправленные до выката (их номеров нет).
- Подтверждённая запись уровня C (карточка «Подтвердить») доказательства номера не даёт —
  ссылка в таком ответе станет текстом; карточка подтверждения в Telegram это покрывает.
