# 15.11.2026 — Свои данные меняются сразу, удаление своего клиента и сообщение руководству

- Что изменилось:
  - Одно правило `lib/propertyAccess.ts::canApplyChangeDirectly`: у СВОЕГО объекта (ведущий, приёмщик, создатель; руководство с `properties.editForeign` — любой) цена, данные карточки (CARD_DATA) и перемонтаж применяются сразу. Заявка создаётся и тут же принимается автором тем же исполнителем, что «Принять» директора (`applyOwnChangeRequestNow`). Чужой объект, «убрать из соцсетей», «Другое» и цена объекта в резерве — заявкой, как раньше.
  - Это же правило стоит и в REST (`POST /properties/:id/change-requests` отвечает `applied: true`, окно в CRM пишет «Готово — изменено сразу»), и у Шабнам (`request_property_change` для CARD_DATA, как уже было у цены). `send_to_remake`: хозяину после публикации перемонтаж открыт (`publishedSendBackDeniedReasonAs`); снять из соцсетей — по-прежнему только маркетингу и руководству.
  - Откат «прежней ценой» теперь только у цены: применённые данные карточки его не получают.
  - Новый инструмент Шабнам `delete_client`: СВОЙ (закреплён за самим сотрудником, принят) клиент уходит в Корзину через `trashClient`; чужой — отказ простыми словами, даже руководителю; со сделкой или продавец с объектами в работе — отказ с причиной. Жёсткого удаления из чата нет.
  - О каждом удалении объекта (`delete_property`) или клиента РОП, директор и админ получают ОДНО сообщение через дверь `sendStaffNotice` (новый вид `trash` «Удаления в Корзину», отключается «не присылай мне такое»). Кнопка «Восстановить» — только у тех, у кого есть право (объект `properties.delete`, клиент `clients.delete`); нажатие зовёт те же `restorePropertyFromTrash` и новую `restoreClientFromTrash` (тело вынесено из `POST /clients/:id/restore` без изменения поведения). Без Telegram — лента и пуш CRM.
- Почему: владелец 15.11.2026: «через Шабнам и без неё можно менять любые свои данные»; «можно удалить свои объекты и клиентов через Шабнам, а потом всё идёт на модерацию РОП, директору и админу».
- Чем проверено: `ai-assistant-property-tools` (46), `property-change-requests` (24, в т.ч. новые «своё — сразу»), новый `shabnam-own-delete-notice` (14); сторож одной двери `staff-notice-one-door`, группа смежных тестов Корзины и Шабнам; сборка api.
- Что осталось: РОП по умолчанию не имеет `properties.delete` / `clients.delete` — получает сообщение без кнопки (право не менял); при желании владельца выдать РОП право «восстанавливать». Создателя карточки, передавшего объект коллеге, правило по-прежнему считает «своим» для цены (как с 03.11) и теперь для данных — стоит решить, нужен ли ему этот доступ.
