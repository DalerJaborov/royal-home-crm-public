# 12.11.2026 — #147: почему ship трижды обрывался на тесте кнопок

**Что было.** `assistant-group-callback-gate.unit.test.ts` грузит настоящий `assistantBot.ts`
в песочнице и подменяет импорты картой заглушек. Модуль, которого нет в карте, получал
пустой объект `{}`. Каждый новый обработчик кнопок (`staffNotice`, `paymentReminders`),
вызванный на пути колбэка раньше проверки связок, ронял все 13 тестов безликим
`TypeError: X is not a function` — и только в облачном прогоне ship: локально файл перед
ship не гоняли (холодный импорт `tests/setup.ts` на Windows дольше 20 с хука — нужно
`--hookTimeout=180000`).

**Что сделано.** Свод с main (схема: `StaffNotice` + `RobotCallStop`, заглушки обеих
сторон: «Не присылать такое»/оплаты и озвучка/ролики сотрудников). Незаглушенный модуль
теперь — Proxy: вызов его функции падает с текстом «нет заглушки для <модуль> (вызов
<имя>) — добавь её в dependencies». Сторож проверен поломкой: без заглушки staffNotice
тест называет модуль и функцию.

**Проверено.** Файл локально 13/13 на стенде agent_4731; precheck.

**Четвёртый обрыв (12.11, облако run 43182049632).** Тот же класс во втором тесте-песочнице
бота `assistant-voice-replay.unit.test.ts` (нет заглушки `staffNotice`, ошибка тонула в
`describeError` из `{}`), и сторож `staff-notice-one-door` не знал о прямых отправках
озвучки из #149 (`assistantNarration.ts` 13, `staffClip.ts` 11 — рабочие карточки, внесены
с причиной). Помощник `tests/helpers/unstubbedModule.ts` теперь общий для обоих тестов-песочниц.
Локально 31/31.
