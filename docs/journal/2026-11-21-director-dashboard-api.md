# 21.11.2026 — Дашборд директора: сервер (ТЗ владельца)

- Что изменилось:
  - Договор с экраном: `packages/shared/src/directorDashboard.ts` (запрос, сводка,
    список под плиткой).
  - `GET /api/v1/reports/director` — KPI с прошлым периодом той же длины, воронка
    заявок периода (когорта), причины отказа, скорость первого контакта (медиана и
    среднее), без контакта, просроченные задачи, таблица по сотрудникам, источники,
    план и факт месяца. Пресеты day/week/month/quarter/year/custom — сутки по
    Душанбе, неделя с понедельника. Фильтры agentId, source, kind. Кэш 60 с по
    параметрам и правам зрителя.
  - `GET /api/v1/reports/director/drill?key=…` — записи, из которых сложилась
    цифра (limit ≤ 100, offset). Условие каждой цифры задано в одном месте
    (`drillWhere` в `lib/directorDashboard.ts`), плитка считается `count` по нему
    же — сумма записей равна цифре построением.
  - `GET /api/v1/reports/director/export.xlsx` — настоящий .xlsx (листы KPI,
    Воронка, Агенты, Источники, Причины отказа), с фильтрами в листе KPI.
    Писатель без зависимостей: `lib/xlsxWrite.ts` (zip + XML, пара к
    `lib/xlsxRead.ts`; SheetJS не берём из-за уязвимостей).
  - `GET /api/v1/reports/director/history?clientId=` — лента «кто, когда, было →
    стало» по статусу, состоянию работы, источнику и ответственному.
  - Журнал переходов в `db.ts` теперь ловит и смену `Client.source` (только
    изменение; создание карточки строку не пишет). Так история источника пишется
    при любой записи, а не только из PATCH карточки.
  - `buildFunnelCohort` принимает фильтры, условия шагов вынесены в
    `funnelCohortStepWhere` — «Обработанные» на дашборде и «Связались» в
    «Отчётах» одно и то же число.
- Решения по смыслу (сверить с владельцем):
  - «Обработанные» = из новых заявок периода те, с кем связались (на сегодня);
    «Без контакта» = остальные. Сумма двух = новые заявки.
  - Выручка = `Deal.commissionAmount` закрытых за период сделок (в сомони), как в
    «Отчётах» и «Финансах».
  - Конверсия сотрудника — когортная: из его заявок периода сколько закрыто сделкой.
  - План один на компанию (`Settings.monthlyCommissionPlan`), месяц — месяц конца
    периода, факт — по всей компании; личных планов и отделов в CRM нет.
  - Статус клиента PATCH-ем больше не меняется (400 с 17.11), поэтому история
    статуса берётся из журнала переходов, который ловит все места записи.
