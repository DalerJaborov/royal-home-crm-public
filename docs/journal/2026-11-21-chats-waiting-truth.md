# 2026-11-21 — «Ждут» в «Чатах» стало правдивым

**Жалоба владельца (iPhone):** вкладка «Ждут 514», хотя агент с клиентами уже общался.

**Причина.** Срез `needsHuman` (routes/conversations.ts) значил только «последняя реплика — от клиента». Сюда попадали мёртвые переписки месячной давности, финальные «ок, спасибо», клиенты, которым уже позвонили. Красная плашка «ждёт человека N ч» брала тот же признак (плюс пауза бота и 24 ч).

**Что сделано.**
- Новый модуль `apps/api/src/lib/inboxWaiting.ts` — одна дверь. Диалог «ждёт», если: последняя реплика клиента моложе 48 ч (`NEEDS_HUMAN_WINDOW_HOURS`); после неё нет контакта другим путём; реплика не «закрывающая» (словарь `CLOSING_WORDS`, рус. + тадж., границы слов через `ai/wordBoundary.ts`; смайлик/стикер/пусто — тоже закрытие; «?» — всегда настоящая реплика).
- Контакт: `staffContactAfterSql` в `lib/noContact.ts` — зеркало `STAFF_CONTACT_INTERACTION_WHERE` для сырого SQL (+ `Client.lastAgentAttemptAt` позже реплики). Тест сверяет обе записи на одних строках.
- Подключено во все четыре места: список страницы, `countMatches`, `loadSegmentCounts` (число на кнопке), сгруппированный вид, красная плашка (`loadInboxAlerts`). Число и список — одна и та же функция.
- Производительность: порядок и LIMIT не тронуты (сортировка по индексу переписки, как раньше); добавлено условие по свежести и `EXISTS` по `Interaction(clientId)` (индекс есть), считается только у уже отобранных строк.

**Проверено.** `tests/inbox-waiting-truth.test.ts` (66): старое >48 ч, позвонили после, позвонили ДО, пропущенный входящий не считается контактом, сообщение агента из CRM, агент ответил в чате, «ок спасибо», «спасибо, а сколько стоит?», каждое слово словаря, JS = SQL на всех фразах, число = длина списка (плоский и сгруппированный), плашка. Соседние: inbox-segments, grouped-conversations, property-interest-chat-access, no-contact-rule — зелёные. Замер на фикстуре: по старому правилу ждали 8 из 8, теперь 4.

**Не сделано / в зоне бота (не трогали).** Флаг «ждёт человека» выставляет бот (`ai/operator/*`, `messengers/conversation.ts`, `customerDmAgentTurn.ts`, `clientWaitingAlert.ts`) — только фильтр показа у нас. Сообщения агента с личного телефона мимо CRM не видны системе (в переписку не попадают).
