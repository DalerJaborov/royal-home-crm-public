- Что изменилось:

    шаблоны со словами `{вид} {комнаты} {площадь} {этаж} {этаж_пор} {этажей} {район}` и
    необязательными `[ … ]`). Таджикские числа словами — модуль `tajikSpeechNumbers` переехал

    Шаблоны — текст владельца: живут в `Settings.propertyNarrationConfig.templates`, три
    стартовых положила миграция `20261111120000_narration_flow` (только если шаблонов ещё не было).
  - Конец мастера CRM (`NarrationChoice` на шаге «Проверка»): шаблон, правка текста, голос
    (женские/мужские). Выбор уходит полем `narration` запроса создания. Шабнам показывает
    текст тем же построителем; голос, шаблон и текст агент меняет кнопками, когда озвучка придёт.
  - `lib/narrationAutoFlow.ts` + задача `narration-auto-flow` (каждую минуту): после создания —
    версия WIZARD, генерация через ОДНУ дверь `lib/narrationGeneration.ts` (её же зовёт кнопка
    маркетинга), одно сообщение агенту (CRM-лента; Telegram — файл и кнопки «Одобрить / Править
    текст / Другой голос / Другой шаблон», `telegram/assistantNarration.ts`). Агент одобряет тем
    же маршрутом `approve` (готовое аудио; черновой текст по-прежнему подтверждает маркетинг).
    После одобрения — передача «только озвучка» монтажёру существующим `lib/narrationDelivery.ts`,
    когда объект в очереди монтажа; постоянный ключ запроса — повтор не плодит передач.
  - Правка фактов любым путём (CRM, Шабнам, импорт) → обход видит другой хэш фактов → новая
    версия; несколько правок подряд сливаются в одну (пауза `debounceMinutes`, по умолчанию 3).
    Цены в озвучке нет — смена цены озвучку не трогает. Перемонтаж не запускается никогда:
    если ролик уже смонтирован, агенту одна строка «нажмите «Вернуть монтажёру»».
  - Риски: дневной потолок символов и озвучек (под общим замком, считается и неудачная попытка),
    захват версии под замком объекта (двойной генерации нет), 429 — тихий повтор до трёх раз,
    прочие отказы — `logSystemError` один раз на версию, агенту ничего. Напоминаний нет.
  - Настройки озвучки (ПК и телефон, один экран): рубильник «Автоозвучка», потолки, пауза,
    шаблоны, пол голоса. PUT настроек сливает поля — старый экран не стирает шаблоны.
  - Модель: таджикский есть только у `eleven_v4` и `eleven_v4_turbo` (ФАКТ, документация и API

    другой моделью не сохраняется (`narrationModelError`), а автоозвучка его не отправит.
  - `scripts/elevenlabs/narration-model-bench.mjs` — замер моделей (по умолчанию v4 и v4 Turbo);
    без `--yes` ничего не платит. Сам замер голосов сделал координатор, скрипт не запускался платно.
- Почему: схема владельца 10.11.2026 (HANDOFF_2026-11-10-narration-elevenlabs.md).

## Дополнение 11.11.2026 — цену говорим, звук в вышедшем ролике, кончились кредиты

- Решение владельца: «Да, говорить цену». Слово шаблона `{цена}`: по-таджикски словами
  (`ҳаштоду панҷ ҳазор доллар`, `сомонӣ`), по-русски цифрами со склонением (`2 доллара`,
  `сомони`), без цены — «бо мувофиқа» / «договорная» (таджикскую форму проверить носителем).
  Цена теперь входит в факты озвучки: смена цены → новая версия (пауза 3 мин сливает правки) →
  агенту на одобрение. Запрет цены в тексте снят. Миграция `20261111150000_narration_price`
  дописывает `{цена}` в стартовые шаблоны ТОЛЬКО если их текст не правили (проверено на базе:
  правленый и свой шаблон владельца остались как были).
  Побочный эффект: у уже сохранённых версий старый хэш фактов — они станут «устаревшими» (сейчас
  это только PREVIEW-данные).
- «Заменить только звук»: после одобрения новой озвучки, если ролик уже вышел, а прошлая версия
  реально ушла монтажёру (SENT), объект возвращается монтажёру существующим `sendBackToMontajer`
  с новой причиной `NARRATION_CHANGED` («заменить только звук, монтаж прежний», не брак монтажёра)
  и `removeFromSocial: "on-new-video"` — старые посты снимет публикация нового ролика (тот же путь,
  что у перемонтажа по цене). Только самая новая одобренная версия, только при LIVE, не когда
  объект уже у монтажёра. Одобрение агента = согласие (решение владельца), поэтому зовётся сам
  возврат, а не обёртка кнопки «после публикации — руководству».
- Кончились кредиты ElevenLabs (`quota_exceeded`): код `PROVIDER_QUOTA_EXCEEDED`, денег не
  списано. Автоозвучка не теряет версию: она снова ждёт (раз в час одна проверка), одна запись
  `logSystemError`, агенту ничего; в Настройках озвучки — «Кредиты ElevenLabs закончились».
  Кнопка маркетинга отвечает 402 понятным текстом.
- Проверено: vitest narration-* (68 + 2 новых), 26 файлов перемонтажа/проверки ролика/мастера на
  локальной базе (347 тестов), web 122 файла (729), tsc api/web, мутация «нет ролика» краснеет.

## Дополнение 11.11.2026 (вечер) — звук и описание меняет CRM сама, голос выбирают на слух

- Решение владельца дословно: «где просто меняется звук и описание нам монтажер ненужен и надо
  сделать чтобы автоматически это сработало и все».
- Новый порядок для монтажёра: озвучка уходит ему только для длины и темпа, подпись к файлу —
  «Пришлите ролик БЕЗ голоса (музыка и звуки можно), голос CRM наложит сама». План передачи
  несёт `mixByCrm: true` (это и есть признак «монтажёру сказали»).
- Приём ролика (`finishReceivingVideo`): если по объекту ушла такая передача и рубильник
  «Озвучку накладывает CRM» (`propertyNarrationConfig.mixByCrm`, по умолчанию включён) не
  выключен, файл сохраняется мастером в закрытое хранилище (`Property.videoMasterStorageKey`,
  миграция `20261111180000_narration_master_samples`, только добавления), а в сети уходит ролик,
  сведённый CRM (`lib/narrationMix.ts` — одно место сведения: голос поверх с 0,3 с, музыка под
  голосом приглушается sidechaincompress, картинка `-c:v copy`, при отказе один повтор с x264).
  Ролик без звуковой дорожки в этом случае принимается (голос её даст). Озвучка длиннее ролика —
  ролик не принят с понятной причиной; ffmpeg упал — не принят, строка в журнал.
  Ролик с голосом монтажёра (без указания) — по-старому и гасит прежний мастер.
- Смена цены/фактов: новая версия → если шаблон, голос и модель те же, что у последней
  одобренной, и тот текст не правили руками — одобряется сама на имя того же агента, без
  сообщения (`autoApproveSameChoice`); иначе — агенту, как раньше. Дальше `remixFromMaster`
  (в обходе `narration-auto-flow`): перемикс из мастера, новый файл, `VideoRemakeRequest`
  NARRATION_CHANGED с `replaceOldPostsOnPublish` — старые посты снимет задание публикации нового
  ролика (тот же механизм, что у перемонтажа по цене), подпись строится заново. Монтажёру ничего.
  Идемпотентно: наложенная версия пишется вместе с файлом под замком объекта; повтор тика пуст.
  Отказ — `videoMasterMixError` на версию + `logSystemError`, вышедший ролик прежний, без повтора
  каждую минуту. Без мастера (старые объекты) — прежний возврат NARRATION_CHANGED, но с текстом
  «пришлите тот же ролик без голоса» — следующая смена цены пройдёт уже без монтажёра.
  Возврат по другой причине при мастере добавляет монтажёру строку «пришлите без голоса».
- Образцы голосов: фраза — константа `NARRATION_VOICE_SAMPLE_TEXT` (tg/ru, текст владельца),
  таблица `NarrationVoiceSample` (уникально голос + модель + хэш фразы), генерация — та же платная
  дверь `lib/narrationGeneration.ts`, общий дневной потолок (образцы считаются в нём), кнопка

  `components/VoiceSamplePicker.tsx` в мастере и в карточке (один адаптивный блок); в Шабнам
  «Другой голос» сначала присылает готовые образцы файлами.
- Найдено попутно (класс): уборка диска не знала файлов озвучки в закрытом хранилище и при
  `DISK_CLEANUP_DRY_RUN=0` стёрла бы их как «исходник без записи»; добавлены озвучки, образцы и
  мастера, тест. Тест «кредиты кончились» падал после 13:00 по Душанбе: начало генерации писалось
  реальным временем, а пауза считалась по переданному — теперь одно «сейчас».
- Проверено: vitest `narration-crm-mix` (6, настоящие база и ffmpeg), `narration-voice-samples`
