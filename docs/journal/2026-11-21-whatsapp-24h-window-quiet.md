# 2026-11-21 — WhatsApp: окно 24 часа проверяется до отправки, отказ не шумит в журнале

**Запрос владельца:** «сделай так, чтобы не было этих строк у нас» (записи «WhatsApp не доставил наш ответ ... Re-engagement message»).

**Причина (замер прода, 7 дней, только чтение):** 4 записи с 131047 из 9 «не доставил наш ответ»; все — свободный текст сотрудника из CRM клиенту, не писавшему больше суток (например, 9 дней). WhatsApp принимает такое сообщение с 200 и сообщает отказ позже статусом `failed` из вебхука (routes/webhooks.ts), поэтому проверка по ответу отправки (isMessagingWindowClosedError) его не видела. Правило проверено по документации Meta (Cloud API, Error codes): 131047 — прошло более 24 часов; 131026 (номер не в WhatsApp), 131049, 131051 — другие причины, остаются как есть.

**Что изменено:**
- `lib/conversationDelivery.ts`: `windowClosedBeforeSend` до отправки текста, голосового и медиа (WhatsApp/Instagram/Facebook): время последней реплики клиента из переписки; вне окна — `window_closed` (409) без отправки. Нет отметки времени — не блокируем.
- Сотруднику: «Прошло больше 24 часов, напишите клиенту шаблоном «Написать в WhatsApp».» (Instagram/Messenger — прежний текст).
- Автоматике: тот же `window_closed`, строка в консоль, без записи в Журнал ошибок.
- `routes/webhooks.ts`: `failed` с кодом 131047 — консоль, не `logSystemError`; сообщение остаётся помеченным «не доставлено» в переписке.

**Проверено:** tests/whatsapp-24h-window-quiet.test.ts (7), соседние тесты доставки/окна/задач, сборка api.
**Осталось:** диалоги, начатые из CRM без единой реплики клиента, проверкой не отсекаются (нет отметки) — их отказ Meta теперь тихий.
