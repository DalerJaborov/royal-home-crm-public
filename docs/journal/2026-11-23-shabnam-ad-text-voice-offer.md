# 23.11.2026: Шабнам: рекламный текст из фактов, голос как текст озвучки, кнопка «Озвучить этот текст»

Продолжение #394 (владелец: «делай всё это» про три оставшихся пункта).

## Что сделано

1. **Рекламный текст из сырых фактов без объекта в CRM.** «Сделай рекламный текст и озвучь: <факты>» (или факты следующим сообщением).
   Модель (Gemini через кошелёк расходов хода `createAssistantMoneyWallet`, новых ключей нет) пишет сценарий строго из фактов
   (`ai/assistant/adScript.ts`). Сторож в коде, а не только в промпте: каждое число сценария обязано быть в фактах, ссылки и
   адреса тоже, нет «—», слова «брон», Direct, долларов и других валют, длина в пределах потолка озвучки. Не прошло: одна
   повторная попытка с названной причиной, иначе честный отказ. Таджикский пишет сильная модель (как у разбора таджикской речи).
   Показ: текст + кнопки «Озвучить / Править / Переписать / Отмена»; «Озвучить» ведёт в обычный выбор голоса. Переписать
   не больше пяти раз на черновик. Рубильник `freeNarrationAdText` (по умолчанию ВКЛ), в Настройках → Озвучка.
2. **Текст для озвучки голосом.** Голос в ожидании текста (и длинная голосовая диктовка «озвучь, …») расшифровывается и
   показывается текстом с кнопками «Озвучить как есть / Исправить (пришлю текстом) / Отмена». ElevenLabs до подтверждения
   не вызывается. Исправленный текст приходит набранным. Если расшифровка не вышла, ожидание не теряется.
3. **Кнопка «🎙 Озвучить этот текст» под длинным сообщением без «озвучь».** Решение: показывать ПОСЛЕ ответа помощницы
   отдельным сообщением (не вместо ответа, не пересылая текст), только если набрано (не голос, не пересланное, не файл,
   не контакт), от 30 слов, без «?», не начинается с команды помощнице («найди», «покажи», «внеси», «почему»…), текст
   дошёл до модели (то есть не взят расходами, мастером объекта, клиентом и т.п.), не чаще раза в пять минут на чат,
   текст не длиннее потолка. Кнопка держит черновик в базе, текст по сети не гоняется. Рубильник `freeNarrationOfferButton` (ВКЛ).

## Как устроено

- Без миграции: строки `FreeNarration` получили статусы `DRAFT` (черновик; вид в `errorCode`: VOICE|AD|OFFER, число
  «Переписать» в `chars`) и `AD_FACTS` (факты для «Переписать», `requestKey = adfacts:<id>`). Ожидание фактов: строка
  `AWAITING_TEXT` с `errorCode = "AD"`. Уборка `purgeFreeNarrations` сносит брошенные черновики старше суток.
- Кнопки `fnr:o|e|r:<id>`. «Переписать» идёт в фоне (общая очередь бота не держится).
- Порядок в `assistantBot.ts`: ожидание текста (с голосом) → … → рекламный текст → разбор диктовки → «озвучь» без текста.
- Правило «озвучка читает слово в слово» не тронуто: к выбору голоса текст приходит подтверждённым.

## Живой пример владельца (14:13) и язык ответа

«Надо приготовить текст для озвучки и озвучить вот это» + таджикские факты раньше попадал в подсказку «Матнро овоз кун:».
Теперь различаем по просьбе: «приготовь/подготовь/составь/напиши текст для озвучки» (и таджикское «матнро барои овозонӣ тайёр кунед») + факты
= «реклама из фактов»; «озвучь вот это» + длинный текст = дословно: просьба снимается, принятый текст показан (черновик TEXT) с кнопками,
деньги до выбора голоса не тратятся. Язык ответов Шабнам берётся по ПЕРВОЙ строке просьбы (до двоеточия), а не по языку фактов.
