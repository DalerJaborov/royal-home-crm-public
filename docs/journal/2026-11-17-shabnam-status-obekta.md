# 17.11.2026 — Шабнам: статус объекта меняется по-настоящему, «принято» больше не врёт

- Что изменилось:
  - Смена статуса объекта — одна дверь `apps/api/src/lib/propertyStatusChange.ts`:
    проверки (сделка, таблица переходов, шаг маркетинга, готовность к продаже, закрытая
    сделка), причина снятия в той же транзакции и все последствия (журнал, пуши конвейера,
    автоподбор, карточка продавца, монтаж, фото-посты, сайт). `PATCH /properties/:id`
    зовёт её же — порядок проверок и тексты прежние, поведение экрана не менялось.
  - `change_property_status`: свой объект (или руководитель с правкой чужих) — статус
    меняется СРАЗУ после «Подтвердить», с теми же проверками, что карточка; «Снять с
    продажи» спрашивает причину (как экран). Шаг маркетинга без права на него (вернуть
    снятый объект в продажу) — заявка «Другое» с машинной частью `statusChange`; «Принять»
    исполняет её той же дверью правами принявшего. Не может принявший — заявка FAILED с
    причиной, а не «одобрено». REST-схема заявки эту часть отбрасывает — вручную не подделать.
    Права — как у PATCH (`canManagePropertyAs`), галочка «запрос изменений» нужна только
    для заявки. Выход из монтажа в продажу помощник не делает — это «Готово» у монтажёра.
  - «Применено» при FAILED: `honestAppliedOutcome` в `changeRequestTool.ts` — ничего не
    записалось → отказ с причиной; записалось, а хвост упал → «изменено, но не всё»
    (статус PARTIAL, Telegram показывает строку ⚠️). REST-путь «своё — сразу» уже был
    честным (`applied: request.status === "APPROVED"`), остальные вызовы проверены.
  - Свою карточку ДО публикации помощник правит сразу (цена, данные) тем же исполнителем,
    что «Принять»; модератору/монтажёру уходит «было → стало», как после PATCH. REST
    по-прежнему отказывает «до публикации правьте сами».
  - «Другое» при «Принять»: итог «Принято к сведению: CRM сама это не меняет — руководитель
    делает это руками», пуш автору «Заявка принята — делается руками».
- Почему: живой случай 17.11 — «верни объект в продажу» через Шабнам давал «одобрено»,
  а объект стоял снятым (заявка «Другое» исполнялась как «к сведению»). Класс «ответила —
  не сделала», разведка `docs/design/shabnam-brain-2026-11-17/recon-tools.md`, Т1–Т3, §2 п.3.
- Чем проверено: только чтением кода. Сборка и тесты НЕ запускались (на ПК не было памяти
  и `node_modules` в копии). Прогнать: `npm run build:api`, затем
  `cd apps/api && npx vitest run tests/ai-assistant-property-tools.test.ts tests/property-change-requests.test.ts tests/ai-assistant-tool-registry.test.ts tests/assistant-human-tool-instructions.unit.test.ts tests/property-moderate-permission.test.ts tests/property-goes-on-sale.test.ts tests/property-history.test.ts`
  и все тесты, задетые `routes/properties/crud.ts` (`node scripts/impact-tests.mjs --for=apps/api/src/routes/properties/crud.ts`).
- Что осталось:
  - Карточка подтверждения в CRM (веб) показывает «Сделано» и для PARTIAL — причина видна
    только в Telegram и в заявке объекта.
  - В общей группе Telegram смена статуса теперь пишет сразу (раньше — заявка); подтвердить
    может только автор, но список инструментов группы ждёт решения владельца (разведка §4).
  - MANAGER/MARKETING/EDITOR без `properties.requestChange` для цены и данных (разведка §2 п.2)
    не трогались.
