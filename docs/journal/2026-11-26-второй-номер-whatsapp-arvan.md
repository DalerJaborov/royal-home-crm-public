# 26.11.2026 — Второй номер WhatsApp (Arvan, +992 87 791 4444): код готов к подключению

- **Что изменилось.**
  1. `lib/customerMetaTransport.ts` — оба номера одного аккаунта WhatsApp Business отвечают ОДНИМ ключом системного
     пользователя. Раньше, как только появлялась строка второго номера с тем же ключом, любая отправка WhatsApp без
     сохранённого транспорта падала `account_mismatch` — на ОСНОВНОМ номере тоже (напоминания, повторы, служебные
     сообщения). Теперь номер выбирается по единственной переписке этого человека; нет переписки или она на чужом
     номере — отказ, как раньше, без догадки.
  2. `lib/customerAgentEnrollment.ts` + `lib/customerRoutingHold.ts` + `lib/customerHeldMessage.ts` — человек, у которого
     уже есть переписка с одним нашим номером, пишет на другой. В WhatsApp собеседник — это номер телефона, а ключ
     `BotConversation(channel, subscriberId)` пока общий на канал (Gate A), поэтому второй переписки завести нельзя.
     Раньше это была «защита от столкновения»: ответ Meta 503, Meta повторяет и в итоге теряет сообщение — и так в ОБЕ
     стороны, в том числе для основного номера. Теперь причина `whatsapp_peer_on_other_number` (только WhatsApp):
     Meta получает 200, текст ложится в ЕДИНСТВЕННУЮ переписку человека, ответственному — уведомление «Ответьте
     вручную». Бот сам такому человеку не отвечает (чтобы не ответить с чужого номера). Instagram/Facebook — без
     изменений (там 503 остаётся).
  3. `messengers/accounts.ts` — первая строка канала больше не становится «по умолчанию» сама, если WhatsApp/Facebook
     уже отвечает через Настройки. Иначе строка Arvan забрала бы ответы всем старым перепискам Royal Home
     (1262 переписки WhatsApp с `accountId = null`). Вход через Facebook и так передавал `false`; ручное добавление в
     Настройках → Каналы — нет.
- **Почему.** Владелец: второй номер «должен отвечать полностью такой же, как наш основной, просто имя другое… Одна
  CRM-ка на все. Один бот, один мозг». Приём тот же, что у Instagram/Facebook Arvan: строка `MessengerAccount`
  (канал WHATSAPP, `externalId` = phone_number_id, `brandName` = «Арван»), а не второй механизм.
- **Чем проверено.** `tests/whatsapp-shared-token-send.test.ts` (4), `tests/whatsapp-second-number.test.ts` (3, на
  настоящей базе), `customer-routing-hold-disposition` и соседние тесты аккаунтов/удержания/ядра. Проверка «ломаем
  нарочно»: без правки 1–2 три теста красные.
- **Что НЕ сделано и почему (важно).**
  - Строка аккаунта на проде НЕ заведена — это запись в прод-данные, нужно «да» владельца. Путь без кода: Настройки →
    Каналы → «Войти через Facebook» → номер +992 87 791 4444 (`metaWhatsappConnect.ts`), затем у этой строки
    «Как бот называет компанию» = «Арван». После первого сообщения появится область номера; чтобы отвечало ядро
    («один мозг»), отметить её в Настройки → «Новый бот» → области (`CustomerAgentRolloutSection`). До этого первые
    сообщения ответит прежний бот, тоже с именем «Арван».
  - Пока строки нет, сообщения на второй номер получают 503 (`routing_target_not_verified`) — Meta повторяет доставку
    и затем бросает. Подключать номер стоит скорее.
  - Настоящее решение для «одного человека на двух номерах» — переход на ключ переписки по области (contract-cutover:
    снять общий уникальный ключ `(channel, subscriberId)`; ~190 мест чтения переписок). Это отдельная большая правка с
    ревью архитектора; до неё такие люди отвечаются вручную, сообщения не теряются.
  - Звонки на второй номер: шлюз `ops/whatsapp-gateway` принимает INVITE только на `+WA_BUSINESS_NUMBER` (основной),
    остальное — «вызов на чужой номер — отбой», и пароль Meta проверяется одним `[meta-inbound]` с именем основного
    номера. План правки шлюза — в памяти `handoff-arvan-second-wa-number-26-11.md`; включать звонки у Meta раньше
    правки шлюза нельзя: у клиентов появится кнопка звонка, а шлюз будет сбрасывать каждый вызов.
