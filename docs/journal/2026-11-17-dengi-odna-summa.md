# 17.11.2026 — Деньги: одна сумма на всех экранах

Основа — аудит `D:/TASKS-2026-11-14/reports/audit-2026-11-17/data-money.md` (прод только чтение). Владелец 17.11 через
диспетчера: «закрой все вопросы, чтобы всё было на сервере, всё сработало». Ветка поверх PR #228 (подписки и учредители).

- **Отчёт за месяц — деньги живые** (D1). Отчёт хранит снимок с 1-го числа, а расходы октября внесли 11.11: в отчёте
  8 786,32 с., в «Финансах», PDF и у Шабнам 16 608,32 с. Теперь комиссия, расходы и прибыль отчёта считаются при открытии
  той же функцией, что «Финансы» (`liveMonthlyMoney` → `buildExpenseSummary`), снимок отдаётся справкой `*AtClose`, на экране
  строка «расходы изменились после закрытия месяца: было …». Пуш 1-го числа по-прежнему берёт снимок (это и есть момент
  закрытия). Месяц вне 1900–2199 показывает снимок.
- **Период видит месячные строки** (`lib/expenseAccounting.ts`). Список «с 01.10 по 31.10» и инструмент Шабнам `list_expenses`
  брали только строки с днём оплаты (7 822 с.). Строка без дня (реклама, ИИ, доля по сделкам) теперь входит, если период
  накрывает её месяц целиком; часть месяца её не берёт.
- **«Пульс» за день и неделю — по дням**: реклама из `AdSpendDaily`, ИИ из журнала обращений с правилом «счёт поставщика
  сильнее оценки». Раньше весь месяц рекламы ложился на день заведения строки. Месяц и год — по строкам месяца, как «Финансы».
  Остаток округляется до копейки.
- **Оценка ИИ — месяц по Душанбе** (`dushanbeMonthRange`): последние 5 часов месяца уходили в следующий и терялись.
- **Ручная правка автостроки** (реклама, ИИ) не перезаписывается (сделано в #228); расхождение с источником — запись в
  журнал ошибок раз в неделю.
- **Суммы автострок пишутся ровно двумя знаками** строкой (в базе были 76.65000000000001, 10.620204). Сами старые строки
  не трогаются; смена типа колонок (`numeric(14,2)`) не делается — она округлила бы строки на проде.
- **Курс закрытого месяца**: 9–11 числа долларовым строкам рекламы и ИИ ПРОШЛОГО месяца без курса ставится курс Настроек
  (`freezeClosedAutoExpenseRates`, крон финансов 01:20). Первый такой месяц — ноябрь 2026 (закрепится 9.12). Выкат ничего
  не меняет в октябре и раньше.

## Дозаполнение курса старых строк — НЕ применено, ждёт сигнала

На проде 17 долларовых строк без курса (`exchangeRate IS NULL`): реклама Meta по месяцам и оценка ИИ, по октябрь включительно.
Курса тех дат в базе нет, поэтому любое дозаполнение — решение, а не исправление. Вариант (одна транзакция, только эти строки):

```sql
BEGIN;
-- сколько строк и на какую сумму — посмотреть ДО:
SELECT "autoKey", amount, currency FROM "Expense"
 WHERE currency = 'USD' AND "exchangeRate" IS NULL AND "deletedAt" IS NULL
   AND ("autoKey" LIKE 'ads:%' OR "autoKey" LIKE 'ai:%') AND month < '2026-11-01';
UPDATE "Expense" SET "exchangeRate" = (SELECT "usdToTjsRate" FROM "Settings" WHERE id = 'singleton'), "rateCapturedAt" = now()
 WHERE currency = 'USD' AND "exchangeRate" IS NULL AND "deletedAt" IS NULL
   AND ("autoKey" LIKE 'ads:%' OR "autoKey" LIKE 'ai:%') AND month < '2026-11-01';
COMMIT;
```

Что поменяет: суммы этих месяцев в сомони перестанут меняться вслед за курсом и останутся по курсу дня применения (сейчас
9,24). Снимки отчётов за прошлые месяцы не меняются (они справка). Применять — только по сигналу диспетчера/владельца,
с копией таблицы до применения.

Проверено: `money-one-sum` (Финансы = список за период = отчёт; Пульс неделя = дневной расход; ИИ 23:30 последнего дня;
ручная правка; два знака), monthly-report*, expense-workspace, overlap, пачка Шабнам, ad-spend, subscriptions — зелёные.
