# 2026-11-23. Шабнам: сотрудники из Telegram директора без кода Google Authenticator

## Решение владельца (дословно)
«сделай так, чтобы шабнам добавляла и удаляла сотрудников из Телеграма директора без всяких разрешений, а то эти Google аутентификаторы и так далее, мне это не нужно».

## Что сделано
- Рубильник компании «Код Google Authenticator для действий с сотрудниками в Telegram» (`Settings.assistantStaffTotpEnabled`, миграция `20261123110000_assistant_staff_totp_switch`). По решению владельца по умолчанию ВЫКЛ. Подписи — `packages/shared/src/assistantStaffTotpSwitch.ts`, экран — Настройки → Система → Безопасность (`SystemTab.tsx`, блок «Сотрудники через Шабнам»; видит и переключает только директор, сервер остальным отвечает 403). Помощнице через `set_switch` этот рубильник не отдаётся (`FORBIDDEN_SWITCH_PATTERNS`: totp/stepUp/2fa).
- Одна дверь `apps/api/src/lib/assistantStaffStepUpWaiver.ts`. Её спрашивают брокер (`assertStepUp`, `assertStepUpPossible` в `lib/assistantActions.ts`) и кнопка карточки (`bundleNeedsStepUp` в `telegram/assistantStepUp.ts`), так что надпись на кнопке и исполнение не расходятся.
- Пока рубильник выключен, код не нужен только если сходится всё:
  - **кто:** активный ДИРЕКТОР, ЛИЧКА с Шабнам, и это его привязанный кодом `telegramChatId` (id чата берётся из апдейта Telegram, не из текста). Админ — с кодом, как раньше: решение «директора» понято узко, админ этот рубильник тоже не переключает;
  - **что:** `create_staff` (кроме роли «Директор»), `update_staff` только с `isActive` и/или `role` (отключить, включить обратно, сменить роль; не на директора), `set_staff_permissions`. Учётку директора (понизить, отключить, права) — только с кодом или в CRM.
- Одно нажатие «Подтвердить» на карточке осталось: ошибка модели людей молча не создаёт.
- Остаётся: сообщение руководству о смене состава (`notifyStaffChangeLater` из `lib/staffAdmin.ts`) и запись в журнал. Журнал брокера помечает такое исполнение `stepUpWaived: true`.
- С кодом, как раньше: удаление навсегда (`delete_staff`), заморозка, передача дел, сброс 2FA, смена телефона и другие поля карточки, рубильники Настроек. Отказ `TOTP_REQUIRED` директору с выключенным рубильником подсказывает модели, что можно сделать без кода («отключить учётку»).
- Включение отключённого сотрудника (в карточке, через Шабнам с кодом и без, возврат передачи дел) теперь тоже шлёт руководству сообщение «♻️ Учётка включена снова» — иначе уволенного можно было вернуть тихо (ревью 23.11).
- Рубильник ВКЛ — всё как до 23.11.
- Тексты для модели (промпт `ai/assistant.ts`, канал лички в `promptSections.ts`, описание инструментов сотрудников) больше не обещают код всегда: «если нужен — спросит карточка».
- CRM (веб-вход, окно подтверждения личности для сотрудников, деньги, Настройки) не менялся.

## Проверено
- `tests/assistant-staff-rights.test.ts` — 44 зелёных (34 прежних при ВКЛ + 10 новых при ВЫКЛ: добавить, отключить, права без кода; админ, агент, группа, чужой чат, директорские учётки, удаление и заморозка — нет; ВКЛ — как раньше; переключает только директор).
- Сторож проверен поломкой: отключённая дверь — 6 красных; «без кода любой, кроме агента, в любом чате» — 2 красных; «без кода всё подряд» — красный тест «за рамками».

## Риски
- Украденный или оставленный открытым телефон директора с открытым Telegram: одно нажатие создаёт сотрудника с чужим номером (не директора) и отдаёт ему вход в CRM по СМС. Защита — уведомление руководству и журнал; полная защита — включить рубильник.
- После отключения сотрудника его клиенты остаются за ним; передать дела из Telegram без кода нельзя (только в CRM или с кодом).

## Не сделано
- Кадры экрана Настроек (ПК и телефон) не снимались в этой пачке.
- Нормализация номера при создании сотрудника — в параллельной ветке `fix/staff-phone-login-23-11`, здесь не тронута.
