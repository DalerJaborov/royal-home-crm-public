# 26.11.2026 — Суточный денежный потолок бота клиентов (CRM-47)

## Было (ФАКТ, код main 6f143f36a)

- Ядро свободной модели пишет траты в `AiProviderDailyBudget` с политикой `royal-customer-gemini`, но суточный предел
  там `null` и закреплён в неизменяемой версии бота (`ai/customerAgentProviderConfig.ts`, хеш политики в версии).
- Оператор заявок (`lead-only-intent`, `lead-only-operator-compose`), комментарии и старый бот зовут модель через общую
  дверь `ai/client.ts::callAiText` вовсе без учёта суток. Есть только счётчики ходов на собеседника (`aiDailyBudget.ts`).
- Петля (07.09: ~19 000 вызовов по одной переписке; 30.10: месячный лимит Google за ночь) останавливалась только лимитом
  проекта Google, а он кладёт всю CRM: звонки, Шабнам, расшифровки.

## Что изменилось

- `lib/customerBotSpendCap.ts` — одна дверь. Сумма за сутки по Душанбе = ядро (`AiProviderDailyBudget`, списано + резерв,
  ключ суток ядра `providerDayKey`) + вызовы точек бота клиентов через `callAiText` (`AiLog.costUsd`, без строк ядра,
  чтобы не считать дважды). Точки — `CUSTOMER_BOT_AI_ENDPOINTS` (оператор, показы, старый бот, комментарии, проверка
  ценности ответа). Ответ кешируется на минуту. Сбой чтения — потолка нет (учёт не делает бота немым).
- `callAiText`: при достигнутом потолке точка бота клиентов не зовёт модель, возвращает «нет ответа». Оператор заявок при
  этом отвечает правилами (`understandFallback`) и готовыми фразами (шаблон вместо «своими словами»): клиент не без ответа.
- Тревога руководству (право «Менять настройки CRM») — одна на сутки на все процессы: отметка в `ProcessedMessage`,
  строка `[alarm]` в журнале ошибок и пуш.
- Настройки: рубильник `botDailySpendCapEnabled` («Автоматика ИИ» → «Бот клиентов», ВКЛ) и сумма `botDailySpendCapUsd`
  (поле «Потолок трат бота» под рубильником, умолчание 5 $, 0 — без потолка, верх 200 $). Миграция
  `20261126130000_bot_daily_spend_cap` — только две новые колонки. Изменение суммы пишется в журнал действий.

## Чем проверено

- `apps/api/tests/customer-bot-spend-cap.test.ts` (7): умолчание колонок, ниже потолка зовёт модель, выше — не зовёт и
  одна тревога, сумма ядра + оператора без двойного счёта, чужие точки не трогаются, рубильник, 0. Без проводки в
  `callAiText` красный (проверено).

## Что осталось / решение владельца

- **Сумма потолка — решение владельца.** 5 $ в сутки выбрано как безопасное: обычный день бота заметно меньше (ОЦЕНКА по
  памяти: норма всей CRM 1–3 $ в день), а петлю останавливает в тот же день.
- Ядро свободной модели (комментарии через ядро, каналы вне режима «только заявки») этой дверью НЕ останавливается — только
  учитывается в сумме: его предел закреплён в версии бота, менять его можно новой версией с подтверждением качества.
  Следующий шаг: в `customerDmAgentTurn`/`customerPublicAgentTurn` при достигнутом потолке идти страховочной строкой без
  модели.
- Старый бот (`lead-qualify`) на «нет ответа» ставит фоновый повтор: при потолке он крутится вхолостую (без трат) до
  сдачи. Живые каналы WhatsApp/Instagram/Facebook идут через оператора, не через старый бот.
- Кадры поля «Потолок трат бота» (ПК и телефон) не сняты: стенд без Docker не поднимается.
