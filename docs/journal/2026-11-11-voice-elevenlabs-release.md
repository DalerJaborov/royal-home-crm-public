## Конфликты, разведённые руками

1. `liveVoiceConsultant.ts` — #150 и #152 независимо завели `consultantToolsFor`:
   у #150 параметр-объект `{ transferAvailable, showingsEnabled }` (функций показа нет,
   когда показ назначает человек), у #152 — один флаг. Оставлена версия #150; прогрев
   (`liveVoiceWarmup.ts`) готовит теперь все четыре набора консультанта (перевод × показы),
   иначе звонок с выключенными показами шёл бы без прогрева и ждал подготовку в тишине.
2. `elevenLabsAgentSync.ts` — #151 добавил словарь произношения в настройку агента и в ключ
   памяти подготовки, #153 — сверку tool_ids после PATCH и ключ по содержимому функций.
   Нужны оба: словарь передаётся в `buildAgentTuningPatch`, итог идёт через `outcome` и
   сверку; ключ памяти = содержимое функций + голос + настройки + политика + правила
   произношения + слова распознавания.
3. `docs/product-*` — пересобраны `npm run map`.

## Стыки, которых не было ни в одной ветке (указания сессии волны 1)

- **П1+П3:** мгновенная проверка «поставщик на паузе / у ElevenLabs нет минут»
  (`liveVoiceProviderHoldNow`, без базы и сети) стоит ПЕРЕД дверью П3 в
  `originateLiveVoiceCallToClient` и `originateLiveVoiceScenarioCall`: пауза поставщика —
  перенос звонка, а не отказ «звонить ли этому человеку».
- **П1+П2:** мост передаёт поставщику `direction` («inbound» для входящего консультанта и
  тестового номера) — у входящего ElevenLabs не отказывает из-за неполного набора функций;
  `resetLiveVoiceProviderHolds` снимает и паузу подмены функций
  (`clearElevenLabsToolOverridePause`); после 1008 подготовка забывается и прогрев идёт
  заново (`onElevenLabsAgentSyncForgotten`, подписка из `liveVoiceWarmup.ts`, без цикла
  импортов).
- **П3 и prompt-gaps** задели одни файлы сценариев — git свёл их без конфликта; смысл обеих
  сторон проверен тестами обеих веток.
