# 01.11.2026 — одобренный перемонтаж уходит в публикацию

**Что было.** №164: модератор одобрил перемонтированный ролик, а CRM ответила «Объект уже вышел во всех
пяти сетях со старым роликом — новый туда сам не уйдёт». Проверка `handoffNotPublishingReason`
(lib/videoHandoff.ts) отказывала ДО постановки задания публикации, поэтому снятие старых постов
(`replaceOldPostsBeforeRemakePublish`, правка #65) не запускалось ни разу — у каждого перемонтажа
объект уже во всех пяти сетях.

**Что изменилось.** Если у объекта есть заявка на перемонтаж с `replaceOldPostsOnPublish` и старые посты
ещё не сняты, отказ «во всех пяти сетях» не срабатывает: слот и задание ставятся, задание снимает старые
посты и публикует новый ролик.

**Проверка.** Тест в `video-handoff-replace-classes.test.ts` (перемонтаж с заменой → слот и задание
PENDING); прежний тест «во всех пяти сетях без перемонтажа → отказ» остался. Полный прогон — `npm run ship`.

**Осталось.** После выката поставить публикацию №164 (одобрен 01.11 11:17) вручную через
`schedulePublishAfterAccept`.
