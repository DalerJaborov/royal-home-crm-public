# 24.10.2026 — Устойчивый тест недельного ограничения звонков

- Что изменилось: один тест планировщика проверяет начало первого звонка и пропуск второго по ID собственных показов. Внутри этого же теста создаётся второй собственный клиент с более ранним показом; его строки удаляются по сохранённому ID в finally. Проверяются ровно один вызов моста для своего клиента и ровно одна собственная строка с историей попытки.
- Почему: глобальный результат тика планировщика не показывает результат конкретного клиента. Артефакт CI сохранил первую ошибку expected 0 / received 1 во втором тике; контролируемый второй клиент воспроизвёл её со старой проверкой. Какая именно строка конкурировала в исходном CI, неизвестно.
- Чем проверено: чистый исходный сценарий 30/30 без retry; контролируемый старый oracle RED, новый строгий инвариант GREEN; итоговый файл 44/44 PASS, native 0, retry 0. Настоящая собственная PostgreSQL, мок телефонии, внешний fetch запрещён и не вызывался. Собственные тестовые сущности после завершения — 0. Подробности: `docs/audit-20261024/FINAL-SCHEDULE-FIXTURE.md`.
- Что осталось: полный пакет проверяет координатор, включая последующее исправление nullable-типизации двух строгих проверок через optional access; отдельно после этой правки тесты не повторялись. Приложение, политика звонков и остальные 43 теста не менялись. Реальных звонков, проверки production или выката не было.
