# 16.11.2026 — Шаблоны озвучки по типу объекта, концовки, случайный выбор без повтора

Владелец 16.11 дословно: «через одно ядро место пусть проходит, чтобы 10 раз не переделывать», «все шаблоны берутся из одного и того же места», «в случайном порядке». Библиотека текстов утверждена им же («Да, все принимаю. Выкатывай»).

- **Что изменилось (ядро, `packages/shared/src/propertyNarration.ts`).**
  - У шаблона новое необязательное поле `propertyTypes` (квартира, дом, участок, коммерция). Нет поля или пусто: подходит всем, поэтому все прежние шаблоны читаются как раньше.
  - Новый отдельный список `endings` в настройках озвучки: концовка (призыв) с языком и типами. Итоговый текст = основная часть шаблона + одна подходящая концовка.
  - Один выбор на всех: `chooseNarration`. Им пользуются автоозвучка, мастер CRM, карточка объекта, кнопка «Другой шаблон» в Шабнам. Старые `narrationRotatedTemplateId` и `nextNarrationTemplateId` (по кругу) удалены, чтобы не жили два способа.
  - Правила выбора: подходящие по языку и типу, не «только вручную», не равный прошлому шаблону и не равная прошлой концовке (если есть из чего выбрать). Выбор человека (кнопка, мастер) уважается всегда. У объекта, у которого версия уже есть, шаблон и концовка остаются те же, пока тип подходит: смена цены даёт тот же текст с новой ценой, а не новую случайность. Сменился тип объекта (квартира стала домом): берётся шаблон нового типа.
  - Случайность только в момент выбора. Выбранная концовка хранится в версии озвучки (новая колонка `PropertyNarrationVersion.endingId`, миграция `20261116150000_narration_endings`, только добавление). Текст собирает `narrationDraftText(config, facts, templateId, endingId)` без случайности, поэтому проверки «текст версии = шаблон по её фактам» (самоодобрение при смене цены, `autoApproveSameChoice`) не ломаются. Версии без концовки (все старые) собираются как раньше.
- **Сторож шаблона и концовки при сохранении** (`narrationTemplateError`, один на оба списка, вызывается из `PUT /properties/narration-settings`): цифры (числа только словами; в фигурных скобках не считаются), «Direct» латиницей (надо «Директ»), слово «брон» (любой регистр и окончание), плюс прежние: неизвестные слова, скобки, длинное тире. Сообщения простыми словами и с названием шаблона. **Цифры запрещены только в таджикском тексте**: в русском озвучка читает их верно, а правило владельца про числа словами относится к таджикскому. Если нужно запретить и в русском, это одна строка в `narrationTemplateError`.
- **Библиотека владельца вынесена в отдельный PR (решение ревью 17.11).** Этот PR (#216) несёт только код и колонку `PropertyNarrationVersion.endingId` (миграция `20261117220000_narration_endings`). Данные (20 шаблонов, 9 концовок) вносит второй PR, ветка `feat/narration-template-library-17-11`, миграция `20261117230000_narration_template_library`; **выкатывать его только ПОСЛЕ #216**. Причина: в main предел шаблонов был 20, миграция клала 26; сервер выката гонит миграции при ещё работающем старом API, а тот молча счёл бы озвучку ненастроенной, и откат с сохранением настроек стёр бы голоса и шаблоны. Теперь предел 100 (шаблоны и концовки) выкатывается раньше данных. Утверждённые тексты для тестов лежат данными `apps/api/tests/fixtures/narrationLibrary.json`.
- **Нечитаемые настройки больше не стираются молча.** Если схема не читает сохранённые настройки озвучки, это пишется в журнал ошибок (`narration-config-unreadable`), а `PUT /properties/narration-settings` отвечает 409 и ничего не сохраняет.
- **Сторож только к новым и изменённым текстам.** Структура (скобки, неизвестные слова, тире) проверяется у всех шаблонов, а цифры, «Direct» и «брон» только у новых или изменённых: старый живой шаблон с цифрой не мешает, например, выключить автоозвучку.
- **Что со старыми шестью стартовыми шаблонами (11.11).** Не удалены и не изменены по тексту. Помечены `manualOnly: true`: в случайный выбор не входят и случайную концовку не получают (у них свой призыв внутри), но агент может выбрать их руками, а все версии на них продолжают собираться как раньше. Без этой пометки старые шесть попадали бы в случайный выбор на равных с новыми (3 из 8 для квартиры). Если владелец захочет убрать их совсем, это снятие в экране Настроек.
- **`defaultTemplateId` (решение, как совместить со случайным).** Остаётся: он задаёт ЯЗЫК автовыбора (шаблон по умолчанию на таджикском значит, что случайный выбор идёт среди таджикских) и запасной шаблон, если для типа объекта нет ни одного подходящего. Выбирать конкретный шаблон автоозвучке он больше не заставляет: новый объект получает случайный подходящий, не равный прошлому выбору этого сотрудника.
- **Экраны.** Настройки озвучки (ПК и телефон, один адаптивный экран): у шаблона галочки типов и «Только вручную», отдельный блок «Концовки» с языком, типами и текстом. Мастер и карточка: показаны только подходящие типу шаблоны, текст ставится с концовкой, «Другой вариант» берёт случайные другие шаблон и концовку; предвыбор уходит в запрос кодами, чтобы сервер собрал ровно то, что агент увидел. Шабнам: в «Другой шаблон» первой кнопкой «Случайный другой шаблон», дальше шаблоны языка версии и типа объекта.
- **Чем проверено.** Тесты: `narration-templates-by-type` (выбор по типу, без повтора, выбор человека, сторож, вся библиотека из миграции проходит сторож и схему, К1 без этажа теряет фразу про этаж целиком), `narration-template-library-migration` (на живой базе: настройки владельца целы, идемпотентность, JSON-скаляр вместо объекта), дополнения в `narration-auto-flow` (версия хранит коды, смена цены сохраняет шаблон и концовку и самоодобряется, смена текста концовки владельцем отправляет на прослушивание человеку, смена типа объекта), `property-narration-routes` (сторож и типы при сохранении), тесты фронта мастера, карточки и экрана настроек.
- **Что осталось / вопросы владельцу.** (1) Предпросмотр текста озвучки внутри мастера Шабнам показывает не случайный, а шаблон по умолчанию без концовки; настоящий выбор делает сервер при создании. Подпись «текст поменяете, когда придёт» это уже говорит. (2) Названия шаблонов в списках для агента «Квартира 1», «Дом 1» и т. д. (мои, не кодовые К1/Д1 владельца): можно переименовать в Настройках. (3) Библиотека только на таджикском: пока в настройках нет русских шаблонов по типам, русский идёт старыми шестью вручную. (4) Живые Настройки на проде этой правкой не тронуты: данные попадут туда при выкате миграцией.

## Правки по ревью 17.11 (architect)
- Русский язык: при заданном языке выбор берёт обычные шаблоны языка и типа, затем «только вручную» того же языка и типа, затем любой шаблон языка; таджикский запасной только когда языка нет вовсе (в том числе кнопка «Случайный» в Шабнам на русской версии).
- Карточка объекта: клиент всегда присылает `endingId` (null значит «без концовки»); готовый текст без `endingId` получает концовку null, сервер её не подставляет; при смене шаблона концовка берётся через `chooseNarration`.
- «Другой шаблон» при единственном варианте: тот же шаблон, концовка, голос и текст возвращают `UNCHANGED`, платной копии нет (Шабнам отвечает «текст остался тем же»).
- Кнопки «Другой шаблон» в Шабнам ссылаются на код шаблона (`nar:m:<версия>:<код>`, случайный `r`), коды длиннее 21 знака в кнопки не попадают (лимит Telegram 64 байта); старые кнопки с номером после выката отвечают «устарело».
- «Последний раз выбран» ставится только на то, что выбрал сам человек; случайно выпавшее хранится отдельно (`usedTemplateId/usedEndingId`) и нужно лишь для «не повторять». Предвыбор мастера помечен `autoPicked`.
- Мастер: предвыбор не может зациклить перерисовку, даже если запасной шаблон типу не подходит. Настройки на телефоне: блоки шаблонов и концовок свёрнуты, галочки 24 px.
- **Порядок выката:** сначала #216, затем PR библиотеки (после того как #216 на проде).
