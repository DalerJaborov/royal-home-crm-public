# 03.11.2026 — Внутренний помощник в Telegram: личка и общая группа (П5)

- Что изменилось: новый `telegram/assistantBot.ts` — два входа в то же ядро помощника (`runAssistantDetailed` + брокер подтверждений), своей логики записи нет.
  1) Личка: сотрудник (не монтажёр) пишет/диктует боту; история в `TelegramDialogState kind:"assistant"` (12 реплик, 15 мин, `/new` — заново); голосовые идут через `transcribeAudio` (путь `/transcribe`); ссылки в ответе абсолютные (`CRM_PUBLIC_URL`); общий суточный потолок `claimAgentAiAction` (150 ходов, 40 голосовых).
  2) Общая группа: бот отвечает только на @упоминание, `/ai` или ответ на своё сообщение. Группу подключает директор/админ командой `/assistant_on` (таблица `AssistantTelegramGroup`; `/assistant_off` снимает; чужая группа молчит). Отправитель — по Telegram `from.id` → `Agent.telegramUserId` (новое поле, заполняется при привязке кодом; миграция переносит `telegramChatId` уже привязанных). Не привязан — «привяжите аккаунт в личке». Чтение в группе без телефонов клиентов, финансов и отчётов (права для чтения урезаны + маска в тексте ответа, быстрый путь по номеру телефона в группе выключен).
  3) Запись: цепочка действий одного ответа («цена + перемонтаж») — ОДНА карточка «было → станет» и одна кнопка (`as:ok:<связка>` / `as:no:<связка>`, `AssistantAction.bundleId`). Нажать может только автор (сверка по Telegram user id), права перечитываются на нажатии, акционер/неактивный — отказ; повтор доставки (`claimCallback`) и двойное нажатие не исполняют дважды; первое упавшее действие отменяет остальные. Тихого выполнения свободного текста нет.
  Для Telegram включён канал у `change_property_price/status`, `request_property_change`, `send_to_remake` (step-up у REST-аналогов нет). `change_client_agent` остаётся только в CRM.
- Почему: владелец (31.10–03.11) хочет помощника в Telegram, в том числе в общем чате сотрудников. Решение по группам: вместо прежнего запрета (док. §2.4) — режим «только по упоминанию + права автора + одна карточка».
- Чем проверено: `tests/assistant-telegram.test.ts` (30 тестов: группа без упоминания/не подключена, не привязанный, неактивный, чужой жмёт кнопку, повтор и параллельное нажатие, снятые права, акционер, цепочка с падением, маска телефонов, голос, привязка); проверка «ломай нарочно» — без сверки автора тест чужой кнопки краснеет. Старые `telegram-agent-link`, `montajer-bot` обновлены под новое поведение (не-монтажёр теперь получает помощника, а не шаблон).
- Что осталось: в группе голосовое принимается только ответом боту; у BotFather для упоминаний выключить privacy mode (иначе бот видит только команды и ответы ему); кнопки «Отменить» после исполнения (undo) в Telegram нет; живая проверка на реальном боте — за владельцем.
- Ревью диффа (Opus, «найти ошибки») нашло и поправило: отвязка в профиле/увольнение теперь снимают и `telegramUserId`; в группе закрыты инструменты сделок/статистики/финансов и запись уровня B (`AssistantActor.hiddenTools`, и подсказка модели, и отказ при вызове); маска телефонов в карточке и подписях ссылок; карточка не режется ответом модели (слишком длинная — не показывается, действия отменяются); частичная привязка связки — всё отменяется; «Отмена» после частичного исполнения говорит правду; ответ на нажатие не роняет обработку; расшифровка голоса не платится при выключенном помощнике.
