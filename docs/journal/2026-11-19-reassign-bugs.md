# 19.11.2026 — Четыре ошибки передачи клиента между агентами (аудит 18.11)

Владелец одобрил починку четырёх находок аудита переназначения от 18.11.2026.
Правила «не позвонил за 15 минут — забрать», выбор получателя по KPI и карусель
не тронуты.

## 1. «Передать» подписывал не того, кто нажал

- Что изменилось: `transferClientByAgent` (`lib/clientTransfer.ts`) принимает
  `actorId` — кто нажал. Маршрут `POST /clients/:id/transfer` передаёт
  `req.agent.id`. Хронология, `CLIENT_AGENT_CHANGE` и `CLIENT_TRANSFER` теперь
  подписаны нажавшим; владелец карточки — в `CLIENT_TRANSFER.meta.fromAgentId`.
  Квота передач по-прежнему считает передачи клиентов агента: новые строки по
  `meta.fromAgentId`, старые (без meta) по `agentId`.
- Почему: с 16.11.2026 передаёт только руководитель, а в журнале выходило, что
  клиента отдал сам агент.

## 2. Принятие и снятие предложения реактивации могли пройти оба

- Что изменилось: `acceptReactivationOffer` и `releaseReactivationOffer`
  (`lib/reactivationOffers.ts`) пишут через `changeClientAgent` с условием
  «предложение ещё открыто и адресовано этому агенту» прямо в `updateMany`.
  Проигравший получает `count = 0`: принятие отвечает 409, снятие возвращает
  `raced: true` и не шлёт пушей, аудита и эскалаций. «Отклонить» на уже снятом
  предложении — 409. Кроны не считают проигранные гонки снятыми.
- Почему: крон истечения читал предложение, агент в это время жал «Принять»,
  и крон следом отдавал уже принятого клиента третьему агенту.

## 3. intake.ts менял владельца мимо единой двери

- Что изменилось: в `services/leads/intake.ts` все записи владельца идут через
  `changeClientAgent` — возврат из Корзины (внутри той же транзакции, после
  снятия `deletedAt`/`acceptedAt`), возврат из «Неактивных» (оставить своему /
  по очереди), «держатель потерянной недоступен», «стало прочим обращением».
  Отметок `LAW-A2-PENDING` в файле больше нет. Ручные `logSystemAudit` и
  ручной вызов спутников убраны — их делает дверь. В `AuditLog.meta` остались
  прежние ключи `from`/`to` (новое поле `auditMeta` у `changeClientAgent`) и
  добавились стандартные `fromAgentId`/`toAgentId`, которые читают
  `selection.ts` и другие.
- Закон П-3: вердикт «можно» передаётся двери готовым, только когда текущий
  держатель пуст или выбыл (уволен, заморожен, не продажник) — законный случай
  «держателя нет». Если держатель жив, закон проверяет сама дверь.
- Следствия единой двери, которых раньше на этих путях не было (так ведут себя
  все остальные передачи): у прежнего агента гаснут «новый лид» и
  уведомления по клиенту, его открытые задачи уезжают новому, объекты продавца
  переезжают вместе с продавцом, `lastAgentId` ставится по общему правилу.
  Защита от гонки с ручным назначением: запись идёт с условием «владелец тот
  же, что в снимке»; проиграл — обращение не меняет карточку (как уже было у
  ветки «прежний активный агент»).

## 4. Спутники смены владельца срабатывали до коммита

- Что изменилось: `changeClientAgent` с чужой `tx` больше не гасит спутников и не
  перегенерирует сводку сразу. Он ждёт в фоне, пока его же строка `AuditLog`
  станет видна вне транзакции (это и есть коммит), и только тогда запускает
  их. Не появилась за 30 секунд — транзакция откатилась, спутники не нужны.
  Работает для всех ~18 вызывающих с `tx` без правок у них.
- Почему: при откате (`throwIfNotClaimed`, таймаут, ошибка следующего шага)
  задачи и требования уже уезжали «новому» агенту, а у прежнего гасли
  уведомления по его же клиенту; сводка ИИ читала ещё старого владельца.

## Чем проверено

- `apps/api/tests/reassign-bugs-19-11.test.ts` — 7 тестов. С починкой 7 из 7
  зелёные. Без починки (исходники вернул к `origin/main`) красные 6 из 7;
  седьмой — проверка «после коммита спутники срабатывают», он зелёный в обоих
  случаях намеренно.
- Смежные тесты владения, передачи, реактивации, Корзины, спутников — см.
  отчёт правки. `npm run build:api`, `npm run map`, `npm run map:check`.

## Что осталось

- Полный `test:api` — на `npm run ship`.
- Тот же класс «подписан владелец, а не нажавший», вне этой правки (ОЦЕНКА, не
  проверено глубже): `routes/clients/matching.ts` — запись «Ссылка на объект
  отправлена клиенту» пишется от `assignedAgentId`, хотя отправить мог
  руководитель.
- Спутники с чужой `tx` теперь приходят на 25–200 мс позже коммита (раньше —
  раньше коммита). Тест, который ждал их без `waitFor`, мог бы это заметить.
