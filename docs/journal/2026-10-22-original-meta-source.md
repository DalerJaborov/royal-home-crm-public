# 22.10.2026 — Сохранять исходное сообщение до обхода нового ядра

- Причина: ветка старого обработчика сохраняла владельца собеседника, но могла
  пройти OFF/LEGACY bypass до записи исходного MID. Это воспроизведено отдельным
  тестом PostgreSQL; тест не доказывает причину всех исторических пропусков.
- Изменение: существующий ingress ticket получает неизменяемые версию, хеш
  исходного конверта, ревизию пространства аккаунта и происхождение записи.
  LEGACY сохраняет эту запись до асинхронной обработки; CORE сохраняет метаданные
  вместе с прежним зашифрованным RAW и заданием. Старые NULL-записи не обновляются.
- Повторы: изменённое содержимое или ревизия пространства не получает новое
  право обработки. Уже известный пользовательский MID из точного scoped native
  сохраняет отдельный запрет повторного запуска; сообщения assistant таким
  доказательством не считаются. Удаление native сохраняет прежний tombstone.
- Восстановление до native: первый binding делает один SQL compare-and-set.
  Подлинная идентичная повторная доставка может восстановить потерю процесса
  до binding в исходном 15-минутном окне; время первого приёма не обновляется.
  Одновременно пришедшие свидетели не дают несколько fresh-admission.
- Проверки: первый RED на реальной отдельной PostgreSQL; затем сборка API и
  проверки original-source/enrollment. Расширенный прогон выявил слишком широкий
  first-binding gate, блокировавший существующую CORE-admission: он ограничен
  только LEGACY metadata, без ослабления тестов или исходной CORE-authority.
  Все 53 упавшие существующие проверки повторно прошли; затем расширенный повтор
  завершился 597 прошедшими тестами в 47 файлах, включая 16 новых сценариев.
- Версия ядра: новые source/admission модули входят в явный coreHash.
  Изменённые routing/producer/enrollment уже входят в него. Выпуск потребует
  новой штатно зарегистрированной и подтверждённой ревизии с сохранением 50%,
  cohort/idle/lineage и прежних receipts. До этого нельзя считать прежнюю
  ревизию совместимой с новым runtime. Проверки покрытия и окончательные
  проверки регистрации/обновления версии после расширения покрытия прошли:
  73 теста в пяти файлах, включая два теста изменения только coreHash.
  Облачный полный прогон, независимая проверка и production ещё требуются.
- Ограничения: эта правка не включает 100%, новый cutover root, массовый перенос
  старой истории, другие адаптеры, голос, страховку или передачу сотруднику.
  Она не доказывает качество живых ответов и не устраняет все окна сбоя после
  native binding. Прежние закреплённые владельцы и подтверждения доставки сохраняются.
