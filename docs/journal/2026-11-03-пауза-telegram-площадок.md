# 03.11.2026 — Пауза Telegram-уведомлений с площадок Somon/Paydo и предохранитель локального запуска

- Что изменилось: `Settings.telegramPortalAlertsPaused` (по умолчанию **true** — пауза включена; нет строки Settings — тоже пауза), одна дверь `lib/telegramPortalPause.ts`. Единственный путь отправки в Telegram по площадкам — `lib/somonLeads/sendReserved.ts` (Paydo в Telegram ничего не шлёт, это сбор рынка): при паузе отправка снимается как при выключенном получателе (доставка CANCELLED, объявление снова PENDING), а тик мониторинга `runSomonMonitorTick` при паузе вообще не разбирает объявления и не трогает очередь — после снятия паузы всё продолжается. В CRM (колокольчик, ленты, карточки) ничего не меняется. Других путей отправки по площадкам в коде нет (проверено поиском по somon/paydo/portal + импорту `telegram/api` в `lib/somonLeads` и `lib/market`; сторож в тесте не даст добавить второй файл-отправитель без двери).
  Предохранитель: при `NODE_ENV=development` плановые задачи (`startCronJobs`) не стартуют, пока не задано `DEV_CRONS=1` — первый локальный запуск не разошлёт реальные уведомления; Telegram-поллер (ответы ассистента, привязка) работает. Прод и тесты не затронуты.
- Как снять паузу: `UPDATE "Settings" SET "telegramPortalAlertsPaused" = false WHERE id = 'singleton';` (или Prisma Studio). Включить кроны локально: `DEV_CRONS=1`.
