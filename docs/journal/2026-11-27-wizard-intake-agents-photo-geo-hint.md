# 27.11.2026 — мастер объекта: «Кто принял» только агенты, подсказка когда у фото нет геометки

**Жалоба владельца (кадр с iPhone, 22:07):** в «Кто принял объект» шага продавца стояли директор и учредитель; фото добавили через мастер, точка не определилась, мастер молчал.

## Что изменилось
- `apps/web/src/lib/intakeAgents.ts` (новый) — одно правило «кто может принять объект»: активный, не замороженный, роль AGENT. Те же условия у обычной формы (`PropertyFormModal`) и у сервера (`assignableAgentError`).
- `StepSeller.tsx` — список мастера берёт это правило (раньше брал всех сотрудников подряд); выбранный «принявший», которого в списке нет (хозяин продавца — директор, старый черновик, `?intake=`), сбрасывается: именно так в строке оказывался директор.
- `draftUploads.ts` + `photoGeoHint.ts` + `useDraftMedia.ts` — счётчик итогов разбора снимков (разобрано / с точкой / вне Душанбе); `PropertyWizard.tsx` показывает под картой на шаге «Где» причину, если точка по фото не появилась и ещё не поставлена руками.

## Что проверено и что нет
- ФАКТ (прод-база, чтение): снимок `IMG_9010.jpg` 1 048 214 байт, image/jpeg ушёл на сервер как есть (меньше 1,5 МБ — клиент не пережимал). Сжатие клиента точку не теряет: разбор идёт по исходному файлу до сжатия; сервер на черновике геометку не читает.
- НЕТ ДАННЫХ: была ли геометка в самом файле. Сервер хранит только WebP без метаданных. Самая вероятная причина — телефон вырезал геометку при выборе из галереи (разрешение «Фото → Геопозиция» у браузера). Код вернуть её не может, поэтому теперь мастер говорит об этом и что делать.
- Тесты: `apps/web/src/lib/__tests__/intakeAgentsAndPhotoGeoHint.test.ts`.

## Осталось
- «Ноза РОП» (роль HEAD_OF_SALES) из списка ушла вместе с руководством — как и в обычной форме; сервер её принять позволяет. Вернуть, если владелец хочет, чтобы РОП принимала объекты.
