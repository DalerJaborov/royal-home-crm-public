# 19.11.2026 — оператор приёма заявок: модуль `ai/operator/` (этап 1.1, без подключения)

**Что изменилось.** Новый модуль `apps/api/src/ai/operator/` по эталону `docs/bot-operator/SPEC.md`
(с дополнением «Тон», торг, случаи 21–26):

- `types.ts` — состояние разговора v2, `Understanding`, `OperatorContext`, `OperatorDecision`, действия
  `accept_lead` / `append_note` / `call_staff`;
- `decide.ts` — чистая функция шага (роли, шаги, пределы, запреты SPEC; вариант фразы — счётчик);
- `phrases.ts` — все тексты клиенту, ru и tg, по 2 варианта, одно предложение на вариант;
- `state.ts` — память в `BotConversation.leadOnlyPending` версии 2, чтение версии 1 переводом, без миграции;
- `understand.ts` — один структурированный вызов модели на ход (транспорт режима), проверка кодом, запасные правила;
- `index.ts` — одна дверь `runOperatorTurn`.

`ai/leadOnlyIntent.ts`: вынесены общий транспорт `leadOnlyStructuredModel`, `askLeadOnlyModel` и `leadOnlyQuoteFound`
(поведение двери намерения прежнее, `tests/lead-only-intent.test.ts` 66/66).

**Почему.** PLAN.md, этап 1: один хозяин разговора в режиме «только заявки».

**Чем проверено.** `tests/bot-operator-{decide,phrases,state,understand}.test.ts` — 80 тестов (случаи SPEC 1–26,
пределы, перебор 2000 разговоров, сторож фраз, v1→v2, модель подменена). Сторожа проверены внесённой поломкой
(«Рудаки» и два предложения во фразе, предел вопроса о роли, комиссия покупателю — все красные). `npm run build:api`.

**Что осталось.** Подключение к живому пути (этап 1.2): к ядру и старому пути модуль не подключён.
