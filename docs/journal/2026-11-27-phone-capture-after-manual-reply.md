# 27.11.2026 — Кто написал нам, тот в CRM: номер из переписки без хода бота

- Что изменилось:
  1. Сторож «номер есть — карточки нет» (`apps/api/src/lib/phoneLeadWatchdog.ts`, каждые 15 минут, окно 72 часа)
     теперь видит WhatsApp-переписку, где клиент написал по делу, а бот 20 минут не ответил (ядро держало ход,
     пауза оператора, сбой). Номер — сам отправитель (wa_id); карточка заводится тем же тихим приёмом (`acceptLead`),
     то есть с теми же отсечками (аренда, другой город, услуги, номер сотрудника) и той же раздачей агентам.
     Номер уже у карточки — переписка привязывается к ней. Не заводит: ответ бота был, «спасибо/ок/жду», одно
     приветствие, спам, вакансия, переписка с пометкой «рассылка», карточка в Корзине. Правило — `lib/unansweredChatTurn.ts`.
  2. Номер одним сообщением («+992 900 12 34 56», «900123456 вотсап») в переписке с УЖЕ заведённой карточкой
     дописывается в запасные номера той же дверью `captureExplicitClientPhone` (раньше только «мой номер …»).
     Номер с другими словами («номер мужа», «позвоните собственнику») — по-прежнему решает человек.
  3. Удержанное ядром сообщение (HELD, `lib/customerHeldMessage.ts`) теперь тоже несёт номер в карточку: в переписку
     ложится копия с замаскированным новым номером, и номер раньше пропадал совсем.
  4. Тот же тик проходит переписки с карточкой за 72 часа и дописывает номера, пришедшие мимо хода (≤300 переписок
     за тик, идемпотентно).
  5. Безопасность: реплика роли «клиент» с автором (эхо сотрудника из телефона компании) больше не считается словами
     клиента; номер агентства (+992 44 650 14 14 и прежний) клиентом не становится.
  6. Рубильник «Клиент в WhatsApp без ответа бота: карточка сама» (`Settings.chatUnansweredCardEnabled`, ВКЛ по
     умолчанию, Настройки → Автоматика → Бот клиентов) выключает пункты 1, 2 и 4.
- Почему: владелец 27.11 — «иногда отвечаем вручную, и номер клиента не попадает в CRM или клиент теряется».
  26.11 16:30–19:33 ядро держало ходы (HELD, current_artifact_revision_mismatch), около 15 переписок WhatsApp
  остались «Без имени» без карточки. Корень: сторож искал номер только в тексте, а в WhatsApp его пишут редко
  (журнал 14.11 уже называл эту дыру: «WhatsApp-клиент без набранного номера сторож не видит»).
- Добор вчерашнего: отдельного скрипта нет — окно сторожа 72 часа, первый тик после выката подберёт 26.11
  (не больше 25 заявок за тик, остаток — следующими тиками).
- Чем проверено: `apps/api/tests/phone-capture-after-manual-reply-27-11.test.ts`; смежные тесты сторожа и захвата.
- Что осталось: живая проверка на проде после выката (сколько карточек завёл первый тик); Instagram/Facebook без
  набранного номера по-прежнему без карточки (номера нет — нечего заводить, сигнал «клиент ждёт» остаётся);
  номера из переписки с карточкой, которые раньше уже замаскированы в истории, восстановить нельзя.
