# 27.11.2026 — Кто написал нам, тот в CRM: номер из переписки без хода бота

- Что изменилось:
  1. Сторож «номер есть — карточки нет» (`apps/api/src/lib/phoneLeadWatchdog.ts`, каждые 15 минут, окно 72 часа)
     теперь видит WhatsApp-переписку, где клиент написал по делу, а бот 20 минут не ответил (ядро держало ход,
     пауза оператора, сбой). Номер — сам отправитель (wa_id); карточка заводится тем же тихим приёмом (`acceptLead`),
     то есть с теми же отсечками (аренда, другой город, услуги, номер сотрудника) и той же раздачей агентам.
     Номер уже у карточки — переписка привязывается к ней. Не заводит: ответ бота был, «спасибо/ок/жду», одно
     приветствие, спам, вакансия, переписка с пометкой «рассылка», карточка в Корзине. Правило — `lib/unansweredChatTurn.ts`.
  2. Номер одним сообщением («+992 900 12 34 56», «+992•••••3456 вотсап») в переписке с УЖЕ заведённой карточкой
     дописывается в запасные номера той же дверью `captureExplicitClientPhone` (раньше только «мой номер …»).
     Номер с другими словами («номер мужа», «позвоните собственнику») — по-прежнему решает человек.
  3. Удержанное ядром сообщение (HELD, `lib/customerHeldMessage.ts`) теперь тоже несёт номер в карточку: в переписку
     ложится копия с замаскированным новым номером, и номер раньше пропадал совсем.
  4. Тот же тик проходит переписки с карточкой за 72 часа и дописывает номера, пришедшие мимо хода (≤300 переписок
     за тик, идемпотентно).
  5. Безопасность: реплика роли «клиент» с автором (эхо сотрудника из телефона компании) больше не считается словами
     клиента; номер агентства (+992 44 650 14 14 и прежний) клиентом не становится.
  6. Рубильник «Клиент в WhatsApp без ответа бота: карточка сама» (`Settings.chatUnansweredCardEnabled`, ВКЛ по
     умолчанию, Настройки → Автоматика → Бот клиентов) выключает пункты 1, 2 и 4.

## 27.11.2026, позже — правки по независимому ревью #497
- B1: карточка по несостоявшемуся ходу WhatsApp — только при ДОКАЗАННОМ сбое: реплика записана мимо бота (heldRouting),
  сотрудник ответил руками, или у билета ядра причина молчания не из общего списка `lib/customerIntendedSilence.ts`
  (`turnFailureProven`). Просто «бот промолчал» — не сбой. Не обращение: стикер/фото без подписи, одна чужая ссылка,
  приветствие, «не пишите мне». Пропуск: заглушённый спам (`leadDraft.spamMute`), `optedOutAt`, режим «только заявки»
  без номера WhatsApp, неясное направление без сотрудника (никаких пушей в общую раздачу по «Салом»).
- S1: у этой ветки свой предел 10 за тик; не влезшее в предел (любая ветка) ждёт следующего тика, тревогой не становится.
  Один номер дважды в тике (человек на двух наших номерах) — вторая переписка ждёт тика.
- S2: разовый добор (`ignoreAttempts`) эту ветку не включает без явного параметра.
- S3: сотрудник CRM вёл переписку — карточка ему же через `requestedAgentId` (та же дверь назначения).
- S4: «просто номер» не пишется, если перед ним спрашивали номер хозяина, мужа, родственника; в проходе тоже.
- S5: номер агентства и номера сотрудников отсекает сама дверь `captureExplicitClientPhone`; номер отправителя WhatsApp
  тоже сверяется с ними.
- S6: проход по карточкам ставит отметку `BotConversation.phoneSweepAt` и разбирает переписку заново только при новом
  сообщении; уже записанный номер дверь не зовёт; рубильник читается раз на проход.
- S7: удержанное сообщение пишет номер через `captureClientPhoneWithRetry` (до 3 попыток при параллельной правке карточки).
- Свой рубильник «Номер одним сообщением — в карточку клиента» (`chatBarePhoneToCardEnabled`), подпись WhatsApp-рубильника
  уточнена. Проверяющий из Настроек больше не считается заявкой.
- Тесты: `tests/phone-capture-review-497.test.ts` (14), `tests/phone-capture-after-manual-reply-27-11.test.ts` (14);
  нарочно сломанная проверка доказательства сбоя краснит 2 теста B1.
