  - `marketing`: строки «Публикаций» (значки каналов), кнопки «Откатить»/

  - `new-look-analytics.spec.ts`: для «Инсайтов» ждём `.pg-h h1` — на телефоне
    список выпусков без `.sec-h`, тест ждал его на 320 px (экран исправен).
- «Готово» в карточке объекта на телефоне нажималось как «Открыть»: настоящая
  ошибка старого вида. Невидимая зона нажатия `.lnk::after` (44 px) после
  сброса `.rh2.screens .lnk{position:revert}` отсчитывалась от всего экрана, и
  полосы всех таких ссылок ложились поперёк страницы. В чистой оболочке это
  уже было закрыто (`theme-2026-clean.css`); правило перенесено для всех в
  `theme-2026-overflow-guard.css`. Проверено: `elementFromPoint` в центре
  «Готово» теперь сама кнопка (было — четыре чужие `.lnk`).
- Стенд в этот раз запущен на 4811/5311 НЕ через `serve`, а фоновыми процессами
  с живым родителем — API снова исчез на `serve` в 04:41:17. ОЦЕНКА механизма:
  `taskkill /PID <старый> /T` убивает всех, у кого записан тот же номер
  РОДИТЕЛЯ; у процессов `serve` родитель (powershell `Start-Process`) умирает
  сразу, его номер освобождается, и чужой стенд с устаревшим файлом PID уносит
  наш сервер как «дочерний». Защита `down` из первой части закрывает это для
  тех, кто на новой версии скрипта.

- `new-look-home.spec.ts`: вход ролей — через общий `pages/roleAuth.ts` (третьего
  механизма нет): сессия на диске, проверка живости через refresh, повтор кода по
