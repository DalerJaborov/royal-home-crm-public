# 20.11.2026 — Три красных @smoke и обвязка стенда для автотестов (Чат 3)

- Что изменилось (все три красных — устаревшие тесты при исправных экранах,
  плюс обвязка стенда, из-за которой @smoke нельзя было прогнать вовсе):
  - `login-sms-code.spec.ts`: ждал подписи до #104 (04.11) — «Прислать в
    Telegram», «Отправить ещё раз через N с». Сейчас отсчёт стоит строкой
    состояния, кнопки «Отправить ещё раз» и «Через Telegram» выключены до конца
    отсчёта; тест проверяет то же поведение по новым подписям.
  - `team-member-card.spec.ts`: ждал «Лиды по этапам», снятые с карточки 16.11
    вместе со статусами-папками (#220, решение владельца). Вместо них —
    «Цифры за неделю» (есть на обеих ширинах).
  - `profile-same-sections.spec.ts`: не тронут. Красным был только из-за стенда
    (вход не проходил, API падал на новых колонках); на исправном стенде зелёный.
  - Вход e2e — одна проверка живости сессии `tests/e2e/pages/sessionProbe.ts`
    для `auth.setup.ts` и `pages/roleAuth.ts`: решает ответ `/auth/refresh`, а не
    адрес сразу после загрузки. Профиль лежит в localStorage, приложение сперва
    рисует главную и уходит на /login только после отказа refresh; прежняя
    проверка успевала раньше и принимала чужой `chromium.json` (и вчерашний
    `role-agent.json`) за живой — весь набор шёл на экран входа.
  - `auth.setup.ts`: десктоп и телефон входят одним номером параллельно, а
    второй код раньше минуты сервер не выдаёт (защита от СМС-бомбинга, не
    трогали) — проигравший setup ждёт конца отсчёта и просит код снова; общий
    таймаут setup 150 с (холодный Vite).
  - `list-filters-survive-back` и `list-not-empty` (Объекты) открывают каталог
    `?view=table`: с 12.11 по умолчанию плитка (#159), в старой теме её ячейка —
    кнопка без ссылки и без названия; тесты ждали строку-ссылку.
  - `scripts/agent-stand.mjs`: окружение стенда в одном месте (`standEnv`) для
    `up` и `serve` — две разошедшиеся копии, ни в одной не было
    `LOGIN_CODE_DEV_ECHO=1`, без неё код входа стенд не отдаёт и войти формой
    нельзя; `up` докатывает миграции этого дерева в СВОЮ базу поверх эталона
    (эталон отставал на 28–36 миграций); `up`/`serve` печатают строку e2e;
    `down` гасит процесс, только если это всё ещё процесс этого стенда (в
    командной строке лог `api-<порт>.log`): по устаревшему файлу PID Windows
    отдавала номер чужому процессу, и `taskkill /T` уносил API соседнего
    стенда — у Чата 3 API исчезал посреди прогона четыре раза, последний в
    04:01:41, за 10 с до чужого `serve` на 4796 (связь — ОЦЕНКА по времени;
    защита закрывает механизм целиком).
    Сторож — `scripts/agent-stand-template.test.mjs` (в `test:scripts`).
  - Эталон общего контейнера пересобран (`refresh`, ~25 мин): 624 → 664
    миграций. Чужие базы — независимые копии, их это не задевает; эталон
    заменяется только после успешной сборки нового.
