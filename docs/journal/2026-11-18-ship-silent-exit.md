# 18.11.2026 — `npm run ship` больше не выходит молча с кодом 0 посреди ожидания

- Что изменилось: запуск `scripts/ship.mjs` как команды обёрнут в `holdProcessUntilSettled`. Пока выкат не дошёл до итога, процесс держит один пустой интервал. Таймауты чтений GitHub (`AbortSignal.timeout`, сам процесс не держит) теперь срабатывают, и повисший запрос кончается громкой остановкой «связь оборвалась». Если процесс всё же уходит до итога (`beforeExit`), печатается «Выкат оборвался» и ставится код 1.
- Почему: за 18.11 четыре выката (#286, #288, #272, #290) завершились кодом 0 без финальной строки и без вливания. Логи: дважды на 9-й минуте облачного прогона («заданий готово 20 из 21»), дважды после «жду завершения обязательных проверок и правил GitHub». Node выходит сам, когда в цикле событий не осталось держащих таймеров и сокетов, даже если main() ещё ждёт. Чаты читали код 0 как «готово», каждый повтор стоил 15–20 минут прогона.
- Чем проверено: `node --test scripts/ship.test.mjs` — 48 из 48 (один пропущен, как и раньше). Новый тест показывает сам сбой: без защиты дочерний процесс выходит с кодом 0, не дождавшись обещания на неудерживающем таймере; с защитой доживает до итога.
- Что осталось: точный сокет, который повисает, не найден, сеть в этот момент не записывалась. Теперь такой обрыв будет виден строкой «связь оборвалась (ETIMEDOUT)» с путём запроса.
