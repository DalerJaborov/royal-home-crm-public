# 02.11.2026 — блок «Рынок» в карточке объекта (Somon + Paydo)

**Решение владельца:** агент сразу видит, стоит ли объект своей цены. Порог «в рынке» ±10% к середине, MIN_SAMPLE = 8 (меньше — «Данных мало», без числа). Paydo — только чтение. «Новостройка» = признак дома.

## Что сделано
- Рыночный слой перенесён из локальной ветки `feat/market-intelligence` (21.08, не в main) на свежий main: `lib/market/*`, `routes/market.ts`, миграции `20260821030000`, `20260821120000`.
- Схема: `MarketListing` + `MarketPriceSnapshot`; миграция `20261102120000_market_listing_similarity_fields` — ремонт, тип дома, признак дома, готовность, обмен, координаты и `publishedAt` (в схеме был, в миграциях — нет; дрейф закрыт, `migrate diff` пуст).
- `lib/market/similarComps.ts`: подбор ПОХОЖИХ (район, комнаты, площадь ±15% (дома ±30%), ремонт, признак дома); лестница exact → без ремонта → без признака дома → без площади (объект обязан попадать в 10–90 перцентиль выборки); топ-5 по близости; вердикт ±10%. Выборка берётся по свежести (`lastSeenAt desc`, 800 строк), а не по цене — обрезка по цене сдвигала бы медиану.
- `GET /api/v1/market/property/:id` — объект и курс читаются на сервере (одна дверь); `condition → ремонт` (NEEDS_REPAIR→коробка, NEW_BUILDING→предчистовая, GOOD→средний, EXCELLENT→с ремонтом), `marketType → признак дома`. Старый `/market/estimate` (карточка клиента) остался, порог там тоже ±10%.
- Сборщик Paydo (JSON API, только чтение), поля Somon, блок `MarketBlock` в карточке — см. ниже (раздел обновляется по отчётам исполнителей).

## Не сделано / риски
- Сборщики запускаются руками (`runCrawl.ts`, `runPaydoCrawl.ts`); расписание «раз в сутки ночью» не включено — включать после первого прогона под присмотром и подтверждения владельца.
- Маппинг «состояние объекта → ремонт» грубый (у объекта 4 значения, у рынка 5); при нехватке похожих лестница отпускает ремонт.
- Цены объявлений ≠ цены сделок.

## Дополнение (после PR)
- Somon (HTML-выдача) не отдаёт ремонт и признак дома: поля у его объявлений null. Ступень «без ремонта, неизвестный тип дома допустим» подключает Somon; в основании это сказано.
- Paydo район не называет — `lib/market/districtResolver.ts` определяет район по координатам (граница района, иначе ближайший центр до 6 км, иначе null).
- Ночной сбор `lib/market/nightly.ts` (Somon: квартиры+дома; Paydo: оба раздела) в `cron.ts` на 02:30 Душанбе; включается только `MARKET_CRAWL_ENABLED=1` в .env сервера, по умолчанию выключен.
- Живые кадры блока не смотрены (вход на стенде по СМС); проверено тестами компонента.

## Дополнение 2 (единый каталог, динамика, свои объекты, WhatsApp)
- Один сборщик Somon: рыночный обход идёт через общий бюджет `fetchSomon` (темп 10 с на всех, 403/429 — стоп); минутный парсер лидов пишет те же страницы в каталог без второго запроса, ошибка рынка лиды не ломает. Полный обход — раз в неделю (вс 02:30), замок advisory, лимит 3 ч; «исчезло» только после полного обхода + страховка от подозрительно малого обхода.
- Динамика (`lib/market/dynamics.ts`, `/market/property/:id/dynamics`): сколько дней висят ушедшие, цена ушедших vs висящих, доля снижавших цену, доля риелторов. «Ушло с площадки» ≠ «продано».
- Свой объект на площадках (`ownMatch.ts`, `PropertyMarketMatch`, `/market/matches/*`): совпадение по телефону владельца/координатам/параметрам, пуш агенту один раз, смена цены, снятие; кнопки «Это наш / Не наш».
- WhatsApp к объявлению (`/market/listing-contact`, `MarketWhatsAppButton`): номер Somon берётся по клику одним запросом через общий бюджет и кешируется; текст «Здравствуйте! Интересует объявление …». Номера публичных объявлений не скрываем (решение владельца); исключение — номер владельца нашего объекта без доступа.
- Все рыночные задачи cron включаются одной переменной `MARKET_CRAWL_ENABLED=1` (по умолчанию выкл).
