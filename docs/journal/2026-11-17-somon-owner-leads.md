# 17.11.2026 — Somon: почему с 03.11 нет заявок собственников, и сторож тишины

## Причина (проверено на проде чтением, 17.11)

Не код и не переезд. `Settings.telegramPortalAlertsPaused = true` — пауза Telegram-уведомлений
площадок, введённая 03.11 (#99, «временно приостановить»; столбец по умолчанию `true`). При паузе
`runSomonMonitorTick` выходит в самом начале: объявления не разбираются, очередь не трогается,
агентам ничего не уходит. Крон `somon-owner-leads` при этом каждую минуту отчитывается «ок» за
~50 мс — поэтому тишина длилась две недели незаметно.

Факты с прода (rh-new, сессия только для чтения):
- `SomonMonitor`: `enabled=true`, разметка завершена 27.10, `sourceStopped=false`, сбоев 0,
  последний регулярный скан `nextScanAt` 03.11 08:28Z; последняя принятая отправка 03.11 08:13Z
  (выкат #99 — 03.11 ~08:00Z). Всего ACCEPTED 283, затем ноль.
- Ключ сверки контактов (`SETTINGS_ENCRYPTION_KEY` → отпечаток) в api и worker совпадает с
  сохранённым — после снятия паузы монитор не встанет на «ключ сменился».
- Somon с нового сервера отвечает: рыночный инкремент `market-somon-incremental` проходит.
- Получатели: Сурайё, Умед, Маъруф включены и с Telegram; Ноза выключена (02.11 Telegram отклонил
  отправку ей, «агент временно исключён»).

Отвергнуто: (а) монитор выключен — нет; (б) переменная окружения не доехала — нет (ключ совпал,
флаг монитора в базе, не в env); (в) блокировка Somon по IP — нет; (г) некому раздавать — нет,
трое получателей годны.

## Что изменилось в коде

- `lib/somonLeads/silenceAlarm.ts` + крон `somon-owner-leads-silence` (ежечасно, :47): монитор
  включён, а принятых отправок агентам нет 24 ч → `logSystemError` с названной причиной
  (источник остановлен / нет получателей с Telegram / разметка не закончена / «видит новые
  объявления, но ни одно не ушло» — отбор продавцов или Telegram); на паузе площадок —
  напоминание после 72 ч. Окно дедупа — сутки. Выключенный монитор — тишина законна.
- `lib/functionStatus.ts`: текст «на паузе … (в CRM заявки видны)» был неправдой — при паузе
  заявки собственников не разбираются вовсе; исправлено.
- Строка крона добавлена в реестр «Состояние функций» (shared + подпись на экране).

## Чем проверено

`tests/somon-silence-alarm.test.ts` (решение по входу + чтение состояния, без базы: сторож

## Что осталось

- Снять паузу на проде — решение владельца (операция в отчёте; SQL одной строкой).
- Ложной тревоги после снятия паузы не будет: без видимой причины тишина считается с первого
  нового объявления, увиденного после последней отправки (тест «сразу после снятия паузы»).
  Падение самого тика ловит пульс крона, а не этот сторож.
- Экрана для паузы в Настройках по-прежнему нет (снимается только на сервере).
