# Paydo: инкремент каждые 10 минут + ночной полный обход (03.11.2026)

Просьба владельца: Paydo каждые 10 минут добирает НОВОЕ, раз в сутки ночью — полный обход.

## Что выяснено про Paydo (3 пробных поиска + статические файлы сайта, 03.11.2026)

- Выдача `POST /api/v1/search/` без параметров идёт так: сначала платные продвижения (VIP/PREMIUM, на пробе — 3 объявления, среди них старые), затем BASIC по убыванию времени публикации. ФАКТ: поле `search_after` в курсоре (JWT) = [ранг продвижения, оценка, время публикации в мс, id]; на живой выдаче даты шли «Вчера 14:41 → 14:39 → 14:36 → 14:31».
- В ответе есть список сортировок `sorting`: default / date / price_low / price_high. КАК передать сортировку в `POST /api/v1/search/` — НЕТ ДАННЫХ: сайт в этом запросе её не шлёт (в `combinedSearch` только query, category, subcategory, filters, cursor, limit); в GET-ручках рекомендаций она едет внутри `filters_json`. Не проверяли (лимит пробных запросов), порядок по умолчанию для инкремента достаточен.
- Оговорка: опираемся на порядок по умолчанию, поэтому стоп не по одной известной странице (наверху бывают старые продвинутые), а по двум подряд + потолок 15 страниц на раздел.

## Что сделано

- `lib/market/paydoIncremental.ts` — `runPaydoIncremental()`: разделы 201 и 203 с первой страницы; страница «известная», если все её объявления есть в каталоге, активны и с той же ценой/валютой (проверка ДО `saveListings`); две такие подряд или 15 страниц — стоп. Исчезнувшими ничего не помечает. Общий замок `withMarketCrawlLock`: занят — тик тихо пропущен (`null`). 403/429 — стоп, в журнал только код; прочие ошибки — без тела. Предел тика 8 минут.
- `paydoCrawler.ts`: `onPage` может вернуть `"stop"` (причина `caught_up`).
- `nightly.ts`: `runMarketFullCrawl` теперь ТОЛЬКО Somon (в статистике нет `paydo`); новая `runPaydoFullCrawl()` — полный обход Paydo под тем же замком, страховка «меньше 60 % от прежнего» сохранена.
- `marketStore.ts`: `markDisappeared(source, hours)` — порог обязательный параметр, без умолчания; `PAYDO_DISAPPEAR_AFTER_HOURS` = 72 (ночной обход ×3), Somon остаётся 264 ч. Ручной `runPaydoCrawl.ts` тоже на 72 ч.
- `cron.ts` (всё за `MARKET_CRAWL_ENABLED=1`): `market-paydo-incremental` каждые 10 минут, `market-paydo-daily` 03:00 ежедневно (предел тика 3 ч 30 мин, как у недельного), `market-weekly-crawl` — только Somon.

## Почему так

- Полный недельный обход Paydo отдавал сведения раз в неделю; ночной даёт «сняли» за 3 суток, а инкремент — новое за 10 минут (~30 запросов в тик при самом плохом случае, обычно 4–6, пауза 0,7 с).
- 72 ч, а не 24: одна неудачная ночь (блок, обрыв, занятый замок) не должна гасить живые объявления.
- Замок один на всё, чтобы не складывать нагрузку на Paydo и не писать в каталог из двух обходов сразу.

## Чего не хватает

- В воскресенье Somon-обход с 02:30 может идти за 03:00 — тогда ночной Paydo пропускается (замок), следующий — через сутки; порог 72 ч это переживает.
- Параметр сортировки Paydo не найден — при желании проверить `filters_json`/`sorting` отдельной разведкой.

Тесты: `market-paydo-incremental.test.ts` (новый), `market-full-crawl.test.ts` (ночной Paydo, недельный только Somon), `market-store.test.ts`.
