# 16.11.2026 — новая озвучка на вышедший ролик без монтажёра

## Решение владельца (16.11, по смыслу дословно)

«Старые ролики массово не трогаем. Агент поменял свою цену и хочет перезалить в соцсети — наш ИИ
быстро берёт старый ролик, убирает старый голос, кладёт новую озвучку и всё выкладывает. Секунды
должны совпадать: ролик 25 с — аудио не может быть 35 с. Скорость — главный приоритет».

## Что было

Путь «без монтажёра» (remixFromMaster) работал только при «мастере» — ролике без голоса от
монтажёра. ФАКТ (база прода 16.11): мастеров 0 у всех 90 вышедших роликов, значит каждая смена
цены уходила монтажёру. Голос длиннее ролика — сразу монтажёру (VOICE_LONGER).

## Что сделано

1. **Мастер из вышедшего ролика сам** — `lib/narrationAutoMaster.ts`, задача `narration-auto-master`
   (раз в минуту, ОДИН объект за тик, предел 15 мин, замок `videoMasterMixingAt` общий с перемиксом).
   Звук ролика (ffmpeg, WAV) → сервис `voice-separator` (новый контейнер, `apps/voice-separator`:
   MDX `Kim_Vocal_2.onnx` на процессоре) → картинка + музыка без голоса = мастер
   (`storeNarrationMaster`, `Property.videoMasterSource = "MACHINE"`) → сразу `remixFromMaster`.
   Только для ВЫШЕДШЕГО ролика: новый (ещё не вышел) по решению 12.11 озвучивает монтажёр.
   Ролик без звука вовсе — мастер = сам ролик.
2. **Сторож качества** — сервис распознаёт речь в оставшейся музыке (faster-whisper small, int8).
   Слов больше `VOICE_SEPARATOR_RESIDUAL_WORDS_MAX` — мастер бракуется, причина в
   `videoMasterAutoError` (на этот готовый файл повтора нет), журнал ошибок, объект — монтажёру
   прежним возвратом (`sendNarrationToMontajer`). Отказ или таймаут сервиса — то же самое.
3. **Длина голоса = длина ролика** (`planNarrationFit`, `lib/narrationMix.ts`), только при перемиксе:
   (а) голос длиннее до 15 % — `atempo` (высота голоса та же); (б) больше — другой шаблон того же
   языка, текст короче, ОДНА платная перегенерация на версию (`shortenedFromId`; только если текст —
   шаблон без ручной правки и по оценке «секунды ∝ символы речи» встаёт лучше), версия одобряется
   сама на того же человека; (в) всё ещё длиннее — ускорение 15 % + стоп-кадр последнего кадра ≤ 3 с;
   (г) иначе — монтажёру, как раньше. Ролик длиннее голоса — норма. Что сделано с длиной — строка
   агенту в карточке (`PropertyNarrationVersion.mixNote` → `mix.note`). Приём ролика от монтажёра
   прежний: там голос длиннее — отказ, монтажёр пришлёт длиннее.
4. **Рубильник** `autoSeparateVoice` в Настройках озвучки — по умолчанию ВКЛЮЧЁН (решение 16.11);
   работает только при `CRM_NARRATION_EXECUTION_MODE=LIVE` и заданном `VOICE_SEPARATOR_URL`
   (в compose по умолчанию `http://voice-separator:8090`).
5. **Сервер**: сервис `voice-separator` в `docker-compose.prod.yml` (read-only, /tmp в памяти, 6 ядер,
   4 ГБ, наружу не открыт). Выкат образ НЕ собирает (~15 мин, предел службы выката 900 с): один раз
   руками `docker compose --env-file .env.production -f docker-compose.prod.yml build voice-separator`;
   `ops/deploy.sh` шаг 3.1 только поднимает готовый образ и не роняет выкат, если его нет.

## Новый объект (пункт 4 задания)

Цепочка «мастер выбирает озвучку → шаблон → генерация → агент одобряет → монтажёру → ролик →
хозяин одобряет / сам через 3 ч» — проверена существующими тестами (narration-auto-flow,
narration-delivery, narration-crm-mix, clip-owner-approve): все зелёные. Код этого PR её не меняет
(машина трогает только вышедшие ролики).

## Замеры (ноутбук i7-10750H, перегружен: свободно 0–1 ГБ памяти из 15,8)

ФАКТ, venv, Kim_Vocal_2 + whisper small int8, весь ролик:

| ролик | длина | отделение | проверка речи | всего | слов в оригинале | слов в музыке |
|---|---|---|---|---|---|---|
| №143 | 38 с | 98,9 с | 6,7 с | 107,9 с | 66 | 0 |
| №192 | 75 с | 117,7 с | 20,0 с | 170,9 с | 76 | 0 |
| №197 | 119 с | 163,0 с | 93,2 с | 258,5 с | 60 | 73 (103 с речи) |

- №197: голос НЕ отделился (в «музыке» та же таджикская речь). Сторож это ловит → объект уходит
  монтажёру. Причину (моно-сведение? голос без отдельной музыки?) надо послушать в исходнике.
- Docker-образ: 1,83 ГБ, сборка ~15 мин (скачивание torch и моделей; на ноутбуке whisper падал по
  сети трижды). Проверен в режиме прода: `--read-only --tmpfs /tmp --cpus 6 --memory 4g` — health,
  №143 → 0 слов, записи вне /tmp нет. Время в контейнере на ноутбуке (594 с на 38 с) не показатель:
  WSL дал Docker 3,8 ГБ при 0,3 ГБ свободных на хосте.
- ОЦЕНКА для прода (AMD EPYC 12 ядер, 6 отданы сервису, без нагрузки): в 2–4 раза быстрее ноутбука —
  ~0,5–1 мин на 40-секундный ролик, ~1,5–2,5 мин на 2-минутный; плюс ~10–30 с сведения. НЕТ ДАННЫХ
  замера на сервере: первым делом после выката посмотреть строку `[narration-auto-master] … готов за N с`
  в журнале worker.
- Сведение и подгонка длины на стенде (тестовые ролики 6 с): 2–5 с на ролик.

## Порог сторожа

Чистая музыка — 0 слов; ложные срабатывания распознавания — 1–2 слова (Demucs в прошлом тесте);
голос не ушёл — десятки слов. Брак: **5 слов и больше или 3 с речи и больше**
(`VOICE_SEPARATOR_RESIDUAL_WORDS_MAX = 4`, `…_SPEECH_SEC_MAX = 2.9`). Данных мало (3 ролика) —
проверить на 5–10 настоящих случаях.

## Что не трогали и что открыто

- 90 старых роликов без версий озвучки: смена цены у них озвучку не создаёт (как и раньше) —
  решение владельца «массово не трогаем». Чтобы и они получали новую озвучку при смене цены,
  нужен отдельный шаг (черновик при правке цены у объекта без версий) — предложено владельцу.
- `audit:deps`: два цикла импортов в телефонии/заявках (`autoLeadFromCall`, `agentOccupancyShield`)
  уже есть в main, к этой правке не относятся. Свой цикл narrationAutoFlow ↔ narrationAutoMaster
  разорван (шаги потока передаются параметрами).
- Тесты фронта uiPrefs/aiSounds/draftUploads на ноутбуке падают и на чистом origin/main
  (тайм-ауты) — окружение, не эта правка.

## Ревью architect (16.11) и что исправлено

1. Адрес сервиса был только у worker, а «Одобрить» в CRM работает в api → объект уходил монтажёру.
   Исправлено: `VOICE_SEPARATOR_URL` в общем наборе переменных (`crm-env`).
2. fetch (undici) ждёт заголовки не дольше 300 с, а сервис шлёт их в конце работы → «12 мин» были 5.
   Исправлено: запрос через node:http со своим таймаутом 15 мин; нет итога проверки речи — отказ
   (сторож закрыт при сбое).
3. Сборка образа внутри выката упиралась бы в предел службы 900 с и ночную чистку кэша.
   Исправлено: выкат не собирает образ, только поднимает готовый.
4. Обход брал 50 старейших и мог застрять. Исправлено: условия в запросе + курсор по кругу; машину
   выключили после одобрения — обход отдаёт объект монтажёру (одна отметка на ролик).
5. Отказ отдавал монтажёру версию, снятую до отделения. Исправлено: свежая версия на момент отказа;
   монтажёру уйти нечем (голос вклеен не по передаче CRM) — журнал и карточка говорят «в соцсетях
   прежний ролик», а не «заменит монтажёр».
6. Временный сбой сервиса клеймил ролик навсегда. Исправлено: до трёх попыток с паузой 10 мин
   (`videoMasterAutoAttempts/RetryAt`), клеймо — брак сторожа и окончательный отказ; новый готовый
   ролик сбрасывает отметки. Предел тика 30 мин, замок объекта 40 мин.
7. Telegram обещал «CRM заменит» и для не вышедшего ролика — исправлено.

Не исправлено, вынесено владельцу: калибровка сторожа на 3 роликах (предложение — первые машинные
ролики через одобрение результата); замер на сервере; 90 старых роликов без озвучки.

### Повторное ревью (16.11)

Все находки подтверждены закрытыми. Дополнительно: сервиса нет вовсе (образ не собран, ENOTFOUND)
или не уложился в 15 мин — сразу монтажёру, без повторов (однопоточный сервис всё равно досчитывает

## Решение владельца 16.11 (вечер): монтажёр сдаёт ОДИН файл

Дословно: «Я хочу, чтобы монтажер не присылал тебе отдельный этот файл… просто монтажер отправлял тебе
один файл с музыкой, с озвучкой и так далее, а дальше мы сами делали». Сделано: пока включено
«CRM сама убирает старый голос» (`autoSeparateVoice`, по умолчанию вкл.), второй файл «без голоса»
у монтажёра не просится нигде — строка задания (`narrationLineForMontajer`), подпись к mp3
(`narrationDelivery`), возврат «замените голос» и «вклейте голос», кнопка-вопрос после сдачи
(`voicelessCopyAsk`). Одно место решения — `voicelessCopyHint(config)`. Если монтажёр всё же пришлёт
такой файл сам — он по-прежнему принимается и лучше машинного. Выключили рубильник — прежняя просьба.
Следствие: у новых роликов при смене цены голос убирает машина; где не выйдет (как №197) — монтажёр.
