# 31.10.2026 — ИИ-помощник: права как у REST, поля клиента в границах «данные» (П2, задачи 2.1 и 2.5)

Источник: `docs/design/internal-assistant-architecture-2026-10-31.md`, §1.2 №1, №8, №11, №14; §6 строки 2.1 и 2.5.

- Что изменилось:
  - **Одна сборка прав помощника.** `ai/assistant/actor.ts`: `AssistantActor` переехал сюда
    (из `assistant.ts` переизлучается), `actorFromAccess(agentId, access)` строит его из того же
    `AgentAccess`, что `requireAuth` (тип теперь экспортирован из `auth/middleware.ts`).
    Новые флаги: `canAssignClients`, `canEditForeignProperties`, `canModerate`, `canRequestChange`
    и полный набор `permissions`. `routes/ai.ts` строит актора одной строкой.
  - **Дыра в правах на задачи закрыта.** `create_task`/`reschedule_task` пускали в чужую карточку
    любого с `clients.viewAll` — служба безопасности (viewAll без `clients.assign`) заводила задачи
    и двигала встречи там, куда экран её не пускал. Правило `foreignWriteDenied` вынесено чистой
    функцией `clientWriteDenied` (`lib/clientWriteAccess.ts`); REST зовёт её через прежний
    `foreignWriteDenied`, помощник — через `assertClientWritable` (плюс акционер «только смотрит»,
    агент — только свои принятые). `reschedule_task` больше не трогает отменённые задачи, записи
    расследования (не директору/админу) и — у рядового агента — чужие задачи в своей карточке
    (как `PATCH /interactions/:id/complete`).
  - **Поля клиента — в `wrapUntrusted`.** Имена клиентов, названия объектов, текст задачи в ответах
    инструментов идут модели в границах `<client_content kind="crm_note">` (`safeField`, потолок
    300 знаков); закрыть границу из имени нельзя.
  - **Промт из прав.** Справочник разделов собирается из прав актора
    (`ai/assistant/promptSections.ts`, те же условия, что меню `navigation.ts`); недоступные
    инструменты (финансы, источники лидов, запись для акционера) модели не объявляются.
    Версия промта `2026-10-31.2-rights`.
  - `get_finance_summary`: `settings.upsert` → `findUnique` (инструмент чтения больше не пишет).
- Почему: архитектура помощника, пункты 2.1 и 2.5 волны П2 — помощник не должен давать
  сотруднику больше, чем обычный REST.
- Чем проверено: `tests/ai-assistant-rights-gaps.test.ts` (19 тестов, из них 12 новых): матрица
  ролей AGENT/MANAGER/ADMIN/DIRECTOR/SECURITY/EDITOR/SHAREHOLDER × своя/чужая/завершённая карточка
  сверяется с решением REST (`foreignWriteDenied` + проверка владения); объявленные инструменты и
  разделы промта по ролям; инъекция через имя и название объекта; отсутствие `upsert`. Сторож
  проверен нарочной поломкой (вернуть `viewAll` вместо `assign`, снять обёртку, фильтр инструментов,
  фильтр задач, вернуть `upsert`) — 8 тестов красные. Смежные: все `ai-assistant-*`,
  `foreign-card-write-all-actions`, `access-control`, `client-transfer-access`,
  `deal-security-read-only`, `law-lead-ownership` и др. — зелёные. `build:shared/api/web` — 0,
  `map` + `map:check` + `map:gate`, `audit:deps:gate`, `audit:rules`, `audit:mocks` — чисто.
- Что осталось: перенос показов (`SHOWING`) через `reschedule_task` мимо `rescheduleShowingById` и
  выбор «самой дальней» задачи — задача 2.4 (другой исполнитель); флаги `canEditForeignProperties`,
  `canModerate`, `canRequestChange` пока не используются ни одним инструментом — заготовка под
  инструменты объектов. Вход из Telegram должен строить актора тем же `actorFromAccess(loadAgentAccess(...))`.
