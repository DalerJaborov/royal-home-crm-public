# 17.11.2026 — Выключатели автоматики «Работа с продавцами»

Начато 14.11.2026 одним исполнителем, доведено 17.11.2026: сведено со свежим
`main`, добавлен сторож одной двери, проверено.

- Что изменилось: в Настройках → «Сроки» (вкладка дисциплины) появился блок
  «Работа с продавцами»: главный выключатель и восемь своих. Все включены по
  умолчанию (`@default(true)`), поэтому после выката ничего не меняется —
  выключает владелец сам. Действующее значение = главный И свой. Пока главный
  выключен, свои строки на экране скрыты (их значения запомнены).
  - Поля `Settings` (миграция `20261118170000_seller_automation_switches`, только
    `ADD COLUMN ... BOOLEAN NOT NULL DEFAULT true`): `sellerAutomationMasterEnabled`,
    `sellerNoPropertyAlarmEnabled`, `sellerPropertyMissingAntifraudEnabled`,
    `agentUnansweredAlarmEnabled`, `dealStaleSellersEnabled`, `sellerProbeCallEnabled`,
    `dealAfterCloseMessagesEnabled`, `sellerAiAnalysisEnabled`,
    `morningSellerLinesEnabled`. Метка времени миграции поставлена ПОСЛЕ
    последней миграции `main` (20261118160000), а не 14.11: иначе новая миграция
    легла бы в истории раньше уже применённых на проде.
  - Одно место: список, схема сохранения, правило и подписи —
    `packages/shared/src/sellerAutomationSwitches.ts`; чтение — одна дверь
    `apps/api/src/lib/sellerSwitches.ts::sellerSwitchOn` (без кэша, вызов в начале
    тика/задания; выключено — тихий выход без ошибки и тревоги).
  - Что гасит каждый: «агент не отвечает» и «застой сделки» — только продавцов,
    покупатели как раньше (список для дашборда не прячется); «сообщения после
    сделки» — вопрос об отзыве ПРОДАВЦУ (`deal-review-ask`; покупателя спрашиваем всегда) и пуш интейкеру «ваш объект
    продан» внутри `deal-close-followup`, а пересчёт карточки продавца, запись о
    продаже, задача про пост и снятие объекта с сайта остаются; «ИИ разбирает фото
    и переписку» — только вызов модели (`seller-photo-insight`, `seller-facts`),
    приём фото и сообщений не трогается; «робот звонит собственнику» — оба тика
    набора (`seller-probe-call` и `approved-owner-verification`), итог уже начатого
    звонка записывается; «продавцы в утренней сводке» — две строки push-сводки
    директору в 08:00 (`cron.ts::sendDirectorDigest`) и строка голосового брифинга
    (`lib/morningBriefing.ts`).
  - PATCH `/settings` принимает поля через `sellerAutomationSwitchesUpdateSchema.shape`,
    смена каждого пишется в журнал действий (`SETTINGS_UPDATE`).
  - Сторож (новый): `tests/seller-automation-switches.test.ts`, блок «сторож» —
    у каждого своего выключателя есть вызов `sellerSwitchOn("<ключ>")`, имя поля
    в коде сервера встречается только внутри такого вызова (прямое чтение мимо
    двери забыло бы про главный), миграция только добавляет колонки с DEFAULT true.
    Проверен внесением поломки: прямое чтение поля вместо вызова двери — оба
    правила красные; лишняя колонка с DEFAULT false в миграции — красное.
- Почему: владелец хочет иметь возможность остановить любую автоматику по
  продавцам из Настроек, без правки кода.
- Чем проверено: `build:api`, `build:web`, `test:web` (383 файла, 2385 тестов),
  точечно 10 файлов сервера на стенде (141 тест), `map` + `map:check`, `precheck`;
  кадры блока: ПК и узкий телефон, светлая и тёмная тема (локально, не в git).
- Что осталось:
  - «Работа встала» и «заявлено больше, чем добавлено» — заглушки с 02.10.2026,
    их выключатели сейчас ничего не меняют (подпись на экране так и говорит).
  - Вопрос об отзыве, время которого пришло при выключенном выключателе, не
    отправляется и позже не досылается (задание завершается молча).
  - Не охвачено (не было в задании): строка про продавцов в голосовом брифинге
    (`lib/morningBriefing.ts`) и на экране утреннего отчёта (`routes/morningReport.ts`);
    эпизоды контроля продавца (`lib/sellerControlEpisodes.ts`, держатся отдельным
    серверным флагом) и предпросмотр проверки собственников
    (`lib/ownerVerificationSources.ts`) — без своего выключателя.
  - Шабнам («режим директора», `lib/settingsSwitches.ts`) эти выключатели не
    переключает: в белый список они не добавлены.
