# 17.11.2026 — свободный ролик в соцсети загружается частями

**Что было.** Экран «Ролики в соцсети»: файл 87 МБ (Surayo Pro Max) → «Файл слишком большой для
отправки.» (HTTP 413 без JSON — отвечал прокси, не API). Ролик шёл ОДНИМ запросом
`POST /api/v1/social-videos`. Перед сервером стоит Cloudflare (замер 17.11: тело 95 МБ проходит,
105 МБ — 413 `Server: cloudflare`) и Caddy на хосте; приложение (multer 2 ГБ, nginx 2100m)
обещало 2 ГБ, а цепочка прокси столько не пропускает.

**Что сделано.** Ролик режется на части по 8 МБ — тот же приём, что у роликов объектов
(`upload-sessions`), и та же склейка с диска (`lib/localVideoStorage.ts`), но без записи в базе:
- API: `POST /social-videos/upload-sessions` (старт, план частей) →
  `PUT …/:sessionId/parts/:n` (сырые байты, повтор безопасен) →
  `POST …/:sessionId/complete` (склейка → тот же `createSocialVideoFromUpload`).
  План и владелец сессии — `meta.json` рядом с частями; чужая сессия — 404; брошенные
  сессии старше суток убираются при старте следующей. `lib/socialVideoUploadSessions.ts`.
- Экран: `lib/socialVideoUpload.ts` — части по очереди, упавшая часть повторяется до 4 раз
  (сеть, таймаут, 5xx), сборку сами не повторяем (дубль); прежние правила ожидания сохранены.
  Фото-пост и одиночный `POST /social-videos` (старые вкладки) не тронуты.
- nginx: блок для `/api/v1/social-videos/upload-sessions` — без буферизации, ожидание 600 с.

**Чем проверено.** `apps/web` socialVideoUploadWait.test.ts 6/6 (порядок шагов, повтор 502,
обрыв после всех попыток, 400 не повторяется, ожидание сборки 5+ мин, 10 мин — подсказка);
`apps/api` social-video.test.ts 58/58 (новый: старт→часть→сборка, 409 до частей, 400 не тот
размер, 404 чужая сессия, повтор сборки не делает второй черновик, 422/403 на старте).

**Осталось.** Сборка больших файлов идёт синхронно: при перепаковке дольше 100 с Cloudflare
отдаст 524, хотя черновик создастся (экран подскажет открыть список). Если такое будет —
сборку в фон с опросом статуса.
