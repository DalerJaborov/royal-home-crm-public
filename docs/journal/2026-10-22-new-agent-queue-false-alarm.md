# 22.10.2026 — Заведение сотрудника: ложная тревога «в очередь не добавили (станция не ответила)»

## Что случилось

При заведении обычного агента CRM ответила директору:
«Внутренний номер 1016 выдан, но в очередь входящих на АТС его добавить не удалось
(станция не ответила) … добавьте участника в FreePBX». Станция при этом ответила,
а в очередь обычный агент и не должен был попасть: с 20.09.2026 незнакомые
звонки получают только операторы (`Agent.takesUnknownCalls`), агент отвечает
только своим клиентам.

## Почему

Проверка в `routes/agents.ts` (POST /agents) написана 19.09, когда в очередь шли
все агенты, и после правила 20.09 не менялась: она считала «не оказался в
`added` → не добавили → станция не ответила». Схема создания сотрудника
`takesUnknownCalls` не принимает, поэтому новичок никогда не оператор, и
тревога звучала на КАЖДОМ заведении агента с номером — директора слали в FreePBX
добавлять участника, которого по правилу владельца быть не должно.

## Что изменилось

- `lib/telephony/agentIncomingReadiness.ts`: новый помощник
  `describeNewAgentQueueOutcome(agent, fix)` — ответ выводится из ОЖИДАНИЯ, а не
  из факта добавления. Не оператор → молчим (сверка всё равно отработала: она
  ещё и снимает с очереди прежнего владельца номера из пула). Оператор → только
  настоящая неудача с настоящей причиной; «станция не ответила» — только когда
  сверка упала целиком.
- `routes/agents.ts`: блок заведения зовёт помощника вместо своей логики.
- При отказе исключить обычного агента предупреждение называет именно исключение
  и возможные лишние входящие, без совета добавить не-оператора обратно.
- Карта продукта пересобрана: предыдущая облачная проверка остановилась на
  `map:check`, потому что карта ещё описывала удалённый `stillOut`.

## Чем проверено

- `agent-incoming-queue.test.ts` — 21/21, отдельная новая PostgreSQL 16 с 537
  миграциями и заглушкой АТС. До исправления исключения: 20 успешных и ровно
  один упавший регрессионный тест; после исправления все успешны.
- `npm run map:check` — успешно после пересборки.
- `npm run build:api` — успешно.
- Облачные проверки исправленного коммита и производственный выпуск проверяются
  отдельно; локальный результат не подтверждает выкат.

## Что осталось

- Обычного агента добавлять в очередь не нужно: свои звонки он получит.
  Если владелец хочет, чтобы он принимал незнакомые — включить «Принимает
  незнакомые звонки» в карточке (PATCH принимает `takesUnknownCalls`); обход
  раз в 15 минут допишет его в очередь сам.
- Схема создания не принимает `takesUnknownCalls` — оператора можно назначить
  только после заведения. Не трогал: отдельное решение.
