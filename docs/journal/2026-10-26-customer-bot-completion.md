# Customer bot: bounded failure recovery and prepared property photos

Managed function responses could expose syntactically valid tool calls even when the provider reported an incomplete or blocked generation. The managed adapter now checks the native finish state before exposing calls, retains usage accounting, and reports a closed diagnostic cause. The legacy adapter and existing operation, turn and tool budgets are unchanged.

Private DM instructions now explicitly exclude public-only skip/moderation decisions. Remaining-budget metadata is supplied through initial context, real function responses and existing correction feedback; signed model history is preserved. A narrow unresolved standalone-link case can ask for clarification. A verified committed receipt can close a later model exception only while the original operation, deadline and ownership remain live; unknown writes and stopped operations stay held.

Recruitment continuation suppresses previously presented current conditions instead of repeating the vacancy at every answer. A title mention alone, changed conditions and explicit detail questions retain the appropriate response; both languages are checked independently. Exact stop and validated rejected-decision metadata are optional, closed and text-free.

The new-lead observer can initialize buyer room/type/explicit TJS criteria from authenticated own statements. It preserves raw notes, omits ambiguous/quoted/foreign-currency criteria, and does not update existing cards or staff-owned fields. Provided authoritative context keeps precedence.

Property photos are prepared behind `CUSTOMER_PROPERTY_MEDIA_EXECUTION_MODE`, which defaults to `OFF`; missing/invalid values also mean OFF. PREVIEW does not enqueue images. LIVE is a separate operator decision and is not enabled by this change. Existing photo permission and per-offer cap still restrict it. Only current server-resolved offerable CRM assets can receive an endpoint/revision/focus/source-bound witness. Text stays first; durable image attempts record MID/UNKNOWN, accepted projection preserves reply-to reference, and an unknown send is never an implicit retry. Revalidation precedes physical dispatch; model URLs cannot create media authority. No new voice/file transport or permission is granted.

Local validation before full cloud verification: 274 Core/renderer/trace/intake/media tests, 75 provider/transport tests, and 85 PostgreSQL integration tests across eight suites passed on a dedicated synthetic database. This includes signed ingress through FINAL_IN, actual journal/lead creation, ordered outbox delivery with mocked provider HTTP, opt-out/pause and source revocation, immutable payload enforcement, UNKNOWN non-retry, and reply-to-photo resolution. Shared/API type checks and the product map passed; the map retains 52 screens and 714 flows. Full exact-commit cloud checks and any deployment/activation remain separate.

Historical production inputs and diagnostic exports remain outside the public repository. The inspection corrected an older raw event-key lookup: traces use account-scoped HMAC pseudonyms. Historical outcomes are not rewritten or blindly resent. Synthetic replay proves the tested branches; it does not establish live-model conversational accuracy or complete historical behavior.
