# 16.11.2026 — Убраны папки и статусы клиента, лимит заявок, светофор и автокорзина (шаг 1)

- **Что изменилось.** Решение владельца 16.11.2026: «удалить все папки и статусы
  типа активный и так далее, ничего лишнего… лимитов заявок больше нет и не будет».
  Клиент теперь либо в списке агента, либо со сделкой, либо в Корзине (её делает
  только человек).
  - **Лимит активных лидов снят целиком.** `lib/leadLimits.ts` удалён; раздача
    (`services/leads/selection.ts`) никого не отсекает по числу клиентов, «пауза
    после слива» (cooldown) тоже снята. Осталось только число нагрузки
    (`lib/agentLoad.ts`, покупатели в работе) — им стратегия fair выбирает, кому
    дать лид, и его показывают «Команда»/помощник. Убраны «освобождение места под
    свой объект» (`requiresRelease`, `releaseClientId`), уведомления «портфель сверх
    лимита», плитки/списки «агенты у лимита», «свободно мест», «Свободны: …».
  - **«Неактивные», «Отложенные», светофор — удалены.** Модули
    `inactiveTrafficLight`, `noAnswerTrafficLight`, `clientInactiveTextDetector`,
    `silentClientAutoDeactivate`, `deferredClients`, `clientWorkStatus` удалены;
    ветка «ИИ приостанавливает клиента» в `ai/callAnalysis.ts` и поле
    `inactiveReason` в запросе к модели убраны; первый звонок при исчерпанном
    пределе передач больше не переводит в «Неактивные» (только эскалация).
    Маршруты `POST /clients/:id/activate`, `POST /clients/:id/deferred/return`,
    `GET /clients/deferred`, `GET /oversight/traffic-light-summary`,
    `GET /oversight/inactive-clients`, `GET /oversight/agents-at-limit` удалены.
  - **«Потерянные» и «Архив» как состояния — убраны.** `markClientLost` удалён.
    «Без сделки» с исчерпанным пределом передач теперь кладёт клиента в Корзину
    с причиной в хронологии (`lib/clientRefuse.ts` → `trashClient`), а не в LOST;
    вердикт СБ закрывает карточку Корзиной вместо ARCHIVED; «Передача» с
    исчерпанным пределом оставляет клиента у агента с эскалацией руководителю;
    продавец без объектов в работе больше не уходит в LOST сам. Входящий звонок
    вернувшегося клиента идёт его агенту (закрыта только сделка — DEAL_CLOSED).
    Возврат из Корзины при новом обращении (`resumeExistingChannelLead`) не тронут.
  - **Автокорзина через 90 дней** (`lostInactiveTrashSweep`) и **ночные автостатусы**
    (`clientAutoStatus`: Новый/На контакте/Горячий/Холодный/Не отвечает/Архив)
    удалены вместе с кронами `inactive-traffic-light`, `deferred-clients-return`,
    `client-auto-statuses`, `silent-client-auto-deactivate`, `lost-inactive-trash-sweep`.
  - **Список клиентов один.** `CLIENT_IN_WORK_WHERE` прячет только закрытую сделку
    и назначение с завершённой работой; старые LOST/ARCHIVED снова видны в списке
    (новых таких переходов код не делает). Экраны `LostClients`, `DeferredClients`,
    «Воронка лидов», `InactiveLevelBadge`, вкладки «Неактивные/Отложенные/
    Потерянные/Воронка» на ПК и телефоне, фильтр «Статус», цветные отметки статуса
    в строках, «Вернуть в работу»/«Поднять из Отложенных» в карточке, светофор и
    «агенты у лимита» в «Контроле», настройки лимита/взвешенных слотов/светофора/
    «учитывать неактивных и отложенных в подборе» — удалены. Старые адреса
    (`/lost-clients`, `/inactive-clients`, `/deferred-clients`, `/lead-funnel`)
    ведут на `/clients`. Отметка у клиента — только факт: Корзина, прочее
    обращение, закрытая сделка, ждёт принятия, причина с сервера.
  - **Светофор вырезан из кода целиком** (уточнение владельца через координатора):
    никто больше не читает и не пишет `inactiveLevel`, `inactivePingCount`,
    `inactiveSince`, `inactiveReasonKey`, `inactiveEnteredAt` (снимки ручного
    назначения, восстановление из Корзины, звонок клиента, подбор, дубли, общий
    тип `MatchingClient`); `inactiveExitData` заменён на `resumeWorkData`
    (только workStatus=ACTIVE). Удалён «хвост» дозвона: крон `no-answer-tail`,
    `processNoAnswerTailAnchors`, маячки `noAnswerTail:` при эскалации и поля
    `noAnswerTail*` в правилах дисциплины. Сигнал «Серия у агента» считает только
    старые LOST. Прочие кроны (inactivity-check, тревоги) не тронуты — отдельное
    решение владельца. Колонки остаются до миграции.
  - **Миграция данных** `20261117160000_client_work_status_normalize`: INACTIVE/
    DEFERRED → ACTIVE, каждое изменение — строкой в `StageEvent` (откуда), колонки
    не трогаются, повторный запуск ничего не делает. Карточки с нерешённым
    предложением прежнему агенту (`reactivationOfferedToAgentId`) не трогаются.
  - **Сторож** `apps/api/tests/no-client-status-folders.test.ts`: удалённые модули
    не возвращаются, новых записей/поисков INACTIVE/DEFERRED/LOST/ARCHIVED вне
    списка исключений нет, лимит никто не читает, кроны не регистрируются.
- **Ответы владельца 16.11 (вечер).**
  - **Старые «Потерянные» — в обычный список.** Миграция
    `20261117170000_client_lost_back_to_work`: LOST → CONTACTED (был первый
    контакт) или NEW, `lostAt`/`refusalCount` остаются историей, каждое изменение
    — строкой в `StageEvent`, повтор ничего не делает. ARCHIVED не тронут и в
    список не попадает («архив — та же корзина»). Подписи «Потерянный» убраны из
    экранов (окно передачи, настройки, команда).
  - **«Без контакта» — одно правило, один счётчик.** Правило и порог —
    `packages/shared/src/clientNoContact.ts` (`NO_CONTACT_AFTER_DAYS = 1`,
    `isWithoutContact`): контакт — только разговор по телефону (TALKED или
    длительность) или сообщение самого клиента в любом чате (агенту или боту);
    заметки, задачи, исходящие — не контакт; новая карточка считается от
    создания, `lastContactAt` не читается. Сервер — `lib/noContact.ts`
    (`noContactWhere`): счётчик сводки, плитка и срез «Без контакта» в
    «Контроле руководителя» (`GET /oversight/no-contact-clients`, флаги и
    «Принято»), блок в карточке сотрудника «Команды», контекст помощника директора,
    фильтр `/clients?noContact=1` для главной агента. Удалены: «горячий клиент
    без контакта» (`/oversight/stalled-clients`, `stalledClients` у сотрудника),
    «без касания» в пульте, свой подсчёт «остывших» на главной агента по
    `lastContactAt`, подпись «больше суток без разговора». Тест
    `apps/api/tests/no-contact-rule.test.ts` прибивает правило (бот-чат считается,
    заметка нет, новая карточка — от создания).
  - **Окружение проверки.** В общем `node_modules` основной папки нет `recharts`,
    `clsx`, `jsdom`, `@testing-library/react` и др. (нет и в apps/web), поэтому в
    этой рабочей копии ссылки на общий node_modules сняты и сделан свой `npm ci`;
    основная папка не трогалась. С полными зависимостями все тесты сайта зелёные —
    прежние 6 падений были от окружения (нет jsdom).
  - **Конец работы — заявка на удаление руководителю (после ревью PR #220).**
    Отказ на пределе передач, исчерпанная передача и отказ продавца после снятия
    последнего объекта больше НЕ убирают карточку в Корзину сами: «пусть сами люди
    решают» = руководитель. Одна дверь `lib/clientDeleteRequest.ts` (ей же
    пользуется кнопка агента): заявка в очереди «Заявки на удаление» и пуш тем, у
    кого `clients.delete`. «Продан в обход» остаётся у агента (проверка СБ).
  - **Доводки ревью.** Утренняя раздача — только настоящие новые заявки
    (`newLeadOnlyWhere`: свежие 48 ч или поставленные в очередь за 48 ч, или
    ни разу не тронутые и не бывшие потерянными) — бывшие LOST без агента не
    рассылаются как «новый лид с ночи». Миграция
    `20261117180000_client_lost_back_to_work_list` снимает
    `assignmentCompletedAt` у бывших LOST (иначе они не в списке «в работе») и
    заполняет `lostAt` как историю. Честная раздача считает ЖИВУЮ нагрузку
    (`activeBuyersLoadWhere`: контакт за 30 дней, сделка в работе или заявка за 30
    дней) — иначе новичок получал бы каждую заявку. Возврат из Корзины всегда
    обнуляет отказы и круги передачи. «Серия потерь» и «потери по каналу» —
    по отметке отказа (`assignmentRefusedAt`), не по LOST. Звонок по карточке в
    Архиве — в очередь (Архив владелец не трогал). Рассылка «вернуть клиента» и
    снятие старой паузы бота — по общему правилу «без контакта» со своими порогами.
    «Горячий/Холодный/Не отвечает» больше никто не пишет (отмена и аннулирование
    сделки возвращают «На контакте»), значки и «Лиды по этапам» сняты, «из N»
    убрано. «Без контакта» — порог явно: без единого контакта — сразу, был контакт
    — через сутки после последнего; тем же правилом пульт директора и плитка
    «Сделки в работе»; список руководителя отсортирован по последнему настоящему
    контакту; на компьютере в «Клиентах» тот же счётчик и срез, что на телефоне.
    Имя в строке списка на телефоне больше не сжимается до 2-3 букв рядом с чипом.
  - **Тесты удалённого поведения.** `law-lead-ownership` (П-6 лимиты, П-11 причины
    скрытия), `conducted-showing-gate` (`/activate` → теперь закреплён 404),
    `seller-refusal-review` приведены к новым правилам.
  - **Ловушка прогона.** Полный `test:api`, запущенный фоновой командой чата,
    дважды обрывался без итоговой строки `[тесты] … файлов N, тестов M, упало K`,
    а обёртка печатала код 0. Верить только итоговой строке раннера; полный
    прогон запускать отдельным процессом. Причина обрыва не установлена.
  - **17.11.2026 — решения владельца в ту же ветку.**
    - Подписи статусов клиента сняты с экранов ЦЕЛИКОМ, «Новый» и «На контакте»
      тоже: значки и колонки «Команды», «Лиды по этапам», «Где застревают
      клиенты», статус в карточке помощника, «Сделка закрыта» как отметка,
      фильтр и сортировка по статусу. Статус больше никто не пишет вручную:
      PATCH со статусом — 400 для всех, вебхук сайта статус не меняет. Колонка
      осталась для внутреннего (закрытая сделка, Архив); Архив — отдельным срезом
      `archived=1` для экрана «Архив». ИИ-помощник статус не называет.
    - Вкладки «Не на виду» нет (телефон и компьютер); старая ссылка
      `/clients/all-mine` ведёт в обычный список. Карточку с заявкой на удаление
      агент просто не видит — решает руководитель.
    - Этапов покупателя «Подбор»/«Переговоры» (`buyerStage`) в коде нет; в
      «Итоге показа» остались «Повторный показ», «Клиент думает», «Подготовка
      договора», «Клиент отказался». Подбор исключает только последний отказ
      «уже купил»; возврат из Корзины снимает и его.
    - Заявки на удаление решает РОП («РОП тут главнее») вместе с директором:
      у роли HEAD_OF_SALES по умолчанию `clients.delete`. Права = набор роли +
      личные надстройки (granted/revoked), поэтому миграция не нужна: у
      действующих РОП право появится само, если директор не снял его галочкой.
      Пуш о новой заявке идёт по этому праву — РОП и директору.
    - Сторож `no-client-status-folders.test.ts` дополнен: подписи статусов на
      сайте и в сервере, сортировка/фильтр по статусу, «Не на виду», `buyerStage`
      (проверен внесением поломки).
