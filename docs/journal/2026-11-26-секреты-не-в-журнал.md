# 26.11.2026 — Секреты не попадают в журнал ошибок

- Что изменилось: новая общая функция `redactSecretsInText`
  (`apps/api/src/lib/secretRedaction.ts`) маскирует `***`-ом значения
  `access_token=`, `token=`, `api_key=`, `key=`, `client_secret=`, `k=`, `t=` и
  соседей в адресах, `"access_token":"…"` в JSON-тексте, `Bearer …`/`Basic …` и
  ключ бота Telegram в пути `/bot<id>:<ключ>/`. Её зовут обе записи в ErrorLog:
  `logSystemError` (текст, адрес, стек; до лога контейнера) и приём ошибок
  браузера `POST /api/v1/errors`. Значение короче четырёх знаков не трогается,
  запись никогда не удлиняется. `code=` намеренно не маскируется:
  `ai/geminiClient.ts` пишет туда номер ошибки.
- Почему: проверка безопасности 26.11. Больше двадцати вызовов Graph API несут
  маркер доступа в адресе, браузер шлёт адрес страницы с подписанной ссылкой, а
  журнал читают все с правом auditLog.view. Сейчас ни один найденный путь
  адрес с ключом в журнал не пишет (ОЦЕНКА) — это защита по умолчанию, чтобы
  следующая ошибка с адресом в тексте не унесла ключ.
- Чем проверено: `tests/secret-redaction.test.ts` — 21 тест: маска по формам,
  обычный текст ошибок (включая `code=429`) не меняется, длина не растёт, обе
  двери чистят запись в базе целиком. Сторож: файл, который пишет в ErrorLog и
  не зовёт `redactSecretsInText`, валит тест. Без правки — 3 красных (обе двери
  и сторож), с правкой — 21 из 21.
- Что осталось: тот же механизм в колонках `lastError`/`failReason` фоновых
  таблиц — PropertyNarrationDelivery, OwnerReportDelivery, LeadMagnetDelivery,
  StationOutage, CronHeartbeat, BackgroundJob, WhatsAppFirstContact. Туда
  пишется текст ошибки внешнего вызова; маску стоит провести через ту же
  функцию отдельной правкой. BotTurnTrace уже чистит себя сам
  (`traceKnownSecrets`), AiLog свободного текста не хранит.
