## А. Замок платных скриптов (`scripts/elevenlabs/paid-guard.mjs`)

- Платный запрос — только при `--budget-credits=N` И `ELEVENLABS_PAID_TESTS_APPROVED=<сегодняшняя дата ГГГГ-ММ-ДД по Душанбе>` в оболочке (с 12.11 — разрешение на один день, по ревью). Без них
  `voice:sim` не делает ни одного запроса вообще (тест). Перед стартом — остаток подписки (бесплатный GET), бюджет
  больше остатка — отказ; между видами звонка — стоп, когда потрачено ≥ бюджета или счётчик не читается; в конце —
  «потрачено N из бюджета».
- Дыра, найденная по ходу: `load-env.mjs` переносил ВСЕ `ELEVENLABS_*` из `apps/api/.env` — «1», вписанная туда
  однажды, открыла бы замок навсегда. Теперь разрешение из файла не читается никогда (тест).
- Сторож `unguardedPaidScripts`: любой скрипт в `scripts/` и `apps/api/scripts/` с платным адресом
  (`PAID_ENDPOINT_PATTERNS`) обязан звать `openPaidBudget(`. Проверен нарочной поломкой дважды: копия `suite.mjs` без
  вызова и выдуманный `narration-model-bench.mjs` во вложенной папке ловятся; плюс ручная поломка самого `suite.mjs` —
  тест краснеет.
- Обход по классу: других платных скриптов в репозитории нет (поиск адресов TTS/STT/agent-testing/dubbing/music по
  `scripts/`, `apps/api/scripts/`, `.github/`). `narration-model-bench` и TTS-замеров в этом репозитории нет — есть
  только в продукте (`propertyNarration.ts`, `assistantVoice.ts`), это не скрипты. preflight и patch-check бесплатны:
  только GET/PATCH агента и функций (тест: в их исходниках нет платных адресов).
- Ограничение (ОЦЕНКА): сторож статический — платный вызов через функцию продукта или адрес, собранный из кусков, он
  не увидит. Бюджет проверяется между видами звонка: внутри одного вида (одна пачка run-tests) перерасход возможен на
  стоимость этой пачки; ElevenLabs может обновлять `character_count` с задержкой — НЕТ ДАННЫХ.

## Б. Потолок минут робота (`apps/api/src/lib/liveVoiceSpend.ts`, чистая часть — `packages/shared/src/liveVoiceSpend.ts`)

- Учёт по `LiveVoiceSession` поставщика `elevenlabs`: конец − начало, у незакрытой — до сейчас, но не больше 15 мин
  (потолок звонка в мосте; совпадение чисел сверяет тест). Сутки и месяц — по Душанбе.
- Настройки: `liveVoiceDailyMinutesCap` = 30, `liveVoiceMonthlyMinutesCap` = 250; 0 — без потолка. Экран: Бот →
  «Живой голос по телефону» (виден при голосе ElevenLabs): два числа, одна кнопка, строка «Сегодня: X из 30 мин · за
  месяц: Y из 250 мин». Один адаптивный экран — у Настроек нет отдельной мобильной версии.
- Расчёт умолчаний (ОЦЕНКА, подтвердить у владельца): 250 мин ≈ 220 000 кредитов — в пределах лимита периода с запасом
  на озвучку; 30 мин/сутки ≈ 26 400 кредитов ≈ 15 разговоров по 2 мин — робот в цикле за сутки съест не больше ~11%
  лимита. Месяц календарный, не период подписки ElevenLabs.
- Дошли до потолка: исходящие — дверь П3 `robotCallAllowed` отвечает «перенести» (`minutes_cap_day` /
  `minutes_cap_month`, попытка не тратится, повтор — в начале окна звонков следующих суток/месяца); входящие — то же
  «у ElevenLabs нет минут» (`elevenLabsQuotaExhausted`), что у кончившихся кредитов: звонок сразу автоответчику станции.
  Второй двери в мосте нет, `liveVoiceBridge.ts` не тронут. Идущий разговор не рвётся. Проверочный звонок владельца не
  держится. Удачный разговор, перепроверка остатка и смена ключа снимают только отметку «кредиты кончились» — не потолок.
- Тревога директору на 80% и 100% — через очередь алармов руководству (`enqueueDirectorAlert`, уровень CRITICAL), одна
  на порог за период (тег `live-voice-spend:<сутки|месяц>:<порог>:<ключ периода>`, повтор гасит `shouldAlert`; после
  перезапуска процесса тоже). Перескочили 80% разом до 100% — одна тревога. ФАКТ (push.ts): прежний путь «КРИТИЧНО» в
  `logSystemError` директору пушем НЕ доходит с 02.10.2026 — только журнал и утренний отчёт.
- Тик `live-voice-spend-ceiling` раз в минуту в процессе api (там память моста), первый проход при старте; сохранение
  потолка или голоса перечитывает сразу. Сбой базы при подсчёте — дверь «попробуйте позже», а не «звоните».
- Найдено тестом до выкатки: конец месяца считался по UTC-месяцу начала месяца по Душанбе (1-е 00:00 Душанбе = последнее
  число 19:00 UTC) — пауза «до следующего месяца» кончалась бы сразу. Исправлено на часы Душанбе.
