# 27.11.2026 — клиент по объекту доходит до хозяина объекта во всех каналах

**Просьба владельца (27.11):** «очень важно, чтобы бот ИИ узнал объект и по рекламе, и по переписке, и по скриншотам,
и когда кто-то обращается конкретно к этому объекту; как сделать, чтобы агенты не теряли своих клиентов».
Повод — звонок 26.11 (клиент ПК-001086 по объекту №230 ушёл чужому агенту); звонковое узнавание уже выкачено в #470.

## Что было (разведка по origin/main 806749910)
Общий шаг раздачи `services/leads/assignment.ts::assignAgentForLead` умеет «объект назван явно» (`propertyId`), но:
1. Новый бот (CORE, WhatsApp/Instagram/Facebook) узнавал объект (номер, ссылка, пересланный пост/ролик, скриншот с
   логотипом) в `BotConversation.customerPropertyFocus`, а в заявку передавал только рекламу; связь «диалог ↔ объект»
   (будит хозяина объекта) не писал вовсе.
2. Звонок клиента, пришедшего с рекламы объекта, рекламу не учитывал (прежний узнаватель сравнивал внешний id Meta с
   внутренним `Ad.id`, убран в #470).
3. Скриншот карточки без нашего логотипа не узнавался.
4. Личка Telegram (Direct Messages канала): номер объекта в словах клиента игнорировался.
5. WhatsApp: заказ из каталога показывал голый id товара; переход с публикации (`referral.source_type = post`) искался
   среди объявлений.
6. Клиент уже у другого агента: перенос непринятой заявки был только переменной окружения.

## Что сделано
Рубильники в Настройках (группа «ИИ решает за агента», миграция `20261127120000_object_to_owner_switches`):
- `chatObjectToOwnerEnabled` (ВКЛ) — п.1, 3, 4. ВЫКЛ = как в main.
- `callAdObjectToOwnerEnabled` (ВКЛ) — п.2. ВЫКЛ = как в main.
- `objectInterestPullsQueueLeadEnabled` (**ВЫКЛ**) — п.6. Владелец 27.11 выбрал «Оставить + показ хозяину»: клиент
  остаётся у своего агента, хозяину объекта уведомление (оно было и раньше). Переменная
  `OBJECT_INTEREST_PULLS_QUEUE_LEAD` осталась аварийной ручкой поверх ("1"/"0").

По пунктам:
1. `lib/customerFocusOwner.ts`: `customerFocusPropertyForLead` — объект фокуса (только «узнан», та же переписка и
   область) кладётся в заявку ПОКУПАТЕЛЯ (`customerNewLeadBridge.ts`), дальше обычный путь «назван явно» (там проверка
   «продан/снят», «хозяин отключён»). Объект разговора сильнее первой рекламы. `linkResolvedCustomerFocus` — после
   записи фокуса (`customerPropertyTurnContext.ts`, `customerAgentMediaFocus.ts::enrichFocus`) пишет связь «диалог ↔
   объект», та будит хозяина. Ответ клиенту не ждёт и не ломается.
2. `lib/telephony/callAdProperty.ts` + `qualifyIncoming.ts`: если расшифровка объект не назвала, а покупатель за
   30 дней писал нам с рекламы одного объекта, — объект рекламы считается названным явно (перебивает снявшего
   трубку, как узнанный консультантом). Запись в хронологию «Клиент пришёл в переписку с рекламы объекта №…».
3. `customerAgentMediaFocus.ts::customerListingCardFactsSelectors`: карточка объявления без логотипа — по цене и
   площади/комнатам (`sharedPostCard.ts::matchPropertyByFacts`), только если в продаже ровно один такой объект.
4. `telegramDirectMessages.ts`: номер/ссылка в словах клиента → `propertyId` заявки, только покупателю.
5. `meta.ts`: id товара из цифр → «объект №N» (`home_listing_id` фида = номер объекта); `source_type = post` → номер
   поста (`adPostId`). **Без рубильника**: разбор вебхука синхронный; это подпись и маршрут поиска, не раздача.
   `referral.source_url` не разбирается (не нашлось формата, который даёт номер объекта без догадок).

Продавцу ни один из новых путей объект не подставляет: он описывает своё жильё.
