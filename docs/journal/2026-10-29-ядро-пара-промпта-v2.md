# 29.10.2026 — ядро бота: вторая закреплённая пара промпта (V2) для #41

**Что.** Выкат #41 остановило облако: три теста Codex (`customer-agent-routine-refresh-postgres`,
`customer-agent-revision-advance-postgres`, `customer-recruitment-upgrade`) закрепляют хеш текущего
промпта как `CUSTOMER_AGENT_QUALITY_CONTINUITY_UPGRADE_V1.toPrompt`. #41 добавляет в промпт правило
адресата комментария (`serverPublicState.addressee`) и поля в общие схемы — хеши промпта и схемы знаний
сменились, а без закреплённой пары обычное «Обновить версию бота» на проде отказывает
`revision_advance_configuration_changed`.

**Как.** По образцу Codex (PR #51): `lib/customerAgentQualityContinuityUpgrade.ts` получает
`CUSTOMER_AGENT_QUALITY_CONTINUITY_UPGRADE_V2` (from = V1.to, инструменты те же, схема знаний
9221c… → f78386…), `isCustomerAgentQualityContinuityUpgradeV2` и `customerAgentQualityContinuityUpgradeVersion`
(ровно одна пара; прыжок V1.from → V2.to — не обновление). `customerAgentOwnerPolicy.ts` проверяет пару через
версию и пишет её в аудит (`qualityContinuityUpgradeVersion: "v2"`). V1 остаётся историей, не псевдонимом.

**Чем проверено.** `npx vitest run` трёх файлов на стенде: 73/73; `tsc --noEmit` чисто. Полный прогон —
облако `npm run ship -- --pr=41`.

**На проде после выката.** Обычное обновление версии откажет `quality_continuity_upgrade_confirmation_required`;
нужен вызов с `confirmQualityContinuityUpgrade: true` (окно обслуживания настроек у директора действует до 21.11).
