# 15.11.2026 — Никого не пропускать, вторая волна: Telegram, WhatsApp, сообщение без чата CRM

Ответ владельца 15.11 (В4 «да»): сверка «сообщение не дошло до CRM» нужна не только для Messenger. Задача 5 — тикет ядра без чата.

- **Telegram (В4).** `TelegramConversation` и `TelegramDirectConversation` не смотрел ни один сторож. Теперь сторож
  «клиент ждёт ответа» (`runClientSilenceSweep`, раз в 10 мин, в часы раздачи) смотрит и их; сигнал — через ту же дверь
  `alertClientWaiting` (`source: "telegram" | "telegramDirect"`): агенту клиента, без агента — руководству, раз на эпизод
  (отметка эпизода — `ProcessedMessage` канала `client-waiting-telegram`, миграции ради неё нет). Ссылка `/messages?open=tg_…`
  или `td_…`; для Telegram Direct подсказка «ответьте в Telegram» (из CRM туда не ответить). Прод: 10 переписок Telegram,
  3 за неделю, Direct — 0. Намеренное молчание бота Telegram («спасибо» без нашего вопроса, повтор поста/фото) не тревожит —
  тот же признак `silentTurnReason`, по которому молчит сам бот. Рубильник `telegramSilenceWatchEnabled` (ВКЛ). Чат сайта уже в `BotConversation`.
- **WhatsApp (В4).** ФАКТ (developers.facebook.com/docs/whatsapp/cloud-api/guides/set-up-webhooks): входящие Cloud API
  приходят только вебхуком, метода «список входящих» нет — сверить по одному сообщению нельзя. Сделано лучшее доступное:
  `lib/whatsappWebhookWatch.ts`, крон раз в 20 мин в рабочие часы: входящих нет дольше обычного (самая длинная пауза в
  рабочие часы за 7 дней ×1,5, в пределах 3–8 ч; ночь не в счёт) — тревога руководству в «Здоровье системы» раз в 6 ч с
  причиной из Graph (только чтение): номер не CONNECTED, маркер не читает номер, приложение не подписано на кабинет WhatsApp,
  или «всё живо — проверьте адрес вебхука». Меньше 20 входящих за неделю — не судим. Рубильник `whatsappWebhookWatchEnabled` (ВКЛ).
  Не ловит: потерю отдельных сообщений при живом потоке, тишину ночью и в первые часы спокойного дня, второй номер при живом первом.
- **Сообщение без чата CRM (задача 5).** Тикет ядра без `conversationId` (`reportUnansweredCustomerTurn`) и непереданное сообщение
  без записи в чат (`scope_denied`/`no_mid`) раньше давали только строку в журнале. Теперь `pushStaffAboutUnrecorded`: пуш CRITICAL
  «Ответьте вручную» всем с правом «Сообщения» — канал, наш аккаунт, у WhatsApp номер; кто писал — из зашифрованного входа самого
  тикета. Раз на человека за 6 ч (атомарная отметка, при сбое снимается). Чат, удалённый сотрудником, не зовёт (его решение).
  Прод (30 дней): без чата и не намеренно — `own_identity_registry_incomplete` 56 (23 чел., 08–10.11), `sender_read_unavailable` 19 (14 чел.).
