# 24.10.2026 — Удаление расхода учитывает показанную версию

- Что изменилось: таблица передаёт существующему обработчику удаления ID и версию расхода, сохранённого в открытом подтверждении. Если другой сотрудник уже исправил расход, сервер возвращает существующий409 и исправленная запись остаётся активной.
- Почему: таблица отправляла только ID и обходила уже реализованную защиту от устаревшего подтверждения. Собственная HTTP/PostgreSQL проверка подтвердила архивирование исправленной суммы250 после подтверждения старой100; запрос с версией0 корректно отклонялся.
- Чем проверено: исходный Chrome —2ошибки устаревшего подтверждения и4проходящих обычных/readonlyконтроля; итоговый Chrome1440/390 —6/6PASS, включая точный query версии0,409/ошибку без успешного Undo и нормальное удаление с настоящим Undo. Существующие unit3/3PASS, отдельная строгая типизация fixture/spec/config PASS. Подробности: `docs/audit-20261024/FINAL-EXPENSE-TABLE-ARCHIVE.md`.
- Границы: изменён один вызов таблицы; API, hook и политика прав сохранены. Браузер использовал перехваченный синтетический транспорт, PostgreSQL — отдельную собственную БД. Production и реальные провайдеры не затрагивались; полный пакет проверяет координатор.
