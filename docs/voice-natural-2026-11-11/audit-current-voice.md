## 3. Путь звука (звено за звеном)

Звонящий (мобильный, Таджикистан) -> оператор -> станция:
1. Сотовая сеть/оператор -> транк станции. Кодек и потери неизвестны (НЕТ ДАННЫХ). Обычно G.711/AMR-WB сжатие уже на этом звене. Потеря качества: ВОЗМОЖНА (ОЦЕНКА), мы её не контролируем.
2. Станция: Asterisk мост (ARI) + externalMedia ulaw 8 кГц -> RTP по UDP через OpenVPN tun0 в Германию. Задержка: ~106 мс RTT станция-сервер (ФАКТ 11.11), в одну сторону ~53 мс, плюс джиттер VPN. Потеря: UDP поверх VPN, потери пакетов -> «провалы» в речи; джиттер-буфера на нашей стороне НЕТ, кадры сразу идут дальше (ОЦЕНКА по коду wireRtpSocket: liveVoiceBridge.ts:4540-4625).
3. CRM (netcup, Германия): RTP -> ulawDecode -> эхо-гейт -> (зануление кадра, если «эхо») -> resamplePcm16 8->8 (ничего не меняет) -> ulawEncode -> base64 в JSON -> WebSocket в ElevenLabs. Качество: без потерь, ulaw туда-обратно детерминирован (ФАКТ по коду: pcmCodec.ts:223-254, liveVoiceBridge.ts:4624-4625). Задержка: по 20 мс на кадр + base64/JSON, мелкая.
4. CRM -> api.elevenlabs.io (США по умолчанию, ОЦЕНКА): TLS WebSocket. Замер 24.10: «дорога до США 0,2 с» (память sip-test-24-10; со старого VPS; с netcup не измерялась, НЕТ ДАННЫХ).
5. ElevenLabs: ASR (Scribe realtime, ru ИЛИ tg по языку разговора) -> turn_v3 / eager -> LLM (DeepSeek Flash 4.1, промт 20-70 КБ с досье) -> TTS eleven_v4_turbo -> ulaw_8000 обратно. Звенья задержки: конец реплики (turn_timeout до 5 с в «неуверенных» случаях), TTFT модели, первый чанк TTS. Потеря качества: TTS синтезирует сразу в 8 кГц mu-law (самое узкое звено по частоте, но это штатно для телефона).
6. Обратно: ulaw_8000 -> ulawDecode -> + офисный фон 0.45 -> ulawEncode (повторное квантование, шум квантования) -> очередь пейсера -> RTP -> VPN -> станция -> оператор -> телефон. Ответ ElevenLabs приходит быстрее реального времени, мост кладёт его в очередь до 10 с и играет по 20 мс; перебить хвост может только событие interruption от ElevenLabs или локальное перебивание.
7. Конец реплики для моста = 1 с без аудио от ElevenLabs (ELEVENLABS_TURN_IDLE_MS, elevenLabsVoiceClient.ts:79, 616-624): пауза внутри ответа дольше 1 с (вызов функции, долгая генерация) выдаёт ложное turnComplete (ОЦЕНКА, влияет на сторожа/язык/окончание звонка).

Суммарно (ОЦЕНКА по звеньям, не измерено на линии): VPN 106 мс RTT + Германия-США ~100-200 мс + ASR endpointing + LLM TTFT + TTS = типично 1,5-3 с до первого слова. Метрика на звонке есть (liveVoiceMetrics.ts, строка итога в журнале) — смотреть её по conv_5301m75ff68pewj83er5q76dy2gf в логах api rh-new.

## 4. Жалобы владельца и что их объясняет

### Качество звука
- ФАКТ: CRM примешивает свой офисный фон с голосами на 0.45 под речь робота и в паузы (settingsConstants.ts:70-72). Владелец проверял «фон выключен» в кабинете ElevenLabs, но этот фон собственный, из CRM, и от кабинета не зависит. Источник «шума/людей на заднем плане» и ухудшения разборчивости (повторное квантование ulaw поверх микса).
- ОЦЕНКА: TTS сразу в ulaw_8000 + сотовая сеть + возможные потери UDP по VPN = «телефонный» тембр; speed 1.15 при stability 0.45 звучит торопливо.
- ОЦЕНКА: голос «Kate» русский; на таджикском даёт «аканье» (journal 2026-11-11-voice-tajik-speech.md).

### Таджикский язык
- ФАКТ: язык разговора (ASR + голос) выбирается на старте. Поправка CRM при переходе звонящего на таджикский — только текст `user_message` модели («дальше говори по-таджикски»), она НЕ меняет ни язык ASR, ни голос (liveVoiceBridge.ts:3962-3975, liveVoiceCallerLanguage.ts:157-161). Стартовали в ru -> распознавание таджикской речи ломается (замер 11.11: в ru-режиме таджикская речь теряется почти полностью, СРЫВ_1 1/9; в tg-режиме 3/9 и 9/12).
- ФАКТ: переключение на другой язык CRM делает только после ДВУХ уверенных кириллических реплик подряд (CALLER_LANGUAGE_SWITCH_AFTER=2, liveVoiceCallerLanguage.ts:38) -> это дополнительные секунды неправильного языка в начале таджикской речи.
- ФАКТ: если голос tg не задан, таджикский говорит русский голос Kate (elevenLabsVoiceClient.ts:253-258). Задан ли ELEVENLABS_VOICE_ID_TG/`elevenLabsVoiceIdTg` на проде — НЕТ ДАННЫХ; HANDOFF пункт 4 просит проверить.
- ФАКТ (замер 11.11): числа на таджикском нормализатор читал неверно -> перешли на system_prompt (числа словами). Подтверждённого словаря произношения нет (подтверждённых правил нет).
- ОЦЕНКА: sovsem таджикский ASR Scribe слабее Gemini Pro; «шумное» распознавание уже отмечено 24.10.

### Задержка / пауза
- ФАКТ (HANDOFF:116-117): пауза ~6 с на «хона доред»: модель выдала «...», через 5 с CRM вставила служебное «человек говорит по-таджикски…», ответ на 1:33. Причины в коде: (а) гистерезис 2 реплики; (б) сторож «модель молчит» MODEL_STALL_NUDGE_MS=10 с / служебные реплики идут как user_message, то есть ещё один ход LLM; (в) turn_timeout=5 с у ElevenLabs (elevenLabsAgentSync.ts:346) — при неуверенной конечной точке агент ждёт до 5 с.
- ОЦЕНКА: фоновая задержка линии: 106 мс VPN + Германия-США + ASR + LLM + TTS; DeepSeek Flash 4.1 через ElevenLabs не измерялась на таджикском в этом аудите (24.10: Gemini-3.8-flash 1,3-2,2 с на ru/tg).
- ФАКТ: подготовка агента перед звонком может занять до 12 с, если память процесса пуста (после выката); прогрев на старте и по кнопке это снимает (liveVoiceWarmup.ts).

### Эхо и перебивания (bargeIns 10, interrupted 4, echoFrames 3046, echoThreshold 64, talkOver до 11 с)
- ФАКТ: ElevenLabs принимает наш звук как есть; «interrupted» присылает ОН сам по своему VAD. Мы лишь зануляем кадры в хвосте речи бота тише порога (liveVoiceBridge.ts:4558). Порог эха 64 (очень низкий, адаптивный) -> гейт почти не режет эхо, ElevenLabs сам видит всё, что вернулось в трубку.
- ОЦЕНКА: самоперебивание = эхо/шум звонящего в канале (возможно, свой же офисный фон 0.45 с голосами, который ушёл в трубку и вернулся с микрофона телефона; прямых данных нет) + eager turn_eagerness + 15 слов игнора поддакиваний. 11 с «talkOver» объясняет очередь пейсера: ElevenLabs отдаёт звук быстрее реального времени (до 10 с в очереди), а сброс хвоста приходит либо по событию interruption (его сетевой путь Германия-США-VPN-станция), либо по локальному перебиванию, которое выключено в приветствие и пока модель считается «говорящей» (liveVoiceBridge.ts:4540-4570).

### Сокет 1006 в конце звонка
- ФАКТ: код 1006 = закрытие без close-кадра (обрыв TCP), нормальный конец у ElevenLabs — 1000 (isElevenLabsNormalEnd, elevenLabsVoiceClient.ts:219-221). Лог сокета пишется строкой «сокет ElevenLabs закрыт: код…» (elevenLabsVoiceClient.ts:~485).
- ОЦЕНКА: обрыв маршрута Германия-США или закрытие со стороны ElevenLabs после нашего hangup. Решить можно только по логам api rh-new 14:16-14:20 UTC и их журналу разговора conv_5301m75ff68pewj83er5q76dy2gf. Данных в репо нет.

### Расход кредитов (880/мин)
- ФАКТ (HANDOFF:113): 1816 кредитов за 2 мин 4 с (~880/мин), в 2 раза выше прежней оценки 450/мин (память credits-spent-by-tests). Причина: длинный промт (персона + справочник + досье) и LLM внутри ElevenLabs оплачиваются кредитами; ОЦЕНКА, замер размера промта по виду звонка не делался.
