# Робозвонок на ElevenLabs: порядок проверки с ключом (11.11.2026)

Цель: от «ключ пришёл» до включённого переключателя за несколько команд. Скрипты лежат в
`scripts/elevenlabs/`, все они **только читают или меняют ТЕСТОВОГО агента**, боевого не трогают,
ключ нигде не печатают (тест-сторож `scripts/elevenlabs/elevenlabs-scripts.test.mjs`).

## 1. Переменные (`apps/api/.env` или окружение сессии; в git не попадают)

| Переменная | Что | Нужна для |
|---|---|---|
| `ELEVENLABS_API_KEY` | ключ ElevenLabs | всех шагов |
| `ELEVENLABS_AGENT_ID` | боевой агент (тот же, что в Настройках → голос робота) | preflight; для PATCH и симуляций служит только защитой «тестовый ≠ боевой» |
| `ELEVENLABS_TEST_AGENT_ID` | **отдельный** тестовый агент, созданный в кабинете ElevenLabs | patch-check, симуляции |
| `ELEVENLABS_VOICE_ID_RU`, `ELEVENLABS_VOICE_ID_TG` | голоса из Настроек (необязательно) | preflight, пресет tg |
| `ELEVENLABS_API_BASE` | адрес API через посредника (необязательно) | всех шагов |
| `VOICE_REPORT_DIR` | куда класть отчёты; по умолчанию `~/royalhome-voice-reports` (вне git) | отчётов |

Скрипты сами читают `ELEVENLABS_*` из `apps/api/.env`, и значения из .env ПЕРЕКРЫВАЮТ переменные оболочки (устаревший ключ в окружении Windows давал 401 при свежем ключе в .env; скрипт скажет, какие имена заменил, значения не печатает).

Тестового агента завести вручную один раз: в кабинете скопировать боевого (или создать пустого с тем же
языком и моделью). Он будет перезаписываться скриптами.

## 2. Порядок

```bash
npm run build:shared && npm run prisma:generate        # один раз в свежей копии
npm run voice:preflight -- --dry                       # без сети: что будет проверено
npm run voice:preflight                                # 1) доступ, ключ, агент, голоса, tg у модели
npm run voice:patch-check                              # 2) живой PATCH на ТЕСТОВОМ агенте
npm run voice:sim                                      # 3) 19 симуляций разговоров (тратят кредиты)
```

1. **preflight** (только чтение). Печатает код ответа и задержку `api.elevenlabs.io`, валиден ли ключ,
   есть ли агент, голоса, и знает ли модель `eleven_v4_turbo` таджикский (по списку языков из `/v1/models`).
   С сервера rh-new его запускают командой выше (проверка доступа из Германии); **запуск на сервере —
   только с «да» владельца**. Распознавание таджикского API не отдаёт: оно проверяется только на слух.
2. **patch-check**. Делает то же, что сервер перед звонком (`ai/elevenLabsAgentSync.ts`): заводит наши
   функции, PATCH №1, PATCH №2, после каждого GET и сравнение. В отчёте: принято / потеряно / изменено,
   ключевые поля (`built_in_tools.language_detection`, `language_presets.tg`, формат звука, `turn.*`) и
   «глубокое слияние»: что из НЕ отправленного пропало. Красное здесь = править `buildAgentTuningPatch`
   (`ELEVENLABS_PHONE_AGENT_TUNING`) до включения переключателя. Снимок агента «до» лежит в отчёте
   (`agent-before.json`) для ручного отката в кабинете.
   С 11.11.2026 PATCH №2 ещё кладёт слова распознавания (`asr.keywords`, ≤50) и — только из правил,
   подтверждённых владельцем, — таджикский словарь произношения (`ai/tajikVoiceLexicon.ts`,
   `approved: true`). Словарь агента звучит и в русской речи, поэтому в нём только слова с ҳ/ӯ/ӣ/қ/ғ/ҷ
   (разбор — `docs/journal/2026-11-11-voice-tajik-speech.md`).
3. **voice:sim**. 19 симуляций (приглашение кандидата ru и tg, опрос после показа, проверка собственника,
   звонок клиенту) на ТЕКУЩИХ промптах CRM: промпт вида звонка и его функции пишутся в тестового агента,
   затем тесты-симуляции ElevenLabs (`agent-testing`), функции подменены заглушками. Проверяется: не
   выдумывает, не переносит встречу сам, без «лутфан», честно отвечает «вы робот?», дошёл до `end_call` с
   правильной причиной или до `save_client_request` с полными полями. Модель разговора на прогон: `-- --llm=gemini-3.8-flash` (пишется в ТЕСТОВОГО агента и остаётся там; без `--llm` идёт та модель, что стоит у агента, итог её называет). CRM сама `llm` в PATCH не ставит — берёт то, что выбрано у агента в кабинете. Сетевые сбои (UND_ERR_CONNECT_TIMEOUT и т.п.) повторяются с паузой; «неопределённо» в отчёте — разговор оборвался до прощания агента (предел ходов), а не ошибка агента. Судья ElevenLabs не видит промпт: факты, которые у агента есть (адрес, ориентиры, телефон, условия вакансии), перечислены в `scenarios.mjs` (NO_INVENT) — при смене `ai/vacancyFacts.ts` обновлять там. Фильтр: `-- --only=client` или
   `--only=invite-ru-agree`; `--keep` — не удалять созданные тесты. Отчёт: `sim-<время>/report.md` с расшифровками.
   Старый `simulate-conversation` ElevenLabs снят с 31.10.2026 — скрипт использует новый метод.
4. **Один живой звонок на номер владельца** — решение владельца, не скрипта: Настройки → «Тестовый звонок»
   на свой номер (после включения поставщика ElevenLabs там же). Слушать: таджикский, паузы, «лутфан».
5. **Переключатель** Настройки → голос робота → «ElevenLabs» (`Settings.liveVoiceProvider`), вписать ключ,
   id агента и голоса (ключ в Настройках хранится зашифрованным). Кнопка «Проверить агента» повторяет
   подготовку и показывает причину отказа PATCH.

## 3. Откат на Google

Настройки → голос робота → «Google (Gemini)». Действует со следующего звонка, идущий разговор доводит
прежний поставщик. Значение по умолчанию в базе — `google`: при сбое чтения настроек звонок сам идёт
через Gemini. Агента в кабинете ElevenLabs откатывать не нужно: подготовка пишет в него только
наши поля, звонки Gemini его не используют.

## 4. Что скрипты НЕ делают

- не звонят и не создают звонков (ни одного запроса к SIP/outbound/call);
- не меняют боевого агента (отказ при `ELEVENLABS_TEST_AGENT_ID == ELEVENLABS_AGENT_ID`);
- не отдают ключ в вывод и отчёты (`redact` чистит ключ и всё, похожее на ключ);
- не оценивают голос и задержку на линии: это слух владельца на живом звонке (пауза 1,3–2,2 с по замеру 24.10).
