# План: все тексты объекта из одного места (владелец 15.11.2026)

Владелец: «чтобы все описания были одинаковыми … у сайта другое описание, у
Инстаграма другое, потом когда меняешь — и обложка, и всё такое».

## Сейчас (ФАКТ по коду)
| Что | Откуда берётся | Когда собирается |
|---|---|---|
| Обложка (цена на картинке) | `video/coverOpenAi.ts::makePropertyCover` из полей карточки | в момент публикации |
| Подпись Instagram/FB/TG/YouTube | `Property.reelsCaption` — сохранённый текст (шаблон или ИИ `reelsCaptionAi.ts`) | при создании, дальше правится заменой |
| Описание на сайте | `Property.description` — ИИ `seoGenerator.ts` или текст агента | при создании, дальше правится заменой |
| SEO (title, h1, meta) | `seoGenerator.ts`, пересобирается при правке нужных полей | при правке |
| Подпись монтажёру, Telegram-модерация, дайджесты, репосты, сторис | каждая собирает цену/факты сама (`buildPriceDisplay` в 6+ местах) | в момент отправки |

Корень разъезда: факты (цена, площадь, этаж…) лежат КОПИЕЙ внутри готовых
текстов, и каждую копию потом пытаются найти и заменить. Любая замена, которая не
нашла старый текст, молча оставляет старое.

## Цель
1. Текст объекта = «живая часть» (вступление, концовка — пишет ИИ или человек,
   хранится отдельно) + блок фактов, который НИКОГДА не хранится, а собирается из
   полей карточки одной функцией `renderListingFacts(property, channel)` в момент
   показа/публикации.
2. Сайт, все соцсети, обложка, монтажёр, сторис зовут одну функцию; формат цены —
   одна функция (уже есть `buildPriceDisplay`).
3. Сторож в CI: запрет нового `formatPrice`/`buildPriceDisplay` в текстах объекта
   мимо `renderListingFacts`.
4. Старые объекты: разовый перенос — вырезать блок фактов из сохранённых текстов,
   оставить живую часть.

## Шаги (каждый — своя ветка)
1. `renderListingFacts` + тесты «сайт = соцсети = обложка» по одной карточке.
2. Подпись соцсетей: хранить только живую часть, факты — при публикации.
3. Описание сайта: то же; сайт получает собранный текст.
4. Перевести дайджесты, репосты, сторис, монтажёра.
5. Перенос старых объектов (пробный прогон на копии базы, потом «да» на прод).
6. Ревью всего диффа агентом architect перед выкаткой (деньги/публичные тексты).

Перед началом — проверить по базе 3–5 последних объектов, где тексты разошлись
(нужен «да» на чтение базы прода), чтобы список багов был по фактам, а не догадкам.
