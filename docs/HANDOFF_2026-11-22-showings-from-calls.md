# HANDOFF 22.11.2026 — показы из звонков и переписки: объект, напоминание, «показ был?»

## Что выяснено (аудит кода origin/main, 21.11)
- `apps/api/src/ai/callAnalysis.ts`: ИИ из расшифровки берёт исход, `showingAt` (Душанбе, не прошлое, ≤90 дней), цитату.
- Автопоказ (`scheduleShowing`) ставится ТОЛЬКО если `findMatchingPropertiesForClient` дал ровно 1 объект.
  Объект берётся из подбора, а НЕ из разговора; доказанный объект `resolveCallPropertyId` (matchedPropertyId)
  вычисляется, но для показа не используется → риск «не тот объект».
- 0 или 2+ объекта → показ не создаётся; окно «Назначьте показ» удалено 13.09; остаётся тихая запись
  `BuyerShowingCandidate` (PREVIEW, никого не будит) → договорённость теряется.
- Переписка агента: `lib/operatorShowingDetector.ts` ставит показ сам (рубильник `aiAgentShowingAutoBookEnabled`, умолч. ВКЛ).
- Напоминания агенту: `lib/meetingReminders.ts` — за день, 2 ч, 40 мин.
- Робозвонок после показа: `lib/postShowingCall.ts`, рубильник `postShowingCallEnabled` (умолч. ВЫКЛ). Состояние на проде — НЕТ ДАННЫХ.
- Окна «Итог показа» убраны 14.09.

## Решения владельца 22.11 (дословно по смыслу)
1. «За 2 час хватит одно напоминание» — у показа оставить ТОЛЬКО напоминание за 2 часа (убрать «за день» и «за 40 мин»).
2. Робозвонок после показа — «не надо» (держать выключенным).
3. «Итог показа» вернуть, но по-другому: крупно спросить «У вас был показ?» → Да → следующий шаг
   (что дальше с клиентом); Нет → перенести/отменили.
4. Вопрос владельца: если ИИ услышал/прочитал о показе, но не понял до конца — через минуту спросить агента,
   возможно через бота Шабнам (Telegram). Ждёт моего мнения.

## Рекомендация (дал владельцу 22.11, ждёт «да»)
- Главный путь — в CRM (пуш + крупная карточка, НЕ блокирующая экран: блокирующие окна владелец уже отменял, «достало»),
  Шабнам — дубль того же вопроса с кнопками (правило owner-build-rules: Telegram только альтернатива).
  Ответ в одном месте закрывает вопрос в другом.
- Неясная договорённость (нет объекта или даты): через ~1 мин после разбора — «Договорились о показе с X на 22.11 18:00? Да / Нет»,
  при Да — выбор объекта в одно касание.
- Через ~1 ч после времени показа: «Показ с X состоялся?» Да → шаг: ещё показ / подобрать другие / думает, перезвонить (дата) / отказ.
  Нет → перенести / отменён.
- Плюс починка выбора объекта: названный в разговоре (ОБ-код/адрес) → matchedPropertyId → подбор ровно 1.
- Всё за рубильниками (умолч. ВКЛ), тесты на «не тот объект» и «объект неясен». >5 файлов → ревью architect перед ship.

## РЕШЕНИЕ ВЛАДЕЛЬЦА 22.11 (заменяет рекомендацию выше)
«Лучше показы делать уведомлением с кнопками в Шабнам, там люди охотнее нажимают кнопку, и после разговора
можно своими словами отвечать Шабнам: да, у нас показ».
- Главный канал вопросов о показах — Шабнам (Telegram): кнопки + ответ свободным текстом/голосом
  (Шабнам уже понимает «добавь объект» любыми словами — тот же приём).
- Вопросы: (а) через ~1 мин после звонка/переписки, если ИИ понял не до конца — «договорились о показе? когда? какой объект?»;
  (б) через ~1 ч после времени показа — «показ был?» → Да: следующий шаг; Нет: перенести/отменили.
- Ответ обязательно пишется в CRM (показ, календарь, хронология), CRM — хранилище, Шабнам — интерфейс.
- Страховка (моё предложение, без отказа от решения): агент не привязан к Шабнам или не ответил N часов → тот же вопрос пушем в CRM.
- Напоминание агенту — одно, за 2 ч. Робозвонок после показа — не включать.
